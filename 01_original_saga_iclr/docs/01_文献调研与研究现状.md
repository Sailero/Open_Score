# 文献调研与研究现状报告

**主题**：集群对抗中可扩展、可泛化的动态分组分簇与底层协同作战
**调研日期**：2026年7月
**目标会议**：ICLR 2027（预计截稿：2026年9月下旬）

---

## 1. 调研范围与方法

围绕"两个集群对抗时，如何以数量无关（scale-invariant）、对手无关（opponent-agnostic）的方式完成高层动态分组分簇 + 底层小规模作战"这一核心问题，本报告调研了五条研究主线：

1. **数量无关/置换不变的可扩展 MARL 架构**（可扩展性的架构基础）
2. **平均场与大种群竞争博弈**（可扩展性的博弈论基础）
3. **种群自博弈、PSRO 与对手泛化**（泛化性的训练范式）
4. **对手建模与在线适应**（泛化性的推理机制）
5. **分层 MARL 与集群空战应用**（问题场景的直接相关工作）

另附：可用仿真环境与基准的调研。

---

## 2. 主线一：数量无关/置换不变的可扩展架构

**核心思想**：把每个智能体/实体的观测视为一个无序集合（set），用共享编码器 + 置换不变聚合（Deep Sets、注意力池化、Set Transformer）处理，使网络结构与智能体数量解耦。

### 代表工作

- **SPECTra**（arXiv:2503.11726, 2025）：提出 Single-Agent Query Attention（SAQA），只用观察者作为 query 做交叉注意力，把复杂度从自注意力的 O(n²d) 降到 O(nd)；配合 Set-Transformer 超网络生成 mixing 网络权重，实现智能体数量可变时的值分解。在 SMACv2 与 GRF 上验证，并显式支持"动态种群 + 课程学习"。
- **CPE / GLPE**（arXiv:2508.11706, 2025）：提出中心化置换等变（Centralized Permutation Equivariant）策略，Global-Local PE 网络从局部观测抽取全局信息再融合回局部特征，网络复杂度与智能体数量基本无关，可直接插入价值分解类与 actor-critic 类算法。
- **SetDQN**（IEEE SAMI 2025）：用 Set Transformer 做智能体数量不变的 Q 网络，4 智能体预训练直接迁移到 3 智能体，验证了"数量不变性带来抗损毁韧性"。
- **HRL for Optimal Agent Grouping**（arXiv:2501.06554, 2025）：把"分组"本身作为高层 option，用置换不变的 Deep Sets 架构对"组"做嵌入，避免枚举指数级分组空间。**与我们最相关**——但它只处理**合作**场景下的静态最优分组，不涉及对抗、对手驱动的动态重组。

### 小结与空白

架构层面"数量无关"已较成熟（注意力/Deep Sets 是标准答案），但现有工作几乎都在**合作任务**（SMAC、GRF）上验证；在**竞争性两队博弈**中，"我方数量变化 × 敌方数量变化 × 对抗中途增减员"的三重可扩展性尚无系统研究。分组分簇结构与数量无关架构的**联合设计**（分簇数 K 如何随双方规模与态势自适应）是明确空白。

## 3. 主线二：平均场与大种群竞争团队博弈

- **MF-MAPPO**（arXiv:2504.21164；ICLR 2026 投稿）：面向零和**团队**博弈（队内合作 + 队间竞争）的平均场 PPO，每队一个共享 actor 和最小信息 critic，可扩展到数千智能体；提供 MFEnv 基准（攻防战场、种群级石头剪刀布），并做在线平均场估计作为对手建模。
- 经典平均场 MARL（Yang et al., ICML 2018）及后续 MFG/MFTG 理论工作。

### 小结与空白

平均场路线在"千级智能体"上可扩展性最好，但**抹掉了个体与小组结构**——恰恰丢掉了我们关心的"分组分簇 + 小规模底层作战"这一中观层次。平均场统计量适合作为**高层观测摘要**（我们可借用），但不能替代显式的分组决策。MF-MAPPO 的存在也说明 ICLR 社区当前对"大规模竞争团队博弈"有明确兴趣。

## 4. 主线三：种群自博弈、PSRO 与对手泛化

**核心思想**：对手策略空间巨大且非传递（non-transitive），单一自博弈容易过拟合到特定对手风格；解法是维护一个多样化策略种群，通过元博弈求解与最优反应迭代逼近均衡。

### 代表工作

- **PSRO**（Lanctot et al., NeurIPS 2017）及大量后续：JBR-PSRO（arXiv:2602.06599，联合经验最优反应，把 BR 训练摊销为离线 RL，大幅降低样本成本）；Global PSRO（arXiv:2605.28273，以种群可利用度 Population Exploitability 显式指导策略扩张）；Fusion-PSRO、Conflux-PSRO（策略路由/融合降低可利用度）。
- **AlphaStar 联赛训练**（Vinyals et al., Nature 2019）：main agents + main exploiters + league exploiters 的三层种群结构，是"泛化到聪明/笨/怪对手"的工程标杆。
- **CSRO**（arXiv:2603.10098, 2026）：用 LLM 生成可解释代码策略作为 PSRO 的最优反应 oracle——提示了"LLM 生成多样化脚本对手"的低成本路线。
- **对抗性课程/无监督环境设计**：Adversarial World Model curricula（arXiv:2509.03771, NeurIPS 2025）——训练一个"出题者"生成敌方单位配置，专门攻击当前策略弱点，自动生成无限课程；UPD（arXiv:2508.06336）——无种群的伙伴设计，用生成-选择机制替代昂贵的策略种群。

### 小结与空白

种群训练是对手泛化的公认答案，但完整 PSRO/联赛在集群对抗上**算力开销极大**。近两年趋势是"轻量化种群"（JBR、UPD、生成式出题者）。对于我们的问题，空白在于：**没有工作把"对手种群多样性"与"跨规模多样性"统一到一个课程里**——即对手不仅风格不同，数量、编成、增援模式也不同。

## 5. 主线四：对手建模与在线适应

- **OEOM**（AAAI 2025）：开放式对手建模——种群训练 + 轨迹空间信息论多样性正则，持续生成不同强度/风格的对手来消除 OOD；配套 In-Context RL 对手建模（IOM），用 Transformer 根据对手轨迹在上下文中识别并响应，**无需梯度更新即可在线适应未见对手**。
- **QOM**（NeurIPS 2025）：把对手策略空间量化压缩为有限潜类型目录，在线维护贝叶斯信念，配合规划实现对未见对手的稳健外推。
- **MAGE**（arXiv:2603.03680, 2026）：元 RL 使 LLM 智能体学会"战略性试探-利用"，对未见对手零样本适应。
- Fictitious Co-Play（Strouse et al., NeurIPS 2021）与 ad-hoc teamwork 一系（伙伴侧的同构问题）。

### 小结与空白

"in-context 对手推断 + 条件策略"是当前对未见对手零样本适应的最有效轻量路线（对比显式贝叶斯规划更可扩展）。空白：现有对手建模几乎全部在**小规模或单体**博弈（poker、MPE、格斗）验证；**集群层面的对手风格推断**（对方在如何分组？主攻方向？激进度？）完全没有被形式化，而这正好可以与我们的高层分簇决策天然结合——把"对手集群行为嵌入"作为分组决策的条件输入。

---

## 6. 主线五：分层 MARL 与集群空战

- **AHDRL_LRS**（Sci China Tech Sci 2025）：异步分层 DRL 做多机空战，高层目标分配 + 低层机动，多头自注意力使高层可处理变长输入，6v6 训练迁移到 20v20；**与我们的可扩展性主张部分重叠，是需要明确区分的近邻工作**。
- **LFMAPPO**（Knowledge-Based Systems 2025）：Leader-Follower 三层架构做 6-DOF 多机空战。
- **HMARL for Air Combat**（Selmonaj et al., ICMLA 2023 / ICA 2025）：3D 空战环境 + 分层 MARL + 课程 + league-play。
- **HRL 空战决策**（Sci Rep 2024）：战术动作类型分层。
- 大量国内期刊工作（DCBCA 深度聚类分组、角色解耦等）。

### 小结与空白

该应用领域论文多但**方法学贡献薄弱**：(a) 分组多为**预定义/启发式**（leader-follower、固定角色、K-means），不是学出来的、不随对抗态势重组；(b) 对手几乎都是**固定脚本或镜像自博弈**，没有系统的对手泛化评测；(c) 规模迁移最多做到 6→20，且无中途增减员；(d) 均发表在应用类期刊/会议，ICLR 级别的方法学抽象（把问题提炼为"双重零样本泛化"）尚无人做。这是我们的机会窗口。

## 7. 可用环境与基准

| 环境 | 特点 | 适用性 | 本机验证 |
|---|---|---|---|
| **JaxMARL / SMAX** (NeurIPS 2024 D&B) | JAX 全 GPU，比 SMAC 快 3-4 个数量级，原生支持自博弈，单位数可自定义 | ★ 主推：改造为两队对抗 + 变规模 + 中途增援 | JAX 在 Windows 无 GPU 支持，正式训练需 Linux/WSL2 |
| **Gigastep** (NeurIPS 2023 D&B) | JAX，10⁹ steps/s，>1000 智能体，异构类型，对抗场景内置 | ★ 备选/第二环境：验证千级规模 | 同上 |
| **MAgent2 battle** (PettingZoo 生态) | 经典大规模格子两队对抗，公认基准，pip 即装 | ★ 公开基准评测轴：架构通用性 + 大规模离散对抗 | ✅ 已装入 gpu_py_310 并跑通（12v12，可扩至百级） |
| **MPE simple_tag** (PettingZoo) | 最经典的连续对抗基准（追捕-逃跑），审稿人零解释成本 | ★ 公开基准评测轴：小规模连续对抗 sanity check | ✅ 已装入 gpu_py_310 并跑通 |
| SMAC / SMACv2 | 社区最公认，但需 StarCraft II 引擎（~4GB、CPU 慢、Windows 配置繁琐），且原生不支持双方都受控的自博弈 | 引用其单位设定；正式实验用 SMAX 替代（同源设定、快 4 个数量级） | 不在本机部署 |
| MFEnv (MF-MAPPO) | 平均场团队博弈基准 | 对比 MF-MAPPO 时引用 | — |
| JSBSim 类高保真空战 | 6-DOF，慢 | 不采用（算力不可行，且ICLR不要求高保真） | — |

**结论（更新）**：采用"自研主环境 + 公认基准佐证"的双轨制——
1. **主战场**：SMAX 风格自研 SwarmBattle（完全可控：规模、编成、增援、对手脚本库，这三者是评测协议核心变量，现有公开环境均不完整支持）；
2. **公开基准轴**：同一网络架构在 **MAgent2 battle**（大规模离散对抗）与 **MPE simple_tag**（连续追捕）上复用，证明方法不是为自研环境定制的——这直接回应 ICLR 审稿人对自研环境的最常见质疑；
3. **规模压力测试**：Gigastep（Linux/WSL2 阶段）。

原型阶段已在本机 `gpu_py_310` 环境（RTX 3060, torch 2.4.1+cu124）打通 SwarmBattle + MPE + MAgent2 三个环境的统一适配层，见 `prototype/envs/adapters.py`。

## 8. 总体空白定位（Gap Analysis）

把五条主线交叉后，可以精确定位出一个**尚无人占据且各部件技术成熟度都足够高**的位置：

> **在两队集群对抗中，学习一个"数量无关的动态分组分簇高层 + 目标条件化的底层作战策略"的分层架构，通过"跨规模 × 跨风格"联合种群课程训练，实现对（i）任意双方规模与中途增减员、（ii）任意未见对手风格的双重零样本泛化。**

各部件的技术成熟度与组合空白：

| 部件 | 成熟度 | 已有工作 | 组合空白 |
|---|---|---|---|
| 置换不变实体编码 | 高 | SPECTra, CPE | 未用于竞争博弈的分组决策 |
| 可学习动态分组 | 中 | HRL-grouping(仅合作) | 无对抗驱动、无自适应簇数 K |
| 种群自博弈 | 高 | AlphaStar, PSRO 系 | 未与规模课程联合 |
| in-context 对手推断 | 中高 | OEOM/IOM, QOM | 无集群级对手行为嵌入 |
| 跨规模零样本 | 中 | SPECTra, AHDRL_LRS | 无对抗中途增减员评测协议 |

**双重零样本泛化（规模 × 对手）作为统一的评测框架本身，就是一个可以立住的贡献。**

## 9. 对适应性（异构机型）的调研结论

用户提出的第三目标（对手换型号，如小飞机→重载远程打击机）在文献中对应"异构智能体/单位类型泛化"。现有做法是把单位属性（速度、射程、血量、伤害）作为实体特征向量输入置换不变编码器（SMAX、Gigastep 均原生支持异构类型），属性插值可获得一定的零样本类型泛化。LLM 驱动的策略适应（如 CSRO、认知分层框架 Frontiers 2026）尚不成熟且算力昂贵。**建议**：把"属性化异构单位 + 属性外推评测"作为论文的附加实验（低成本、顺手），把 LLM 路线明确写入 Future Work，不进入本文核心贡献。
