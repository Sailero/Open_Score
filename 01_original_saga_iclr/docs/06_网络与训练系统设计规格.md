# 网络与训练系统设计规格（正式版 v1.0）

**定位**：从原型（`prototype/saga/`，已验证接口与形状）到正式实验系统的完整工程规格。任何实现者（包括未来的你）按本文档可以无歧义地搭出网络与训练系统。与 `paper/04_method.md` 的方法描述一一对应，与 `docs/07_技术路线图.md` 的排期对应。

## 1. 实体 token schema（v1.0，冻结）

所有环境/宿主统一 20 维（原型 16 维 → 正式版扩充 4 维，冻结后不再改动）：

| 维度 | 内容 | 归一化 |
|---|---|---|
| 0-1 | 相对位置 (dx, dy) | / arena_half |
| 2-3 | 相对速度 (dvx, dvy) | / v_max_global |
| 4-5 | 朝向 (cosθ, sinθ) | — |
| 6 | 血量比 hp/hp_max | [0,1] |
| 7-8 | 阵营 one-hot (ally, enemy) | — |
| 9 | 存活标志 | {0,1} |
| 10-15 | 类型属性向量 x_u（速度/射程/血量/伤害/冷却/视野） | 各除以全局参考值 |
| 16 | 冷却剩余比 | [0,1] |
| 17 | 进场时间比（增援新旧度，新=1 衰减到 0） | [0,1] |
| 18-19 | 保留位（宿主自定义，默认 0） | — |

新增 16/17 维的理由：冷却是开火决策的必要信息（原型缺失导致无效开火）；进场时间让指挥层可区分"新到增援"与存量兵力（支撑预备队语义）。

## 2. 网络规格（d=128 主配置）

### 2.1 模块 A：实体场编码器

```
EntityEmbed:   Linear(20→128) → GELU → Linear(128→128)        [参数共享于全部模块]
ObserverEnc:   1 层 SAQA: MHA(query=learned token, kv=entities, heads=8, d=128)
               → LayerNorm → FFN(128→256→128, GELU) → LayerNorm    残差连接
PopSummary:    masked-mean ⊕ masked-max over 全实体嵌入 → Linear(256→128) → GELU
```
- 正式版与原型差异：加残差与 FFN（原型只有单层 attention+FF，训练深度不够）；嵌入层与 B1/C 目标头共享（原型各自独立，浪费参数且表征不一致）。
- 初始化：注意力投影 Xavier；输出层 zero-init gain 0.1（策略平滑起步）。

### 2.2 模块 B：指挥层

```
B1 EnemyCluster:  SlotAttention(K_max=8, L=3, d=128)
                  - slots init: learned μ,σ 高斯采样 (打破对称且置换鲁棒)
                  - 实体维 softmax 竞争归一; GRUCell(128) slot 更新
                  - 输出: slots (8×128), assign (M×8), occupancy (8,)
                  - L_coh 正则: Σ_κ Σ_j A_jκ · ||pos_j − μ_κ||² / Σ A   (μ_κ=软质心)
                  - L_sparse 正则: β·Σ_κ sqrt(clamp(o_κ/M, 1e-4)) 凹稀疏项, β=0.02
                    ** β 必须 warmup (前 40% 训练线性升至目标值), 否则早期塌缩单簇 **
                    ** sqrt 参数必须 clamp, 否则 0 处梯度爆 NaN (P0 实测教训) **
B2 StyleEnc:      GRU(输入 16 维统计, hidden 64) over 最近 T=32 个指挥步
                  统计量 v1.0 (16 维): [敌计数比, 敌质心距, 敌散布, 敌接近速度,
                  敌开火率*, 我方受损率, 交换比滑窗, 敌重组频率*, 敌簇数变化率,
                  敌前压深度, 我方存活率, 双方规模比, 增援事件标志, 时间进度, 保留×2]
                  (*由可观测事件估计)
B3 TaskMatch:     task tokens = FFN([c_κ; e_type; z]) , 3 类 × 8 簇 + 2 free = 26 tokens
                  单位-任务打分: (W_u h_i)·tasks / √d + log(occupancy 门控)
                  goal g_i = softmax 加权任务和 (128 维)
```
- K_max=8（原型 6；64v64 时敌方可能形成更多战术群）。
- **P0 单元测试：✅ 已通过（2026-07-20，`prototype/test_clustering_p0.py`）**：合成 1-4 群态势、完全无监督（L_coh + L_sparse），3 种子平均 |有效簇数−真实群数|≤1 准确率 **96%**，相关系数 **0.81**，逐群均值跟踪真实群数。动态分簇方案确认保留，Sinkhorn 备选方案封存。

### 2.3 模块 C：微观策略 + 中心化 critic

```
Trunk:        Linear(128+128 → 128) → GELU → Linear(128→128) → GELU   (h_i ⊕ g_i)
ManeuverHead: Linear(128→n_move_bins)  离散 9 bins (3 转向 × 3 加速)
TargetHead:   query=Linear(128→128)(trunk out); key=EntityEmbed(敌token)
              logits = q·k/√d, 前置 null-target logit = Linear(128→1)
Critic:       置换不变 set network over 全实体 (训练期全局可见, CTDE):
              EntityEmbed → 2 层 SAB(自注意 128, heads 8) → mean-pool → MLP(128→128→1)
              输出团队 value; 另加每单位 utility head (128→1) 供任务对齐塑形的 baseline
```
- Critic 用 2 层自注意（O(n²) 只在训练期发生，可接受）。

### 2.4 参数量预算

| 模块 | 约参数量 |
|---|---|
| 共享 EntityEmbed | 20K |
| 模块 A | 200K |
| B1 slot attention | 120K |

## 3. 训练系统架构（JAX，Linux/WSL2）

### 3.1 分层设计

```
┌ experiment runner (hydra 配置, 3 种子并行) ─────────────────┐
│  ┌ SxS 调度器: (σ,μ) 胜率表 + 前沿采样 ┐                    │
│  │  league 存储: scripts(参数化) / snapshots / exploiters   │
│  └───────────────┬──────────────────┘                      │
│  ┌ 采样引擎 ──────▼─────────────────┐  ┌ 学习器 ──────────┐ │
│  │ vmap(env.step) × 1024 并行实例    │→│ padded-bucket     │ │
│  │ SwarmArena-JAX (纯函数式 state)  │  │ MAPPO + L_coh    │ │
│  │ 脚本对手 = JAX 纯函数            │  │ + 任务对齐塑形     │ │
│  └──────────────────────────────────┘  └──────────────────┘ │
│  评测 harness: S×G 矩阵 cell 定义为配置文件, 每 cell 64 局   │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 关键工程决策

0. **交战同时结算（对称性硬约束）**：双方开火基于同一状态快照结算、阵亡统一生效——原型曾因顺序结算产生先手优势（镜像对局 18/20，修复后 20/40）。**环境任何改动后必须重跑镜像对称性回归测试**（greedy vs greedy ≈ 50%）。
1. **变长处理 = 静态 shape + mask**：JAX 要求静态形状。实体数组按 N_max=80（训练）/ 256（评测）预分配，alive mask 控制有效性。增援 = 翻转 mask 位 + 写入属性，**零动态分配**。
2. **分桶批处理**：episode 按 (N₀, M₀) 桶分组做 padded batch；bucket 边界 {8, 16, 32, 64}。这是吞吐的生命线（审视报告 §1.3 教训的正式解）。
3. **对手统一为策略函数接口** `μ(params, obs_B, rng) → actions_B`：脚本=无参数纯函数；快照/exploiter=同一网络不同参数——league 存储即参数字典，采样引擎无分支。
4. **吞吐目标（决策门 G2）**：SwarmArena-JAX 16v16 ≥ 1×10⁵ env-steps/s/A100（含双方策略前向）。达不到 50% 即触发规模降级预案（训练域上限 12、评测上限 48）。
5. **exploiter 流水线**：独立进程组，每 200 主更新触发；预算 = 主策略 5%；训完自动注册 league 并更新胜率表。
6. **实验追踪**：wandb + 本地 parquet 双写；S×G 矩阵 cell 结果落库，图表脚本从库生成（图表合同 §5 的自动化）。

### 3.3 训练超参（v1.0 起点）

| 项 | 值 |
|---|---|
| 优化器 | AdamW, lr 3e-4, cosine 到 3e-5, clip 0.5 |
| PPO | clip 0.2, epochs 4, minibatch 4096 transitions, γ=0.995, λ=0.95 |
| 熵系数 | 机动 0.01 / 目标 0.005（分开控制） |
| λ_coh | 1e-2（P0 测试后定） |
| 任务对齐塑形权重 | 0.1 × 团队奖励尺度 |
| 指挥周期 k | 8 |
| 总预算 | 3e9 env-steps 主策略 + 6 exploiters × 1.5e8 |
| 快照/exploiter 频率 | 每 50 / 200 次更新 |

### 3.4 PyTorch 原型的角色（保留，不废弃）

原型继续承担：P0 聚类单元测试床（快速迭代）、宿主适配层参考实现（MPE/MAgent2）、延迟基准（部署契约）、回放前端。正式训练全在 JAX 侧。两侧共享 token schema v1.0 与配置文件格式。
