# 开源与可复现性审计

**触发问题**：所有内容都基于开源环境吗？自研部分符合开源标准吗？
**日期**：2026-07-20

---

## 1. 诚实的现状盘点：什么是开源的、什么是自研的

| 组件 | 来源 | 性质 |
|---|---|---|
| MPE simple_tag | PettingZoo（MIT 系许可，pip 安装） | ✅ 第三方开源基准 |
| MAgent2 battle_v4 | Farama 生态（pip 安装） | ✅ 第三方开源基准 |
| JaxMARL/SMAX、Gigastep | Apache/MIT，GitHub | ✅ 计划用的第三方开源（正式训练/压力测试） |
| **SwarmArena 主环境** | **自研** | ⚠️ 本审计的对象 |
| SAGA 网络/训练/评测代码 | 自研 | ⚠️ 随论文开源 |

**为什么主环境自研（论文必须讲清的理由）**：评测协议的三个核心变量——双方规模分布、episode 内增援过程、参数化对手脚本库——没有任何现有开源环境同时支持（SMAX 无增援与对手库、Gigastep 无参数化脚本谱、MAgent2 无连续属性异构）。自研不是偷懒，是协议先行的必然。**但这条理由成立的前提是：自研环境本身达到开源可复现标准**——否则"协议"就只是我们自己的说法。

## 2. 本次落实的开源标准动作（已完成 ✅）

### 2.1 社区标准 API：PettingZoo ParallelEnv 封装 + 官方合规测试通过

这是"自研环境可信"的最硬证据，比任何文字承诺都有效：

- 新增 `prototype/swarmbattle/pz_env.py`：SwarmArena 以 PettingZoo ParallelEnv 标准接口暴露，**双方全部单位皆为可控 agent**（self-play ready），变规模通过 `reset(options={"n_red":..,"n_blue":..})` 在标准 API 内表达；
- **`pettingzoo.test.parallel_api_test` 官方测试：PASSED**（300 cycles）；
- **同种子确定性：PASSED**（同 seed 逐步轨迹完全一致，异 seed 可区分）——可复现性的底线保证；
- 变规模 reset（4v12/16v16/2v3）：PASSED。
- 测试套件固化为 `prototype/test_pz_env.py`，进入回归清单。

**已知规范边界（主动披露）**：(a) PettingZoo 不支持已终止 agent 复活，因此**中途增援**在标准 API 下默认关闭——增援语义由研究用原生接口（`envs/adapters.py`）提供，开源发布时两种接口并存并在 README 说明差异；(b) api test 有一条良性 warning（容量内未激活的 possible_agents 无终止记录），属规范允许的子集激活模式。

### 2.2 许可证

- 新增仓库根 `LICENSE`（MIT）——环境/基准类项目的社区惯例（PettingZoo/JaxMARL 同为 MIT/Apache 系），最大化复用。

## 5. 结论

- 第三方基准部分本来就是开源的（MPE/MAgent2 已装且跑通，JaxMARL/Gigastep 在计划内）；
- 自研主环境此前**不满足**开源标准；本次已补齐最关键的两件（标准 API + 官方测试通过、LICENSE），确定性验证通过；
- 其余差距（打包/CI/英文文档/CITATION）全部是 W8-9 的机械工作，已排期，无风险。
