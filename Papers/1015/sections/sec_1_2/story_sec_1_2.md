## 1. 写作口径

- **篇幅**：引言正文约 1000 词，含单栏 Fig. 1 约 1.2 页；相关工作约 380 词。
- **数字**：摘要与引言的叙述中只保留训练与部署规模一处数字（至多 10 名防御者、3 个目标 → 50 名防御者或 12 个目标）。
- **优势写法**：不写降损百分比，也不写 significantly（只有三个训练种子，没有显著性检验，IEEE 审稿人会把它理解为统计显著）。改用两条可直接核对的定性陈述：每个测试配置损伤最低；每个测试组中 LEAF 最差的训练种子也胜过各基线最好的种子。降损 43%–64% 留给第五章表格与结论。
- **文献支撑**：每个核心观点、假设和设计主张都有引用，对照见第 3 节。实验主张由第五章支撑。

## 2. 故事主线

1. **问题**：防御者、攻击者和目标的数量事先未知，策略应在小规模上训练一次后直接用于大规模，即零样本规模泛化。
2. **难点一，威胁是关系性的**：攻击者的危险程度取决于它飞向的目标和该目标是否已有队友覆盖，即威胁情境。单看攻击者自身特征无法区分（Fig. 1(a)），必须先关联实体再决策，而且这种计算要能用于任意规模。
3. **难点二，读取方式与记忆**：同一情境对不同防御者含义不同，应按各自当前状态读取。记忆因攻击意图不可见而必要，但规模变大时循环状态会进入训练中没见过的区域；若记忆参与构建或读取情境，漂移会扭曲对当前场景的判断。
4. **难点三，推理深度**：一轮注意力只建立成对关系，覆盖关系需要多轮组合；所需深度随输入变化，固定深度的网络截短后会退化。
5. **洞察**：构建情境只需当前实体，读取只需当前状态，推断意图才需要历史。每步一个模块，历史最后进入，构建模块在任意深度都可用。
6. **方法**：LEAF 用跨轮共享的实体注意力循环构建情境，用当前状态 query 读取每一轮并融合，记忆在读取后进入；训练时随机采样轮数。
7. **证据**：零样本部署到更大规模，每个测试配置损伤最低；单因素消融证实情境构建、多轮精炼和记忆后置；记忆探针证实漂移；随机深度让每个执行深度可用，固定深度模型在少轮时崩溃。

## 4. 与基线的区别

引言不再使用逐方法的设计表。原表中大多数方法在“实体注意力层数、记忆是否进入注意力、深度是否可调”三列上取值相同，区分度不足。现在的分工是：

- **Fig. 1(b)（单栏）**：三行信息流对比三种组织方式。Single read（REFIL、SPECTra）读取前不关联实体；Entity Transformer（TransfQMix）关联实体，但记忆进入每一层且深度固定；LEAF 用共享循环关联实体、深度部署时可设、记忆在读取后进入。
- **引言正文**：用一段话说明四个方法族各缺哪一项，并指向 Fig. 1(b) 的对应行。
- **相关工作**：按四个方法族组织，与第五章基线一一对应。

| 方法族 | 基线 | 与 LEAF 的差别 |
|---|---|---|
| 分配型目标防御 | Rule、ALMA | 把威胁情境压缩成离散配对，攻击者换目标时必须重新指派 |
| 值分解与显式协调 | QMIX、DCG | 改进效用的组合方式，但每个效用仍来自一次读取 |
| 跨规模的实体方法 | REFIL、SPECTra | 自身 query 只读一次，读取前没有建立实体关系 |
| 实体 Transformer | TransfQMix | 记忆 token 进入每一层，层数固定 |

## 6. 三条贡献

1. **Diagnosis**：指出零样本规模泛化取决于威胁情境，并把学习方法在规模变化下的失效归结为两个设计选择：读取前不关联实体，让随规模漂移的记忆参与读取。
2. **Method**：LEAF 分离情境构建、当前状态读取和记忆，并在随机深度上训练一个共享循环，一个策略覆盖任意规模和执行深度。
3. **Evidence**：在小规模上训练后，迁移到大数倍的团队和目标集，每个测试配置损伤最低，只执行一轮推理也几乎保持全部保护效果。

## 8. 随机深度训练能否提高性能

现有数据不支持“随机深度提高性能”。在含记忆 query 的变体族中，随机深度在四轮时还有代价（12 个种子–组别对中 10 个更差）；去掉融合的 Last read 也不比 Memory query 差。LEAF 的满深度优势来自情境构建、多轮精炼和记忆后置，随机深度与融合换来的是任意出口可用。若要声称随机深度在满深度下没有代价，需要补训“Fixed depth + 当前状态 query”三个种子，按项目约定需你同意后再运行。
