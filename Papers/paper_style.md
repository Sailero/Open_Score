# Paper Style Guide

## 1. 投稿定位

- 目标期刊是 IEEE Transactions on Automation Science and Engineering (TASE)。
- 论文研究的是多目标攻防这个特定场景中的协同防御问题。方法服务于这个场景，不要包装成适用于所有多智能体任务的通用方法。动机、例子和结论都要落回攻防场景。
- 组织和论证方式参考 NeurIPS、ICLR、TNNLS 的高质量论文：问题清楚，动机层层推进，方法设计与要解决的难点一一对应，实验能回答引言中提出的每个主张。
- TASE 格式要求：
  - 摘要一段，不超过 200 词。
  - 摘要后附 Note to Practitioners，100 到 300 词，用非专业语言说明这项工作对实际系统有什么用，不要复述摘要。
  - 附 Index Terms。
  - 使用 IEEE 期刊格式。

## 2. 结构与论证

- Introduction 按"问题重要性、核心难点、现有方法为何不足、关键洞察、方法、实验发现、贡献"展开。每个难点在方法中都要有对应的设计，在实验中也要有对应的验证。
- Related Work 按方法类别组织。每一类先说明它做到了什么，再用一两句点出它与本文场景的差距，不要逐篇罗列。
- Method 先给整体框架和信息流，再逐个模块说明"它做什么，为什么这样设计"。公式只保留理解方法必需的部分，符号全文统一。
- Experiments 按"主结果、消融、机制分析"组织，每个小节开头先说明它回答哪个问题。
- Conclusion 总结发现，可以简要提到局限和未来工作。

## 3. 语言风格

- 写成有经验的研究者自然写出的学术英语。用常见词，句子清楚、直接，一句话只讲一个意思。
- 不用分号。两个意思就写两句。
- 正文尽量不用括号。缩写首次定义、引用编号、公式编号、图表编号除外。
- 不用引号表示强调或给概念起别名。新概念直接命名，比如 we call this the threat context。
- 破折号尽量少用，复合词中的连字符除外。
- 不堆砌连接词，避免 Moreover、Furthermore、Notably、Importantly、Crucially 等反复出现。段落之间靠逻辑自然衔接。
- 避免生僻或浮夸的词，比如 delve、leverage、paradigm、pivotal、seamlessly、unprecedented、groundbreaking。
- 不写"不是 A，而是 B"这类对照句式，直接说 B。
- 不写防御性句子。正文中不要主动强调方法局限、适用范围或待解决的问题。表述的范围由用词本身准确体现，而不是靠补充免责声明。
- 正面、自信地表达观点。用主动语态陈述设计理由和发现，比如 LEAF builds、This shows、We find。

## 4. 实验写作

- 用概括性的语言描述结果，具体数值放在表格和图中，正文只在关键结论处引用少量数字。
- 重点写洞察：结果为什么会这样，它说明了方法的什么性质，它如何支撑引言中的主张。
- 每段遵循"现象、原因、结论"。比如先说明某个变体在外推中退化更明显，再解释原因，最后点出这说明了哪个设计的作用。
- 主张必须与实验结果一致。没有统计检验时不用 significantly，可以用 substantially、clearly、consistently。
- 不写"所有指标在所有设置下都最好"这类过度概括。优势要说到结果真正体现的那一层。

## 5. 输出前自检

- 搜索全文的分号、多余括号、引号、"not ... but"句式，确认没有残留。
- 检查引言里的每个主张是否都有对应的实验证据。
- 检查局限和未来工作是否只出现在 Conclusion。
- 检查摘要字数、Note to Practitioners 字数，以及缩写首次出现时是否已定义。
