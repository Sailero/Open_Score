# 推荐路线与方法框架

推荐路线暂称 **OPAA：Open-Population Adversarial Allocation**。名称只是工作代号，待 P0 通过后再固定。

## 1. 问题定义

在时间步 (t)，红蓝双方活动智能体集合分别为 (N_t^R,N_t^B)，局部任务/目标集合为 (X_t)。伤亡、撤离和增援使这些集合在回合内变化。双方都采用层级策略：

1. 上层每隔 (K) 个低层步或在开放事件后输出分配 (z_t^k:N_t^k\to X_t^k\cup\{\varnothing\})；
2. 下层技能策略根据个体观察和分配目标执行 attack/intercept/defend；
3. 红方团队回报为 (R)，蓝方近似为 (-R)，主场景按两队零和建模。

研究对象只包括上层策略 (mu_R,mu_B)。下层 (pi_{mathrm{low}}) 在所有主比较中共享并冻结，避免把机动学习差异误写成编组贡献。

## 2. 最小架构

### 2.1 活动集合编码

将活动队友、对手和任务分别编码为变长 token 集合，使用共享 MLP + attention/DeepSets 得到置换等变表示。该结构只保证数量和顺序变化时网络仍可用，不作为论文贡献。

### 2.2 上层分配头

对每个活动队员和任务计算 compatibility score，按任务容量 mask 输出分配。首版使用 PLATO 式单步 pointer；如果冲突严重，再启用候选 C 的约束匹配，不能一开始就增加求解器复杂度。

### 2.3 固定下层技能

先在静态小场景训练三类通用技能：

- attack：接近并优先消灭被分配敌方组；
- intercept：阻止被分配目标进入保护区；
- defend：在局部区域阻滞对手并保护资产。

主实验冻结同一组技能检查点。补充实验允许各上层分别联合微调固定步数，用于回应 ALMA“联合训练更优”的已知结论。

## 3. 对手池训练：唯一主要算法变化

普通 self-play 每轮只面对最新对手，容易沿一条循环克制链更新。OPAA 保存定期上层快照形成 (mathcal{P}={\mu^{-1},\mu^{-2},...\})，每个 batch：

1. 以一定概率选择最新对手，其余从历史池采样；
2. 根据当前策略对各历史对手的低胜率，提高难对手采样权重；
3. 只用最终团队回报更新上层策略；
4. 达到固定训练间隔或 payoff 显著变化时加入新快照。

最小采样分布可写为

\[
p(j)=(1-\eta)\frac{1}{|\mathcal P|}+\eta\,\mathrm{softmax}(-\bar R_j/\tau),
\]

其中 (ar R_j) 是当前策略对快照 (j) 的滑动平均回报。它不是对手类别识别，而是直接把易被利用的 matchup 转成训练权重。

## 4. 训练流程

1. 在静态 4v4/6v6 场景预训练低层技能，选一个共同检查点。
2. 冻结下层，训练上层结构与普通 self-play baseline。
3. 启用双方减员/增援事件分布，训练 OPAA 对手池版本。
4. 在训练未见的队伍规模、兵力比、事件时间和对手策略上做零样本评估。
5. 冻结待评策略，给对手固定交互预算训练经验最佳响应，估计可利用度。

## 5. 经验可利用度

大规模随机博弈无法精确求 NashConv。本文不应滥用“达到纳什均衡”，而采用可复现的经验定义：

\[
\widehat{Exploit}(\mu)=V(\mathrm{BR}_B^H,\mu)-V(\mu_B^{ref},\mu),
\]

其中 (mathrm{BR}_B^H) 是在固定 (H) 环境步和多随机种子下训练的蓝方最佳响应近似，(mu_B^{ref}) 是同一候选池的参考混合。所有方法使用相同响应结构、预算和初始化。

论文同时报告 payoff matrix 与 worst-case return，防止单个不稳定 best-response 训练决定结论。

## 6. 与三篇核心论文的区别

| 方法 | 本文复用 | 本文增加 |
|---|---|---|
| ALMA | 上下层分解、子任务分配、低层 mask | 双方上层、回合内双方开放、跨对手评价 |
| PLATO | 活动集合与 pointer baseline | 团队竞争、反编组训练、经验可利用度 |
| DT-GAT | 动态拓扑、双时间尺度 baseline | 智能对手、双方人口变化、对手池而非被动目标 |

## 7. 贡献表述上限

若实验通过，可主张：

1. 提出并操作化一个开放人口团队竞争下的层级分配问题；
2. 发现合作式/单一对手式上层分配在开放反制测试中的性能缺口；
3. 给出一个轻量历史对手池训练方法，在相同下层下改善跨规模最坏表现并降低经验可利用度。

不能主张“首个开放博弈”“求得 Nash 均衡”“首个可变数量 MARL”或“首个动态分组”。

## 8. 最小实现顺序

- P0.1：给 SwarmBattle 增加上层 assignment API 与三种脚本下层技能。
- P0.2：固定对手下训练一个 pointer allocator，确认上层选择会改变胜负。
- P0.3：构造三种反编组脚本，测单一对手训练的 worst-case gap。
- P0.4：加入 4–8 个历史快照的均匀池；若已改善最坏结果，再实现难例加权。
- P1：复现 ALMA 最小任务，并移植同一实验协议。
