# 核心论文、基线与复现底座

## 1. 三篇核心参考

### 1.1 ALMA：方法与代码主底座

- 论文：[ALMA: Hierarchical Learning for Composite Multi-Agent Tasks](https://proceedings.neurips.cc/paper_files/paper/2022/hash/2f27964513a28d034530bfdd117ea31d-Abstract-Conference.html)，NeurIPS 2022。
- 代码：[shariqiqbal2810/ALMA](https://github.com/shariqiqbal2810/ALMA)，MIT License。
- 可直接继承：高层 allocation Q-learning、低层 REFIL/QMIX、子任务 mask、SaveTheCity、复合 StarCraft、COPA 与启发式配置。
- 需要改造：把单方合作分配改为红蓝双方上层策略；增加双方伤亡/增援事件和对手策略池；主实验冻结同一低层检查点。
- 风险：代码基于 Python 3.7、PyMARL/SC2 与 Docker，仓库提交历史很短；必须先用作者配置跑通一个小场景，三天内不通就停止深度绑定。

### 1.2 PLATO：最新开放性定义与强结构基线

- 论文：[PLATO: Pointer Learner for Agent and Task Openness](https://arxiv.org/abs/2607.25082)，2026-07。
- 可直接继承：Task-and-Agent-Open Markov Game 表述、按当前任务集输出的 pointer actor、变长 agent-task critic、零样本开放性测试协议。
- 不应照搬：仅用 pointer/GNN 就宣称创新；其任务一项对应一个动作且主要是合作式野火环境。
- 复现状态：论文给出完整算法和配置，但截至调研日未定位到作者公开代码仓库；只能作为轻量结构重实现基线，不宜成为唯一底座。

### 1.3 DT-GAT-MARL：最近邻工程基线与直接缺口

- 论文：[Graph attention network-enhanced multi-agent reinforcement learning for dynamic interception task allocation in counter-drone defense](https://doi.org/10.1038/s41598-026-55576-9)，Scientific Reports 2026。
- 可直接继承：高层离散分配/低层 MAPPO、双时间尺度、动态节点 mask、有效重分配率与振荡率。
- 明确差异：其对手是恒速直线入侵目标，主要由入侵者侧增量变化；本文让两方都有上层策略并用对手池训练与经验可利用度评价。
- 复现状态：论文称代码和数据可向通讯作者索取，没有可直接 clone 的公开实现；只重实现必要机制，不复刻全部连续动力学。

## 3. 环境选择

### 首选组合：现有原型 + ALMA

1. **P0：OpenSwarmBattle**。在当前 `src/swarmbattle/` 上增加 protected asset、attack/intercept/defend 三类子任务、显式事件表和上层分组接口；优点是两边控制、伤亡和增援已经具备，适合一周内否证问题。
2. **主复现：ALMA SaveTheCity 或 composite StarCraft**。先复现作者的一个最小配置，再把活动敌军组视为子任务，加入双边上层或至少智能敌方分配器；优点是论文和 baseline 体系完整。
3. **规模补充：MAgent2 Battle**。该环境公开、维护活跃、支持 162 个智能体和并行 API，适合做规模压力测试；但原生没有增援和显式子任务，且官方支持 Linux/macOS，因此只列为 WSL/Docker 下的扩展证据。[文档](https://magent2.farama.org/environments/battle/)

### 备选工程底座：JaxMARL/SMAX

[JaxMARL](https://github.com/bold-lab-ai/JaxMARL) 有单文件 MAPPO/QMIX/VDN 基线与纯 JAX 的 SMAX，不依赖 StarCraft II 引擎；SMAX 原生队伍固定，因此需用预分配槽位 + active mask 实现回合内增援。若 ALMA 的老依赖在三天内无法稳定复现，推荐转到这个底座。

### 不建议作为主环境

- MOASEI/FreeRangeZoo wildfire：开放性标准且实现现代，但它是合作任务，PLATO/MOHITO 已经覆盖，最多做迁移验证。
- 原生 SMAC/SMAX：有死亡但通常没有回合内新增智能体，不能不改环境就声称开放人口。
- 仅使用自定义 SwarmBattle：可用于 P0，但单一自造环境对 Q2 证据不足；至少补一个公开环境或公开全部生成器、基线和脚本。

## 4. 必须复现的 baseline

### 必须运行

1. Nearest/type-matching heuristic：最近目标或兵种匹配，固定周期重分配。
2. Hungarian/greedy value heuristic：基于距离、血量和目标威胁的约束匹配。
3. ALMA-style AQL：作者高层分配器；下层使用同一冻结策略。
4. PLATO-style pointer MAPPO：集合输入、逐智能体任务 pointer，不带对手池。
5. DT-GAT-style allocator：动态二部图 + 固定双频更新，不带智能对手训练。
6. Plain self-play：与本文同结构，但只对最新对手训练。
7. Proposed opponent-pool training：本文完整方法。

### 有余力再做

- COPA、flat MAPPO/QMIX/REFIL、RAC-style roles；
- REDA-style learned value + solver（候选 3 成为主线时才必做）；
- GIRA（仅在获得代码或可可靠重实现时）。

## 5. 复现审计与止损

| 资产 | 公开代码 | 与主问题贴合 | 工程风险 | 决策 |
|---|---:|---:|---:|---|
| ALMA | 是 | 高 | 中高，依赖旧 | 三天复现闸门 |
| PLATO | 未定位到 | 高（开放） | 中 | 重实现最小 pointer baseline |
| DT-GAT | 按请求提供 | 很高（动态分配） | 中 | 重实现上层，不复制动力学 |
| JaxMARL | 是且活跃 | 中 | 低至中 | ALMA 失败时切换 |
| MAgent2 | 是且活跃 | 中（规模） | Windows 上高 | 仅扩展实验 |
| 当前 SwarmBattle | 本地可控 | 很高 | 低 | P0 与消融，不单独支撑论文 |

任何 baseline 若无法复现，应在论文中明确标注“independent reimplementation”，禁止把未经核对的实现结果写成作者方法原结果。
