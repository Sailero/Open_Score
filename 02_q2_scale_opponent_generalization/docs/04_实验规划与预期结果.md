# 实验规划与预期结果（阵容—策略解耦版）

## 1. 实验问题

- **Q1：混淆存在吗？** 通用时序对手上下文是否把减员、增援或类型比例变化误判成策略变化？
- **Q2：CDOC 真能分开吗？** 是否降低 composition-only 误报，同时保持 strategy-only 检测率与延迟？
- **Q3：表示改善有决策收益吗？** 是否降低策略切换后遗憾、恢复时间并提高最差未见对手胜率？
- **Q4：跨规模/未见策略时仍成立吗？** 上述结果是否在未见阵容和 held-out 对手实现上保留？
- **Q5：代价是否足够小？** 参数、显存和推理延迟是否符合轻量定位？

## 2. 主协议：阵容变化 C × 策略变化 S

每类事件固定前置观察窗口、事件时刻和后置评估窗口。为避免把战局阶段当标签，事件时刻、初始位置和血量分布进行随机化，并用同一随机种子生成匹配事件。

| Cell | 阵容变化 | 策略变化 | 主要目的 |
|---|---|---|---|
| `C0S0` | 无 | 无 | 估计正常 latent 波动与基础误报 |
| `C1S0` | 减员/增援/类型变化 | 无 | 测策略误报，是最重要的诊断 cell |
| `C0S1` | 无 | 追击↔拉扯/集火↔撤退 | 测策略检测 AUROC 与延迟 |
| `C1S1` | 有 | 有 | 测最困难的识别和切换后决策恢复 |

阵容干预强度分三级，例如 10%、30%、50% 敌方数量变化；策略切换包含至少四个方向且保持动作边际尽可能重叠，避免单帧即可识别。

## 3. 环境

### E1：SwarmBattle（P0/P1，受控因果诊断）

- 使用现有 greedy、kite、focus-fire、coward、focus-greedy 控制器并增加回合内切换接口；
- 显式添加不改变剩余单位策略的 remove/reinforce/type-swap 事件；
- 为四个 cell 生成相同初始 seed、相同事件时刻的匹配 episode；
- 训练策略：greedy/kite/focus；held-out：coward/focus-greedy 及参数外推变体；
- 训练初始规模：6v6、8v8、10v10；测试：12v12、8v16、16v8。

该环境承担“问题是否存在”和机制消融，不独占最终证据。

### E2：MAgent2 Battle（P2，公开主环境）

- 用官方 Battle 作为公开、大规模双队对抗基础；
- 自然击杀产生未经人工注入的连续战损；
- 为严格事件标签增加评测 wrapper：在预定窗口加载/切换规则控制器，并记录真实 composition/strategy change；
- held-out 对手按代码实现而非随机种子划分；
- 只在 SwarmBattle 通过 P1 后运行完整五种子矩阵。

### E3：可选公开第二环境

只有在第 5 周前主结果稳定时，加入 MPE simple_tag 或可复现的 SMAC/SMAX 竞争 wrapper。SMACv2 默认敌方机制不能直接支持 unseen-opponent 主张，只用于 HPN 骨架趋势复现。

## 4. 方法与基线

| 方法 | 角色 |
|---|---|
| Padding-IPPO / DeepSets-IPPO | 固定输入与简单集合弱基线 |
| HPN | 无显式对手历史的顶会 backbone |
| OC-HPN | 通用 set-summary + GRU，最关键近邻和被诊断对象 |
| CDOC-HPN | 推荐方法：阵容/条件行为分支 + 成对损失 |
| CDOC-noInv | 去掉同策略跨阵容不变性 |
| CDOC-noSep | 去掉异策略同阵容分离 |
| CDOC-shuffledPair | 打乱成对标签，排除普通正则化效应 |
| OC-HPN-size-matched | 容量对照 |
| Oracle-change | 读取真实切换标签的上界，不参与公平排名 |

OM-TCN 或 TAO 风格编码器仅在有稳定实现时加入，不能用不忠实的简化版本冒充原论文。

## 5. 指标与计算

### 5.1 表示和检测

- `FPR_comp`：在 `C1S0` 窗口内超过冻结阈值的 episode 比例；
- `FPR_base`：`C0S0` 的基础误报率；
- `AUROC_switch`：用 change score 区分 `S=1` 与 `S=0`；
- `Delay_switch`：真实切换到连续 `q` 步超过阈值的时间；
- `ScaleProbe(z)` 与 `StrategyProbe(z)`：只作机制分析，不作为成功的充分条件；
- change score 与阵容变化幅度的 Spearman 相关。

阈值仅在训练/验证策略上确定一次，held-out 测试不重新调阈值。

### 5.2 决策

- win rate、episode return；
- `PostSwitchRegret@K = Σ_{t=t*}^{t*+K}(r_t^oracle-r_t^model)`；
- 恢复到切换前滑动回报 90% 的步数；
- `WorstOpp`：held-out 对手中的最差胜率；
- 补充旧版规模 ID/OOD × 对手 ID/OOD 四象限结果，以证明不是牺牲总体泛化换取 probe 指标。

### 5.3 成本

- 参数量与实体数；
- 1,000 次 forward 平均/95 分位延迟；
- 峰值显存；
- 实体数增加时的时间斜率。

## 6. 统计协议

- P0 用 3 个训练种子筛选问题；正式表格使用 5 个独立训练种子；
- 每个 seed × cell × change intensity × held-out opponent 至少 100 个评估 episode；
- 以训练 seed 为重复单位报告均值和 seed-level bootstrap 95% CI；
- CDOC 与 OC-HPN 使用同 seed、同事件 manifest 配对比较；
- 三个预注册 primary endpoints：`FPR_comp`、`AUROC_switch`、`PostSwitchRegret@K`；
- 胜率与 `WorstOpp` 为关键 secondary endpoints；
- 超参数只用训练策略与验证阵容选择，测试对手冻结后只评一次。

## 8. 预期判据，不是实验事实

| 指标 | 继续投稿的目标 | 失败边界 |
|---|---:|---:|
| OC-HPN `C1S0 - C0S0` 误报差 | ≥15 pp | <5 pp：问题在该环境不显著 |
| CDOC 相对 OC-HPN 的 `FPR_comp` | 相对降低 ≥30% | <10%：解耦价值弱 |
| `AUROC_switch` | 不下降 >0.02，最好 +0.03 | 降低 >0.05：过度不变 |
| `PostSwitchRegret@K` | 降低 ≥15% | 无改善：表示未转化为决策价值 |
| `WorstOpp` | +3 至 +8 pp | 只提高平均、不提高最差：弱化鲁棒性主张 |
| ID 胜率 | -3 至 +3 pp | 下降 >5 pp 不接受 |
| 推理延迟 | <20% 增量 | >35% 违背轻量定位 |

严禁把表中数字写成已经取得的结果。

## 9. 两周内的执行顺序

1. 增加四类事件 wrapper 与冻结 manifest；
2. 训练或加载 HPN/OC-HPN，定义不看测试集的 change score/阈值；
3. 完成 P0：确认阵容变化确实导致误报；
4. 实现条件动作/位移行为编码器和阵容分支；
5. 先只加 `L_inv`，再加 `L_sep`，每次只改变一个因素；
6. 通过 P1 后才运行 MAgent2 五种子和完整消融。
