# 核心论文与复现审计

## 1. 结论先行

主复现对象仍锁定为 **HPN/PyMARL3**。本目录已完成架构级最小重写与性质测试；论文级数值复现尚未完成，必须在 Linux + SMACv2 上执行官方配置。现有 OC-HPN 现在是通用时序上下文基线。CDOC-HPN 是待实现主方法；TAO/OEOM、OM-TCN 和 2026 HyperJD2TSSM 是创新边界近邻，不要求完整复现其大模型。

## 3. 两层“复现”的定义

### R0：架构复现（已完成）

`src/q2marl/models.py` 实现以下论文级契约：

- 实体逐项共享超网络；
- masked 对称聚合，固定动作对实体顺序不变；
- 对敌目标逐项打分，敌顺序变化导致 logits 同步变化；
- recurrent actor/critic 接口；
- 参数量与实体数无关。

`tests/test_models.py` 对上述性质做自动测试。它只能证明架构契约，不证明 HPN 论文的胜率。

### R1：数值复现（待执行）

在官方 PyMARL3 上选择论文公开的 1 个中等难度 SMACv2 场景：

1. 记录 PyMARL3 commit SHA、SC2/SMACv2 版本、地图 hash、CUDA 与 Python；
2. 使用官方 HPN-QMIX 或 HPN-VDN 配置，不先改方法；
3. 跑 3 个种子，复现论文曲线趋势和最终区间；
4. 若均值相差超过论文图示 10 个百分点，先定位环境/实现差异，不进入改进方法；
5. 保留 TensorBoard/CSV、命令、配置和失败日志。

### R2：任务迁移（待执行）

把 R0 的 PI/PE 契约接入 MAgent2/IPPO 或 PyMARL3 兼容 runner，先完成 HPN 和 OC-HPN，再完成 `C0S0/C1S0/C0S1/C1S1` 事件生成与冻结 manifest。只有 OC-HPN 通过“阵容变化确实导致策略误报”的 P0 问题门后，才实现 CDOC-HPN。所有方法共享采样器、优化器、事件清单、参数预算和评估对手。

## 4. 推荐实验代码结构

```text
runner/
  train.py                 统一算法入口
  evaluate_events.py       C×S 四事件与检测/遗憾评估
  evaluate_matrix.py       补充规模/对手四象限与 worst-opponent
  seed_sweep.py            多种子调度
opponents/
  train_styles.py          训练脚本集合
  heldout_styles.py        测试时才可导入
  switching.py             episode 内策略切换
  interventions.py         减员/增援/类型替换事件
models/
  mlp_ippo.py
  hpn.py
  oc_hpn.py
  cdoc_hpn.py
logging/
  schema.json              含 seed/composition/strategy/event/checkpoint
```

关键防泄漏规则：held-out 对手的回报不能用于调参或 early stopping；选模型只看验证规模与训练对手，最终测试只运行一次冻结配置。
