# 完整调研报告：可扩展竞争 MARL 的规模—对手联合泛化

> **状态说明（2026-08-27 二次复核）**：本文保留为第一阶段研究地图，其中“通用 OC-HPN 是核心创新”和“联合规模—策略 OOD 是最终主线”的判断已被后续近邻文献否证。当前有效定位以 `06_研究价值与创新性复核.md` 为准：OC-HPN 降为基线，主问题改为对抗减员/增援下的阵容—策略混淆，主方法改为 CDOC-HPN。

**检索截止**：2026-08-27  
**范围**：置换不变/等变 MARL、跨规模零样本迁移、竞争性团队学习、对手建模、公开大规模基准  
**说明**：优先使用论文原文、会议/期刊官网和官方代码。原归档中尚未核验的 2026 预印本不作为核心证据。

## 1. 执行摘要

原方案提出的“动态分组 + 双重零样本泛化”仍有学术价值，但已不适合短周期：规模可扩展方向已有 HPN、SPECTra、SHPPO，动态人口与角色方向又出现 GIRA；如果同时声称动态分组、规模泛化和角色适应，创新边界会很难守住。另一方面，现有可扩展架构大多在合作任务或固定敌方机制上评测；对手建模工作又多在小规模、多游戏或固定规模条件下研究。两条线的交叉仍有一个可控空白：

> **使用不随实体数增长的在线对手上下文，增强 PI/PE 团队策略在未见规模与未见对手策略同时出现时的性能。**

主复现底座选 HPN，而不是 SPECTra：HPN 是 ICLR 2023 论文、官方 PyMARL3 清楚，且 PI 输入/PE 输出正好对应变长敌目标动作。SPECTra 方法更新、复杂度更低，但公开工程成熟度较弱且其发表定位不满足“顶会主基线”。OEOM 作为对手泛化的核心依据，但不复现其开放式种群；本项目只取其“时序上下文识别未见对手”的可迁移思想。

## 2. 三篇核心参考论文

### 2.1 主基线：HPN（ICLR 2023）

Hao et al. 提出统一的 agent permutation framework，并给出 DPN 与 HPN。核心是实体逐项处理后用对称聚合构成 PI 输入层，同时让与实体一一对应的动作输出随实体顺序共同置换，构成 PE 输出层。HPN 用 hypernetwork 为实体生成定制权重，可接入 VDN、QMIX、MADDPG 和 MAPPO。论文在 SMAC/SMACv2、GRF、MPE 上评测。

- 论文：https://openreview.net/forum?id=OxNQXyZK-K8
- 官方代码：https://github.com/tjuHaoXiaotian/pymarl3
- 本项目继承：PI 输入、PE 目标动作、共享参数、CTDE。
- 本项目不继承：以合作任务上的训练性能作为对手泛化证据。
- 已知局限：瞬时实体聚合没有显式刻画对手跨时间的行为模式；原论文目标不是竞争性 unseen-opponent generalization。

### 2.2 强近邻：SPECTra（2025/2026）

SPECTra 用 single-agent query attention（SAQA）把实体注意力复杂度降低到对实体数线性，并提出 set-transformer hypernetwork 生成可扩展非线性 mixer。其 SMACv2/GRF 结果显示变规模课程与迁移潜力。

- 论文：https://arxiv.org/abs/2503.11726
- 代码：https://github.com/funny-rl/SPECTra
- 本项目继承：把实体数无关、计算效率和规模迁移作为设计约束。
- 与本项目差异：SPECTra 关注合作 MARL、排列与规模；本项目关注竞争中未见对手策略及联合 OOD。
- 工程审计：仓库运行说明简短、无 release；适合强基线/近邻，不适合作为唯一复现支柱。

### 2.3 对手泛化依据：OEOM（AAAI 2025）

Jing et al. 指出固定训练对手集会导致测试 OOD，提出基于 population-based training 与轨迹空间多样性正则的开放式对手生成，并用 in-context Transformer 从轨迹中识别和响应对手。论文覆盖合作、竞争和混合环境。

- 论文与 DOI：https://doi.org/10.1609/aaai.v39i22.34488
- 本项目继承：对手表示必须来自行为历史，而非静态 ID；训练/测试对手必须严格隔离。
- 本项目删除：开放式对手生成、种群演化和大 Transformer。它们会把 8 周项目重新扩张成 SAGA。

## 3. 邻近研究地图

### 3.1 置换结构与通用策略

- **UPDeT（ICLR 2021 Spotlight）**通过 Transformer 和 policy decoupling 处理不同观测/动作配置，证明单一架构可跨任务，但全自注意力成本随实体数二次增长，官方实现对地图/单位类型仍需人工配置。论文：https://openreview.net/forum?id=v9c7hr9ADKx；代码：https://github.com/Theohhhu/UPDeT。
- **HPN（ICLR 2023）**用 PI/PE inductive bias 减少排列导致的冗余，是最合适的顶会复现底座。
- **SPECTra**进一步解决 HPN/UPDeT 在实体数与 mixer 上的效率/规模限制，是必须对比的最近架构。

共同缺口不是“还没有置换不变网络”，而是这些网络很少把**未见对手行为分布**作为独立 OOD 轴。

### 3.2 跨规模、异质性与动态人口

- **SHPPO / Zero-Shot Scalable Collaboration**用 latent network 生成异质层参数，研究不同规模下的策略模式，后发表于 Neurocomputing（DOI: 10.1016/j.neucom.2025.130716）。预印本：https://arxiv.org/abs/2404.03869。
- **GIRA**引入动态 replay 对齐、population encoder 和基于群体交互的角色生成，在合作与 MAgent Battle 对抗任务上处理加入/退出及未见规模。官方页面：https://doi.org/10.1016/j.neucom.2026.134437。
- **Zero-Shot Transfer for Robot Soccer**更早展示了队友、对手与场地规模变化下的零样本迁移，说明“跨规模”本身不能再单独作为强创新：https://www.cs.cmu.edu/~mmv/papers/18aamas-SchZhuVel.pdf。

因此，本项目不应再声称“首次动态规模 MARL”或以角色/分组为主贡献。对手策略 OOD 与规模 OOD 的交叉才是安全定位。

### 3.3 对手与伙伴泛化

- **Opponent Modeling in Deep RL（ICML 2016）**使用混合专家自动发现对手策略模式，是神经对手建模经典：https://proceedings.mlr.press/v48/he16.html。
- **RPM（ICLR 2023）**按回报排名保存历史策略，采样行为策略以扩大交互分布，在 Melting Pot 上研究未见智能体泛化：https://openreview.net/forum?id=HnSceSzlfrY。
- **OEOM（AAAI 2025）**把训练对手的强度和轨迹风格多样性显式化，并采用 in-context 序列模型。
- **RAC（2023 预印本）**在团队竞争 Markov game 中预测对手角色，但仅有两个游戏、未形成可靠跨规模协议：https://arxiv.org/abs/2301.05873。

这些工作说明仅与一个脚本/镜像策略训练不够，但完整 population training 不是短周期项目的必要条件。严格 held-out 对手划分 + 小型时序上下文已经能形成清楚问题。

### 3.4 训练框架与基准

- **SMACv2（NeurIPS 2023 D&B）**通过程序化生成提高闭环决策与泛化要求，但本质是合作 CTDE，敌方由环境控制；适合复现 HPN/SPECTra，不足以单独验证 unseen opponent：https://proceedings.neurips.cc/paper_files/paper/2023/file/764c18ad230f9e7bf6a77ffc2312c55e-Paper-Datasets_and_Benchmarks.pdf。
- **JaxMARL/SMAX（NeurIPS 2024 D&B）**提供 GPU 加速与自博弈潜力，论文报告显著墙钟加速；但 JAX/Linux 迁移不应成为首轮 P0 前置：https://proceedings.neurips.cc/paper_files/paper/2024/hash/5aee125f052c90e326dcf6f380df94f6-Abstract-Datasets_and_Benchmarks_Track.html。
- **MAgent2 Battle**是公开、大规模、双队对抗环境，Parallel API 可用；默认最多 162 个智能体、21 个离散动作，适合规模与自然减员评测：https://magent2.farama.org/environments/battle/。
- **SwarmBattle**是本项目已有可控环境，含 5 类脚本对手。它适合严格的训练/保留风格诊断，但只能作次级环境，不能独占证据链。

## 4. 精确研究空白

现有研究形成两个近似正交的集合：

| 研究线 | 解决了什么 | 通常没解决什么 |
|---|---|---|
| HPN / UPDeT / SPECTra | 实体排列、变长观测/动作、跨规模结构 | 未见对手的时序行为分布 |
| RPM / OEOM / opponent modeling | 对手/伙伴策略变化、轨迹适应 | 大规模团队、双方数量变化与 PE 目标动作 |
| SHPPO / GIRA | 规模、人口变化、角色异质性 | 严格 held-out 对手策略与联合 OOD 因果拆分 |

交叉空白可以表述为：

> 现有可扩展 MARL 策略把对手当作当前观测集合中的实体，却很少将对手跨时间的集体行为压缩为与人口数量无关的上下文；现有对手模型又没有检验该上下文在团队规模同时超出训练分布时是否仍有效。

## 5. 研究内容与论文主张

### 5.1 核心机制

OC-HPN 在 HPN backbone 旁增加一个固定维度路径：每时刻对所有可见敌实体共享编码，计算 masked mean、masked max 和 log-count，得到置换不变的步级摘要；GRU 累积最近行为；context 通过门控 FiLM 调制 actor 隐状态；辅助头预测下一步对手摘要，避免 context 只依赖稀疏胜负奖励。

### 5.2 贡献边界

- 方法创新是**对手集合的时序、数量无关条件化**，不是新 RL 优化器。
- 协议创新是**规模 ID/OOD × 对手 ID/OOD 四象限**，不是声称定义了普适 benchmark。
- 实证目标是比等容量 HPN 更稳健，不追求在所有环境刷新 SOTA。

### 5.3 可证伪假设

- H1：HPN 相比 padding-IPPO 主要改善规模 OOD，但对策略 OOD 的优势有限。
- H2：OC-HPN 相比 HPN 主要改善对手 OOD 和联合 OOD；训练域差异小。
- H3：去掉时间记忆后，动态策略切换测试的性能显著下降；去掉辅助预测后，held-out 策略可分性与最差胜率下降。
- H4：若只给脚本 ID 而不给行为，训练脚本内性能可能更高，但 held-out 对手不能使用，说明方法不是标签查表。

## 6. Introduction、Related Work、Preliminaries 的章节映射

### Introduction 逻辑

1. 大规模团队竞争部署时双方数量和行为策略都不会固定。
2. PI/PE 架构解决“有多少实体、按什么顺序”但不解决“对方正在采用什么策略”。
3. 对手建模解决行为适应，却通常没有保持变人口下的结构合法性。
4. 提出联合 OOD 问题与轻量 OC-HPN。
5. 给出协议、方法、实证三条贡献，不使用“first”。

### Related Work 分三节

1. Permutation-aware and scalable MARL：UPDeT、HPN、SPECTra、SHPPO/GIRA。
2. Generalization and opponent modeling：经典 opponent modeling、RPM、OEOM、RAC。
3. Benchmarks：SMACv2、JaxMARL/SMAX、MAgent2；解释为什么主实验需要真实可控的对手划分。

### Preliminaries 必须定义

- 两队部分可观测 Markov game；
- entity-factored observation 与 PI/PE；
- 规模条件 `s=(N,M)`、对手策略 `pi^-`；
- 四象限泛化矩阵 `ID/ID, OOD/ID, ID/OOD, OOD/OOD`；
- 平均回报、胜率、worst-opponent score 与 generalization gap；
- CTDE 与参数共享。

## 7. 结论

最稳妥、可在 8 周内闭环的论文不是“小号 SAGA”，而是围绕 OC-HPN 的单机制论文：顶会 HPN 提供可复现结构，SPECTra 提供强近邻，OEOM 提供对手泛化依据；MAgent2 提供公开大规模对抗，SwarmBattle 提供对手风格严格控制。动态分组、league 和理论界全部留在归档项目，避免两个论文互相稀释。
