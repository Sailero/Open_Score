# 三条技术路线与风险门

## 1. 三条路线各用一句话说清

### 路线 A：COGAR 二区主线（推荐）

> **做什么：**在冻结通用下层上学习同态势候选编组的校准战果分布，并用风险收益矩阵滚动求双方分兵；**为什么：**手工兵力比和隐式 critic 会高估陌生编组；**预期效果：**减少危险错配并守住更多关键点；**怎么证明：**选中方案校准、oracle regret、最坏对手和端到端任务四条证据同时改善。

### 路线 B：能力评估与可靠选择的精简版

> **做什么：**只研究完整编组的干预式战果预测与一个固定结构化求解器；**为什么：**先回答“调兵前能否可靠知道哪种编组更好”；**预期效果：**以较小工程量减少 false-safe 和选择遗憾；**怎么证明：**在多个求解器与未见对手上相对 critic、XGBoost、Fu/Carion 风格模型保持可靠，但不强求完整双边 commander 自博弈。

### 路线 C：预测器一致的上下层共同适应（一区伸展）

> **做什么：**交替更新 commander 和下层，并在每次能力变化后主动刷新/校准战果模型；**为什么：**冻结下层可能限制整体上限，而普通联合训练会让能力接口漂移；**预期效果：**在不破坏 ID 和校准的前提下继续提高 OOD 任务成功；**怎么证明：**对比冻结、朴素联合、交替、交替+KL/回放/刷新，并测 policy drift 与 evaluator drift。

## 2. 路线 A：推荐主线

### 最小方法

- 阶段 1：共享实体注意力 MAPPO，主实验冻结；
- 阶段 2：paired intervention + EGOM ensemble + temperature scaling；
- 阶段 3：每方至多 32/64 候选，风险收益矩阵 + 正则化 maximin；
- 阶段 4：不进入主方法。

### 优点

- 问题、方法和价值在同一条因果链；
- 不需要训练一个昂贵的端到端上层神经策略；
- 能与 Carion、Double-IC、ALMA 和 oracle 做清楚对照；
- 预测模型的错误可以审计，而不是把一切隐藏在 RL return 中；
- 当前 SwarmBattle 很容易先做 P0。

### 最大风险

- “学习效用 + 优化器”很接近 Carion/REDA；
- “双方联盟博弈”很接近 Double-IC；
- 若 calibration 不改变最终分兵，只会像工程拼接。

所以必须把同态势干预、选择后校准、optimizer-aware 补数据和未见对手决策证据一起做，不能只换 Set Transformer。

## 3. 路线 B：六周保底版

### 适用触发条件

第 3–4 周出现以下任一情况时转 B：

- 双边候选矩阵或自博弈不稳定；
- Double-IC/ALMA 移植占用过多时间；
- EGOM 的预测/选择信号很强，但双边 game solver 相对 robust greedy 没有额外收益；
- 只控制一方的防御场景更容易建立完整证据。

### 论文定位

把核心写成 **calibrated interventional coalition outcome prediction for reliable task allocation**。上层只用统一的 beam + min-cost/robust solver，强调 false-safe、selection regret 和 optimizer's curse。

### 价值与局限

这仍可能是一篇应用型二区文章，尤其适合 Applied Intelligence 或 EAAI，但对多智能体博弈期刊的吸引力下降。必须有强 OOD、完整数据协议与外部环境，不能只报预测 MAE。

## 4. 路线 C：一区伸展版

### 真正可能的新意

不是“上下层一起训”，而是**预测器一致的共同适应**：下层更新改变真实能力边界，上层会主动选择模型外推区域，EGOM 必须及时刷新且不遗忘旧边界。

### 最小交替算法

1. 冻结下层，训练 EGOM 与 commander；
2. 固定 commander/EGOM，使用任务回放和 KL 锚定微调下层；
3. 在旧任务、当前 commander 任务和高不确定任务上重新 rollout；
4. 更新并重新校准 EGOM；
5. 重训 commander，最多两轮。

### 为什么不适合 1–2 个月主线

- 三个组件产生三重非平稳；
- 需要更多训练预算和漂移指标；
- ALMA、C2、DT-GAT、HH-MAPPO 已覆盖一般联合/交替训练；
- 没有稳定性理论或多环境强结果，很容易被审稿人视为附加训练技巧。

第 6 周最多投入一周。若相对冻结下层 OOD 提升不足约 5 个百分点、ID 下降超过 2 个百分点或校准恶化，就停止。

## 5. 决策矩阵

| 维度 | 路线 A | 路线 B | 路线 C |
|---|---:|---:|---:|
| 预计周期 | 8 周 | 5–6 周 | 3–6 个月更合理 |
| 方法复杂度 | 中 | 低—中 | 高 |
| 与用户四阶段一致性 | 高，阶段 4 可选 | 中 | 完整 |
| 二区可行性 | **最高** | 中，偏应用 | 高风险高收益 |
| 一区潜力 | 中 | 低 | 最高 |
| 最大近邻 | Carion + Double-IC | Fu + AAMAS 2025 + Carion | ALMA + C2 + HAVEN |
| 必须证明 | 校准改善双边最终分兵 | 可靠选择而非预测好看 | 稳定共同适应而非普通联合 |

## 6. 分周切换规则

### 第 1 周：场景门

若三战线、伤亡和增援下 force-ratio 与小规模 oracle 差距小于约 5%，环境没有研究瓶颈；先改任务，不训练模型。

### 第 2 周：下层门

若统一下层在训练覆盖内的各任务成功率过低，先用强脚本隔离上层；不能让下层训练失败拖垮整篇论文。

### 第 3 周：评估器门

若 EGOM 不优于 XGBoost/critic 的选择遗憾，检查干预数据与完整 partition context；两轮仍无改善，终止 A/B。

### 第 4 周：决策门

若 COGAR-risk 不优于 COGAR-mean/no-EGOM 的端到端结果，说明校准没有决策价值；降为路线 B 或换问题。

### 第 5 周：对抗门

若双边矩阵 game 不优于 robust greedy，但 EGOM 有价值，转路线 B，不继续堆 self-play。

### 第 6 周：阶段 4 门

只在 A 已经成立时尝试 C 的一个小消融；不能用阶段 4 去挽救阶段 2+3 不成立。

## 7. 最终推荐

现在直接选择路线 A，同时把路线 B 作为明确降级路径、路线 C 作为后续论文。这样既忠于用户的四阶段思想，又不会为了“工作量看起来像一区”而把首篇论文做散。
