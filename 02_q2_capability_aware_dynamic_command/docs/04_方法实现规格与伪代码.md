# Open-SCORE 四阶段详细技术方案与核心代码

> 本文档逐阶段固定：参考论文及源码、基础数学模型、最终技术方案、当前核心代码和尚缺工作。代码以 Windows 原生 PyTorch 可运行为第一约束；论文复现仓库作为算法和 baseline 来源，而不是把旧 Docker/SC2 工程直接嵌入 HAD。

## 0. 最终技术选择

| 阶段 | 最终方法 | 首要源码基础 | 本文新增接口 |
|---|---|---|---|
| S1 | 变规模实体 QMIX | QMIX/PyMARL + REFIL | 任务 token、变数量单调 mixer、HAD 离散动作适配 |
| S2 | 双边集合结果模型 | ALMA AQL + Set Transformer | 同快照双方编组、有限窗失守标签、选择关注损失 |
| S3 | 数量候选 + 保守 minimax | ALMA allocator | 双方风险矩阵、事件重规划、切换代价 |
| S4 | 带规模守卫的交替 RL | ALMA joint training + HARL | checkpoint 蒸馏、held-out 最坏规模验收、回滚 |

## 1. 统一接口与时间尺度

微观步执行连续动力学；S1 接收离散动作原语并由适配器映射到连续加速度。宏观指挥每 $H_c$ 步或开放事件后更新任务 token。S2 的结果窗为 $H_o=K_oH_c$，只用于候选比较；在线仍只执行一个 $H_c$。

共同张量协议如下：

```python
@dataclass
class TeamObservation:
    entity_obs: Tensor      # [B, N, E, F_e]
    entity_mask: Tensor     # [B, N, E]
    self_obs: Tensor        # [B, N, F_s]
    task_obs: Tensor        # [B, N, F_m]
    agent_mask: Tensor      # [B, N]
    avail_actions: Tensor   # [B, N, A]
```

这里 $N$ 和 $E$ 是当前 batch 的 padding 上限，不进入网络参数维度。跨场景 batch 使用 mask；不同 roster 的 episode 可以并行收集后按 batch 内最大值 padding。

## 2. S1：Scale-Generalized Executor

### 2.1 参考论文与可开发源码

1. **QMIX**：Rashid et al., JMLR 2020。论文给出单调价值分解，官方 [PyMARL](https://github.com/oxwhirl/pymarl) 为 Apache-2.0 源码；核心参考是 agent RNN、target network、episode replay 和非负 mixing weights。
2. **REFIL**：Iqbal et al., ICML 2021。论文明确处理不同类型和数量的实体，官方 [REFIL](https://github.com/shariqiqbal2810/REFIL) 为 MIT 源码；核心参考是 entity-wise input、mask 和 attention-QMIX。
3. **ALMA**：Iqbal et al., NeurIPS 2022，官方 [ALMA](https://github.com/shariqiqbal2810/ALMA) 为 MIT 源码；其 `qmix_atten/refil + subtask mask` 是下层任务条件化的最接近实现。

不直接 fork PyMARL/REFIL 训练 HAD 的原因是它们的公开运行路径依赖旧 Python、Docker 和 SC2。当前仓库依据论文公式实现一个小型纯 PyTorch 核心，并保留未来导入 checkpoint/配置的清晰映射；正式 baseline 仍要锁定上游 commit 复现。

### 2.2 基础数学模型

QMIX要求

$$
\frac{\partial Q_{tot}}{\partial Q_i}\ge0,
$$

从而联合贪心动作等于各个体贪心动作组合。普通 mixer 的第一层权重为固定 $N\times d$，必须预设容量和槽位顺序，超过容量就无法运行。本文改为共享的实体条件权重：

$$
w_{ik}=\operatorname{softplus}f_w(g(s),c_i),\qquad
v_k=\operatorname{softplus}f_v(g(s)),
$$

$$
h_k=\operatorname{ELU}\left(
N_t^{-1}\sum_i m_iw_{ik}Q_i+b_k(g(s))
\right),
\quad
Q_{tot}=\sum_kv_kh_k+b(g(s)).
$$

$m_i$ 是存活 mask，$c_i=[o_i^{self},o_i^{task}]$。所有乘在 $Q_i$ 上的权重非负，ELU 单调，因此仍满足 QMIX 条件。除以 $N_t$ 是为降低价值尺度随人数机械增长；状态编码显式含对数计数，所以网络仍知道规模。

TD 目标使用 Double-Q：

$$
y=r+\gamma(1-d)
Q_{tot}^{-}\left(s',\arg\max_{\mathbf u'}Q_{tot}(s',\mathbf u')\right),
\qquad
\mathcal L_{QMIX}=\operatorname{Huber}(Q_{tot},y).
$$

### 2.3 核心技术方案

- 所有同阵营打击智能体共享一个实体编码器、GRU 和动作头；
- 观测特征包括相对位置/速度、健康、存活、阵营/目标/自身类型；
- task token 包括分配目标的相对位置、健康、存活和归一化编号；
- HAD 连续加速度映射为 9 个原语：悬停、六轴方向、朝任务目标、朝最近敌人；规则开火暂由环境负责；
- 每个 episode 从训练规模集合采 $(N_D,N_A,M)$，创建相应 HAD 实例；同一模型参数跨实例共享；
- 第一版只训练红方对固定蓝方追击脚本，随后换边训练蓝方；不同时引入 PSRO。

### 2.4 主要代码

实际实现：[stage1/entity_qmix.py](../src/open_score/stage1/entity_qmix.py)。核心 mixer 为：

```python
positive_w1 = F.softplus(self.first_weights(torch.cat([state, agent_ctx], -1)))
active = agent_mask.float().unsqueeze(-1)
mixed = (positive_w1 * chosen_q.unsqueeze(-1) * active).sum(1)
mixed = mixed / active.sum(1).clamp_min(1.0)
hidden = F.elu(mixed + self.first_bias(state_ctx))
q_tot = (F.softplus(self.final_weights(state_ctx)) * hidden).sum(-1)
```

HAD 适配器：[envs/had_stage1.py](../src/open_score/envs/had_stage1.py)。最小训练配置：[stage1_had_demo.yaml](../configs/stage1_had_demo.yaml)。当前 `one_step_qmix_td_loss` 只是验证梯度链，正式训练器必须补 episode replay、burn-in、sequence TD($\lambda$)、target sync 和 epsilon schedule。

### 2.5 S1 Demo 验收

训练规模先用 $N_D,N_A\in\{2,4,6\}$、$M\in\{1,2,3\}$，held-out 用奇数人数和更不利比例。三 seed 初步门槛：训练规模胜率不低于 0.65、held-out 不低于 0.50、平均下降不超过 0.20。这些只是决定是否进入 S2 的工程门槛，不是论文最终效应量。

## 3. S2：Bilateral Outcome Model

### 3.1 参考论文与可开发源码

1. **ALMA/AQL**：官方 [ALMA 源码](https://github.com/shariqiqbal2810/ALMA)学习 state–allocation 条件 Q 并用候选筛选，是最直接的结果评分基础。
2. **Set Transformer**：Lee et al., ICML 2019，官方 [PyTorch 源码](https://github.com/juho-lee/set_transformer) 为 MIT 许可，提供可变集合交互编码。
3. **Decision-Focused Learning through Learning to Rank**：Mandi et al., ICML 2022，作者公开 [ltr-predopt](https://github.com/JayMan91/ltr-predopt)；借用同 query 候选的 pairwise ranking 思路。

### 3.2 基础数学模型

对根快照 $s_r$、防守编组 $z_i^D$、攻击编组 $z_j^A$ 和冻结执行器版本 $v$，执行 $R$ 个公共随机数 rollout：

$$
y_{rij\ell}=\mathbb 1[\text{breach within }H_o],
\quad
p_{rij}=\Pr(y=1\mid s_r,z_i^D,z_j^A,v).
$$

模型使用三个掩码 Set-Transformer 编码器：全局实体、防守 assignment token、攻击 assignment token：

$$
\hat p=\sigma\,\operatorname{MLP}
\left([g_s(\mathcal E),g_D(\mathcal T_D),g_A(\mathcal T_A)]\right).
$$

损失为

$$
\mathcal L_{S2}=\frac{\sum_nw_n\operatorname{BCE}(\hat p_n,y_n)}{\sum_nw_n}
+\lambda_r\sum_{(a,b)}\log(1+\exp(\ell_a-\ell_b)),
$$

其中 $b$ 是同一快照下真实风险更高的候选。$w_n$ 由独立 pilot selector 冻结产生，不能用同一标签反复更新权重。

### 3.3 核心技术方案

- 先冻结 S1 checkpoint 和版本哈希；能力变化后必须重新采数据；
- 同一根快照改变双方完整编组，而不是只改变我方、把对方固定成脚本动作；
- 训练/选择校准/经验修正/最终 Test 按 root lineage 隔离；
- 主输出只保留 $H_o$ 内任一目标失守概率；战损、首个失守目标等作为诊断；
- 在独立数据上计算 selector bucket 残差并做经验保守修正，不能宣称有限样本形式保证。

### 3.4 主要代码

实际实现：[stage2/outcome_model.py](../src/open_score/stage2/outcome_model.py)，集合注意力核心见 [nn.py](../src/open_score/nn.py)。核心前向为：

```python
state = self.state_encoder(state_entities, state_mask)
defender = self.defender_encoder(defender_tokens, defender_mask)
attacker = self.attacker_encoder(attacker_tokens, attacker_mask)
logit = self.head(torch.cat([state, defender, attacker], dim=-1))
```

下一步缺少的是 `snapshot -> bilateral branch -> lineage dataset` 采集器、校准器和经验修正估计器；在 S1 没有可用 checkpoint 前不应伪造这些数据。

## 4. S3：Dynamic Robust Commander

### 4.1 参考论文与可开发源码

1. **ALMA** 的 AQL 自回归提议和 heuristic allocator 提供候选生成/评分 baseline，源码同上；
2. **SciPy HiGHS** 提供可复现的线性规划实现；它是标准求解器，不作为论文创新；
3. 后续若加入策略种群，可接 [OpenSpiel PSRO](https://github.com/google-deepmind/open_spiel/blob/master/open_spiel/python/examples/psro_v2_example.py)，但不进入当前 Demo。

### 4.2 基础数学模型

先枚举数量向量

$$
z^D=(n_1,\ldots,n_M),\quad n_m\in\mathbb N,\quad\sum_mn_m=N_D,
$$

再由固定代价匹配到个体。若候选过多，按预注册规则截断到 $K_D,K_A$。S2 产生 $K_D\times K_A$ 风险矩阵，加入经验修正和切换代价：

$$
M'_{ij}=\operatorname{clip}(\hat p_{ij}+\Delta_{ij},0,1)
+\lambda_{sw}C_{sw}(z_i^D,z_{prev}^D).
$$

防守混合策略通过 LP 求解

$$
\min_{x,v}v\quad
\text{s.t. }x^\top M'_{:,j}\le v,\ \forall j;
\quad\mathbf1^\top x=1,\ x\ge0.
$$

在线执行从 $x$ 采样一个防守候选；`selected_index` 只保留最大概率候选用于确定性日志/无随机回退，不能把它误当成混合策略本身。

### 4.3 核心技术方案

- 数量级枚举避免 $M^{N_D}$ 个体组合爆炸；
- S1 task token 保证上层只需传目标编号，不干预微动作；
- 重规划由固定周期或 roster/目标变化触发；
- 主实验候选矩阵控制在约 $16\times8$，以便做真实 rollout oracle；
- 若 SciPy 不可用，代码退化到最小化每行最坏风险的确定性候选，并明确记录 fallback。

### 4.4 主要代码

实际实现：[stage3/commander.py](../src/open_score/stage3/commander.py)。核心约束为：

```python
objective = np.r_[np.zeros(rows), 1.0]
a_ub = np.c_[risk_matrix.T, -np.ones(cols)]
result = linprog(objective, A_ub=a_ub, b_ub=np.zeros(cols),
                 A_eq=np.r_[np.ones(rows), 0.0][None, :],
                 b_eq=np.array([1.0]), method="highs")
```

尚缺个体级 Hungarian matcher、candidate feature builder、S2 批量调用和宏周期 runner。

## 5. S4：Capability–Command Co-Adaptation

### 5.1 参考论文与可开发源码

1. **ALMA**：论文报告同时学习上层分配和下层策略通常优于简单拼接的分阶段训练；官方源码包含 joint high/low learning，是最直接的系统 baseline。
2. **HARL/HAPPO**：Zhong et al., JMLR 2024，官方 [HARL](https://github.com/PKU-MARL/HARL) 是 PyTorch 源码；借用“顺序更新比所有策略同时漂移更可控”的思想，而不直接替换 S1 的 QMIX。

### 5.2 为什么不是 LLM 微调

任务没有自然语言输入、知识问答或长上下文推理，动作和回报来自数值仿真。LLM 会把固定维度控制问题变成昂贵 token 序列，也无法直接保证动力学闭环稳定。除非未来加入自然语言任务说明或人机指挥，首篇不使用 LLM。

### 5.3 基础数学模型

理想目标是双层鲁棒回报

$$
\max_{\phi,\Theta}\min_{\nu\in\mathcal U_A}J(\phi,\Theta;\nu),
$$

但不对离散 LP 和环境做端到端反传。采用坐标更新：

$$
\Theta^{k+1}=\operatorname{FitOutcomeAndCommand}(\phi^k),
$$

$$
\phi^{k+1}=\arg\min_\phi
\mathcal L_{QMIX}(D_{\Theta^{k+1}})
+\lambda_{stab}\|Q_\phi-Q_{\phi^k}\|^2.
$$

接受条件为

$$
\min_{c\in\mathcal C_{guard}}J_c(\phi^{k+1},\Theta^{k+1})
\ge
\min_{c\in\mathcal C_{guard}}J_c(\phi^k,\Theta^k)-\epsilon.
$$

### 5.4 核心技术方案

1. 冻结 S1，采集/更新 S2 并更新 S3；
2. 用新指挥器产生的 assignment 分布训练 S1 若干步；
3. 对旧 checkpoint 做 Q-value distillation，减少旧规模遗忘；
4. 在完全独立的 guard scale grid 上评估；
5. 未通过则恢复模型和 optimizer；通过则登记新 policy-version，重新进入 S2 数据阶段。

这比一次性 end-to-end joint training 慢，但能明确归因“哪次能力更新让上层模型失效”，适合论文审计和单卡算力。

### 5.5 主要代码

实际实现：[stage4/coadaptation.py](../src/open_score/stage4/coadaptation.py)。核心接受/回滚逻辑为：

```python
old_parameters = copy.deepcopy(lower_policy.state_dict())
loss.backward(); optimizer.step()
new_worst = min(evaluate_scale_success().values())
if new_worst < old_worst - allowed_drop:
    lower_policy.load_state_dict(old_parameters)
    optimizer.load_state_dict(old_optimizer)
```

当前只是更新原语。完整 S4 runner 只有在 S1–S3 都通过门槛后才实现，否则无法区分共适应收益和前级缺陷。

## 6. 完整算法伪代码

```text
Algorithm Open-SCORE
Input: scale distributions P_train/P_guard, command interval H_c

1: Train Stage-1 entity-QMIX against registered scripted opponents
2: Evaluate one frozen checkpoint on seen and held-out scales
3: if S1 gate fails: stop and repair the executor
4: repeat for outer iteration k = 0...K
5:     freeze and hash lower policy phi_k
6:     collect root snapshots under registered roll-in policies
7:     for every root and paired (defender, attacker) allocation:
8:         clone root; roll out H_o with common random numbers
9:         record breach label and lineage
10:    fit/calibrate S2 without crossing root lineages
11:    construct S3 candidate matrices and solve minimax commands
12:    run offline regret and online open-population evaluation
13:    if k == K or S4 is disabled: break
14:    freeze S2/S3; collect commander-induced lower-level replay
15:    update S1 with QMIX loss plus old-checkpoint stability loss
16:    evaluate worst success over P_guard
17:    if guard fails: rollback S1 and reduce update budget
18:    else: accept phi_{k+1}; invalidate old S2 cache
19: end repeat
```

## 7. 复杂度与可实现性

- S1 网络前向与活跃实体数和智能体数近似线性；集合 max/mean 不依赖固定维度；
- S2 的主要成本不是网络，而是 $R\times K_D\times K_A\times H_o$ 个环境步；
- S3 的小型 LP 可在 CPU 毫秒级完成，正式部署必须报告实测而非预设；
- S4 会多次刷新 S2 数据，是总工作量最大的阶段；应限制为 2–3 个 outer iterations。

在 Windows 原生上，HAD 和 PyTorch 可运行；JAX 的 NVIDIA GPU wheel 不支持原生 Windows，因此 Open-SMAX-AD 应放到 WSL2。ALMA 官方 Docker/SC2 也建议在 WSL2 独立环境复现，避免污染 HAD 的 Python 环境。

## 8. 当前代码不是完整训练器

已经实现的是研究骨架：张量契约、四阶段核心模块、HAD 适配、配置、测试和一阶梯度 smoke。仍需实现：episode runner、变长 replay、sequence learner、日志/checkpoint、批量 scenario factory、S2 数据谱系、Hungarian 和 S4 outer loop。完整顺序见[代码框架与第一阶段 Demo](07_代码框架与第一阶段Demo.md)。
