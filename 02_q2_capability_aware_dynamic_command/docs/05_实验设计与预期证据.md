# Open-SCORE 实验设计与预期证据

## 1. 整篇论文到底要证明什么

唯一系统级主问题是：

> **在双方人数因伤亡和增援变化时，Open-SCORE 是否比固定规模协作、只做动态分配和朴素上下层联合训练更能维持跨规模、跨对手的最坏防守胜率？**

建议唯一统计主终点为

$$
\operatorname{RobustSuccess}=
\min_{c\in\mathcal C_{scale}}
\min_{\nu\in\mathcal U_{opp}}
\Pr(\text{all protected assets survive}\mid c,\nu).
$$

四阶段的其他指标用于解释为什么主终点变化，不能各自变成一篇互不相干的小论文。

## 2. 最终环境选择

| 环境 | 角色 | 必须完成的内容 | 不应声称 |
|---|---|---|---|
| **Open-HAD** | 第一 Demo 与主机制环境 | 打击智能体/目标、变 episode 规模、伤亡；后补增援、clone/PRNG | 现成标准 benchmark |
| **ALMA `sc2multiarmy`** | 官方复现锚点 | 锁上游 commit，复现一个公开配置；移植 AQL/heuristic baseline | 与 Open-HAD 完全同任务 |
| **Open-SMAX-AD** | 第二动力学确认 | WSL2 下增加资产、任务 token、双方分配和人口事件 | 原始 SMAX 或薄封装 |
| SMACv2 / MAgent2 | 非核心 sanity | 仅在预算允许时做常规规模或大规模压力测试 | 首篇第三主环境 |

HAD 必须先做，因为开发周期短且场景语义可控；ALMA 官方任务必须复现，因为它是最接近的层次分配源码；Open-SMAX-AD 只有在 HAD 的四阶段结论成立后才开发。

## 3. 最终 baseline

### 3.1 S1 下层 baseline

| 名称 | 来源 | 规模处理 | 公平性要求 |
|---|---|---|---|
| Shared-IQL | PyMARL | 参数共享，固定/pad 输入 | 相同实体编码和训练步 |
| VDN | PyMARL/REFIL | mask 后求和 | 相同 replay/探索 |
| Fixed-Capacity QMIX | PyMARL | 预设 $N_{max}=8$ 并 pad；mixer 绑定槽位 | 同容量、同参数量级 |
| Attention-QMIX / REFIL | REFIL 官方源码 | 实体 mask、跨任务 | 官方语义移植，不虚称官方 HAD 结果 |
| **Variable-Scale QMIX** | 本文 | 实体输入 + 变数量单调 mixer | 与上述共用 action/task 接口 |

第一阶段核心比较只需 Fixed-Capacity QMIX、Attention-QMIX/REFIL 和本文方法；IQL/VDN用于确认价值分解是否必要。固定容量 baseline 能运行所有 $N\le8$ 的注册测试，但不能越过容量，且必须固定槽位语义。

### 3.2 全系统 baseline

| 名称 | 下层 | 上层 | 共同适应 |
|---|---|---|---|
| Dynamic Heuristic | 同一 S1 | 按人数/距离均衡分配 | 无 |
| Adapted ALMA-AQL | 同一 S1 或官方下层对照 | AQL 候选评分 | ALMA joint 版本 |
| Point-Estimate Commander | 同一 S1 | S2 点预测 + argmin | 无 |
| Frozen Open-SCORE | 本文 S1 | S2+S3 | 冻结下层 |
| **Full Open-SCORE** | 本文 S1 | S2+S3 | S4 guarded alternating |

可选增加 MAPPO/HAPPO 整体参考，但不能因其训练预算大而挤掉 ALMA 和逐阶段消融。

## 4. 场景划分

### 4.1 第一阶段 HAD Demo

训练 episode 从下列笛卡尔积随机采样：

$$
N_D,N_A\in\{2,4,6\},\qquad M\in\{1,2,3\}.
$$

held-out 规模固定为 $(3,5,2)$、$(5,7,3)$、$(7,5,3)$，再增加两个极端兵力比作为 stress。每种配置使用相同初始位置种子比较方法。

当前 HAD 不支持局内 spawn，因此 Demo 只验证：

- 不同 episode 初始规模共用同一 checkpoint；
- 局内伤亡后 active mask 改变；
- 任务 token 对不同目标和不同组人数有效。

增援属于 Open-HAD P1，不能在 Demo 报告中写成已经完成。

### 4.2 正式开放事件

正式环境实现 0–2 批增援，但首篇训练/核心 ID 不注入外生增援，只让自然伤亡改变人数；增援的到达时间、数量和位置只从预注册的独立 OOD 集合采样。测试分为：

- Scale-ID：训练见过的人数范围与比例；
- Scale-OOD：未见人数或更极端比例；
- Event-OOD：更早/更晚到达和连续两次战损；
- Opponent-OOD：未参加训练的规则编组/微策略。

## 5. 分阶段实验

### E0：环境与接口验收

要做：固定种子可复现、padding/实体排列不改变网络输出、死亡只改变 mask、超时与终局分开、目标不会被防守方误伤、单/多进程吞吐实测。

通过条件：所有单测通过；同种子重复 rollout 一致；不存在只靠环境 bug 获胜的方法。

### E1：S1 规模泛化

训练各下层方法，3 seeds 做 Demo、正式稿 5 seeds。每隔固定环境步在 seen/held-out grid 各跑 200 局，最终表至少报告：

1. seen 平均胜率；
2. held-out 平均胜率；
3. 最坏规模胜率；
4. 从 seen 到 held-out 的胜率下降；
5. 每步推理时间。

Demo go/no-go：本文方法 held-out 胜率至少 0.50、seen-to-held-out 下降不超过 0.20，并优于 Fixed-Capacity QMIX。若做不到，先修 S1，不启动 S2。

### E2：S2 能力/结果评估

从冻结 S1 rollout 抽取非终局根状态。小规模根状态上枚举全部双方数量编组，每对运行 $R$ 个共同随机数分支。按 root lineage 分 Train、Pilot、Calibrate、Test。

只报告五项：Brier、NLL、pairwise ranking accuracy、selected false-safe rate、按规模分层的 ECE。通过条件不是平均 Brier 最小，而是 Test 上被 S3 选中的候选仍能保持较低假安全率。

### E3：S3 动态指挥

在相同根状态真实 rollout 矩阵上比较 heuristic、ALMA-AQL、point commander 和 robust commander。离线指标为 decision regret；闭环指标为资产存活、最坏对手成功率、重编组次数和在线延迟。

若 E2 预测更准但 E3 regret 不下降，则 S2/S3 接口没有实际价值，不能只展示校准图。

### E4：S4 上下层共同适应

从同一个 Frozen Open-SCORE checkpoint 开始比较：

1. `Frozen`：不更新 S1；
2. `Naive Joint`：上/下层持续同时更新，无版本隔离和回滚；
3. `Periodic Retrain`：固定周期重训下层并完全重采 S2；
4. `Guarded Alternating`：本文稳定性正则 + 最坏规模守卫。

主指标仍是 RobustSuccess；补充报告新规模增益、旧规模遗忘量、每轮新增 rollout 数和 rollback 次数。只有 Guarded Alternating 同时提高最坏胜率并减少遗忘，S4 才成立。

### E5：跨动力学确认

先在官方 `sc2multiarmy` 复现 ALMA 的一个配置，记录 commit、依赖、地图、步数和曲线偏差。随后在 Open-SMAX-AD 只复验四个关键方法：heuristic、adapted ALMA、Frozen Open-SCORE、Full Open-SCORE。无需复制所有 S1 baseline。

## 6. 四阶段必要性消融

| 消融 | 删除内容 | 预期影响 | 要证明的关系 |
|---|---|---|---|
| w/o Variable Mixer | 固定人数 QMIX | held-out 规模退化 | S1 是开放规模基础 |
| w/o Bilateral Outcome | 单边/比例特征评分 | 对方改编组时 regret 增大 | S2 必须建模双方方案 |
| w/o Robust Reallocation | 固定或贪心分配 | 伤亡后最坏对手成功率下降 | S3 将能力变成决策 |
| w/o Guard | 朴素 joint update | 旧规模遗忘、结果模型漂移 | S4 需要受控共适应 |

表中“预期影响”是待检验方向，不是已经获得的结果。

## 7. 统计协议

- Demo 3 seeds，正式主结果至少 5 seeds；
- 胜率用 episode-level 分层 bootstrap 95% CI；
- 同一初始状态/事件种子做方法间配对比较；
- 主终点只检验一次，次指标做 Holm 修正；
- 训练失败和被回滚的 S4 更新都保留日志；
- Test 只能在超参数、规模守卫和停止规则冻结后打开。

## 8. 预期证据与停止条件

| 阶段 | 成立所需证据 | 失败后怎么做 | 禁止补救方式 |
|---|---|---|---|
| S1 | 同一 checkpoint 跨规模优于强 baseline | 改输入/训练分布，最多两轮 | 为每个人数单独训练 |
| S2 | selected 候选仍可靠 | 缩短窗口/增加配对数据 | 只报平均准确率 |
| S3 | regret 与最坏胜率同步改善 | 缩小候选/查执行器 | 只报上层预测分数 |
| S4 | 新规模提升且旧规模不遗忘 | 降低更新步/加强稳定约束 | 删除失败 outer loop |

四阶段论文只有在 E1–E4 形成闭环时成立；若 S4 失败，最诚实的收束仍是上一版 S1 冻结的 S2+S3 论文。
