## 1. 摘要

### 1.1 中文摘要

在多目标点攻防博弈中，防守方必须同时守住 $M$ 个目标点，而攻击方只需攻破其中任意一个即可获胜。这种「最弱环节（weakest-link）」结构使得防守方的效用**不是各目标点收益的加和**，而是各目标点风险的**最大值**；同时，攻击方会主动搜索并打击防守方最薄弱的那一点。二者叠加导致：任何基于**点估计期望值**的兵力分配方法，都会系统性地把兵力配置到「看起来平均最优、实则最易被针对」的方案上——这正是决策论中的 optimizer's curse 在对抗场景下的放大版。

本文提出 **COGAR**，一个四阶段框架，其核心主张是：*上层分配决策的质量，取决于「用什么接口去刻画下层兵团的对抗结果」，而这个接口应当是双边的、分布式的、经过校准的、并且以整体胜率为唯一优化目标闭环刷新的。*

四个阶段分别为：**(S1) 规模不变的下层执行器**，采用实体注意力（entity-attention）策略网络，使同一套参数可执行任意规模的兵团任务，训练后冻结；**(S2) 双边校准结果模型**，通过「快照克隆 + 配对干预 rollout + 公共随机数（CRN）」采集数据，学习在给定战场快照、防守分配 $x$、攻击分配 $y$ 条件下，各目标点失守概率、失守时刻与双方战损的**分布**，并经深度集成与温度标定获得可信的不确定性；**(S3) 风险感知对抗分配**，在决策时刻枚举候选分配，用 S2 模型批量填充 $|\mathcal{X}|\times|\mathcal{Y}|$ 收益矩阵，取失守概率的**上置信界**构造悲观效用，再以线性规划求解单步零和矩阵博弈的混合策略；**(S4) 以胜率为唯一目标的闭环协同微调**，采用 expert-iteration 式数据循环：用当前完整系统对局，把规划器均衡支撑集上的样本重加权后刷新 S2，把规划器实际选中的分配分布回灌 S1 做 KL 锚定微调，用固定探针集的 JS 散度检测能力漂移并触发重采集。S4 不对任何中间指标（Brier、ECE）做优化，它们只作为诊断量。

我们在自建的轻量级 **GuardPoints** 攻防环境（NumPy 实现、支持精确状态克隆与 CRN、单核 >10k steps/s）上验证，并在 SMAC-HARD 上做迁移性验证。评价分三层：预测层（Brier / NLL / ECE）、决策层（相对大样本 oracle 的 decision regret、top-$k$ regret）、任务层（防守胜率、对最佳响应攻击者的可利用度 exploitability、跨规模泛化曲线、算力预算–效果 Pareto）。预期在未见攻击者策略与未见规模上，COGAR 相对最强基线取得显著胜率提升，且 decision regret 在相同 rollout 预算下比稀疏蒙特卡洛低一个量级。

**关键词**：多智能体攻防博弈；分层决策；结果模型；不确定性校准；矩阵博弈；规模泛化

### 1.2 English Abstract

In multi-target attack–defense games, the defender must protect all $M$ targets while the attacker wins by breaching **any single one**. This weakest-link asymmetry makes the defender's utility a *maximum over per-target risks* rather than a sum of per-target rewards, and simultaneously incentivizes the attacker to seek out the defender's thinnest coverage. Consequently, allocation policies driven by **point-estimate expected values** are systematically exploitable — an adversarially amplified instance of the optimizer's curse.

We present **COGAR**, a four-stage framework built on the claim that the quality of high-level allocation hinges on *the interface used to characterize the outcome of committed sub-forces*, and that this interface must be **bilateral, distributional, calibrated, and closed-loop-refreshed against end-to-end win rate**. (S1) A scale-invariant low-level executor based on entity attention, trained then frozen. (S2) A bilateral outcome model trained from snapshot-cloned, paired interventional rollouts under common random numbers, predicting the joint distribution of per-target breach probability, time-to-breach and bilateral attrition, calibrated via deep ensembles and temperature scaling. (S3) Risk-aware adversarial allocation: candidate allocations are enumerated, the payoff matrix is batch-filled by S2, pessimistic utilities are formed from upper confidence bounds on breach probability, and a single-step zero-sum matrix game is solved by linear programming. (S4) Win-rate-driven co-adaptation via expert iteration, with equilibrium-support reweighting for the outcome model, KL-anchored fine-tuning of the low-level policy on the planner-induced allocation distribution, and probe-set drift detection.

Experiments on a lightweight, clone-and-restore-capable **GuardPoints** environment, with transfer validation on SMAC-HARD, evaluate prediction quality, decision regret against a large-sample oracle, and task-level win rate / exploitability / scale generalization.

## 2. 一句话定位与最终判断

**一句话**：我们不是提出「又一个分层 MARL 算法」，而是研究**分层攻防决策中上下层之间的那个接口应该长什么样**——并证明在「任一目标失守即输」的最弱环节结构下，这个接口必须同时是**双边的、分布式的、悲观的**，缺一项就会被对手针对性击穿。

**最终判断（诚实版）**：

| 维度 | 判断 |
|---|---|
| 问题真实性 | ✓ 真实。多目标点防御 + 对手规模/策略双变，现有工作确无系统方案 |
| 创新性 | 中上。不是全新范式，但「双边 option 结果模型 + 最弱环节悲观求解 + 胜率闭环」的组合无先例 |
| 可实现性（单卡 5070 Ti + Windows/WSL2） | ✓ 可行，前提是**自建轻量环境**而非直接上 SC2 系 |
| 单人工作量 | 3–4 个月到可投稿，8 周到有说服力的初步结果 |
| 目标档位 | **稳二区**（JAAMAS / Applied Intelligence / IEEE ToG / Neurocomputing）；补齐第二环境 + 可利用度理论界后**冲一区**（TNNLS / AIJ / AAMAS full） |
| 最大风险 | 环境太简单导致所有方法都逼近 oracle，创新点无处体现 → 见 §12「Day-0 判死实验」 |

## 3. 研究背景与动机

### 3.1 应用背景

多目标点防御是军事、安防、反无人机等领域的原型问题：若干高价值资产分散布置，防守方拥有有限的可机动兵力，攻击方从未知方向、以未知兵力配比、针对未知目标发起进攻。防守方的困境有三重：

第一，**覆盖–集中的两难**。兵力分散则每点都薄，攻击方集中兵力可轻易攻破任一点；兵力集中则其余点洞开。这是 Colonel Blotto 博弈的经典结构（Roberson, 2006），但真实场景比 Blotto 复杂之处在于：每一路的胜负不是由兵力数量的简单比较决定，而是由**兵种搭配、地形位置、微观战术执行水平**共同决定的一个随机过程。

第二，**规模持续变化**。战斗过程中双方单位不断阵亡（本工作明确**只考虑消亡、不考虑增援**），意味着同一局内决策问题的维度本身在收缩。一个在 8v8 时最优的分配逻辑，在 3v5 残局时可能完全错误。

第三，**对手不可知且自适应**。攻击方可能采用固定目标强攻、侦察后打最弱点、分兵佯攻、集火消灭防守机动兵力后再拆目标等多种策略，且这些策略在部署时是未见的。

### 3.2 技术动机：为什么点估计一定会输

设防守方对分配方案 $x$ 的各目标点失守概率有估计 $\hat{p}_m(x)$，真值为 $p_m(x)$，估计误差 $\epsilon_m = \hat p_m - p_m$ 零均值。防守方按最小化 $\max_m \hat p_m(x)$ 选择 $x^\star$。由于选择过程本身就是在对**估计值**取极值，被选中的方案倾向于是那些 $\epsilon_m$ 恰好偏负（低估风险）的方案——这就是 optimizer's curse（Smith & Winkler, 2006）。

在**非对抗**场景下，这只造成一个有界的性能损失。但在本场景下有两层放大：

**放大一（最弱环节）**：防守方获胜要求所有目标都不失守，$P(\text{win}) = P(\bigcap_m \{z_m=0\})$。这是一个 min 型（对风险取 max）目标，对最大风险项的估计误差极度敏感。加和型目标里一个 +0.1 的误差可以被另一个 −0.1 抵消；min 型目标里不能。

**放大二（对抗性选择）**：攻击方的最佳响应恰好是攻击 $\arg\max_m p_m(x^\star)$——也就是防守方最可能低估的那一点。攻击方相当于一个**主动搜索防守方估计误差的对手**。于是误差不再是零均值噪声，而是被系统性地兑现成损失。

这直接推出本文的三个方法学要求：

- 结果模型必须**输出分布而非点值**，才能构造悲观界；
- 效用必须用**上置信界**（对失守概率取高分位）而非期望，把估计不确定性转化为保守性；
- 求解必须用**minimax / 混合策略**而非 argmax，才能对抗最佳响应型对手。

这三点单独看都不新，但它们在此场景下是**由问题结构强制推导出来的必需品，而非工程选项**——这是本文论证创新性的主线。

### 3.3 为什么现有分层 MARL 不够

主流分层 MARL（如 ALMA, Iqbal et al., NeurIPS 2022；HAVEN, AAAI 2023）用一个**隐式的上层价值函数**来做子任务分配。这个隐式价值有三个致命属性：它是**单边的**（只以己方分配为输入，对手被折叠进环境动力学）、它是**点估计的**（一个标量 Q 值，无不确定性）、它是**在训练对手分布上拟合的**（换对手即失效）。当对手会针对性地攻击最弱点时，这三点同时失效。

而 RTS 领域的分层对抗搜索（Stanescu et al., AIIDE 2014；Ontañón & Buro, IJCAI 2015）虽然是**双边的**，但依赖**解析或脚本化的战斗模型**（Lanchester 方程、手工规则），无法刻画学习型下层策略的真实能力，也不提供不确定性。Uriarte & Ontañón（IEEE ToG 2017）开始用数据学习战斗模型，但仍是**单场遭遇战的点估计**，未接入对抗求解，也未处理多目标点的最弱环节结构。

**空白**：没有工作把「学习得到的、双边条件的、校准的结果分布」作为分层攻防决策的接口，并针对最弱环节目标做风险感知的博弈求解。

## 4. 问题定义（Preliminary）

### 4.1 攻防博弈的形式化

我们将问题建模为一个**部分可观测零和随机博弈（POSG）**，记为


$$
\mathcal{G} = \langle \mathcal{S},\ \mathcal{G}_{\text{tgt}},\ \mathcal{D},\ \mathcal{A},\ \mathcal{U}^D,\ \mathcal{U}^A,\ P,\ \Omega,\ O,\ R,\ T \rangle

$$

**目标点集合**：$\mathcal{G}_{\text{tgt}} = \{g_1,\dots,g_M\}$，$M \in [2,5]$。每个目标点 $g_m$ 有固定位置 $\ell_m \in \mathbb{R}^2$ 与耐久 $h_m(t) \in [0, H]$。目标点**不可移动、不还击、不修复**。

**单位集合**：防守方 $\mathcal{D}_t = \{d_1,\dots,d_{n_D(t)}\}$，攻击方 $\mathcal{A}_t = \{a_1,\dots,a_{n_A(t)}\}$。每个单位由实体特征向量描述：$e = (\text{type},\ \text{hp},\ \text{pos},\ \text{cooldown},\ \text{range},\ \text{speed},\ \text{dmg})$。

**关键约束（本工作明确设定）**：
- **只消亡，不增援**：$n_D(t)$ 与 $n_A(t)$ 单调非增。这保证局内规模变化完全由战损驱动，去除了增援时序这个混淆变量。
- **不分区域**：所有单位在同一张连续地图上自由机动，目标点只是地图上的若干静态坐标。分配 $x$ 表达的是「该单位的当前任务指向哪个目标点」，而不是空间隔离。任何单位都可以在下一个宏步被重新指派到任意目标点，代价是移动时间。

**终止与胜负**：

$$
\text{结局} = \begin{cases}
\text{攻击方胜（防守方负）} & \exists m,\ t \le T:\ h_m(t) = 0 \\[4pt]
\text{防守方胜} & n_A(t) = 0 \ \text{或}\ t = T \ \text{且}\ \forall m: h_m(t) > 0
\end{cases}

$$

这就是**最弱环节结构**：防守方需要 $M$ 个「与」条件同时成立，攻击方只需一个「或」条件。

**零和收益**：$R^D = +1$（防守胜）/ $-1$（防守负），$R^A = -R^D$。

### 4.2 分层决策结构

引入宏步长 $T_m$（例如 25 个环境步）。在每个宏决策时刻 $t_k = k \cdot T_m$：

**防守方分配**（决策变量）：

$$
x^{(k)} : \mathcal{D}_{t_k} \to \mathcal{G}_{\text{tgt}} \cup \{\varnothing\}

$$
其中 $\varnothing$ 表示机动预备队（不绑定任何目标点，由下层自主游走支援）。其**计数抽象**为

$$
\mathbf{x}^{(k)} = (x_1,\dots,x_M,x_\varnothing),\quad \textstyle\sum_m x_m + x_\varnothing = n_D(t_k)

$$

**攻击方分配**（对手变量，防守方不可直接观测）：

$$
\mathbf{y}^{(k)} = (y_1,\dots,y_M,y_\varnothing),\quad \textstyle\sum_m y_m + y_\varnothing = n_A(t_k)

$$

**下层执行器**：给定分配 $x$，每个单位 $i$ 由共享参数策略 $\pi_\theta(u_i \mid o_i, \tau_i)$ 控制，其中 $\tau_i = x(i)$ 是该单位被指派的任务令牌。$\pi_\theta$ 在宏步内保持分配不变，连续执行 $T_m$ 步。

**双层结构的形式化**：

$$
\underbrace{\max_{\mathbf{x}} \min_{\mathbf{y}}\ \mathbb{E}\big[R^D \mid s_{t_k},\mathbf{x},\mathbf{y},\pi_\theta\big]}_{\text{上层：对抗分配（S3）}}
\qquad\text{s.t.}\qquad
\underbrace{\pi_\theta \text{ 固定}}_{\text{下层：S1 冻结}}

$$

### 4.3 结果模型的定义（本文核心对象）

定义**双边 option 结果模型**：

$$
f_\phi:\ (s,\ \mathbf{x},\ \mathbf{y}) \longmapsto \big\{\,\hat{P}(z_m \mid \cdot),\ \hat{P}(\tau_m \mid \cdot),\ \hat{P}(\Delta n^D \mid \cdot),\ \hat{P}(\Delta n^A \mid \cdot)\,\big\}_{m=1}^{M}

$$

其中在**一个宏步之内**（长度 $T_m$）：
- $z_m \in \{0,1\}$：目标点 $m$ 在本宏步内是否失守；
- $\tau_m \in (0, T_m]\cup\{\infty\}$：失守时刻（未失守则为 $\infty$，实践中改为回归 $h_m$ 的剩余耐久比例，避免删失回归）；
- $\Delta n^D, \Delta n^A$：本宏步双方战损数。

$f_\phi$ 输出的是**分布**，不是期望。这是 S2 的全部内容。

### 4.4 三条建模假设（必须在论文中明写）

- **A1（宏步内分配冻结）**：宏步内不重新分配。真实系统当然可以连续重规划，但冻结使 option 语义良定义，且每 $T_m$ 步重规划本身缓解了该近似的损失。
- **A2（下层策略已知且冻结）**：$f_\phi$ 是**相对于特定 $\pi_\theta$** 的结果模型。$\pi_\theta$ 一变，$f_\phi$ 就漂移——S4 正是为处理这一点而存在。
- **A3（给定分配后各目标点条件近似独立）**：$\hat P(\text{def win}) \approx \prod_m (1 - \hat p_m)$。这在预备队 $x_\varnothing$ 较大时不成立（预备队会在目标间流动，制造相关性）。缓解手段：把 $x_\varnothing$ 作为显式输入特征，并在模型中用跨目标点注意力层建模相关性；在消融中报告独立性假设的误差幅度。**这一条要作为局限性明写，不要藏。**

### 4.5 泛化设定

训练与测试的分布划分（这是本文实证主张的核心）：

| 维度 | 训练分布 | 测试分布 |
|---|---|---|
| 防守规模 $n_D$ | $\{6, 8\}$ | in-dist: $\{6,8\}$ / **OOD: $\{12, 16\}$** |
| 攻击规模 $n_A$ | $\{6, 8, 10\}$ | in-dist: 同左 / **OOD: $\{16, 20\}$** |
| 目标点数 $M$ | $\{3\}$ | in-dist: 3 / **OOD: $\{2, 4, 5\}$** |
| 攻击者策略 | 训练池 $\Pi^A_{\text{train}}$（4 种） | in-dist / **OOD: 留出池 $\Pi^A_{\text{held}}$（3 种，训练中从未见过）** |

## 5. 相关工作与研究空白

### 5.1 五条相关脉络

**(a) 规模不变的多智能体策略表示**。UPDeT（Hu et al., ICLR 2021）用 Transformer 对实体集合编码，实现单位数量无关的策略；REFIL（Iqbal et al., ICML 2021）通过随机实体分组因子化提升组合泛化。这条线解决的是「下层执行器如何吃变长输入」，是 S1 的直接基础，但它们不涉及上层分配，也不涉及对手建模。

**(b) 分层子任务分配的 MARL**。ALMA（Iqbal et al., NeurIPS 2022）在 SMAC 类任务上学习「把智能体分配到子任务」的上层策略与「执行子任务」的下层策略，是本文结构上最近的亲戚。HAVEN（AAAI 2023）提出层间双协调机制。二者的上层都是**隐式价值驱动的单边策略**：输入只有己方状态与己方分配，对手被折叠进环境；输出是一个标量价值。在对手会针对最弱点的攻防场景下，这一接口无法表达「对手会怎么应对我这个分配」。

**(c) RTS 分层对抗搜索与战斗模型**。Stanescu et al.（AIIDE 2014）提出 Hierarchical Adversarial Search，在多个抽象层上做双边搜索；Ontañón & Buro（IJCAI 2015）的 AHTN 把 HTN 规划与博弈树搜索结合。这条线**是双边的**，这一点比 (b) 更接近本文。但它们的叶节点评估依赖手工或解析的战斗模型（Lanchester 方程族）。Uriarte & Ontañón（IEEE ToG 2017; arXiv 1605.05305）系统研究了 RTS 战斗模型的自动学习，是本文 S2 的思想源头——但他们学的是**单场遭遇战的点估计**，既未输出校准分布，也未接入对抗求解器，更未面对「任一目标失守即输」的最弱环节聚合。

**(d) 对手不确定下的适应**。Ad hoc teamwork 及其对抗推广，特别是 NAHT（N-Agent Ad Hoc Teamwork, Wang et al., NeurIPS 2024; arXiv 2404.10740）首次把「队友**数量**变化」与「队友**类型**未知」这两件事**同时**纳入。这与本文关心的「规模变 + 对手策略变」高度同构——但 NAHT 在**合作侧**，且不涉及指挥层的资源分配决策。这正是本文要在**对抗侧 + 分配层**填补的位置。此外 PSRO（Lanctot et al., NeurIPS 2017）系的种群式训练提供了对手多样性的手段，但它优化的是策略种群，不解决「单次决策时刻如何分兵」。

**(e) 安全博弈中的资源分配**。Stackelberg security games（Kiekintveld et al., AAMAS 2009；Tambe 系列）研究防守方如何在多目标间随机化配置资源，与本文场景在**问题结构上极为相似**（多目标、覆盖–集中两难、攻击方最佳响应）。但 SSG 的收益矩阵是**外生给定的**（由目标价值和覆盖概率解析定义），而本文的收益矩阵必须**从仿真中学出来**，因为「10 个防守单位能不能守住这个点 25 步」根本没有解析表达式。此外 SSG 通常是 Stackelberg（防守方先动、攻击方观测后响应），本文是同时行动的零和博弈。这个区分必须在相关工作中写清。

**(f) 决策感知的预测学习**。Smart Predict-then-Optimize（Elmachtoub & Grigas, Management Science 2022）与 decision-focused learning（Wilder et al., AAAI 2019）指出：预测模型应当以下游决策质量而非预测精度为目标训练。本文 S4 的「均衡支撑集重加权」是这一思想在博弈求解器上的具体化，而不是在 LP 上做隐式微分——因为我们的下游是一个离散候选集上的矩阵博弈，梯度不可用。

## 6. 方法：COGAR 四阶段框架

### 6.0 全局数据流

```
                  ┌─────────────────────────────────────────────┐
                  │  S4: 胜率闭环协同（Expert Iteration）        │
                  │  唯一目标 = 端到端防守胜率                    │
                  └───┬──────────────┬──────────────┬───────────┘
                      │ KL锚定微调    │ 支撑集重加权   │ 漂移检测
                      ▼              ▼              ▲
   ┌──────────┐   ┌────────┐   ┌──────────┐   ┌────────────┐
   │ S1 下层  │──▶│ 配对    │──▶│ S2 双边   │──▶│ S3 风险感知 │──▶ 分配 x*
   │ 执行器   │   │ 干预    │   │ 结果模型  │   │ 矩阵博弈    │
   │ (冻结)   │   │ rollout │   │ (分布+校准)│   │ (LP/minimax)│
   └──────────┘   └────────┘   └──────────┘   └────────────┘
        ▲                                              │
        └──────────── 执行 T_m 步，回到新快照 ◀──────────┘
```

### 6.1 阶段 1：规模不变的下层执行器

#### 6.1.1 目标

学一个**单一参数集**的策略 $\pi_\theta(u_i \mid o_i, \tau_i)$，能在任意 $n_D, n_A, M$ 下执行「守住我被指派的那个目标点」这一任务。它不做分配决策，只做微观战术：走位、集火、风筝、护点。

#### 6.1.2 技术方案

**网络结构（实体注意力，UPDeT 风格）**：

```
输入：
  self_feat        ∈ R^{d_s}       自身状态
  ally_feats       ∈ R^{n_a × d_e} 可见友军实体（变长）
  enemy_feats      ∈ R^{n_e × d_e} 可见敌军实体（变长）
  target_feats     ∈ R^{M × d_t}   所有目标点（位置、耐久、当前分配的己方兵力数）
  task_token       ∈ R^{d_τ}       本单位被指派的目标点 one-hot / 嵌入

处理：
  tokens = concat([Linear(self), Linear(ally), Linear(enemy), Linear(target), Emb(task)])
  h = TransformerEncoder(tokens, layers=2, heads=4, d_model=128)
  h_self = h[0]                                    # 取 self token
  actor  : logits = MLP(h_self) → 动作分布（移动8向 + 攻击k个最近敌 + 停留）
  critic : V = MLP(mean_pool(h) ⊕ global_feat)     # 集中式 critic
```

关键设计点：动作空间中「攻击敌方单位」用**指针式输出**（对每个敌方 token 打分并 softmax），而不是固定维度 head，这是实现规模不变的必要条件。

**训练算法**：MAPPO（Yu et al., NeurIPS 2022），CTDE，共享参数。

**训练课程**：
1. 阶段 1a：随机分配（每宏步均匀随机分兵），迫使下层在**各种分配下**都尽力执行。这一步至关重要——如果只在「合理分配」下训练，S2 采集数据时那些极端候选分配的标签就不可信。
2. 阶段 1b：对手池自博弈。攻击方从 $\Pi^A_{\text{train}}$ 采样（含脚本与自博弈检查点），随机化 $n_D, n_A, M$、目标点位置、初始阵位。
3. 阶段 1c：残局强化。以随机战损后的残局状态（$n_D \in [1,4]$）为初始状态额外训练，防止残局阶段策略崩坏。

**冻结**：训练结束后保存 $\theta_0$ 并**完全冻结**。后续 S2/S3 全部相对 $\theta_0$ 定义。仅 S4 允许有限度的更新。

#### 6.1.3 参考论文
- Hu et al., *UPDeT: Universal Multi-agent RL via Policy Decoupling with Transformers*, ICLR 2021（arXiv:2101.08001）
- Iqbal et al., *Randomized Entity-wise Factorization for Multi-Agent RL (REFIL)*, ICML 2021（arXiv:2006.04222）
- Yu et al., *The Surprising Effectiveness of PPO in Cooperative Multi-Agent Games*, NeurIPS D&B 2022（arXiv:2103.01955）

#### 6.1.4 降级方案（若 S1 训练耗时超预算）
用**脚本化下层**替代：护点脚本（在目标点周围环形站位、优先集火射程内血量最低的敌人）、拦截脚本、风筝脚本。这完全不影响 S2–S4 的科学主张——因为本文的贡献是**接口**，不是下层策略。论文中可以直接说明「S1 可以是学习策略也可以是脚本，本文两种都做，主实验用学习策略，鲁棒性实验用脚本」。**这是本项目最重要的风险缓冲，务必先跑通脚本版本再上 RL。**

### 6.2 阶段 2：双边校准结果模型（核心贡献之一）

#### 6.2.1 目标

学 $f_\phi(s, \mathbf{x}, \mathbf{y}) \to$ 结果分布。难点不在网络，在**数据怎么来**。

#### 6.2.2 数据采集协议：快照克隆 + 配对干预 + CRN

这是本阶段最需要在论文里讲清楚的工程–科学点。

**为什么不能用日志数据**：如果只从正常对局的轨迹里采集 $(s, \mathbf{x}, \mathbf{y}, \text{outcome})$，那么 $\mathbf{x}$ 是由当前策略选出的，存在严重的**选择偏差**：模型只在「被选中过的分配」上准确，而 S3 恰恰需要在**所有候选分配**上准确（尤其是那些看起来不好、但可能被高估的候选）。这是一个标准的因果推断问题：我们要的是 $P(\text{outcome} \mid do(\mathbf{x}), do(\mathbf{y}))$，不是 $P(\text{outcome} \mid \mathbf{x}, \mathbf{y})$。

**采集流程**：

```python
for snapshot s in sampled_snapshots:            # 从多样化对局中采样决策时刻
    state_blob = env.get_state()                # 精确序列化，含 RNG 状态
    for x in candidate_defender_allocs(s):      # 枚举/采样防守候选
        for y in candidate_attacker_allocs(s):  # 攻击候选（来自对手池的典型意图）
            for k in range(K):                  # K 次重复
                env.set_state(state_blob)
                env.seed(common_seed[k])        # ★ CRN：同一 k 对所有 (x,y) 用同一种子
                out = env.rollout(policy=theta0, alloc=(x,y), steps=T_m)
                record(s, x, y, out)
```

**公共随机数（CRN）的作用**：让不同候选 $(x,y)$ 面对**同一份随机性实现**（同样的命中判定序列、同样的初始扰动）。这使得候选之间的**比较**方差大幅下降——而 S3 需要的正是比较，不是绝对值。这是运筹仿真中的标准方差缩减技术（Glasserman & Yao, 1992），但在 MARL 结果模型的语境下几乎无人使用，是本文一个可以明确宣称的方法学细节。

**攻击候选集的构造**：不枚举攻击方全部 $\binom{n_A+M}{M}$ 种分配（组合爆炸），而是取 $|\mathcal{Y}| \le 12$ 个**代表性攻击意图**：全力打 $g_1$、…、全力打 $g_M$（$M$ 个）、两点均分（$\binom{M}{2}$ 个）、7:3 偏配（若干）、先歼灭防守机动兵力（1 个）。这既控制了预算，又对应真实攻击者的策略空间。

#### 6.2.3 网络结构

```
输入编码：
  unit tokens:   每个单位 → [type_emb, hp, pos_rel_to_each_target, assigned_target_onehot, side_flag]
  target tokens: 每个目标 → [pos, hp, n_defenders_assigned, n_attackers_assigned, sum_hp_def, sum_hp_atk]

层次：
  L1  Set encoder (Deep Sets / self-attn) 对每个目标点聚合其"承诺兵力"
        → per-target embedding  z_m ∈ R^d      （置换不变，天然支持变规模）
  L2  Cross-target Transformer over {z_1..z_M, z_reserve}
        → 建模预备队流动与目标间相关性（缓解 A3）
  L3  多头输出（每个目标点 m）：
        head_breach : Bernoulli logit → p_m
        head_time   : 剩余耐久比例回归（beta 分布参数）
        head_attr   : ΔnD, ΔnA 的离散分布（0..n 的 categorical）
```

#### 6.2.4 不确定性与校准

- **Deep Ensembles**（$K=5$ 个独立初始化，Lakshminarayanan et al., NeurIPS 2017）：提供**认知不确定性** $\sigma_{\text{epi}}$。
- **温度标定**（Guo et al., ICML 2017）：在留出的验证快照上拟合温度 $T$，修正 $p_m$ 的过自信。
- **偶然不确定性**：由 Bernoulli/Beta/Categorical 输出头自然给出。

上置信界的构造（对防守方而言，失守概率越高越糟，所以取**高**分位）：

$$
\tilde p_m(\mathbf{x},\mathbf{y}) = \mathrm{clip}\Big(\bar p_m + \beta\,\sigma_{\text{epi},m},\ 0,\ 1\Big)
\quad\text{或}\quad
\tilde p_m = Q_{1-\alpha}\big[\,p_m\,\big]

$$
其中 $\beta$（或 $\alpha$）是本文的**核心超参数**，需要专门做敏感性分析：$\beta=0$ 退化为点估计（optimizer's curse），$\beta$ 过大则过度保守（永远均分兵力）。

#### 6.2.5 校准诊断（这是要画进图里的关键图）

论文中必须报告一张「**选中候选 vs 随机候选的校准差**」图：把候选按「是否被 S3 选中」分组，分别画可靠性曲线。若点估计模型在**随机候选**上校准良好、却在**被选中候选**上系统性低估失守概率——这就是 optimizer's curse 的直接实证，也是本文动机的最强证据。**这张图如果做出来了，论文的说服力就成立了一半。**

### 6.3 阶段 3：风险感知对抗分配（核心贡献之二）

#### 6.3.1 本质回答：这是什么方法？

**它不是强化学习，也不是纯博弈论——它是决策时刻规划（decision-time planning），其内核是一个用学习模型填充收益矩阵的单步零和矩阵博弈。**

三句话说清定位：
- 与 **RL** 的区别：不学分配策略网络，不做时序信用分配。每个宏决策时刻现场求解一个优化问题。类比 AlphaZero 的 MCTS——「模型 + 搜索」而非「策略网络直接输出」。
- 与**经典博弈论**的区别：收益矩阵不是外生给定的（如 SSG），而是**学出来的、带不确定性的**。因此我们不求「精确纳什」，只求「在悲观效用下的鲁棒混合策略」，且不宣称任何均衡收敛性质。
- 与 **RTS 对抗搜索**的区别：不做多步博弈树展开。因为多步展开需要状态转移模型 $p(s'\mid s,\mathbf{x},\mathbf{y})$，而 S2 只给结果不给状态，误差会随深度爆炸。**我们明确只做单步，并靠高频重规划（每 $T_m$ 步）补偿。这是设计限制，要在论文局限性里主动写出来。**

#### 6.3.2 五步求解流程

**Step 1：候选生成**

防守方计数向量枚举：$\mathbf{x} = (x_1,\dots,x_M,x_\varnothing)$，$\sum = n_D$，候选数 $\binom{n_D+M}{M}$。
- $n_D=8, M=3$ → $\binom{11}{3} = 165$
- 剪枝：去掉「某目标点分配为 0 且预备队距该点超过 $T_m \cdot v_{\max}$」的显然送分方案 → 通常降到 40–80 个。
- 大规模（$n_D=16$）时 $\binom{19}{3}=969$，用**兵力比例网格**（每档 12.5%）离散化把候选压到 ~60 个。

计数向量 → 具体单位指派：用一次**贪心匹配**（按「单位到目标点的到达时间 + 兵种克制评分」做匈牙利算法或贪心），把计数向量落实为 $x: \mathcal{D}\to\mathcal{G}$。这一层不做搜索，避免组合爆炸。

攻击方候选 $\mathcal{Y}$：同 §6.2.2 的 12 个代表性意图。

**Step 2：矩阵批量填充**

把所有 $|\mathcal{X}|\times|\mathcal{Y}|$（约 $60\times12=720$）对打包成一个 batch，单次前向通过 $f_\phi$ 的 5 个集成成员。在 5070 Ti 上，720×5 的 batch 对一个 2 层 Transformer 是**毫秒级**。这是本方法实时可行的关键——所有昂贵的 rollout 都在离线阶段完成了。

**Step 3：悲观效用构造**


$$
U(\mathbf{x},\mathbf{y}) \;=\; \underbrace{\sum_{m=1}^{M}\log\!\big(1-\tilde p_m(\mathbf{x},\mathbf{y})\big)}_{\text{最弱环节：对数联合存活（A3）}}
\;+\;\underbrace{w_A\,\mathbb{E}[\Delta n^A]-w_D\,\mathbb{E}[\Delta n^D]}_{\text{交换比塑形}}
\;-\;\underbrace{\lambda\, C_{\text{switch}}(\mathbf{x}_{\text{prev}},\mathbf{x})}_{\text{换防代价，抑制震荡}}

$$

三点说明：
- 用 $\sum \log(1-\tilde p_m)$ 而非 $-\max_m \tilde p_m$：前者可微、数值稳定，且当某个 $\tilde p_m \to 1$ 时自动 $\to -\infty$，实现了「守不住任一点就极糟」的最弱环节语义。
- 交换比项是**塑形项**，权重要小（$w_A,w_D \sim 0.05$），否则会诱导「为了刷战损而放弃守点」。
- $C_{\text{switch}}$ 统计相对上一宏步改变任务的单位数。$\lambda$ 直接控制「震荡率」这一评价指标。

**Step 4：矩阵博弈求解**

标准零和 LP（防守方求最大化最小收益的混合策略 $\mathbf{p} \in \Delta(\mathcal{X})$）：


$$
\max_{\mathbf{p},\,v} \ v \quad \text{s.t.} \quad \sum_{i} p_i\, U(\mathbf{x}_i,\mathbf{y}_j) \ \ge\ v \ \ \forall j, \qquad \sum_i p_i = 1,\ p_i \ge 0

$$

实现：`scipy.optimize.linprog`（HiGHS 后端，720 变量规模是微秒级）或 `nashpy`。

**熵正则化变体**（推荐作为默认）：加入 $-\eta \sum_i p_i \log p_i$，用镜像下降/Hedge 求解 QRE，得到更平滑的策略，避免 LP 解落在顶点上导致的脆弱性。

**Step 5：执行**

从 $\mathbf{p}^\star$ 采样一个 $\mathbf{x}$（或在评测确定性要求下取 $\arg\max_i p_i$），下发给 S1，执行 $T_m$ 步，回到 Step 1。

#### 6.3.3 备选求解器（消融必做）

| 求解器 | 公式 | 作用 |
|---|---|---|
| **Argmax（点估计）** | $\arg\max_\mathbf{x} \sum_m \log(1-\bar p_m(\mathbf{x}, \bar{\mathbf{y}}))$ | 消融 F4+F7，展示 optimizer's curse |
| **LCB-Argmax** | 用 $\tilde p$ 但对 $\mathbf{y}$ 取期望 | 消融 F7，隔离「悲观」与「minimax」的贡献 |
| **CVaR-BR** | $\max_\mathbf{x} \mathrm{CVaR}_\alpha\big[U(\mathbf{x},\mathbf{y})\big]_{\mathbf{y}\sim q}$ | 比 minimax 温和，作为鲁棒性中间档 |
| **Minimax-LP（默认）** | 上式 | 完整方法 |
| **Entropy-QRE** | LP + 熵正则 | 默认变体 |

这个消融表是审稿人最想看的东西：它把「分布」「悲观」「博弈求解」三个成分的贡献分离开。

#### 6.3.4 攻击者会打哪个目标点？——这个问题的正式回答

这是设计中最需要说清的一点：**攻击者的目标选择在我们的框架里是内生的，不需要预先知道。**

- 在**求解层面**：$\mathbf{y}$ 遍历所有代表性攻击意图，minimax 保证防守方的混合策略对**最坏情况的目标选择**有保障。防守方从不猜「他会打哪」，只保证「打哪都不容易打穿」。
- 在**环境层面**：每局随机指定 1–2 个真实目标（攻击者知道，防守方不知道），攻击者脚本按其类型（固定/最弱点/佯攻）决定行为。防守方只能通过观测到的敌军运动**推断**。
- 在**评价层面**：额外报告「**可利用度（exploitability）**」——针对防守方的固定策略，训练/搜索一个最佳响应攻击者，看能把防守胜率压到多低。这是衡量 minimax 是否真的带来鲁棒性的黄金指标，也是相对 argmax 基线最能拉开差距的地方。

### 6.4 阶段 4：以整体胜率为唯一目标的闭环协同（核心贡献之三）

#### 6.4.1 设计原则（用户明确要求，务必贯彻）

> **S4 的唯一优化目标是端到端防守胜率。所有中间指标（Brier、ECE、decision regret）在 S4 中只作为诊断量与触发条件，不作为损失函数。**

这条原则解决了分层系统一个真实的病理：**分阶段各自最优 ≠ 整体最优**。S1 单独优化会产生「在随机分配下平均表现好、但在 S3 实际会选的那类分配下表现平庸」的策略；S2 单独优化会在整个候选空间上均匀降低预测误差，而不是在**决定决策的那几个候选**上精确。

#### 6.4.2 为什么不能端到端反传

从胜率梯度回传到 $\theta$ 和 $\phi$ 需要穿过：LP 求解器的 $\arg$、候选枚举的离散选择、以及一整段环境仿真。虽然存在对 LP 做隐式微分的技术，但通过离散候选集 + 长仿真链的梯度极其嘈杂且工程代价高。**我们明确放弃端到端梯度，改用 expert iteration 式的数据闭环**——这与 AlphaZero「用搜索结果监督网络」的思路同源（Anthony et al., NeurIPS 2017；Silver et al., 2018）。

#### 6.4.3 算法：Win-Rate-Driven Co-Adaptation

```
输入：θ_0（冻结的下层）, φ_0（结果模型）, 探针集 P（固定的 100 个快照 × 20 个候选对）
输出：θ_R, φ_R

W_best ← Evaluate(θ_0, φ_0)          # 在留出对手池上的防守胜率
for r = 1 .. R (R ≤ 3):

  # ---- (1) 自对局：用完整系统 S1+S2+S3 打 N 局 ----
  D_r ← PlayGames(θ_{r-1}, φ_{r-1}, opponents=Π_train, N=2000)
        记录每个宏步的 (s, X_cand, Y_cand, p*, x_selected, 真实结果, 最终胜负)

  # ---- (2) 结果模型刷新：均衡支撑集重加权 ----
  # 核心：只有影响决策的候选才值得精确
  for each macro-step in D_r:
      w(x_i) = p*_i + κ · 1[x_i ∈ top-k by U]     # 均衡概率 + top-k 指示
  φ_r ← argmin_φ  Σ w(x) · L_NLL(f_φ(s,x,y), outcome)   （在 D_r ∪ 旧数据回放上）
  重新温度标定

  # ---- (3) 下层微调：在规划器诱导的分配分布上，KL 锚定 ----
  ρ_r ← 规划器实际选中的分配的经验分布
  θ_r ← PPO_finetune(θ_{r-1}, alloc_dist=ρ_r,
                     reward = 目标点存活 + 交换比,
                     loss += ζ · KL(π_θ ‖ π_{θ_{r-1}}))       # ζ 防遗忘/防漂移过大

  # ---- (4) 漂移检测 ----
  d ← mean_{P} JS( f_{φ_r}(·) ‖ RolloutTruth(θ_r, ·) )      # 只在探针集上重跑 rollout
  if d > δ:  在探针集邻域补采数据，重训 φ_r（回到步骤 2）

  # ---- (5) 唯一验收标准 ----
  W_r ← Evaluate(θ_r, φ_r)          # 留出对手池 + 留出规模上的防守胜率
  if W_r ≤ W_best + ε:  break（回滚到上一轮）
  else: W_best ← W_r
```

#### 6.4.4 三个关键机制的解释

**(a) 均衡支撑集重加权（equilibrium-support reweighting）**。这是「用胜率目标塑造预测模型训练」的具体化。均衡混合策略 $\mathbf{p}^\star$ 天然给出了「哪些候选真正参与了决策」的权重：$p^\star_i$ 大的候选，其预测误差直接改变决策；$p^\star_i \approx 0$ 的候选，预测再准也无用。这比在 LP 上做隐式微分简单得多，且与 decision-focused learning（Wilder et al., 2019）的动机一致。这是一个**可以单独作为贡献点写的小创新**。

**(b) KL 锚定的下层微调**。$\pi_\theta$ 一变，$f_\phi$ 就过时（假设 A2）。若放任 $\theta$ 大幅更新，$f_\phi$ 会彻底失效，系统崩溃。KL 锚定把 $\theta$ 的更新限制在 $f_\phi$ 的有效邻域内，形成一个「小步慢跑」的信赖域。这是 S4 能收敛的技术前提。

**(c) 探针集漂移检测**。全量重采数据代价极高。固定 100 个探针快照，每轮只在这些点上重跑 rollout 对比预测与真值的 JS 散度，代价约为全量的 2%，却能可靠触发「该重采了」。

## 7. 创新点与「为什么不能简单拼接」

### 7.1 四个创新点（按强度排序）

**I1（最强）：双边条件的、校准的 option 结果模型，作为分层攻防决策的显式接口。**
现有分层 MARL 的上层接口是单边隐式价值；现有 RTS 对抗搜索的接口是解析/脚本战斗模型；现有战斗模型学习工作是单边点估计。把三者合一——**学习的、双边的、分布式的、校准的**——并证明这四个属性各自不可省，是本文的主贡献。

**I2：最弱环节结构下的风险感知 minimax 分配求解。**
我们不是「顺手加了个 LCB」，而是从「任一目标失守即负 + 攻击方最佳响应」这个问题结构，推导出必须用上置信界与混合策略。这条论证链（§3.2）把常规技术升格为**由问题决定的必需设计**，并可以用「可利用度」实证。

**I3：以整体胜率为唯一目标的闭环协同，含均衡支撑集重加权。**
回答了分层系统的经典病理「局部最优不等于全局最优」，并给出一个不依赖端到端梯度的可实现方案。

**I4（方法学细节，可作为亮点）：干预式配对 rollout + 公共随机数的数据协议。**
从因果角度指出「日志数据训出的结果模型必然在候选空间上有偏」，并用 CRN 做候选间比较的方差缩减。这个细节在 MARL 社区几乎无人做，容易在审稿中被认为"扎实"。

### 7.2 三条不可拼接性论证（回应「把表格几行拼起来不就行了」）

**论证一：SSG 的求解器 + MARL 的下层，接不上。**
SSG 的收益矩阵要求对每个 (防守配置, 攻击目标) 对给出解析收益。学习型下层的战斗结果没有解析式，只能仿真。而仿真的代价使得实时求解不可能。**必须**有一个可微/可批量前向的代理模型填这个矩阵——这就是 S2 存在的理由，它不是从任一现有工作里拿来的。

**论证二：RTS 对抗搜索的战斗模型 + 深度集成，不够。**
把 Lanchester 模型换成神经网络并加集成，得到的仍是**单边或对称近似的**遭遇战预测。本场景的关键是「同一批防守单位，面对不同攻击分配，结果差异巨大」——必须以**双方分配为联合条件**，且必须建模**跨目标点的兵力流动相关性**（A3 的缓解）。这需要专门的网络结构（§6.2.3 的 L2 层）与专门的数据协议（配对干预），不是现有工作的直接组合。

**论证三：ALMA 的分层结构 + 对手池训练，解决不了未见对手。**
ALMA 的上层是一个学习的策略网络，它把「对手会怎么应对」隐式编码在权重里。换成未见对手时，这个隐式编码无法在**决策时刻**被修正。而 COGAR 的上层是一个**现场求解的优化问题**：对手模型是显式的输入（候选集 $\mathcal{Y}$），可以在部署时替换、扩充，无需重训。这是「学策略」与「学模型 + 现场搜索」的范式差异，不可通过拼接弥合。

### 7.3 诚实的局限性（论文中必须写）

1. **单步矩阵博弈**，无多步展开，依赖高频重规划补偿。
2. **假设 A3 的条件独立性**在预备队占比高时不成立，需报告误差幅度。
3. **不宣称纳什均衡收敛**——收益矩阵是学出来的近似值，任何均衡性质都只在近似意义下成立。
4. **攻击方候选集是人工设计的代表性意图**，不是完整策略空间。若真实攻击者的策略落在候选集之外，minimax 保障失效。可在未来工作中用 PSRO 自动扩充 $\mathcal{Y}$。
5. **只研究防守侧**（攻击方来自固定对手池），双向共同学习留作未来工作。

### 8.3 「接近 oracle」的精确定义与 Decision Regret

这是本文的核心评价指标，必须定义清楚。

**Oracle 的定义**：在某个决策快照 $s$ 上，对全部候选对 $(\mathbf{x}_i,\mathbf{y}_j)$ 各做 $K_{\text{oracle}}=500$ 次真实 rollout，得到近似真值收益矩阵 $U^\star_{ij}$，再求解得到 oracle 混合策略 $\mathbf{p}^\star$ 与 oracle 值 $v^\star(s) = \max_\mathbf{p}\min_j \sum_i p_i U^\star_{ij}$。

**Decision Regret**：某方法给出策略 $\hat{\mathbf{p}}$，其**在真值矩阵下**的最坏收益为 $v(\hat{\mathbf{p}}) = \min_j \sum_i \hat p_i U^\star_{ij}$，则

$$
\mathrm{Regret}(s) = v^\star(s) - v(\hat{\mathbf{p}})\ \ \ge 0

$$
**注意关键点**：regret 用**真值矩阵**评价方法选出的策略，而不是用方法自己的估计。「接近 oracle」= regret 接近 0，意味着「虽然我的模型不准，但我做出的决策和全知者一样好」。这正是本文追求的东西——**预测精度不是目的，决策质量才是**。

**Top-$k$ Regret**：方法排名前 $k$ 的候选中，最好的那个相对 oracle 最优候选的差距。用于诊断「模型是不是至少把好方案排进了前几名」。

**预测层**（诊断 S2）
- Brier score, NLL, ECE（期望校准误差）
- **分组校准**：随机候选 vs 被选中候选（§6.2.5 的关键图）
- 干预数据 vs 日志数据训练的对比（验证 §6.2.2 的因果论证）

**决策层**（诊断 S3，本文核心）

**任务层**（最终结论）
- **防守胜率**（主指标）：在 in-dist / OOD-规模 / OOD-对手 三个划分上分别报告
- **可利用度**：训练 A7（Learned-BR）攻击者，报告其能把防守胜率压到多低。越低说明越可被利用。
- **平均目标点残余耐久**：连续型的辅助指标，缓解胜率的类别不平衡
- **换防震荡率**：每宏步改变任务的单位占比，检验 $C_{\text{switch}}$ 的作用
- **决策延迟**：每宏步的规划耗时（ms），证明实时可行

### 8.5 消融实验清单

| 消融 | 移除的成分 | 预期效果 | 验证的创新点 |
|---|---|---|---|
| ABL-1 | 分布 → 点估计（$\beta=0$） | 被选中候选上出现系统性低估；可利用度显著上升 | I1, I2 |
| ABL-2 | 双边 → 单边（去掉 $\mathbf{y}$ 输入） | OOD 对手上胜率大跌 | I1 |
| ABL-3 | minimax → argmax | 对 A7 的可利用度大幅上升 | I2 |
| ABL-4 | 最弱环节 $\sum\log(1-p)$ → 加和 $\sum(1-p)$ | 出现「弃守一点保其余」的错误行为 | I2 |
| ABL-5 | 干预数据 → 日志数据 | 未选中候选上的预测误差显著变大，regret 上升 | I4 |
| ABL-6 | 去掉 CRN（独立种子） | 相同预算下 regret 方差显著上升 | I4 |
| ABL-7 | 去掉 S4 闭环 | 下层微调后系统胜率不升反降（模型漂移） | I3 |
| ABL-8 | S4 用均匀权重代替均衡支撑集重加权 | 胜率提升幅度减半 | I3 |
| ABL-9 | $\beta$ 敏感性扫描（0, 0.5, 1.0, 1.5, 2.0） | 呈 U 型，存在最优保守度 | I2 |

### 8.6 算力预算核算（可行性证明）

**Oracle 数据采集（一次性，最贵的一步）**：
```
快照数              : 30
防守候选 |X|        : 45（剪枝后）
攻击候选 |Y|        : 12
每对 rollout 数 K   : 200（oracle 用 500，训练用 200）
每 rollout 步数     : 25（一个宏步）

总环境步 = 30 × 45 × 12 × 200 × 25 = 8.1 × 10^7 步
单核 10k 步/s → 8100 s ≈ 2.25 小时
16 进程并行      → 约 9 分钟
```
**结论：完全可行。** 这个核算要写进论文的 reproducibility 部分。

**S2 训练集（完整）**：500 快照 × 45 × 12 × 20 次 = 5.4×10⁶ 样本对，环境步 1.35×10⁹，16 进程约 2.3 小时。可接受。

**S1 训练（MAPPO）**：2×10⁷ 环境步，5070 Ti 上约 6–10 小时。

**S4 每轮**：2000 局 × ~400 步 = 8×10⁵ 步（采集）+ 微调，约 1–2 小时/轮，共 ≤3 轮。

**总计**：单卡 5070 Ti + 16 核 CPU，全套主实验 5 seeds 约 **4–6 天**。

## 10. 工程实现方案

### 10.1 硬件与软件栈（已核实的踩坑点）

**已确认的三个硬冲突**（这是不用 ALMA + SMAC-HARD 的原因）：
1. ALMA 官方代码基于 PyMARL/REFIL 的老栈（Python 3.7 + 旧 PyTorch），**无法为 RTX 5070 Ti 的 sm_120（Blackwell）编译 kernel**，该架构需要 CUDA 12.8 + PyTorch 2.7+。
2. ALMA 只提供依赖 NVIDIA-Docker 的镜像，Windows 下需 WSL2 + Docker Desktop GPU 直通，且要自己重写 Dockerfile。
3. SMAC-HARD 在 Windows 上用的 SC2 二进制（5.0.14）与 Linux 基线（4.10）单位数值不同，**结果不可比**；且其基于 raw observation 的决策树脚本**不支持状态快照与恢复**，S2 所需的干预式采集在其上无法实现。

**推荐栈**：

| 层 | 选择 | 备注 |
|---|---|---|
| 系统 | Windows 11 + WSL2 (Ubuntu 22.04) | 开发在 Windows，跑实验在 WSL |
| 驱动/CUDA | Windows 驱动 ≥ 570 + WSL 内 CUDA 12.8 | 不要在 WSL 内装显卡驱动 |
| PyTorch | 2.7+ / cu128 | `pip install torch --index-url .../cu128` |
| 环境 | **自建 GuardPoints（NumPy）** | 主环境 |
| 参考实现 | **SMAClite**（github.com/uoe-agents/smaclite） | 借鉴其纯 Python SMAC 机制实现 |
| MARL 框架 | **EPyMARL**（github.com/uoe-agents/epymarl） | 维护良好，支持现代 Python/PyTorch |
| 求解器 | scipy(HiGHS) / nashpy | LP 与矩阵博弈 |
| 并行 | Python `multiprocessing` / Ray | 16 worker 采集 rollout |
| 实验管理 | Hydra + Weights & Biases | 5 seeds × 多配置 |

### 10.4 三个必须先做的工程验证

1. **确定性单测**：同一 `state_blob` + 同一 seed，两次 rollout 的每一步观测与奖励必须逐位相同。这个测试不过，后面全都是假的。
2. **速度基准**：单核 rollout 吞吐 ≥ 10k 环境步/s。达不到就要优化（向量化伤害计算、去掉 Python 循环、必要时用 numba）。
3. **CRN 有效性**：对同一快照的两个不同候选 $\mathbf{x}_1,\mathbf{x}_2$，用 CRN 估计的 $\hat U(\mathbf{x}_1)-\hat U(\mathbf{x}_2)$ 的方差应显著小于独立种子下的方差（预期降低 30–60%）。这个数字本身就是论文的一个小结果。

| 风险 | 概率 | 触发信号 | 降级方案 |

| R1 环境太简单，所有方法逼近 oracle | 高 | 判死实验 T1 不过 | 按 §11.1 的四步加难度；仍不过则改用 SMAClite 改造版 |

### 13.2 审稿人最可能的三个攻击点与预备回答

**Q1：「这不就是把 SSG 的求解器套在学习的战斗模型上吗？」**
答：SSG 的收益矩阵是外生解析给定的，且是 Stackelberg 结构。本文的核心难点恰恰在于**矩阵本身必须从仿真中因果地学出来**，这引出了干预式采集、CRN、校准、以及 optimizer's curse 三个 SSG 中不存在的问题。§7.2 论证一。

**Q2：「为什么不做多步搜索？单步太弱了。」**
答：多步需要状态转移模型，而 S2 只预测结果不预测状态。我们在局限性中明写此点，并用「每 25 步重规划」在实证上补偿。同时提供一个消融：宏步长 $T_m \in \{15,25,40\}$，说明高频重规划确实能缓解单步近似（$T_m$ 越小性能越好但计算越贵）。

**Q3：「自建环境，结果不可比。」**
答：§8.1 的表格说明 SC2 系环境**在物理上无法支持** S2 所需的状态克隆与 CRN。我们额外在 SMAC-HARD 上验证最终系统的迁移性，并完全开源环境与全部实验代码。
