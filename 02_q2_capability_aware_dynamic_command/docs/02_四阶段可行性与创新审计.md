# 四阶段可行性与创新审计

## 1. 总判断

原四阶段流程在工程上合理，但**流程合理不等于论文创新**。目前文献已经分别覆盖通用下层、能力/成功概率学习、动态联盟、分层 commander、对手建模和上下层联合训练。可发表缺口只存在于这些工作的一个窄交集：

> **双方兵力都在回合内变化时，用下层真实执行干预得到的、经校准的多维战果分布，驱动双方多线滚动分兵，并在未见规模和对手上验证决策可靠性。**

## 2. 逐阶段审计

| 阶段 | 必要性 | 已有工作已覆盖什么 | 首稿处理 | 创新权重 |
|---|---|---|---|---:|
| 通用下层能力 | 必须，否则上层没有稳定执行接口 | UPDeT、GPL、COPA、REFIL、FlickerFusion 已处理变实体/变构成或动态加入退出 | 实体集合 + task token 的共享 MAPPO，冻结 | 0–10% |
| 能力评估/胜率预测 | 必须，但普通监督回归不新 | BVR 决策支持已从仿真预测交战质量；Fu 等已学能力/任务需求；AAMAS 2025 已用成功概率下界分配 | 同态势完整编组干预、重复 rollout、校准多结果与 optimizer-aware 补数据 | **40–50%** |
| 上层动态分组 | 必须，但一般动态 assignment 不新 | Carion 学 score 后优化，ALMA 分配子任务，Double-IC 做双方联盟，2026 Dynamic Alliance 做攻防动态联盟 | 风险收益矩阵 + 双方候选分配 + 滚动博弈 | **40–50%** |
| 上下层联合优化 | 有潜在收益，但不是首稿必要条件 | ALMA、HAVEN、C2 交替训练、DT-GAT 和 HH-MAPPO 均已有联合/交替思想 | 一周限时消融，失败即删除 | 0–10% |

## 3. 最直接的创新威胁

### 3.1 “上层分配 + 固定下层”已经存在

[Carion et al., NeurIPS 2019](https://proceedings.neurips.cc/paper_files/paper/2019/hash/3c3c139bd8467c1587a41081ad78045e-Abstract.html) 每一步用学习的 scoring model 参数化集中优化问题，把智能体分到任务，并从小规模零样本泛化到五倍规模；低层策略是预先给定的。因此“固定下层 + 学一个分配分数 + 求解器 + 跨规模”不能作为本文创新。

### 3.2 “分层分配 + 下层联合学习”已经存在

[ALMA, NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/2f27964513a28d034530bfdd117ea31d-Abstract-Conference.html) 同时学习高层子任务分配和低层执行，并报告共同训练优于分开训练。因此阶段 4 不能写成首次联合优化。

### 3.3 “双方竞争联盟”已经存在

[Duan et al., Expert Systems with Applications 2025](https://doi.org/10.1016/j.eswa.2025.127271) 已把队内合作和队间竞争结合成两层联盟形成博弈，并用 Double-IC 在动态目标分配中求联盟结构。因此“把动态分组改写成双方博弈”本身也不够新；本文必须依靠从实际低层 rollout 学出的校准收益，而非手工态势效用。

### 3.4 “空战/防空 commander + executor”已经很拥挤

- [HHMARL 2D/3D](https://arxiv.org/abs/2309.11247) 已先训练低层 fight/escape，再训练高层 commander，并测试不同 \(n:m\)。
- [Hierarchical C2 with opponent modeling](https://doi.org/10.1007/s40747-025-02128-9) 已做上层任务分配、下层执行、上层他者建模和交替训练。
- [DT-GAT-MARL, Scientific Reports 2026](https://doi.org/10.1038/s41598-026-55576-9) 已做动态图上层拦截分配、下层 MAPPO、双频更新与微调。
- [Dynamic Alliance Operations, Aerospace Science and Technology 2026](https://doi.org/10.1016/j.ast.2026.113058) 已明确面向 UAV 集群攻防的实时 1v1/2v1 动态联盟和专用下层策略。
- [HH-MAPPO, Entropy 2026](https://doi.org/10.3390/e28070793) 进一步覆盖动态规模威胁、层次部署/拦截与联合训练。

这些工作共同否定了“宏观 commander、动态分组、GNN、双时间尺度、联合微调”作为独立新意。

### 3.5 “能力/成功率 -> 分配”已有直接先例

- [Fu et al., 2022](https://arxiv.org/abs/2211.03286) 从团队配置和表现学习线性能力—任务需求，再嵌入优化分配。
- [AAMAS 2025 adaptive bi-level allocation](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/p1336.pdf) 用执行数据估计任务完成概率与下界，再做高层分配。
- [BVR engagement decision support](https://arxiv.org/abs/2111.03059) 用 3,729 次仿真、10,316 个交战样本预测交战质量。
- [REDA, AAAI 2025](https://ojs.aaai.org/index.php/AAAI/article/view/34852) 学习 assignment value 后交给最优分配器。

所以普通“人数+位置 -> 胜率 -> Hungarian”一定不够。

## 4. 我们还剩下什么

保留下来的差异必须同时成立：

1. **干预而非日志相关性：**从同一态势克隆多个完整候选编组，并用共同随机数 rollout；
2. **分布而非一个 Q 值：**输出成功、伤亡、耗时和认知不确定性，并校准；
3. **双边完整上下文：**价值依赖我方完整划分、敌方完整划分和空间态势，而不是可加的单 agent–task score；
4. **决策级而非预测级验证：**测选中方案校准、false-safe、oracle regret、最终关键点任务与最坏对手；
5. **回合内开放事件：**双方死亡与增援发生在同一 episode 内，并严格分离训练/测试规模、时序和对手池。

只做到其中一两项仍可能被视为现有 structured assignment 或 learned utility 的应用。

## 5. 为什么有实际意义

宏观资源分配错误会直接制造不可逆后果：一个关键点被低估而兵力不足，另一个点被过度投入；增援到达后若仍沿用旧编组，会错过窗口；一个看似 3v2 的局部优势也可能因位置、血量、任务时限或对手打法而实际失败。

本文要解决的具体错误是 **false-safe allocation**：模型声称一个局部任务有把握成功，上层因此抽走其他战线兵力，但真实执行失败。相比“对手策略分类准确率”，这个错误可以直接映射到关键点失守、伤亡和任务失败。

## 6. Q1 / Q2 定位

### 二区可行版本

- 阶段 1 冻结，只作为统一测试床；
- 阶段 2 + 3 形成唯一方法链；
- 一个主三路环境 + 一个公认环境外部验证；
- 完整校准、OOD、cross-play、5 seeds 和强 baseline；
- 阶段 4 只做小规模消融。

这仍不是“保证二区”，但问题集中、证据闭环，1–2 个月有现实可行性。

### 一区/强会议版本还需要

- 预测器—commander—executor 共同适应的新稳定算法或理论，而不是普通交替训练；
- 至少两个差异明显的环境和更大规模；
- 对模型被优化器利用的理论界或严格的在线数据聚合分析；
- 更强自博弈/经验可利用度评估和完整开放源码。

把四阶段都实现并不会自动达到一区；深度、对照和一般性比模块数量更重要。

## 7. 预先否证门槛

出现任一结果就应降级或停止主路线：

- 相同 commander 下，校准模型与未校准 Q/score 的最终任务结果无显著差异；
- 上层选中方案的 false-safe 和 oracle regret 没有下降；
- 三路场景中启发式 force-ratio 已与 proposed 相当；
- OOD 对手下模型极度过度自信，且两轮 optimizer-aware 补数据仍无改善；
- commander 选择几乎不影响最终结果，说明下层或环境没有形成真实资源瓶颈；
- 推理时间超过低层控制周期的 10%，无法声称实时。
