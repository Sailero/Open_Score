# 研究结论与阅读路线

## 1. 本轮最终定位

> **本文研究如何在攻防双方因战损和增援而持续改变规模时，通过可变规模执行、能力评估、动态重编组和上下层协同学习，维持多目标防御的总体胜率。**

这比上一版只研究“少选假安全分兵方案”更大，但逻辑仍可统一：开放规模使固定策略和固定编组失效，因此系统必须形成“执行能力—结果认知—在线指挥—能力再适应”的闭环。四阶段不是四个互不相干的新算法，而是一个 **Open-SCORE** 框架的四个必要接口：

1. **S1 Scale-Generalized Executor**：同一套下层参数面对不同队友数、敌人数和目标数执行任务；
2. **S2 Bilateral Outcome Model**：回答“当前态势下，敌我采用这对编组后会不会失守”；
3. **S3 Dynamic Commander**：在伤亡、增援或固定宏周期到来时，重新生成并选择分兵方案；
4. **S4 Capability–Command Co-Adaptation**：让下层针对上层真正产生的困难任务继续学习，同时防止旧规模能力退化。

## 2. 创新应怎样表述

可以主张的是一个**面向开放规模攻防的统一分层决策闭环**，不能把 QMIX、集合编码、监督结果预测、线性规划或交替训练分别包装成首次提出。

更准确的创新句是：

> **Open-SCORE把动态人口攻防分解为规模无关的任务执行、双边编组结果建模、事件驱动的稳健重编组与带规模守卫的上下层交替优化，使同一系统能在伤亡和增援改变可行编组后继续决策。**

现有研究分别覆盖了其中部分问题：QMIX解决合作价值分解，REFIL处理不同数量实体，开放临时团队研究处理成员进出，ALMA处理层次任务分配及联合训练；本工作的空间是它们尚未共同覆盖的“**双方人口变化 + 多目标防御 + 显式能力接口 + 在线重编组 + 能力/指挥共同适应**”。因此不能写“这一问题长期无人研究”，只能写“现有方案沿不同子问题发展，缺少该组合下的闭环方法和证据”。

## 3. 当前完成度

| 部分 | 已有内容 | 当前状态 | 下一步 |
|---|---|---|---|
| HAD | 打击智能体、目标、连续运动和规则开火 | 修复独立导入及防守方误伤目标；已有 S1 适配器 | 增加环境自有 PRNG、clone/restore 和增援事件 |
| S1 | 变规模实体 QMIX、HAD 动作离散化、TD loss | CPU smoke 和 4 个测试通过 | 实现序列 replay、runner 和首个 3-seed Demo |
| S2 | 双边集合结果模型和选择加权 loss | 核心网络可执行 | 等 S1 checkpoint 后采同快照干预数据 |
| S3 | 数量级候选、minimax LP、重规划触发 | 核心求解器可执行 | 接 assignment/Hungarian 和 S2 预测矩阵 |
| S4 | 稳定性正则、最坏规模守卫、失败回滚 | 核心更新原语可执行 | 完成 S1–S3 后再接交替训练循环 |

这里的“可执行”只表示核心张量和算法语义已经通过 smoke，不代表训练收敛或论文结论已经成立。

## 4. 第一阶段优先级

下一步只做 HAD 上的 S1 Demo，不提前引入 PSRO、在线对手辨识或 S4：

- 训练规模：红方人数、蓝方人数、目标数从预注册集合中随机采样；
- 下层算法：QMIX 主干 + REFIL 式实体掩码 + 变数量单调 mixer；
- 对手：先用一个固定追击脚本，之后再增加 2–3 个规则风格；
- 验证：同一 checkpoint 在训练规模和未见规模上测试，报告胜率、规模退化和 padding/排列不变性；
- 判死线：如果未见规模胜率接近随机或换人数必须重训，则 S1 没达到后续三阶段需要的能力接口。

“任意规模”在论文中必须写成：**网络结构接受任意有限实体集合，但经验泛化只对实验覆盖的训练区间和外推区间负责**，不能声称无限规模保证。

## 6. 最重要的研究纪律

- 四阶段可以统一成一个框架贡献，但必须用逐阶段消融证明每一阶段确实必要；
- HAD 是第一验证平台，不是公认 benchmark；论文仍需 ALMA 官方复现锚点和第二动力学；
- S4 不能在 S1–S3 未通过门槛时启动，否则只会把失败原因混在一起；
- 当前没有真实胜率结果，所有预期数字都是 go/no-go 门槛，不是实验结论。
