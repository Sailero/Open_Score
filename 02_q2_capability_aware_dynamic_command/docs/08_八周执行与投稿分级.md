# 八周执行与投稿分级

## 1. 八周主线

### 第 1 周：冻结问题与环境

- 在现有 SwarmBattle 中实现三关键点、assignment、任务 token、clone/restore 和事件触发；
- 用脚本下层跑 static/uniform、force-ratio、greedy 与小规模 oracle；
- 完成 ALMA 与 JaxMARL 三天 upstream smoke gate；
- 冻结训练/ID/OOD split 和主指标。

**交付：**可复现实验协议、环境测试、不同分兵确实改变任务结果的 P0 曲线。若 oracle–heuristic gap 太小，先调整场景。

### 第 2 周：统一下层与数据采集器

- 先用强脚本建立完整 paired rollout；
- 同时训练/迁移一个实体集合 + task-conditioned MAPPO 下层；
- 固定下层 checkpoint 与 policy version；
- 实现同快照、共同随机数、分组 split 防泄漏测试。

**交付：**首批干预数据；下层覆盖表；脚本与学习下层的一致性对比。

### 第 3 周：EGOM 与校准

- Logistic/XGBoost、Fu-style linear、critic、Deep Sets、Set Transformer；
- 3–5 模型 ensemble，独立 calibration split；
- Brier/NLL/ECE、伤亡/耗时误差、false-safe、top-k regret；
- 第一次 optimizer-aware 补数据。

**交付：**随机候选与选中候选两套 reliability/regret 结果。若 EGOM 无选择优势，立即否证。

### 第 4 周：COGAR 与核心 baseline

- 候选计数/beam、min-cost identity assignment；
- 手工收益、Carion-style、Double-IC、小规模 oracle；
- 风险收益矩阵、regularized maximin、switch cost；
- same-capacity no-EGOM 与 shuffled-EGOM 因果消融。

**交付：**ID 三战线端到端主表草稿，明确改善是否来自战果接口。

### 第 5 周：开放事件与对抗泛化

- Scale/Event/Opponent/Joint OOD；
- cross-play payoff matrix；
- 事件后恢复 AUC、重编抖动和 p95 latency；
- 第二次且最后一次 optimizer-aware 补数据；
- 3 seeds 筛选不成立的模型。

**交付：**路线 A go/no-go。双边 game 无增益但 EGOM 有价值时转路线 B。

### 第 6 周：外部验证与阶段 4 限时

- ALMA StarCraft multi-army、SMAX 或 MAgent2 中至少完成一个外部验证；
- 实现 ALMA-style / pointer-style 强基线；
- 只用一周测试 frozen vs naive joint vs alternating refresh；
- 未达门槛立即删除阶段 4。

**交付：**外部有效性结果与阶段 4 明确去留。

### 第 7 周：正式统计与消融

- 5 个训练 seeds；
- 每 matchup/event suite 至少 500 eval episodes 或功效分析等价样本；
- paired bootstrap CI、effect size、失败 run；
- 效果—延迟—重编 Pareto；
- 整理配置、日志 schema、数据卡和环境卡。

**交付：**冻结最终表图，不再按结果修改 test split。

### 第 8 周：论文与复现包

- 完成 Introduction、Related Work、Preliminaries、Method、Experiments；
- 更新文献到提交日，特别检查 2026 新工作；
- 一键 smoke、最小复现实验、Docker/conda 锁定；
- 匿名化代码和补充材料；
- 按目标期刊 scope 重写摘要与 cover letter。

**交付：**可投稿稿件、公开/匿名代码包和结果审计清单。

## 2. 每周不可拖延的关键路径

~~~text
有资源瓶颈的三战线场景
  -> 可克隆 paired rollout
  -> EGOM 在选中候选上可靠
  -> 风险接口改善最终分兵
  -> OOD / cross-play 仍成立
  -> 外部环境复现
~~~

下层更强、网络更大和阶段 4 都不在关键路径上。任何附加模块不得延迟这条链。

## 3. 投稿候选：匹配优先，速度次之

分区会随年份、学科和学校口径变化。下面只引用 2026-08-27 出版社公开的 scope 与流程数字，**不承诺当前中科院/JCR 一定为二区**；投稿前必须用学校认可的当年 JCR / 中科院版本复核。

### 3.1 Autonomous Agents and Multi-Agent Systems（JAAMAS）——科学问题首选

- 官方 [scope](https://link.springer.com/journal/10458/aims-and-scope) 明确覆盖合作与团队、MAS 组织、多智能体规划协调、博弈论、多智能体学习、测试环境和 multi-robot systems。
- [期刊主页](https://link.springer.com/journal/10458) 当前展示 first decision 中位数约 9 天。
- 最合适的包装：开放多智能体系统中的不确定性感知动态联盟与任务重分配。
- 风险：需要清楚的 MAS 一般性和强博弈/分配 baseline，不能只像一个 UAV 应用。

### 3.2 Applied Intelligence——稳妥综合 AI 备选

- 官方 [scope](https://link.springer.com/journal/10489/aims-and-scope) 覆盖 agents、games、intelligent robotics、planning/scheduling、optimization 和 uncertain information，并要求真实复杂问题中的原创智能方法。
- [期刊主页](https://link.springer.com/journal/10489) 当前展示 first decision 中位数约 45 天。
- 适合当前“校准结果模型 + 动态重分配 + OOD”完整算法仿真版本。
- 风险：必须突出方法创新，不能只是把现有 MARL 换到攻防数据集。

### 3.3 Engineering Applications of Artificial Intelligence（EAAI）——工程化备选

- 官方 [期刊描述](https://shop.elsevier.com/journals/engineering-applications-of-artificial-intelligence/0952-1976) 覆盖 distributed AI、multi-agent control、实时智能自动化和机器人，强调真实工程应用与可复现公共数据/基准。
- [期刊主页](https://www.sciencedirect.com/journal/engineering-applications-of-artificial-intelligence) 当前展示约 27 天 first decision、85 天 decision after review、207 天 submission to acceptance。
- 只有在明确落到多无人系统关键目标防护、公开场景与代码时优先。
- 风险：纯抽象 Markov game 或自定义小环境可能被认为工程应用不足。

### 3.4 条件备选

- [Robotics and Autonomous Systems](https://www.sciencedirect.com/journal/robotics-and-autonomous-systems)：当前页面约 32 天 first decision、135 天 review 后决定、244 天 acceptance。只有加入运动学、局部感知、通信或真实时延约束后才优先。
- [Neurocomputing](https://www.sciencedirect.com/journal/neurocomputing)：当前页面约 8 / 62 / 139 天，但本文核心不是新神经架构或学习理论，匹配度低，不因 first decision 数字短而优先。

## 4. 为什么“首次决定 9 天”不等于外审快

[Elsevier 的 submission and decision 流程说明](https://www.prod.webpresence.elsevier.com/publishing/publish-in-a-journal/submission-and-decision) 明确存在送外审前的 scope、创新和基本质量筛选。Springer 也有编辑初筛。因此 first decision 常包含 desk reject，不能解释为“9 天完成同行评审”，更不能当作录用周期。

当前投稿顺序建议：

1. **JAAMAS**：研究问题最对口；
2. **Applied Intelligence**：没有真实机器人时的稳妥备选；
3. **EAAI**：完成公开工程环境和充分应用验证后；
4. 加入物理约束后，可把 RAS 提到第二或第三。

若学校的当年分区不满足目标，再在同一 scope 层级调整；不要先看“快”再硬改论文主题。

## 5. 投稿前分级

### 可投二区版本

- 路线 A 的 H1–H3 至少支持 H1/H2，且 OOD 有一致结果；
- 主环境 + 一个外部环境；
- Carion/Double-IC/ALMA/no-EGOM/Oracle 关键对照齐全；
- 5 seeds、选择后校准、端到端任务、延迟和代码；
- 阶段 4 可完全没有正结果。

### 可尝试更高层级版本

- 双边 game 相对 robust greedy 显著更稳健；
- optimizer-aware 数据聚合有清楚机制和理论解释；
- 多环境、多规模、经验 best response 均成立；
- 预测器一致共同适应稳定改善，而不是偶然微调；
- 论文形成一般 open-population competitive allocation 结论。

### 暂不应投稿

- 只有自定义环境和弱启发式；
- 只报 predictor accuracy，没有选中方案校准和最终任务；
- 只在同配对 self-play 上提高胜率；
- baseline 下层、训练步数或候选预算不公平；
- 预期结果被写成实际结果；
- 没有许可证、版本和数据生成审计。

## 6. 两个月现实判断

如果第一周环境门和第三周 EGOM 门都通过，八周形成一篇完整投稿稿件是现实的；如果阶段 1 从零训练、三套环境同时改造、阶段 4 也作为必做，时间几乎一定失控。因此本文把“完整流程可运行”与“所有阶段都是创新”分开：流程可以保留，创新只压在阶段 2+3。
