# Open-SCORE 方法简版：开放规模攻防的四阶段闭环

## 1. 论文式方法叙述

Open-SCORE以目标级任务作为上下层接口。下层采用共享参数、实体集合输入的变规模 QMIX，在不同队友数、敌人数和目标数下执行被分配任务；中层在冻结执行器版本下，从同一战场快照对双方编组进行短窗干预，学习编组条件失守概率；上层在人口变化或宏周期到来时生成数量级候选，利用保守风险矩阵求解最坏响应下的重编组；最后，通过带旧策略稳定约束和 held-out 规模守卫的交替优化，使下层针对指挥官真实产生的困难任务继续学习，并在能力改变后刷新结果模型和指挥策略。

这一段就是 Method 开头，不需要先介绍十几个技巧。

## 2. 四阶段数据流

```text
动态战场 (实体加入/死亡、目标状态)
        │
        ▼
S1 变规模任务执行器 πφ(u|o,task)
        │ rollout / checkpoint version
        ▼
S2 双边编组结果模型 pθ(breach|s,zD,zA,φ-version)
        │ 风险矩阵
        ▼
S3 动态指挥器 CΘ：候选生成 → minimax → 个体匹配
        │ 指挥器诱导的困难任务分布
        ▼
S4 交替共适应：更新下层 → 规模守卫 → 刷新 S2/S3
        └──────────────────────────────► 回到 S1
```

## 3. S1：变规模任务条件 QMIX

每个智能体共享同一个循环效用网络：

$$
Q_i^t=Q_\phi(\tau_i^t,u_i^t,m_i^t;\operatorname{SetEnc}(\mathcal E_i^t)).
$$

普通 QMIX 的 mixing network 输出维度依赖固定 $N$。Open-SCORE 改为对活跃智能体集合做正权重聚合：

$$
h_k=\operatorname{ELU}\left(
\frac{1}{N_t}\sum_{i\in\mathcal A_t}w_{ik}(s,e_i,m_i)Q_i+b_k(s)
\right),
$$

$$
Q_{tot}=\sum_k v_k(s)h_k+b(s),\qquad w_{ik},v_k\ge0.
$$

它保留 $\partial Q_{tot}/\partial Q_i\ge0$，但不要求训练时人数固定。死亡/缺席实体由 mask 去除，任务 token 告诉下层当前保护或攻击哪个目标。

第一阶段只训练一方对固定脚本对手；对手种群和 PSRO 后移，防止“规模泛化”和“博弈学习”同时失败而无法诊断。

## 4. S2：双边编组条件结果模型

对每个非终局快照 $s_t$，固定 S1 checkpoint 和随机带，分别执行防守候选 $z_i^D$ 与攻击候选 $z_j^A$：

$$
y_{ij}=\mathbb 1[\text{在 }H_o\text{ 内至少一个目标失守}].
$$

集合模型预测

$$
\hat p_{ij}=\sigma f_\theta(s_t,z_i^D,z_j^A,\text{policy-version}).
$$

主损失是带 pilot 选择权重的 BCE，同一快照内再加少量 pairwise ranking。独立数据用于校准和经验保守修正，避免上层专门选中模型最乐观的误差。

S2 输出的是“这个能力版本执行这对编组的结果”，不是一个脱离任务的通用战斗力标量。

## 5. S3：事件驱动的稳健动态指挥

先枚举每个目标分到多少人，而不是直接枚举所有个体排列；再用距离、剩余健康和切换代价做固定个体匹配。对候选对批量调用 S2 得到风险矩阵：

$$
M_{ij}=\operatorname{clip}(\hat p_{ij}+\Delta_{ij},0,1)
+\lambda_{sw}C_{sw}(z_i^D,z_{t-1}^D).
$$

防守指挥器解小型零和 LP，最小化攻击候选的最坏失守风险。以下事件触发重规划：

- 到达固定宏周期 $H_c$；
- 任一方存活人数变化；
- 新增援到达或目标集合变化。

在线只执行一个宏周期，然后重新观察；S2 的长预测窗用于比较候选，不等于一次把未来全部锁死。

## 6. S4：带规模守卫的上下层交替优化

不采用 LLM 微调。这个问题的输入是连续状态、实体集合和数值回报，没有自然语言结构；使用 LLM 会引入额外 token 化、推理延迟和不可控先验。

采用简单的两时间尺度循环：

1. 冻结 S1，刷新双边结果数据并更新 S2/S3；
2. 冻结 S2/S3，让当前指挥器生成下层训练任务；
3. 用 QMIX TD loss 更新 S1，同时蒸馏旧 checkpoint 的动作值；
4. 在封存规模集合上测试最坏胜率，下降超过 $\epsilon$ 就回滚；
5. 接受新 S1 后更新 policy-version，并重新采集 S2 数据。

下层目标可以写成

$$
\mathcal L_L=\mathcal L_{QMIX}
+\lambda_{stab}\mathbb E\left[\|Q_\phi-Q_{\phi^-}\|_2^2\right].
$$

这不是声称全局求解双层博弈，而是一个可审计的坐标更新过程；核心实验要比较冻结、朴素 joint training 和 guarded alternating 三种方式。

## 7. 核心创新只有一条主线

> **开放规模改变执行能力，能力改变编组结果，编组又改变下层训练分布；Open-SCORE用四个显式接口闭合这个循环。**

方法章节可以分四节，但贡献声明写成一个统一框架，再用三条证据展开：

1. 同一执行器是否跨规模工作；
2. 结果模型和动态指挥是否在人员变化后选对编组；
3. 共同适应是否提高跨规模最坏胜率而不遗忘旧规模。
