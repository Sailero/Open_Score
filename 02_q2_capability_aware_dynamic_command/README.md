# 能力感知的动态宏观指挥

## 一句话

> **让指挥官在调兵前知道每支临时小队真能不能打赢，并在双方伤亡和增援后立即重分兵、守住关键点。**

更严格的技术表述是：

> **我们从同一战场态势下多个候选编组的干预式仿真中学习经校准的胜负—伤亡—耗时分布，并把风险下界作为双方滚动分兵博弈的收益。**

## 明确场景

论文只研究一个容易解释、确实需要宏观指挥的场景：**三路关键资产攻防**。进攻方要在时限内攻破三个关键点中的至少两个，防守方要守住至少两个；双方单位会战损，并可能在回合中分批增援。双方各有一个看到全局态势的 commander，每隔若干低层步或在伤亡/增援事件后，把存活单位分配到不同关键点与任务；被分到同一关键点的队友、敌人和目标自然构成一个局部子博弈。

这里不再额外发明一个“聚类模块”：**分到同一任务就是成组**。这使论文研究的是真正影响任务成败的资源分配，而不是聚类形状。

## 论文收缩

| 原设想阶段 | 本文位置 | 是否主创新 |
|---|---|---:|
| 1. 通用下层个体/协作能力 | 共享、任务条件化的低层执行器 | 否，基础设施 |
| 2. 能力评估与预测 | 同态势干预数据上的校准战果分布 | **是** |
| 3. 上层动态分组博弈 | 风险感知的双边滚动分兵 | **是** |
| 4. 上下层联合优化 | 一周限时消融或后续工作 | 否 |

完整四阶段一起做不是更好的首稿：ALMA、C2 分层决策、DT-GAT-MARL 和 2026 Dynamic Alliance 等工作已经覆盖了联合或分层框架的大部分表面结构。本文的唯一因果链是：**更可信地估计实际执行结果，是否能让宏观分兵更可靠并最终守住更多关键点？**

当前 `scripts/smoke_test.py` 可验证已有环境和集合模型，但以下组件仍是 TODO：

1. 三路关键资产、任务 token 与 commander assignment API；

3. Execution-Grounded Outcome Model（EGOM）；
4. 候选分配生成、风险收益矩阵和滚动博弈求解器；
5. ALMA / Carion / Double-IC / learned-commander 对照。

任何文档都不得把这些计划组件写成已经实现。
