# 现行红方规则：nv1 整数规划与逐步直线预测

更新：2026-09-09。当前规则版本为 `rule_nv1_v1`，类名 `CoveragePolicy` / `CoverageExecutor` 保留兼容。环境新增 `task_mode=survival/damage` 与 `spatial_dim=2/3`，默认维度为二维；网页默认伤害任务。二维规则只选平面动作，整数规划与一步匀速预测的定义不变。下表中的损毁和胜负仅适用于存活任务。

本次为实现修改，未运行新的仿真、评估或性能探测。历史 v7 指标对应修改前的覆盖规则，不能当作 nv1 的结果。当前红方分层配置为 `nv1 + predictive_intercept`；旧覆盖策略别名已删除，不再映射至当前规则。

无量纲：\(r/R\approx0.75\)，\(L/2r\approx6.9\)，\(v\Delta t/R\approx0.25\)，\(vH/L\approx2.4\)。

开火：红方射程内有存活蓝方攻击机即开火并自毁；蓝方射程内有存活目标即开火并自毁。伤害与开火都用移动前位置。存活任务同一步目标损毁优先于蓝方全灭。伤害任务目标不被摧毁，每步红蓝奖励为该步新增总伤害的负值和正值，不加胜负奖励；最终未折扣回报为 `−D/+D`。蓝方攻击机全灭自然结束，红方全灭继续推进。

## 2. 每步选取参与拦截的蓝方

令当前存活红方集合为 R、蓝方集合为 B。若 |R| ≥ |B|，所有蓝方参与规划。若 |R| < |B|，对每个蓝方计算其到最近红方的**当前三维欧氏距离**：

\[
d_b = \min_{i\in R}\|p_i-p_b\|_2.
\]

按 `(d_b, 蓝方ID)` 排序，仅保留最近的 |R| 个蓝方，记为 B*。其余蓝方本步不参与指派，也不为其增加避让逻辑；下一步重新排序，集合可以变化。R 为空时 B* 为空。环境仍正常推进所有蓝方、碰撞与自动开火。

## 3. 匀速直线预测

每个物理步只预测下一步位置：

\[
\hat p_b(t+1)=p_b(t)+v_b(t)\Delta t.
\]

不模拟蓝方加速度、转向、目标切换或边界反弹，不展开剩余 100 步轨迹。实际蓝方继续执行原来的 `rush`；每步用新观测覆盖上一步预测。

## 4. nv1 的 0–1 整数规划

令 x_ib = 1 表示红方 i 负责蓝方 b，成本为到预测位置的直线距离：

\[
c_{ib}=\|p_i-\hat p_b(t+1)\|_2.
\]

求解：

\[
\min_x\sum_{i\in R}\sum_{b\in B^*}c_{ib}x_{ib},\qquad x_{ib}\in\{0,1\},
\]

满足：

\[
\sum_{b\in B^*}x_{ib}=1\quad(\forall i\in R),\qquad
\sum_{i\in R}x_{ib}\ge1\quad(\forall b\in B^*).
\]

因此每个红方恰好负责一个蓝方，每个参与规划的蓝方至少有一个红方负责，多余红方允许加入已有小组，构成 n 对 1。双方数量相等时退化为一对一指派。

实现使用现有 SciPy 的 `milp`（HiGHS），二元变量上下界为 0 和 1，约束矩阵为稀疏矩阵，`mip_rel_gap=0`。只接受求解成功且通过整数性、行和、列和检查的解；失败明确上报，不伪装成满足覆盖条件。

这里保证的是**责任分配覆盖**，不保证动力学可达或最终击杀。代价没有嵌套前向仿真，也没有学习模型。

原生 `Group.target` 仍指被保护的目标点；每个蓝方对应一个红方成员组，目标归属仅由公开位置和速度推断。精确的“红方 → 蓝方”映射单独保存在 `last_plan["assignment"]` 并直接传给执行器，不通过目标点配额再次分配。

## 5. 执行与更新顺序

1. 在本步动作前，根据当前存活名单选取 B*，做一步匀速预测并求解整数规划。
2. 红方直接瞄准自己负责蓝方的预测位置，调用现有 `steer` 在 27 个加速度基元中选择动作。保留转向与速度限制；不再搜索时空站位、做贪心覆盖或缓存跨步站位。
3. 执行一个原生物理步，记录本步使用的指派，然后下一步重新求解。

`CoveragePolicy` 和 `CoverageExecutor` 在红方分层运行路径中共享同一个策略实例，只复用**同一步、同一公开状态**已经求出的解，避免上下层重复求解。状态或步号变化就重新规划。

`run_episode(..., command_interval=5)` 中该参数保持控制蓝方及历史规则的指挥周期；nv1 红方固定每步更新。蓝方仍在开局、每 5 步或出现伤亡时按 `reactive` 重新抽样目标，其余步保持目标并执行 `rush`。

## 6. 回放与统计

回放帧保留原有轨迹字段，并增加：

- `interception`：本步执行的红方 ID → 蓝方 ID 指派。
- `selected_blue`：本步纳入整数规划的蓝方 ID。
- `ignored_blue`：本步因红方数量不足而忽略的蓝方 ID。

帧位置是该物理步执行后的状态，指派是执行该步时采用的方案。网页显示每帧参与和忽略数量，不把忽略对象描述成“已覆盖”。API 4 通过对称的 `red_strategy` / `blue_strategy` 对象传递架构与策略；端到端只有 policy，分层包含 layers。任务与维度独立配置。回放含每目标累计伤害与双边回报；伤害任务不标记胜率，旧回放缺失模式与维度时按存活/三维解释。

网页人数、目标数、种子、局数、任务、维度、步数和血量直接在前端设置。训练工厂用 `make_env(task_mode="damage", spatial_dim=2, target_health=2.0, max_cycles=100)`；旧三维存活任务显式传 `task_mode="survival", spatial_dim=3`。网页与训练均支持 `target_initialization="random"/"fixed"`，默认 random。随机模式每局从 `DefaultTargetRegion` 重新采样；固定模式以区域 x/z 中点和内部等距 y 生成确定布局。三维目标高度默认 500–1500 米，二维目标固定为 `PlanarAltitude`。`target_positions` 可显式指定固定坐标。红方在已确定的目标周围初始化，网页不再覆盖底层随机目标。

修改公共配置后，在已有任务结束后重启 `viewer.py` 并刷新页面，让引擎导入值和规则常量一起重新加载。不要仅修改 `outputs/v7/metrics.json` 或报告里的参数快照。

存活任务的网页时限胜负由 `HADStage3Adapter` 的 `horizon_policy="red_win"` 默认参数控制；若要改变时限胜负，应在 `run_episode` 创建适配器处显式传入该参数，不能只改公共配置里的 `HorizonPolicy`。伤害任务忽略此胜负奖励，在上限处按累计伤害报告结果。

## 8. 历史结果

修改前的覆盖规则使用全剩余时域的加速轨迹预测、D'Hondt 人数分配、匈牙利身份匹配和贪心拦截站位。旧评估的唯一正式结果仍见 [实验报告 v7](../实验报告/实验报告_v7.md) 与原位数据。本次没有重新评估 nv1，也没有更改这些历史结果。
