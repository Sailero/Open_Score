# 当前实验分析与论文主张讨论

> 分析日期：2026-09-23。定量依据为 main0921 在北京时间 10:50:42 的正式报告快照及 10:53:47–10:54:09 的逐回合数据只读复核；10:55:48 报告复查时完成度未变。本文是研究决策讨论，包含已完成结果、待确认解释与未来提案，三者分别标明。写作过程中未修改训练、终评、资源配置或实验队列。

## 1. 核心判断与推荐选择

**目前已有一个表现较强的方法家族，但尚未建立“多轮循环提取语义层级，从而改善跨规模泛化”这一中心贡献。** 整体性能、循环必要性、创新性是三个不同问题；第一项有相当明确的正面证据，后两项仍有关键缺口。

现阶段最值得保留的结果，是当前实体关系处理与个体读取的组合在 HAD 上相对 REFIL 及参数匹配版本的改善。最应该放下的预设，是必须让每一轮对应一个语义层级，或者必须证明四轮优于一轮。研究应允许最终答案是“一次关系交互已取得主要收益，额外计算的价值取决于训练和读取方式”。

这次最新数据带来了四项实质更新：

1. **Fixed4 已完成三个种子的正式终评，不能继续依据 seed 0 宣称固定深度更好。** seed 1 在 ID 和所有 OOD 分组都明显较差；已有验证曲线表明其长期较弱，且训练末点还有退化。固定四轮不是已经确认的改良。
2. **Untied4 的 seed 2 很有潜力，但目前只有这一个完整种子。** 它值得关注，不能据此宣布“不共享参数解决了问题”，更不能用它与其他方法的三种子均值直接排名。
3. **No-count 在 K-OOD 和联合 OOD 上三个种子都优于 Full。** “显式数量条件是外推收益的必要来源”与目前结果不符；数量快捷特征、训练耦合等解释尚待区分。
4. **当前 HAD 的存活物理实体是公开可见的。** 实体掩码只处理死亡和 padding，没有距离视野遮挡；观察者相对坐标不是信息遮挡。因此，现有 HAD 实验不能单独支撑“局部受限视野下恢复他者意图”的主张。

我的建议是分两步决策：

- **近期优先完成证据闭环。** 用已经登记的 Untied4、KV0、成本和 SMACv2 结果，确定当前方法究竟是关系结构有效、深度训练方式有效，还是特定种子下的优化优势；把现版本组织成一条诚实、可检验的论文主线。
- **如希望形成更强的方法贡献，再开发一个有失败机制依据的最小结构。** 优先候选是“显式表示拦截机会之间的资源竞争，并据此修正个体投入”，前提是先证明这种失败确实存在、影响真实任务损失，且普通单轮结构尚未解决。不要同时加入层级 token、门控、动态停止、辅助任务和新 mixer。

**现在可以决定研究问题和排除不成立的主张；现在还不能决定最终最优方法。** 等待剩余训练的价值在于完成判别，而不是期待它自动把原来的故事变成事实。

### 2.2 分组与不确定性

HAD 使用目标损伤 D，越低越好。每次训练预算为 1M 环境步，训练规模覆盖 N∈{4,6,8,10}、K∈{1,2,3}；正式终评使用满足预算的 final 权重，不能事后改选 best。训练种子为 0、1、2；每个配置每个训练种子使用 9000–9299 的 300 个评估回合。

| 分组 | 固定配置 | 含义 |
|---|---|---|
| ID，4 格 | 4v4 K2、6v6 K2、8v8 K2、10v10 K3 | 训练范围内表现 |
| N-OOD，6 格 | N=15/20/25/30/40/50，红蓝等人数，K2 | 人数外推 |
| K-OOD，4 格 | 10v10，K=4/6/9/12 | 目标数外推 |
| 联合 OOD，8 格 | N=15/20/30 与 K=4/6 的六格，加 30v30 K9/K12 | 人数与目标数同时外推 |
| 单列支持点与插值 | 10v10 K2、5v5 K2 | 不混入上述四组 |

统计先在每个种子内对固定配置等权平均，再对三个训练种子等权平均。本文“±”为 95% t 区间半宽，df=2。300 局能减小环境评估噪声，不能把三个训练重复变成 900 次独立训练。

三个种子的区间可能很宽；Fixed4 的对称区间甚至跨过不可行的负 D，这是小样本 t 汇总的限制，不能截掉失败种子来美化结果。区间重叠也不是显著性检验。下文的“更好”默认是所报告均值或逐种子方向，除非另有说明，不代表已经建立总体统计显著性。

## 3. 主实验说明了什么

### 3.1 整体方法确有收益，但收益归因还不充分

| 方法 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---:|---:|---:|---:|
| Full | 0.419 ± 0.383 | 0.861 ± 0.794 | 1.036 ± 0.463 | 1.477 ± 1.091 |
| Single | 0.429 ± 0.693 | 0.742 ± 0.983 | 1.225 ± 2.046 | 1.674 ± 2.643 |
| REFIL | 0.715 ± 0.121 | 2.209 ± 0.689 | 1.796 ± 0.756 | 3.308 ± 0.753 |
| REFIL-matched | 0.914 ± 0.411 | 2.269 ± 0.776 | 2.493 ± 0.695 | 4.170 ± 1.888 |
| ALMA | 1.326 ± 0.480 | 3.605 ± 1.844 | 3.022 ± 0.854 | 5.375 ± 2.574 |
| TransfQMix | 2.157 ± 0.584 | 6.226 ± 1.760 | 6.128 ± 4.526 | 10.597 ± 6.920 |
| Rule | 1.462 | 1.545 | 3.212 | 3.060 |

Full 相对 REFIL 的四组均值损伤分别降低约 **41.5%、61.0%、42.3%、55.3%**；在四组内，每个对应训练种子的 Full 都优于 REFIL，也优于 REFIL-matched。这是当前最有分量的正面结果。

但严格含义是：**在当前实现、宿主、训练预算和评估协议下，这套结构与训练安排优于所比较的 REFIL 系统。** 参数匹配对照削弱了“只因参数更多”的简单解释，却不能消除计算量、优化条件、辅助目标和具体容量组织的全部差异。

Single 也取得了大部分性能改善。由此可以把“浅层实体关系处理值得研究”作为工作依据；尚不能把全部收益归因于某一个子模块，更不能归因于已经被移除的多轮机制。

### 3.2 其他基线的差距，既是结果，也提出了公平性问题

在相同快照中，QMIX-Atten、DCG、SPECTra 的四组均值分别为：

| 方法 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---:|---:|---:|---:|
| QMIX-Atten | 2.318 | 5.139 | 5.009 | 7.415 |
| DCG | 2.028 | 5.021 | 5.839 | 8.092 |
| SPECTra | 2.662 | 6.455 | 6.933 | 11.184 |

这些差距不能被忽略，但许多基线在 ID 就明显落后。审稿人会合理地追问：OOD 差距有多少来自规模归纳偏置，又有多少来自当前预算下尚未学好基本任务？

这不证明基线实现有误，也不要求现在推翻全部实验。它要求论文把结论限定为**统一预算下的系统比较**，披露各方法的实际优化器、训练频率、默认超参数与环境适配，并以同宿主的结构对照支撑机制归因。若将来需要额外调参，应对主要近邻采用一致、仅使用训练内验证的选择预算，保留原版本，不对某个方法反复试到满意。

Rule 在 N-OOD 的 D=1.545，已经优于若干学习基线，说明结构化拦截规则是有力参照。现有规则本身使用预测位置和约束分配；未来提出资源竞争方法时，不能将“显式分配”当作从未尝试过的思想。

此外，D 随人数和目标数改变的绝对值不能直接解释为“推理难度同比增加”。任务暴露、威胁数量和保护对象都可能变化；应在同一配置比较方法，并分开报告各外推轴，而不是把所有配置压成一个漂亮总分。

## 4. 消融对各项设计的判决

### 4.1 Full 与 Single：没有证明循环稳定有益

两者四组的逐种子结果如下，斜线依次表示 seed 0/1/2：

| 方法 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---|---|---|---|
| Full | .330 / .329 / .596 | .778 / .591 / 1.214 | 1.078 / .833 / 1.199 | 1.576 / .997 / 1.859 |
| Single | .747 / .227 / .314 | 1.180 / .410 / .636 | 2.174 / .797 / .704 | 2.897 / .964 / 1.160 |

**四个分组中，Full 都只在 seed 0 优于 Single，在 seed 1 和 seed 2 都落后。** Full 在 ID、K-OOD、联合 OOD 的均值优势，很大程度受 Single seed 0 较差影响；N-OOD 的均值则是 Single 更好。

可以写：额外循环未显示跨种子一致收益；单轮版本保留了整体方法的大部分优势。

不能写：循环绝对无用、两者统计等价，或者 Full 已经稳定更好。三个重复不足以证明这些更强结论；同编号种子也不意味着不同结构经历完全相同的随机优化轨迹。

更关键的是，Full–Single 同时改变训练深度安排与部署深度，不能独立识别“多算几轮”的部署收益。M1 才是固定 Full 权重下的执行深度干预，两者必须共同解释。

### 4.2 Count：目前不应作为核心贡献

| 方法 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---:|---:|---:|---:|
| Full | .419 | .861 | 1.036 | 1.477 |
| No-count | .341 | .945 | .819 | 1.132 |

No-count 在 K-OOD 和联合 OOD 三个种子全部优于 Full，分组均值分别改善约 21.0% 和 23.4%。因此，“数量编码帮助处理未见目标数”的正面叙述目前没有成立。

一种解释是，绝对数量条件提供了易拟合训练规模的特征，外推时反而不稳；另一种解释是额外通道与优化、归一化或读取方式发生耦合。**现有结果只支持去掉该通道在这些轴上更好，不支持直接确定原因。**

不应据已看过的 OOD 结果，悄悄把 No-count 改名为原始 Full。若后续选择它作为新版本起点，应承认这是开发阶段的结构选择，并用新的确认设计检验。

### 4.3 No-REFIL：当前捆绑消融不足以判定局部分支和辅助损失各自作用

No-REFIL 四组均值为 **.331 / .887 / 1.028 / 1.472**；ID 三个种子都优于 Full，其他三个分组的均值总体接近 Full。

这个变体同时去掉 REFIL 局部 attention 分支与 imagined loss，不能单独回答“局部分支是否必要”或“辅助损失是否必要”。当前证据不支持把两者都列成不可缺少的创新；也不能据均值接近就宣称两者完全无作用。

若最终主张与这两项无关，就不值得为了凑消融再大规模拆分。只有准备宣称“局部残差稳定训练”或“辅助损失促进外推”时，才需要一个只改变相应因素的对照。

### 4.4 Last：支持研究读取方式，但不证明层级语义

重新训练的 Last 四组均值为 **.627 / 1.076 / 1.187 / 1.795**，均高于 Full。这个结果说明，在当前训练安排下，直接使用末轮结果的版本平均不如现有多轮融合。

它可以支持“读取安排影响最终性能”的有限结论。它不能证明各轮分别编码不同层级，也不能证明当前 learned fusion 优于所有可能的重新训练读出，例如重新训练的均匀融合或直接保留浅层路径。后文 M2 对冻结网络的干预与它不是同一种证据。

### 4.5 Fixed4：最新完整结果推翻了固定深度已解决问题的期待

| Fixed4 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---:|---:|---:|---:|
| seed 0 | .321 | .523 | 1.141 | 1.885 |
| seed 1 | 3.753 | 12.281 | 8.633 | 17.326 |
| seed 2 | .484 | .580 | 1.217 | 1.711 |
| 三种子均值 ± 95% t | 1.520 ± 4.810 | 4.461 ± 16.824 | 3.664 ± 10.690 | 6.974 ± 22.272 |

seed 0、2 的人数外推结果有吸引力，但 seed 1 明显失败，且不是仅在 OOD 失败。训练内验证 D 在约 20k/500k/800k 步分别为 5.374/4.796/2.927；860k/960k/980k 步降到 1.688/1.621/1.836，最终 1M 点又升到 4.348。验证与正式 ID 使用相同四配置，但评估随机流及每配置局数不同：训练内验证每格 25 局，正式终评每格 300 局，因此数值不能直接混算。

这条曲线同时提示长期训练质量较差和末点退化。它不足以诊断 bug，也不能概括为“只是最终一个点偶然坏了”。正式协议使用 final，应保留该种子，不能临时改 best 来挽救均值。

Full 相对 Fixed4 的优势使“随机深度可能改善优化或产生正则作用”成为值得考虑的解释。但目前只有三个种子，不能声称随机深度已获得普遍稳定性保证。

还要区分预算：Full 在 1–4 轮中采样，若均匀采样，循环部分的平均深度为 2.5；Fixed4 为 4。相同环境步数不等于相同计算量，各轮的训练暴露也不同。因此，此比较研究的是完整深度训练安排，不是严格计算匹配的单因素实验。

### 4.6 Untied4：当前最值得等待的判别证据之一

| 仅 seed 2 | ID | N-OOD | K-OOD | 联合 OOD |
|---|---:|---:|---:|---:|
| Full | .596 | 1.214 | 1.199 | 1.859 |
| Single | .314 | .636 | .704 | 1.160 |
| Fixed4 | .484 | .580 | 1.217 | 1.711 |
| Untied4 | .390 | .349 | .635 | .822 |

Untied4 seed 2 的 OOD 结果优于表内其他同编号种子，ID 则不如 Single。这是有价值的积极迹象，但不能推算 seed 0/1 必然重复，也不能给整个 Untied4 画三种子误差条。

完整结果出来后应按下表判读：

| 可能结果 | 更有依据的解释 | 不应跳到的结论 |
|---|---|---|
| Untied4 多种子稳定胜 Fixed4，且胜 Single | 当前共享约束或层间表达可能限制有益计算 | 已经证明递归推理更优；Untied4 本身是不共享堆叠 |
| Untied4 主要救回 ID 很差的种子，OOD 改善随 ID 同步 | 优化、容量或拟合质量更可能是关键因素 | 高阶关系推理导致特定外推收益 |
| Untied4 胜 Fixed4，但不稳定胜 Single | 避免某类深层失败，不足以证明额外深度值得 | 多层比单层必要 |
| 只有一个种子很好 | 对初始化或优化敏感，结论仍不稳 | 挑最好种子作为最终方法 |

Fixed4–Untied4 在相同固定深度下比较共享与不共享，但参数量随之改变。Full–Untied4 又同时改变深度采样与参数共享；后一组不能当作纯共享消融。

### 4.7 KV0：将检验动态 K/V，而非是否存在循环

KV0 将各轮 attention 的 K/V 来源固定为初始实体表示；Q、残差状态和 FFN 仍随轮次更新。因此它仍然有多轮计算，既不是把 K/V 置零，也不是 Single。

若它完整复现 Full 的效果，可以削弱“必须反复改写关系记忆”的主张，但不能据此宣称循环无效。若明显落后，动态 K/V 在这一训练安排下可能有用，仍不能单凭性能差异推导出语义层级。

只有当动态 K/V 的优势跨种子出现、在明确关系条件下更强、并且相对资源匹配替代仍成立，才有理由把它提升为机制贡献。

## 5. M1、M2、M3 对原始动机的检验

### 5.1 M1：增加执行轮数没有稳定的规模适应趋势

以下均为相同 Full checkpoint 改变执行轮数的三种子均值：

| R | 10v10 K2 | 30v30 K2 | 50v50 K2 |
|---|---:|---:|---:|
| 1 | .574 | .923 | 1.136 |
| 2 | .521 | .876 | .962 |
| 3 | .510 | .998 | 1.012 |
| 4 | .499 | .930 | 1.070 |
| 5 | .502 | .942 | 1.069 |
| 6 | .500 | .940 | 1.063 |

10v10 上，从 R1 到 R4 有小幅均值改善；30v30 上 R4 略差于 R1；50v50 上 R4 相对 R1 的逐种子差为 **−.134 / −.680 / +.615**，方向并不一致。R5/R6 接近 R4，只能说明已测范围内的表现接近平台。

当前不支持“规模越大，需要越多轮”“增加测试时计算能持续改善”或“迭代收敛到更优决策”。即便两个大规模点的 R2 均值最低，也不能在看到测试结果后改选 R2，并继续称其为未经调节的外推结果。

Full@R1 与重新训练的 Single 不是同一方法。前者仍承受 Full 的训练方式及多轮读出共同优化，后者从头按单轮学习；不能混用来夸大或否定循环。

### 5.2 M2：模型依赖既有读出组合，不等于后轮更高级

固定 Full 权重和登记计算安排，改变读取方式：

| 读出 | 10v10 K2 | 50v50 K2 | 30v30 K12 |
|---|---:|---:|---:|
| Learned | .499 | 1.070 | 2.260 |
| Read1 | .574 | 1.136 | 2.544 |
| Read2 | 1.565 | 2.320 | 5.976 |
| Read3 | 4.313 | 11.319 | 19.039 |
| Read4 | 5.242 | 13.590 | 21.045 |
| Uniform | 4.332 | 10.786 | 19.631 |

**Uniform 并不接近 Learned，而是明显退化。** Read1 相对接近 Learned，强行只用后轮则可能严重破坏策略。

一种符合数据的解释是：训练出的系统依赖浅层通路以及特定融合校准，后轮表示未被训练为可单独供原动作头使用。另一种可能是后轮提供小幅修正，与浅层一起有效。当前没有足够证据进一步确定这些解释，更不能仅凭此表说 learned 权重必然接近某个值；需要实际权重和表示贡献记录。

冻结网络改读出造成输入分布变化，衡量的是“现有模型依赖什么”。重新训练 Last 衡量的是“替代结构重新适应后能达到什么水平”。两者的差距恰好说明：**严重干预退化不能直接解释为不可替代性。**

Learned 与正式 R4、Read1 与经登记等价核查的 R1 存在复用关系；它们不是新增独立样本。

### 5.3 M3：目前不支持逐轮形成稳定的语义层级

以 50v50 K2 确认集为例，线性探针 R² 三 checkpoint 均值为：

| 标签与控制 | H0 | H1 | H2 | H3 | H4 |
|---|---:|---:|---:|---:|---:|
| 目标距离，训练网络 | .697 | .858 | .838 | .832 | .817 |
| 目标距离，随机初始化 | .696 | .741 | .740 | .760 | .767 |
| 友机距离，训练网络 | .335 | .603 | .641 | .630 | .597 |
| 友机距离，随机初始化 | .320 | .600 | .647 | .659 | .655 |
| 区域失衡，训练网络 | −.356 | −.004 | .005 | −.013 | −.032 |
| 区域失衡，随机初始化 | −.486 | .022 | .141 | .198 | .231 |

目标距离在训练网络中 H1 最强，没有随轮数继续增强；友机距离在后轮的随机初始化控制甚至高于训练网络均值；区域失衡在最重人数外推下未获得可靠的线性可读性。置乱标签控制总体为负，说明不能忽略正常标签结构，但这并不使所有正常标签的可解码性自动成为学习贡献。

其他配置并非完全相同。例如 30v30 K12 的区域失衡，训练网络 H1/H4 约为 .186/.140，随机初始化 H4 约 .013。因此，应保留完整矩阵，不能只挑一个失败面板证明“没有信息”，也不能只挑一个成功面板证明“有层级”。

探针数据使用五配置各 100 条轨迹，来自 Full seed 0 与 REFIL seed 0 各半；各 checkpoint 在公共轨迹前缀上重建各自 hidden。大量状态样本不是大量独立训练种子。它改善了比较的可比性，但仍受行为状态分布与所选标签限制。

线性可解码性只回答特定标签是否可被指定探针读出：

- 可读，不等于策略因果使用，也不等于循环求解了该关系。
- 不可读，不等于信息绝对不存在，可能涉及编码方式、标签定义或跨分布变化。
- 随机网络也可读，说明几何特征和随机投影本身必须作为解释的一部分。

**后续应修改机制实验的问题，而不是修改标签直到画出预期层级。** 保留本次负结果，把主问题从“每层叫什么”改为“额外计算修正了什么可测错误，何时改变动作并减少任务损失”。

## 6. 为什么当前循环可能与原始动机不匹配

### 6.1 步内循环与时间记忆必须分开

当前 Single 去掉的是同一环境步内反复更新实体的计算，仍保留 GRU 时间记忆。Full、Single、TransfQMix 都不能简单分成“有循环”和“完全无记忆”两类。

当前标准结构可以概括为：

**当前实体嵌入 → 实体关系更新 → 自身信息与历史状态条件化读取 → 与局部分支融合 → GRU → 个体 Q。**

Full 重复关系更新和读取，并融合多轮结果；Single 仅保留一次。实体工作区每个环境步重新建立，标准关系更新不直接输入上一时刻 hidden；历史主要进入个体读取 query，随后进入 GRU。实现见 [entity_encoder.py](../Open-SCORE/open_score/models/entity_encoder.py)。

这提供了一个可研究的具体分工：当前场景关系加工与历史条件决策读取。它比“循环提取越来越高级的信息”更符合实际计算，但这种分工是否带来独立收益，还需要同宿主对照。

### 6.2 当前每轮没有被赋予可检验的层级任务

标准循环每轮处理相同类型的实体集合，使用共享变换；全可见实体在第一轮已经可以相互注意。后轮能够表达更复杂的组合，但没有结构约束要求第一轮是实体、第二轮是局部群组、第三轮是全局任务。

标准读取 query 在轮间也没有形成“根据上一轮决策误差重新提出问题”的显式闭环；重复改写工作区不等于在求解某个被定义的约束问题。因此，当前机制更接近共享关系变换的展开，而不是具有明确对象和残差含义的层级求解器。

这不代表设计必然错误。它意味着最初“不同轮次提取不同层级”的动机没有被足够明确地编码进结构或目标，实验也没有提供补充证据。

### 6.3 人数、目标数和关系计算深度并非同一件事

HAD 存活物理实体公开可见，见 [实体环境掩码](../Open-SCORE/open_score/envs/entity_env.py) 与 [特征掩码](../Open-SCORE/open_score/envs/features.py)。这允许第一轮就处理较广的当前关系，并不需要按图跳数逐步传播才能看到远端实体。

蓝方 reactive + rush 规则在事件发生时随机选择一个目标，并由存活蓝方集中攻击；细节见 [环境说明](../README.md) 与 [对手实现](../../HADE/had_env/grouping/opponents.py)。所以 K 增加不自动意味着同时有 K 个独立子任务，也不自动证明存在多层资源调度需求。

蓝方私有随机指派未直接暴露，因此不能把当前环境称为完整状态完全可观测 MDP。但刚抽样、尚未影响公开物理轨迹的指派具有不可消除的不确定性；内部循环不能凭空恢复该抽样结果。

如果原动机需要“不同关系范围逐步整合”，应先找到当前任务中对应的结构需求，而不是将 N、K 变大本身作为证明。

### 6.4 已有 feedback 分支不能直接作为无通信新方法

现有 feedback 实现从各 observer 的 own token 生成偏好，再将各 observer 的偏好按实体 origin 注入其他 observer 的队友 token。这是跨 observer 的数据路径，并非每个 agent 仅从自己的视图估计所有队友。

在当前 HAD 公共物理实体全可见条件下，这些无历史偏好未必增加私有物理信息；但在存在局部视野的任务中，可能传递其他 agent 的私有观测。不能直接沿用这段实现，然后声称一般部分观测下的无通信执行。标准 cycle 没有这条跨 observer 偏好通路。

若未来选择本地资源竞争估计，必须在 agent i 自身的合法输入内完成所有关系行的构造；若选择实际消息交换，则应明确作为通信方法研究，并使用对应比较协议。

## 7. 文献近邻与真实创新空间

以下区分“已有基本思想”和“整个实现相同”。尚未发现完整实现逐项相同的工作，不等于已经证明新颖性；查到多个近邻，也不意味着现有结果没有研究价值。

| 近邻 | 已覆盖的思想 | 对我们主张的约束 |
|---|---|---|
| [UPDeT，2021](https://arxiv.org/abs/2101.08001) | Transformer 策略、可变实体与动作配置、跨任务迁移 | 实体 attention 加价值分解，不能独立作新贡献 |
| [TransfQMix，AAMAS 2023](https://www.ifaamas.org/Proceedings/aamas2023/pdfs/p1679.pdf) | Transformer agent 与 mixer、循环历史、团队规模迁移 | “Transformer 处理信息后做 QMIX”已经有直接近邻 |
| [HGAP，ICML 2024](https://proceedings.mlr.press/v235/lin24m.html) | 实体图注意力、置换性质、实体交互与迁移 | 单轮实体关系更新的基本组织新颖性有限 |
| [SPECTra，2025 作者版](https://arxiv.org/abs/2503.11726) | 可扩展且满足置换性质的 agent 与 mixing 网络，并关注计算成本 | 可变规模、读取和效率都需要具体差异与证据 |
| [Universal Transformers，ICLR 2019](https://arxiv.org/abs/1807.03819) | 沿计算深度的循环 self-attention 与可变计算 | 共享块、多轮处理、动态停止不是新的基础操作 |
| [ALMA，NeurIPS 2022](https://arxiv.org/abs/2205.14205) | 高层子任务分配与低层执行，结构化组合泛化 | 任务层级与分配本身不是空白；必须说明信息和任务条件 |
| [A Structured Prediction Approach for Generalization in Cooperative MARL，NeurIPS 2019](https://arxiv.org/abs/1910.08809) | 学习关系打分，用中央优化做 agent–task 分配，小规模训练后大规模使用 | 资源竞争与跨规模分配已有，不能只换成 attention 宣布首创 |
| [ToM2C，ICLR 2022](https://arxiv.org/abs/2111.09189) | 从局部观察推断意图、选择通信、协调目标，考察规模泛化 | “意图预测促进协作”需要比这一概念更具体 |
| [Intention-Aware Communication，KDD 2023](https://arxiv.org/abs/2307.03119) | 同一步内交流暂定动作、反复修正，并给出学习机制 | “反馈上一轮意图再算一轮”也不能独立建立创新 |

这些原始论文支持上表中的近邻事实；对本项目新颖性强弱的判断是据此作出的研究评估，不是论文原作者对本方法的判断。更广的关系循环、集合处理与任务条件近邻见[既有文献讨论](跨规模多智能体强化学习_文献调研与二区投稿改进方案.md)。

### 7.1 Single 与 TransfQMix 有什么差别

Single 不等于 TransfQMix。当前本地实现中，Single 保留 REFIL 局部分支和残差融合，先更新实体再用自身及历史条件化 query 读取，随后进入 GRU；TransfQMix 把历史 token 与实体一起送进 Transformer，并有自己的 Transformer mixer。训练宿主和辅助目标也不同，见 [ReGIR 编码器](../Open-SCORE/open_score/models/entity_encoder.py) 与 [TransfQMix 实现](../Open-SCORE/open_score/algos/transfqmix/__init__.py)。

这些是可辨认的计算差别，不是独立成立的贡献。若主要收益来自“历史只参与读取，而不污染实体工作区”这一安排，就要直接比较不同历史放置位置；若来自交互后再读取，就要控制读取不变，比较交互前后。整包 TransfQMix 的较差 ID 和 OOD 不能替代这种证据。

### 7.2 竞争力的真实判断

若论文只是“在 REFIL 上添加一个带数量输入的 Transformer 循环模块，并在 HAD 上更好”，目前面对上述近邻，新颖性风险较高；循环、数量与层级证据又不足，较难形成强方法论文。

如果能得到一个跨任务可复现的明确发现——例如历史条件读取比无条件聚合更能保持跨规模决策质量，且额外深度的效果被训练方式系统性控制——可以形成有价值的实证与机制论文。它仍需要公平近邻、成本、完整负结果和独立确认，不能只靠更换术语。

如果希望提高方法贡献的上限，应提出一个被任务失败机制要求的计算状态或更新规则，并证明该规则改善决策的条件。新意不要求部件从未出现，但必须超出“又一种 attention 组合”，并正面回应结构分配、意图通信等最近邻。

## 8. 论文现在应该怎样主张

### 8.1 主张分级

| 候选主张 | 当前判断 | 推荐表述或处理 |
|---|---|---|
| 当前方法在 HAD 的固定协议下优于 REFIL 与匹配版本 | 有明确支持 | 限定任务、预算、训练种子和四个评估轴 |
| 一轮关系处理已保留整体方法大部分收益 | 有支持 | 作为结果，不等同于证明哪一个保留模块必要 |
| 读取安排影响已训练策略和重训版本表现 | 有支持 | 明确区分依赖性干预与重新训练对照 |
| 多轮循环稳定优于单轮 | 不支持 | 删除中心贡献中的这一断言 |
| 每轮形成更高级语义层级 | 不支持 | 降为原始假设，展示检验及局限 |
| count 帮助 K 泛化 | 当前证据相反 | 不作为贡献，讨论可能的尺度依赖 |
| 随机深度改善优化稳定性 | 有线索、未确认 | 保留为竞争解释，不能称普遍保证 |
| 不共享深层更新更好 | 只有 Untied4 seed 2 | 等完整多种子，区分容量与优化 |
| 动态 K/V 对关系推理必要 | 待 KV0 | 不能预写结论 |
| 无通信局部部分观测下恢复协调意图 | HAD 不足以支撑 | 按实际信息边界重写，等待其他环境证据 |
| 方法高效、可扩展且部署成本低 | 缺 M4 | 可说支持可变输入，不能说已证实效率 |
| 方法跨环境普遍有效 | 缺 SMACv2 | 暂不写 |

### 8.2 当前可直接使用的论文叙述

> 本文研究小规模训练策略在实体数量与目标数量变化时的泛化表现，并考察实体关系加工、历史条件读取与计算深度的作用。我们在统一训练与终评协议下发现，当前实体交互与个体读取的组合相对 REFIL 及参数匹配对照降低了 HAD 任务损伤；其单轮版本保留了大部分性能改善。进一步的重训消融、执行深度干预与表征探针显示，重复关系更新尚未产生一致的额外收益，逐轮语义层级也未得到现有证据支持。这些结果表明，跨规模性能与更深计算不能直接等同，额外计算的训练方式及其与决策读取的耦合需要单独检验。

这段可以作为当前实验发现的概括，**不是已经足够的新方法贡献声明**。若投稿定位为方法论文，还应补上一个由对照明确识别的结构价值或新的机制；若定位为实证研究，就应把研究问题、统一协议、跨环境复现和边界发现放在中心。

### 8.3 应避免的叙事方式

不要把 Single 说成失败消融后从正文移除，也不要只展示 Full 获胜的种子。不要用后轮 attention 图更复杂来证明高阶关系，或把可解码标签直接叫作层级。不要从不完整 Untied4 中挑最佳结果，替换原 Full 后仍沿用原始确认协议的口吻。

“这个模块非加不可”也不是合理的证明目标。论文通常能够论证的是：在明确的信息、预算和任务条件下，它相对有竞争力的替代带来稳定、可解释的增量价值。对所有可能替代的绝对必要性，现有实验无法证明，也没有必要声称。

## 9. 两条可执行的研究路线

### 9.1 路线 A：优先完成现有结构的科学解释

**问题：收益主要来自实体间交互与历史读取的分工，还是来自深度及其训练方式？**

这条路线复用现有结果最多，近期风险较低。建议将 Single 保留为结构研究的强参照，而不是立即宣布它为最终版本；根据完整结果再确定用于最终确认的候选。

只围绕拟提出的中心主张增加最直接的同宿主控制：

| 拟主张 | 必要控制 | 必须保持或披露的条件 |
|---|---|---|
| 实体交互后读取有价值 | 读取初始实体 vs 读取交互后实体 | query、GRU、mixer、目标相同；额外计算差别公开 |
| 历史条件选择有价值 | 自身 query vs 自身＋历史 query | 保留相同实体更新和后续 GRU，避免变成是否有时间记忆的混合消融 |
| 历史应进入读取而非实体加工 | 同宿主历史 token 参与更新 vs 历史只参与读取 | 不能仅对比整包 TransfQMix；参数、attention 次数与时间分别披露 |
| 深度训练方式影响稳定性 | 现有 Full、Fixed4、Untied4、Single | 分开 ID 拟合、OOD 变化、逐种子失败与成本 |

不建议默认全部展开训练。先选最有可能进入论文贡献的一项，写清成功与失败两种结果分别怎样改变主张；如果这个对照不能改变结论，就不值得优先占用预算。

此路线有竞争力所需的最低闭环是：一个可辨认的计算差别、一个同宿主受控结论、另一个环境或真正独立关系分布上的复现、以及成本与失败边界。仅增加更多整包算法不足以代替这些环节。

### 9.2 路线 B：有条件地开发资源竞争修正

**问题：当多个可拦截威胁竞争同一批防守资源时，显式表示这种竞争，是否比直接增加实体 attention 深度更能改善决策？**

这是提高方法贡献上限的候选方向，目前属于提案。它不能从现有距离探针直接推出，也不应立刻启动一整套新训练。首先需要在固定 N/K 下确认：候选防守集合重叠是否伴随重复投入、可避免遗漏与更高损伤，且这些现象不能只由总体密度或 ID 训练失败解释。

HAD 的真实动力学对设计有约束：

- 红方动作影响加速度与后续运动，自动开火并自毁；当前步已由位置决定的碰撞或开火，不能被本步偏好修正追溯改变。
- 一次爆炸可能影响多个蓝方；多个红方同时投入也未必都是浪费，不能把每个威胁需求硬设为 1 后称为精确覆盖。
- 蓝方集中攻击一个随机目标，目标数增加不等同于并行任务数增加；最近目标只是公开几何关系，不是蓝方真实指派。
- 已有 overkill 事件计数是代理量，不能自动解释为在相同信息条件下本可避免的损失。

相关实现见 [世界步进](../../HADE/had_env/core/env/world.py)、[攻击逻辑](../../HADE/had_env/core/agents/attack.py) 和 [HAD 指标包装](../Open-SCORE/open_score/envs/had_wrapper.py)。

#### 一个足够小、可被否定的原型

保留 Single 的编码宿主、GRU、Q、mixer、奖励和原训练目标。仅增加一个显式关系分支，在 agent i 自身合法观察与历史内，计算可见红方 j 对可见蓝方 b 的虚拟投入分数：

$$
S^i_{jb}=f_\theta(x^i_j,x^i_b,\text{公开动力学关系},h_i).
$$

所有队友行都由 i 自己计算，不读取队友 hidden 或其他 observer 的预测。对不可见、死亡或不合法机会加掩码，并加入“暂不承诺”列：

$$
P^{i,0}_{jb}=\operatorname{softmax}_{b\cup\{\varnothing\}}S^i_{jb}.
$$

这里 P 的含义只是归一化的虚拟优先投入份额，不是队友真实意图概率，也不是命中率。先用其他防守者的虚拟投入定义拥挤度：

$$
L^{i,r}_{-j,b}=\sum_{\ell\ne j}P^{i,r}_{\ell b}.
$$

最小版本只做一次修正，对真实机会列使用：

$$
P^{i,1}_{jb}\propto
\exp\left(S^i_{jb}-\lambda L^{i,0}_{-j,b}\right),
\qquad \lambda\ge 0,
$$

“暂不承诺”列保持自己的基准分数，并与真实机会列一起归一化。新增分支聚合自己这一行的投入与对应威胁上下文，经投影后作为残差输入接回原个体读取。无修正版读取 P⁰，一次修正版读取 P¹，两者使用相同的聚合、投影和下游路径，避免关闭修正时把整个新增表征也删除。先不增加新的语义监督、动态停止或多层级模块。

这个公式只是最小拥挤修正原型，**不具备最优分配、收敛、准确覆盖或全体一致性保证**，也不应当作新颖性的充分依据。其意义在于有清楚的状态、更新对象和反证：如果显式关系已足够而修正无用，就停止反馈主张；如果拥挤度下降但损伤不下降，就不能把代理量变化当任务贡献。

初始关系打分约为 O(mbd)，每次投入汇总与修正约为 O(mb)，其中 m、b 为该观察者可见的红、蓝实体数。该描述不包含公共编码器和所有 observer 的总开销；仍需实际全队时延才能评价是否高效。

#### 若要进一步主张可解释覆盖，先定义监督语义

可以考虑明确事件，例如“未来固定 H 个物理步内，某蓝机是否在损伤目标前被拦截”。但它是当前行为策略下的结局标签，不是未执行决策的反事实成功率。必须区分截断、自毁、碰撞和红方拦截；一次爆炸影响多机时，也不能硬压成单分类标签。

若使用未来事件或中央状态作为训练标签，应披露额外监督，并让“相同预测头、同样监督、但不反馈”的对照获得相同信息。否则，结果可能来自辅助监督而非反馈结构。未经校准的 latent 分数应继续称为虚拟投入，不要为叙事好看改称真实覆盖概率。

#### 信息与对称性边界

共享关系打分、行归一化和列求和可以保持实体重排等变，但需要在实际实现中验证掩码和动作映射。不要靠固定 agent ID 的优先级打破冲突后，仍称算法只依赖集合结构。

完全相同的观察与内部状态会产生相同的确定性输出；无通信内部推演不会自动让不同 agent 达成一致。若最终必须借助消息或中央求解才能有效，应改变论文的信息设定，并与 ToM2C、结构预测等对应近邻公平比较。

### 9.3 两条路线如何选择

**近期选 A；B 只保留一个经过现象验证的最小候选。** A 的收益是尽快判断已有工作能否形成明确发现，B 的收益是可能建立更具体的方法机制，两者都不保证投稿结果。

如果 Untied4 和 KV0 表明普通浅层或普通堆叠已足够，最合理的选择是接受这一结果。没有必要为了保住“循环”标签继续加复杂模块。若竞争失败诊断明确指出缺失的结构，再让新方法围绕该结构展开，而非围绕轮数展开。

## 10. 后续实验如何安排才值得投入

下表是研究优先级建议，不是本次已启动的新实验。已登记任务继续按原协议完成；本文不改变其预算和队列。

| 优先级 | 要回答的问题 | 最小证据 | 决策用途 |
|---|---|---|---|
| P0：现有闭环 | 共享、深度和动态 K/V 哪些有一致收益 | 完整 Untied4、KV0；与 Single/Full/Fixed4 逐种子、分轴比较 | 确定当前中心主张，淘汰无支持的机制解释 |
| P0：实际成本 | 额外计算是否值得 | 已登记 M4，参数与全队决策时延 | 性能—成本选择，不能由参数量代替 |
| P0：外部有效性 | HAD 结论能否迁移 | 已登记 SMACv2 的完整结果与信息边界 | 确定跨环境主张范围 |
| P1：直接结构归因 | 当前优势来自哪个具体计算差别 | 路线 A 中选一个最贴合主张的同宿主对照 | 建立可辨认的贡献，避免模块列表 |
| P1：失败现象 | 是否真的存在资源竞争失效 | 固定 N/K、公开几何与动力学定义的场景分层及行为结果 | 决定是否值得实现路线 B |
| P2：最小新方法 | 显式关系、一次修正各有何作用 | 原 Single、同新分支无修正、同新分支一次修正 | 区分新增表征与反馈价值 |
| P2：替代计算 | 修正是否优于普通增加容量或深度 | 一个参数相近控制及必要的计算对照 | 排除仅多算、多参数的主要解释 |
| P3：独立确认 | 开发得到的结论是否可重复 | 冻结设计后新种子与未用于设计的场景/关系组合 | 支撑最终论文，而非重复挑选开发结果 |

### 10.1 机制实验要由相关性展示改成判别实验

建议未来机制章节围绕三个层次组织：

1. **表示与计算。** 在公共状态和各自历史重建下比较读取前后、反馈前后，保留随机初始化与标签置乱。不要直接给轮次贴语义名。
2. **动作与行为。** 在预定义几何条件下，记录修正是否改变动作，是否降低真实重复投入或遗漏。只看内部 attention、负载或 probe 分数不足以建立作用。
3. **任务结果。** 在相同场景初始条件和外生随机流协议下，比较完整策略造成的 D；保留低竞争场景、难场景和负结果。

冻结关闭、置零或打乱反馈是依赖性干预，可能造成分布偏移；必须与重新训练的无反馈版本区分。真正解释“反馈有价值”的核心是：同样的额外关系分支与训练信号下，允许修正比不允许修正稳定改善决策。

场景分层不能按 Single 输得最惨来选样本。可按预先定义的候选集合重叠程度、可达时间窗口和威胁紧迫性分层，并在固定 N/K 内检查。已有状态库来自 Full/REFIL，不能据它直接声称已观察到 Single 的行为失败；涉及 Single 实际行为时，需要其已有行为记录或未来独立登记的比较。

如必须增加新对手才能出现资源竞争，应作为所有方法共享的新任务协议，而不是改写旧实验使循环获胜。原 reactive + rush 结果继续保留。

### 10.2 预算与选择规则应预先固定

优先把后续训练预算花在少量能区分机制的比较和更多独立训练重复上，而不是不断增加缺少因果针对性的基线。具体新增种子数需要依据可用预算和希望检测的效应确定；不应仅因前三个种子方向不理想就不断补跑到显著。

新增候选只允许使用训练范围内的验证进行选择。现在已经反复查看过的 N/K OOD，可以用于开发诊断，但不能继续作为完全未参与设计的最终证据。仅更换评估回合种子能检查随机场景复现，不能独立消除对同一 N/K 结构的适配；应同时考虑未用于选择的关系组合或另一个环境。

正式判据建议在训练前写清：

- 主要指标与主要外推轴，以及具有实际意义的最小改善量。
- ID 可接受退化范围、部署时间预算和参数上限；阈值依据任务需求与已有噪声制定。
- 全部训练种子、失败处理和最终 checkpoint 规则。
- 一个主比较及必要次比较，避免通过大量配置挑选获胜切面。

相同环境步数衡量样本预算，相同时间或算力衡量计算预算，两者应分开报告；参数匹配也不等于时延匹配。无需为追求形式上的“完全公平”同时打开庞大实验矩阵，但必须说清每组比较控制了什么。

### 10.3 已有评估执行变化如何处理

当前终评历史上涉及 CPU/GPU 并行以及按回合设置策略随机种子的实现变化。固定场景 seed 并不自动保证 CPU 与 CUDA 的随机流或数值逐位一致。此次核查中，Fixed4 seed 1/2 各自的 96 次 shard 启动为 7 次 CUDA、89 次 CPU；这是启动计数，不是已经核验的逐回合设备分布。

应在来源记录中保留评估器版本、设备、策略随机流和权重身份，不能宣称所有阶段的后端完全相同。**目前没有证据表明 Fixed4 seed 1 的弱表现由混合后端造成**，其训练内验证本身也较差。

如最终中心结论依赖很小的性能差，未来可另行登记一个小规模匹配后端核查，评估其影响；不要悄悄重跑替换正式数据，也不要把尚未执行的核查写成已经通过。实现入口见 [评估协议](../Open-SCORE/open_score/eval/protocol.py)。

## 11. 什么结果会让我们继续，什么结果应该停止

| 观察 | 应采取的研究选择 |
|---|---|
| 多轮方法不能稳定优于 Single | 停止“额外轮次必要”主张；保留单轮作为强基线 |
| Untied4 的收益主要是救回 ID 训练失败 | 转向优化与容量解释，不称语义层级 |
| KV0 与 Full 接近 | 收窄动态记忆改写主张，不把固定 K/V 等同于取消循环 |
| 同结构无修正已达到新方法效果 | 停止反馈必要性主张；只有它也稳定优于原 Single，才保留显式关系贡献，否则一并收窄新增分支价值 |
| 一次修正已足够，继续循环无增益 | 采用简洁版本，不为方法名称保留多轮 |
| 内部拥挤度下降但真实 D 不改善 | 代理量未建立任务价值，不能作为核心成功 |
| 只有中央状态或通信版本有效 | 修改信息设定与近邻比较，停止无通信本地主张 |
| 原任务中没有对应的竞争失效 | 停止这条新机制，避免为维护动机不断改任务 |
| 新方法只在一个外推轴好 | 限定论文贡献到该轴，同时报告其他轴代价 |
| HAD 有效而 SMAC 不复现 | 讨论任务结构依赖，不能写普遍 MARL 泛化 |
| 成本明显上升且收益不稳定 | 优先保留较浅版本，不能仅凭最佳分数宣布胜出 |

这些停止条件可以避免最危险的循环：负结果出现 → 再加一个模块 → 又产生新的解释需求 → 实验规模继续扩大。每项新增计算都应对应一个已经定义的问题和一个可能否定它的比较。

## 12. 最终论文的组织与当前下一步

### 12.1 引言与贡献如何展开

建议引言按以下逻辑写：

1. 小规模训练到大规模部署存在实体数量、目标数量与关系组合变化。
2. 可变长实体网络、Transformer、图注意力和结构分配已有充分研究；“能接收更多实体”不等于“能保持决策质量”。
3. 当前结果表明浅层关系结构很强，但额外深度没有一致收益，且训练与读取方式会改变结果。
4. 因此研究一个具体问题：怎样组织关系信息与历史读取，或怎样对已识别的资源竞争错误作有益修正。

现版本可用的研究题目是 **《实体关系加工与计算深度如何影响跨规模多智能体决策》**。只有新机制获得完整支持后，才考虑以 **《面向跨规模协作的资源竞争建模与决策修正》** 为方法主线。不要在题目中先写“层级推理”“自适应收敛”或“通用泛化”，再让实验追赶措辞。

路线 B 若成功，贡献应围绕“定义了什么可计算的协调状态、该状态如何改变决策、在哪些条件下比近邻和替代有效”来写。不能把 attention、计数、门控、共享权重逐项列为多个贡献。

### 12.2 实验正文与补充实验如何展示

正文保持一条连续证据链：**任务与协议 → 主结果 → 最关键的同宿主比较 → 一个直接机制问题 → 成本与适用边界**。附录保留全部配置、逐种子、学习曲线、原 M1–M3 的完整正负结果、来源与评估实现。

优先展示四类图：

- 各外推轴的主结果及逐种子点，训练支持范围标清。
- 核心候选相对 Single 的逐种子差值，避免只看均值产生错觉。
- 固定 N/K、预定义竞争条件下的性能与行为变化，用来解释机制是否对准问题。
- 性能与全队决策时延的比较；在 M4 完成前不填写猜测值。

Fixed4 的坏种子、No-count 的正面结果、Uniform 的失败和探针的随机网络控制都应保留。版面美化不能替代证据，主图也不应通过坐标截断、挑配置或隐藏种子让结论显得更强。

### 12.3 现在最要紧的顺序

**第一，接受已经清楚的结论。** 整体结构有收益，原来的循环层级叙事尚不成立；Fixed4 已不能被当作解决方案。无需等待所有实验结束才能作这一调整。

**第二，完成已登记的判别证据。** Untied4 与 KV0 决定共享、容量和动态关系更新的解释；M4 决定额外计算是否值得；SMACv2 决定跨环境边界。等待期间可以完成论证与场景定义，不需要盲目新增训练。

**第三，为现版本只选一个真正影响中心主张的结构对照。** 优先考虑实体交互与历史条件读取的分工。如果这一步仍无法产生区别于近邻的明确发现，应承认现版本的方法贡献有限。

**第四，只有在现象成立后才开发一个资源竞争修正原型。** 先验证同结构无修正与一次修正；有明确收益后，再讨论更多轮、监督或跨环境推广。

目前最有价值的资产，是已经形成的统一协议、强单轮参照、完整消融和机制负结果。它们允许我们有依据地缩小研究问题。接下来的竞争力来自一个被直接证据支持的计算差别，而不是把所有原始设计都解释成不可或缺。
