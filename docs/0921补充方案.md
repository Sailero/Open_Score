## 一、要验证的故事，以及与 TransfQMix 的实际区别

### 1.1 把原始直觉拆成五个可被否定的假设

核心研究问题保持不变：

> 小团队训练得到的策略，能否通过复用实体关系处理规则，在更大的实体集合中形成有效的个体决策上下文？

当前机制可以准确称为“共享循环实体更新 + 个体多轮读取”。每轮实体行数和维度都不变，只有读出阶段生成固定宽度上下文。因此，“逐轮压缩全局信息”应先改写为**逐轮重组关系信息，使它更容易被个体决策读取**。不同层关注不同语义、抑制无关信息或形成信息压缩，都需要额外证据，不能从架构名称推出。

| 假设                       | 要回答的具体问题                                        | 关键证据                                       | 什么结果会削弱它                       |
| -------------------------- | ------------------------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| H1：规模外推               | 小规模训练、冻结后在未见人数上是否仍有效？              | HAD 与 SMACv2 的逐规模结果                     | 大规模不优于强近邻，或收益仅存在训练内 |
| H2：循环有用               | 超过单轮的训练/执行，究竟哪部分有价值？                 | 单轮重训、完整模型单轮执行、固定四轮、完整四轮 | 单轮重训即可达到相同性能               |
| H3：共享更新规则有用       | 收益是否来自复用同一处理规则，而非普通多层网络？        | 同一宿主下共享四轮 vs 不共享四层               | 不共享网络同样好或更好                 |
| H4：后轮提供可用的新表征   | H1 之后的轮次是否改变关系可读性，是否需要读取这些轮次？ | 关系探针 + 冻结读出干预 + last 重训            | 仅 H0→H1 改善，后续表征/任务表现无贡献 |
| H5：更新整个实体工作区有用 | 每轮更新后的实体作为后续 K/V，是否优于反复读初始输入？  | 完整模型 vs 固定初始 K/V                       | 两者无稳定差异                         |

H4 中“新表征”不表示出现输入中不存在的新信息，而是关系被重新表达。论文不需要五项全部显著成立，但**最终保留在贡献里的机制必须有对应证据**。

**最新结果已经改变机制判断，不能沿用旧版“消融尚无结果”的结论。** 用户最新报告给出三个终评训练种子的阶段性汇总：

| 变体            | 等规模轴平均 D | 目标轴平均 D | 目前可以说什么                                       |
| --------------- | -------------: | -----------: | ---------------------------------------------------- |
| Full            |          0.750 |        1.330 | 比 REFIL 的 1.836/2.858 好，但这只是整套结构的效果   |
| 单轮重训 Single |      **0.664** |        1.524 | 等规模比 Full 低约 11.5%；目标轴比 Full 高约 14.6%   |
| 去 REFIL 路径   |          0.749 |        1.324 | 与 Full 很接近；不支持原路径是主要增益来源           |
| 去数量编码      |          0.791 |    **0.931** | 等规模略差，目标轴明显更好；必须检查完整格与种子差异 |
| 仅读最后一轮    |          0.961 |        1.699 | 两轴均变差；值得继续检验中间轮读取                   |

这里的“等规模轴”含 N=5 的插值与 N=10 的训练范围内人数，并非纯外推平均；上面的比例仅是给定汇总的描述，不能当显著性结论。按用户公布逐格值，Full 在真正 N=15/20/25/30/40/50 上的平均 D 约 0.862，REFIL 约 2.194；其他消融缺同口径逐格值，暂不能计算它们的纯外推均值。

因此，当前最有依据的候选解释是：**新增实体关系加工与个体读取带来大部分收益；多轮在目标结构更复杂时可能有补充价值，但不是现有证据下的普遍主因。** “仅仅加 Transformer”也过于粗糙，因为编码、读取、路径和训练均改变，仍须对照 TransfQMix、matched 及同宿主结构变体。

最新深度图比较的是同一已训 Full 的不同执行轮数，R1 重训比较的是另一种训练方案。两者可以同时出现“Full 多算有用，但 Single 从头训练更好”，没有逻辑矛盾。图中 R3/R4 接近不证明收敛，也不否定循环在其他配置有效。深度扫描的 checkpoint、种子数、每格局数未与新终评表核对，因此不把旧单种子 6.37% 改善与新三种子消融混合。

有四项数据口径现在就要修正：① 最新报告正文仍写“消融未对齐”，表却写“计入”；以权重哈希、实际终评清单生成报告，删除过期说明。② nocount/last 有 3563、6397、6148 局的部分终评，最终应补齐 24×300，不能以不同配置覆盖计算可比宏平均。③ 最新终评已明确使用 final.pt，本版据此采用最终预算权重，旧版 best 终评单独归档，不能混用。④ REFIL/QMIX seed0 的 920269/940349 步不足标称 1M，需核实日志字段、断点或提前结束原因；若实际少训则补齐或如实报告，不能凭 complete 标签当作预算一致。

### 1.2 TransfQMix 已有关系建模；区别必须落在具体计算上

TransfQMix 已研究实体图结构、Transformer agent/mixer 及团队迁移。不能说它只是拼接实体、没有关系建模、没有历史记忆或不能处理可变攻击动作。[原论文](https://arxiv.org/abs/2301.05334)

本次核查作者公开 PyMARL 实现后，得到以下区别。正式复现必须固定代码 commit；表中“初始 K/V”等描述针对核查到的实现，不推广到所有名为 TransfQMix 的后续实现。

| 维度          | TransfQMix 作者公开实现                                      | 当前 RER                                             |
| ------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| 决策内处理    | 默认多层 Transformer，各层独立参数                           | 同一块沿计算深度重复使用                             |
| 跨层 K/V 来源 | block 返回更新后的 query，同时继续传递初始 key 输入；各层有自己的投影 | 后续轮的 K/V 来自上一轮更新后的实体表征              |
| 时间记忆      | 每个智能体的 hidden token 加入输入，最终 hidden token 跨时刻复用 | GRU 保存时间记忆；每个物理时刻重建循环工作区         |
| 个体读出      | 由最终层 token 形成基本动作与实体动作值                      | 以自身初始表示和历史形成 query，独立读取每轮，再融合 |
| 训练深度      | 作者配置为固定层数                                           | 采集与 replay 使用随机 1–4 轮；主终评固定四轮        |
| 联合价值      | Transformer mixer，含 agent hidden 与额外 hyper tokens       | 继承当前 REFIL 价值学习与 imagined 分支              |
| 可变实体动作  | SMAC agent 已有基本动作头和共享实体动作头                    | HAD 九动作头需要另做 SMAC 适配                       |

源码核查固定到作者仓库 commit `2ef0a0726f1f186097b4b560509ceb5a801fdafe`：[Transformer block](https://github.com/mttga/pymarl_transformers/blob/2ef0a0726f1f186097b4b560509ceb5a801fdafe/src/modules/layer/transformer.py)、[SMAC agent](https://github.com/mttga/pymarl_transformers/blob/2ef0a0726f1f186097b4b560509ceb5a801fdafe/src/modules/agents/n_transf_agent_smac.py)、[mixer](https://github.com/mttga/pymarl_transformers/blob/2ef0a0726f1f186097b4b560509ceb5a801fdafe/src/modules/mixers/n_transf_mixer.py)。固定的是 K/V 的输入来源，各层投影不同，不意味着所有层投影后的 K/V 数值相同。

所以，相比 TransfQMix，值得研究的是：**更新后的关系表征是否需要再进入下一轮交互、同一更新规则是否值得复用，以及个体是否需要访问中间轮次。** 仅在它上面赢分，无法把差距归因给其中任意一点，因为两套方法的 mixer、记忆和训练目标也不同。

本方案同时保留两种比较：

- **完整算法比较：**在 HAD、SMACv2 都加入忠实适配的 TransfQMix，回答整套方法的实际竞争力。
- **同一宿主的结构对照：**在 RER/REFIL 框架内只改共享方式、K/V 来源或深度调度，回答具体机制。不得把这些变体直接命名为 TransfQMix。

作者实现的 Transformer 中每个 head 的维度设置也不能直接按常见 d/heads 假定；“都设 embedding=64”不代表参数或计算相等。用实际可训练参数与全队时延核算公平性。HAD 适配保留 TransfQMix 的 agent、Transformer mixer、时间 hidden token 和原有学习设计，仅替换观测实体接口与九动作输出。

## 二、HAD：补哪些训练、怎样辨别循环作用、如何检查原始直觉

### 2.1 训练矩阵：保留旧实验，补四个核心对照

把 Single 提升为正式主对照，在 HAD 与 SMAC 都保留，不仅藏在消融里。尤其先补齐 REFIL-matched：它已有训练，成本远低于新增机制训练，却直接关系到“是否主要是容量增加”。目前用户未贴它的数值，不假定其优劣。

所有正式 HAD 运行使用原定五个训练种子、1M 物理步、原训练分布与最新统一的 final 终评规则。新增变体共享同一数据口径、mask、优化器、奖励和预算；完整算法基线可保留其合理的作者超参，并记录仅基于训练内验证的适配过程。

先核对已有终评的权重身份：按最新报告，主结果使用完成预算的 final.pt。所有新增 HAD 方法也采用这个规则，禁止根据外推结果改成 best。训练内 best 可以作为预先注明的附加敏感性结果，整张表统一口径。只有权重、配置、预算或评估协议不符时才补跑，不能因分数差剔除；报告每格有效训练种子数/5。

| 编号 | 方法/建议代码键                             | 训练与主执行设置                                             | 状态/用途                    |
| ---- | ------------------------------------------- | ------------------------------------------------------------ | ---------------------------- |
| A    | Single / regir_r1                           | 训练 R=1，执行 R=1；其余新增分支仍保留                       | 已在跑；单轮结构基准         |
| B    | Full / regir                                | 训练 R∼U{1,2,3,4}，执行 R=1                                  | 复用完整模型权重，只追加评估 |
| C    | Full / regir                                | 与 B 同权重，主执行 R=4                                      | 现有完整方法                 |
| D    | Fixed4 / regir_fixed4                       | 采集、replay、online/target 均固定 R=4；共享块与多轮读取保留 | **新增五种子**               |
| E    | Untied4 / regir_untied4                     | 与 D 一致，仅将同一块改为四个独立参数块；每层 K/V 仍来自前层 | **新增五种子**               |
| F    | KV0 / regir_kv0                             | 与 C 相同的随机深度训练；每轮 Q/残差更新，K/V 始终来自当前步 H0 | **新增五种子**               |

关键比较按下面解释，避免含糊地把所有差异叫“循环收益”：

| 比较         | 能识别的效果                         | 必须保留的限制                                   |
| ------------ | ------------------------------------ | ------------------------------------------------ |
| A vs B       | 多深度训练方案是否改善最终的单轮策略 | 包含训练梯度、采集轨迹和调度的共同变化           |
| B vs C       | 同一模型部署增加深度的净收益         | 同时增加计算与可融合的轮次；不是纯计算的独立效应 |
| A vs D       | 固定单轮与固定四轮的整体差异         | 包含深度与多轮读取；结合 last 分析               |
| C vs D       | 随机深度与固定深度的训练方案差异     | 同环境步下计算量不同，必须报告训练墙钟           |
| D vs E       | 固定四层下参数共享的效果             | 同宽度、同层数，参数量不相等；不能称等参数比较   |
| C vs F       | 更新后的 K/V 再参与交互的效果        | 只检验这一差别，F 不是完整 TransfQMix            |
| C vs last    | 多轮读出相对仅读最终轮的整体收益     | 不证明学习权重优于均匀权重                       |
| C vs matched | 一个参数容量匹配替代结构能否解释收益 | 不能排除所有同规模网络                           |

D、E 使用相同中间读取器、深度融合和外部 REFIL 路径；E 仅循环块不共享，不能顺手改成另一套 decoder。D、E 在每个种子下使用同一个随机初始化块：D 复用它，E 将其初始值复制成四组独立参数，再分别训练；外部模块初值也对齐。确认是四个独立参数对象，不能仍引用同一对象。这使初始前向一致，比较参数绑定的训练影响；不使用已训 Full 权重预训练某一臂。

F 的关键实现是：K/V 的**来源固定为 H0，不是对 H0 做 detach**；梯度仍能回到编码器。Q、FFN、残差继续使用当前轮状态，读出仍读各轮 Hᵣ。R=1 时 F 与 Full 的前向形式应一致，这是很有用的实现核查。

参数共享本身是约束，不是额外表达能力：固定 R 时，不共享网络可以通过令各层参数相等复现共享网络。因此若 D 优于 E，更合适的解释是有限数据下的优化/归纳偏置收益，而不是“循环网络表达能力必然比堆叠网络更强”。现有 matched 继续用于控制容量；暂不再新增一个任意缩窄的等参数 Untied 网络。

**第二批仅在要提出对应主张时做：**

| 可追加项                 | 触发条件                                             | 实施方式                                                     |
| ------------------------ | ---------------------------------------------------- | ------------------------------------------------------------ |
| no-imagined-loss，五种子 | 要单独判断辅助目标的作用，或声称脱离该辅助目标仍有效 | 只去辅助损失，保留原路径及主损失系数；不能把主项从 0.5 偷换成 1 |
| Uniform-read，五种子     | 冻结均匀读取明显下降，并准备将“学习深度权重”列为贡献 | 从头训练均匀融合，分清模型依赖与训练后必要性                 |
| 配对初始场景             | 要检验不同队友覆盖条件下的相对表现                   | 见 2.3；需要环境支持合法自定义初始状态                       |

norefil 同时删除原路径和辅助训练，不能替代 no-imagined-loss。单个 no-imagined-loss 也不能证明“协同”；若真要声称相互增强，需循环开/关×辅助目标开/关的 2×2 对照。本轮不默认扩展这条贡献。若不作这些强主张，不需要为了填满实验矩阵全部训练。

### 2.2 冻结模型实验：区分多算几轮与读取哪些轮

**实验 M1：执行深度扫描。** 复用现有设计，在 N=10/30/50、K=2，五个 Full checkpoint 上评估 R=1–6，各 300 局。主结果一直保持 R=4，不根据大规模测试挑 R。R=4 复用主终评；旧的其他深度只有在 final 权重哈希、配置、随机流与局数均符合当前协议时复用，最多新增 22,500 局。

同时评估 A 的 R=1，形成 A/B/C 对照。为了对齐图表，A/B/C 的关键逐格结果必须来自同一配置集合；不要把六个 N-OOD 的平均和某个单独 N=50 值直接相减当因果增益。

**实验 M2：固定计算到第四轮，只改变送入策略的读出。** 采用同一批 Full 权重、同一套初始场景：

| 干预                           | 输入残差分支的上下文      | 回答什么                           |
| ------------------------------ | ------------------------- | ---------------------------------- |
| Learned                        | 原有加权多轮上下文        | 原策略                             |
| Read-1、Read-2、Read-3、Read-4 | 分别仅使用 u1、u2、u3、u4 | 各轮表征单独是否足以支持行为？     |
| Uniform                        | 四个 uᵣ 的算术平均        | 当前策略是否依赖学习到的深度权重？ |

固定配置为 10v10 K2、50v50 K2、30v30 K12；每配置五种子、每种子 300 局，仍只报告 D。单个配置内，各干预共享评估场景随机流。Read-4 是冻结模型的干预，不能与“从头训练的 last”混称。

Learned 从主终评复用。Read-1 在当前无深度位置编码、确定性推理的架构下应与 Full 执行 R=1 等价；先用短核查确认，成立则复用对应 M1/补评结果。Read-2/3/4 与 Uniform 最多新增 18,000 局；如果 Read-1 的联合外推格尚无结果，再加 1,500 局。读出实验不训练新 RL 模型。

这不是六个不同策略重新训练，而是当前模型的依赖性检查。干预引起性能下降，说明该已训模型依赖这一信息路径；不能单独推出任何模型都必须采用同样设计。反过来，Uniform 与 Learned 接近，就不要继续强调“自适应深度权重”是创新核心。

不把“打乱深度顺序”作为默认实验：当前融合是共享评分的集合聚合，没有深度位置编码，单纯同时重排各轮读出和对应权重不会改变结果，无法检验语义分工。

### 2.3 同状态关系探针：检查“不同轮次在处理什么”，但不把解码当因果

本轮增加一项小型监督诊断。它不是重新训练策略，只训练轻量线性读出器。目的为：**在同一场景、同一观察者和同一历史下，某种关系是否随轮数变得更容易读取？**

**状态集固定。** 采用 ID 的 10v10 K2/K3，以及 OOD 的 30v30 K2、50v50 K2、30v30 K12。每配置收集 100 条完整轨迹：一半来自预先固定的 Full seed0、一半来自 REFIL seed0 的 final；它们仅用于构建公共诊断状态集，表示分析仍逐一覆盖五个 Full checkpoint。每条轨迹均匀取四个有效决策时刻，再按固定随机规则选至多两名存活观察者和五名存活敌人。保留完整前缀以重建 GRU 历史；不把所有帧当独立样本。

初始场景使用独立且预登记的 scene_id；若同一初始化产生多个行为策略的轨迹，必须把它们及所有观察者 token 作为一个组划分，不能同场景跨集合。默认上述 100 条轨迹来自 100 个不同初始场景。ID 每配置按场景组分成 50 条 probe 训练、25 条验证、25 条 ID 测试；OOD 每配置前 50 条用于探索、另 50 条作为未查看的确认集。两部分随机流先登记，不能看完再挑“有层次”的片段。实际种子数值在运行登记表核对无重叠后填写，不能假定某个整数范围天然未被用过。

在五个 Full 策略 checkpoint 内，先用标准 R=4 重建该轨迹前缀的历史，再对选中时刻导出 H0–H4 和 u1–u4。比较不同轮次时固定同一个 h_prev；不能分别跑五种深度的不同轨迹后，把状态分布差异当表示变化。不同训练种子各自拟合 probe，不能混合不同 seed 的隐空间或直接迁移 probe 权重。

**预先固定三种可观察的几何关系。** 对观察者 i 和敌方实体 j：

| 标签               | 定义                                                         | 能解释什么/不能解释什么                                      |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 到目标的距离       | y₁=minₖ‖pⱼ−pₖ‖/L                                             | 是否容易读取敌人与目标的空间关系；不是其私有目标意图         |
| 到其他防守者的距离 | y₂=minₗ≠ᵢ‖pⱼ−pₗ‖/L，仅存活防守者                             | 是否容易读取该敌人附近的队友几何覆盖；不是已被可靠拦截的保证 |
| 目标分区人数不平衡 | 把实体按最近目标分区；对 j 所在分区 k，y₃=(Bₖ−Rₖ⁽⁻ⁱ⁾)/(Bₖ+Rₖ⁽⁻ⁱ⁾) | 是否容易读取组合数量关系；不是真实任务分配或最优负载         |

L 沿用环境既定坐标尺度，在所有规模保持不变。第二项没有其他存活防守者时，该样本对 y₂ 无定义，剔除并报告比例；不要伪填零。第三项的 Bₖ 包含 j，分母为正；目标距离并列时使用固定、与实体排列无关的几何规则，仍无法唯一时剔除边界样本。全部标签仅使用该观察者允许的实体信息，不使用蓝方私有 assignment；若可见集不完整，距离和分区统计只在该可见集定义，不能用中心状态补齐标签后再把不可知信息当作表示失败。没有可见目标时，目标相关标签无定义并记录剔除比例。

对每个 Hᵣ 中对应敌人的 token，拟合同容量的带截距 ridge regression。特征标准化只在 ID probe 训练集拟合；正则从预定小集合选择，用 ID 验证的跨轮平均表现确定共用强度，不按 OOD 选。每个关系、每个轮次用相同样本划分、容量和训练预算。

**诊断指标仅用标准测试 R²：**

$$
R^2=1-\frac{\sum_m(y_m-\widehat y_m)^2}
{\sum_m(y_m-\bar y_{\mathrm{test}})^2}.
$$

同一标签、同一测试配置下比较轮次；分母近零则标为不可估计，不强行画分数。允许负值。不同标签或规模的 R² 不能解读成相同单位的信息量，宏平均只作展示摘要，逐格结果在补充提供。

必要控制只保留三项：H0、同架构未训练网络、置乱训练标签的 probe。它们用于识别信息本来就在输入里、随机特征足够或读出器记忆数据等解释。使用轻量 probe 和控制任务的依据来自 [Hewitt 与 Liang](https://aclanthology.org/D19-1275/)，但这里的几何标签是本项目定义，不能说文献替我们验证过这些指标。

判读规则提前固定：

- H0→H1 提升，而 H1→H4 没有提升：支持新增一次关系加工，不支持后续循环逐步细化。
- 多种关系随深度一起提高：支持逐步提升可读性，不支持各轮分工不同。
- 不同关系在不同轮达到优势，且跨种子、确认集重复：可以谨慎称为轮次间的关系侧重差异。
- probe 提升但 M2/重训消融没有任务收益：说明信息可读取，尚不能说策略利用了它。
- M2 有收益、probe 无变化：循环可能改变了未被这三个标签覆盖的信息；如实报告，不能临时试几十个标签只保留显著的三个。

普通注意力图最多作为示例，不能代替这套证据。关于注意力权重与模型实际输出不必然一致的警示可参见 [Jain 与 Wallace](https://arxiv.org/abs/1902.10186)；它来自 NLP 实验，不是对本模型的直接证伪。

**可选：用配对初始场景检查覆盖条件变化下的表现。** 在 N=10、30、K=2 下，保持观察者、敌人、目标、总人数不变，仅把一名其他防守者从目标 A 附近移到目标 B 附近；生成合法、无碰撞、满足初始化约束的两种初始状态，GRU 均从零开始。对 Full、Single、TransfQMix 各跑五种子、每规模 100 对场景，使用匹配环境随机流，比较两种覆盖条件下的完整回合 D。总量为 3×5×2×100×2=6,000 局。

这个受控诊断仍会改变几何与实际难度，不能单凭 D 证明“减少重复防守”，也不构成某个 token 语义的因果证明。它能检验优势是否在重新分配防守压力时仍存在。若现有环境不能合法设定/恢复初始状态，此项标为“接口待支持”，不通过直接修改观测、再把不一致的轨迹当正常环境实验。当前主证据不依赖这一可选项。



## 三、SMACv2：从环境安装到混合规模训练的实施方案

### 3.1 选什么环境、训练什么、怎样测试

**选择官方 SMACv2 的 Protoss 生成任务，暂不再加 MPE。** 它提供原生单位类型与出生位置随机化，能直接构建人数变化；Protoss 没有治疗动作分支，适配比含医疗兵的组合简单。这里补充的是另一类合作控制任务的证据，不是靠增加环境数量弥补机制缺口。[SMACv2 官方仓库](https://github.com/oxwhirl/smacv2)

| 项目         | 固定方案                                                     |
| ------------ | ------------------------------------------------------------ |
| 任务规则     | 官方 Protoss：stalker/zealot/colossus，权重 0.45/0.45/0.10；原生站位生成、观测、奖励 |
| 训练分布     | 每回合独立均匀抽 N∈{4,6,8,10}，我方和敌方均 N；一套共享策略  |
| 正式方法     | Full、Single、REFIL、完整 TransfQMix；四种方法各五种子       |
| 初始训练预算 | 每运行 4M 联合环境决策步，共 20 个运行；不是每个 N 各 4M     |
| 训练内验证   | 每 100k 步，每个训练 N 各 32 局；画四规模等权平均胜率        |
| 主检查点     | 完成统一训练预算的 final，与最新 HAD 规则一致；不按 OOD 选模 |
| Full 深度    | 训练随机 1–4，主终评四轮；Single 训练和执行均一轮            |
| 等人数测试   | 5v5、10v10、12v12、15v15、20v20                              |
| 不对称测试   | 10v10、10v11、10v12、10v15                                   |
| 正式终评     | 每方法每种子每配置 300 局、贪心、冻结参数；正常更新历史 hidden |
| 主指标       | 原生 battle_won 胜率；平局与超时均不算获胜                   |

两条测试轴共八个不重复配置，10v10 复用，总计 **4×5×8×300=48,000 局**。新增 Single 的理由很具体：现在 HAD 单轮已经很强；若 SMAC 只跑 Full 与基线，即使赢了也不能增强循环机制的可信度。

5v5 是人数插值，10v10 是训练边界，12/15/20 才是人数外推。固定己方 10、增加敌方数量同时改变了集合大小和对抗难度，因此第三列叫**敌方数量/兵力比压力**，不能叫“SMAC 防护目标数外推”。SMAC 攻击对象与 HAD 被保护目标不是同一个变量。

这不是四个独立训练任务，也不是在大规模上微调。所有方法在相同混合小规模分布训练，在同一组冻结测试场景评估。官方生成器的参数支持这些人数，但 4/6/8/12/15 等是本项目的自定义划分，不全是官方命名 benchmark；必须先实际验收配置可运行。[人数包装器](https://raw.githubusercontent.com/oxwhirl/smacv2/main/smacv2/env/starcraft2/wrapper.py)、[队伍与站位生成源码](https://raw.githubusercontent.com/oxwhirl/smacv2/main/smacv2/env/starcraft2/distributions.py)

4M 是启动预算，不是保证学会的门槛。先在 1M 处检查训练内学习与吞吐，正式决定总预算时只看训练内证据；若尚未稳定，所有方法统一预留延长到 10M 的选项，**在查看正式 OOD 排名以前锁定**。若资源不够延长，就报告有限预算结果，不能把尚未学会的基线当作泛化失败。原生奖励的 return 可用于调试和附录，主胜率不能因为结果不理想临时换成更好看的指标。

### 3.2 安装与最小验收：先跑原生环境，再接你的学习器

下面是依据官方安装资料整理的执行命令，**不是本次已经安装成功的记录**。先开独立 Python 环境，避免 SMAC 的协议依赖影响正在运行的 HAD。Python 3.10 可作为工程起点；具体 PyTorch/CUDA 沿用服务器已验证组合，不在不知道服务器配置时给出保证兼容的安装命令。当前官方依赖包括 pysc2≥3.0.0、protobuf<3.21 等。[安装依赖](https://raw.githubusercontent.com/oxwhirl/smacv2/main/setup.py)

假设已激活该环境，系统有 git、curl、unzip；SC2 放个人目录即可。解压密码对应 Blizzard AI/ML 包的许可接受，应先阅读许可。[Blizzard 下载与许可](https://github.com/Blizzard/s2client-proto#downloads)、[SMACv2 官方链接的安装脚本](https://raw.githubusercontent.com/benellis3/mappo/main/install_sc2.sh)

最小随机策略验收流程：

1. 读取固定版本的官方 sc2_gen_protoss.yaml 的 env_args，逐实例 deepcopy。
2. 仅替换 capability_config.n_units/n_enemies、seed、game_version，构造 StarCraftCapabilityEnvWrapper。
3. reset，读取 get_env_info/get_obs/get_avail_actions，对每个真实 agent 随机选合法动作，走到回合结束，finally 中 close。
4. 验收全部训练/测试的十一种独立人数配置，至少核对 4v4→10 动作、10v10→16、20v20→26、10v15→21。
5. 此阶段只验收接口和稳定性，不用随机动作成绩筛选对自己有利的正式测试配置。

SMAC 的 step 返回 reward、terminated、info；reset 也不是 Gymnasium 的 reset(seed=...)，现有 runner 要明确适配。[原生环境接口](https://raw.githubusercontent.com/oxwhirl/smacv2/main/smacv2/env/starcraft2/starcraft2.py)

完整任务参数继承 [官方 Protoss YAML](https://raw.githubusercontent.com/oxwhirl/smacv2/main/smacv2/examples/configs/sc2_gen_protoss.yaml)，不要复制一个删漏奖励字段的简化片段代替它。保留 map_name=10gen_protoss、difficulty="7"、step_mul=8、地图 32×32、原生单位能力与观测。map 名中的 10 不等于必须固定十人；人数由 capability_config 指定。episode_limit=200 来自地图注册，不能猜测存在同名构造参数。[地图注册](https://raw.githubusercontent.com/oxwhirl/smacv2/main/smacv2/env/starcraft2/maps/smac_maps.py)

### 3.3 混规模环境池与代码适配契约

**不能只在 reset 前改一次 n_units。** 原生 wrapper 和环境在构造时保存人数、动作数、分布对象与数组形状，reset 不重建所有这些结构。最简单的可靠方案是“每个 worker 缓存四种固定人数环境 + 一个统一 padding 适配器”。官方 wrapper 会修改嵌套配置，必须 deepcopy，不能四实例共用同一个 dict。

建议新增 MixedScaleSMACAdapter，这是本项目应实现的类，不是官方现成 API。每回合用独立 RNG 选 N，取对应环境 reset；环境池可以惰性启动。训练器看见固定上限的 batch，真实人数另存：

| 接口     | 训练端约定                          | 大规模终评约定                       |
| -------- | ----------------------------------- | ------------------------------------ |
| agent 槽 | 最多 10 个，真实 N 单独记录         | 动态创建 20 等实际人数的 hidden 行   |
| 实体槽   | 最多 10 友方+10 敌方；特征维固定    | 可扩到 20+20；不新增可训练参数       |
| 动作     | 6 个非目标动作 + 最多 10 个敌人槽   | 6+实际敌人数；共用敌人评分器         |
| replay   | 固定 shape，保存存在/可见/动作 mask | 测试不写入训练 replay                |
| mixer    | 能正确屏蔽训练 padding              | 分散执行只调用 actor，可不运行 mixer |
| 规模抽样 | 每回合 N 均匀，一套策略与 replay    | 固定测试配置，统一场景库             |

每回合均匀不意味着环境步数均匀，因为回合长度不同；同时记录各规模回合数与联合步数。真实 N 个动作映射回原生环境，padding agent 不传给 SC2。

先用一个 rollout worker 测吞吐：完全缓存后最多四个 SC2 进程；两个 worker 最多八个。不要直接照搬 HAD 的八个 worker，否则可能启动 32 个进程，CPU/RAM 而非 GPU 成为瓶颈。PyMARL 的原始 runner/batch 在初始化时固定 shape，因此 adapter 必须对训练器公布固定容量，不能让第一次 4v4 决定之后所有 batch 大小。[PyMARL runner](https://github.com/oxwhirl/pymarl/blob/master/src/runners/episode_runner.py)

**动作头是第一处必改，上一动作编码是最容易漏掉的一处。** HAD 的九动作输出不能原样用于 SMAC。对 Full（RER）、Single、REFIL 使用同一个适配：

$$
Q_i^{\mathrm{base}}=f(h_i)\in\mathbb R^6,\qquad
Q_i^{\mathrm{attack}}(j)=g(h_i,e_{ij}),
$$

其中 g 在所有敌人间共享，e_ij 来自观察者允许的实体信息。20 个敌人测试时只增加评分次数，不能新增十组从未训练过的输出权重。TransfQMix 保留它已有的共享实体动作头，保持观测与动作语义一致。

如果当前 controller 把 n_actions 维上一动作 one-hot 拼进输入，维度仍会随敌人数变动。建议基础动作采用固定六类表示，加攻击标志；上一攻击对象在对应敌人实体上标记，身份映射跨时间一致。只编码该 agent 自己执行过的动作，不额外透露队友动作或当前不可见敌人的状态。REFIL 官方 controller 的确有依赖 args.n_actions 的路径，不能略过核查。[REFIL controller](https://github.com/shariqiqbal2810/REFIL/blob/master/src/controllers/entity_controller.py)

**局部观测必须贯穿全部循环层。** 用原生 get_obs 的特征定义解析自己、队友、敌人、移动等字段，依据 get_obs_*_feats_size 获取尺寸，不猜固定偏移。保留原生类型、健康、护盾等允许字段；不把 get_state 的全局状态输入 actor。全局状态只用于集中训练部分。

| 掩码         | 作用                      | 常见错误                                 |
| ------------ | ------------------------- | ---------------------------------------- |
| 存在/padding | 哪些槽有真实实体          | 无效槽参与 softmax、计数或 mixer         |
| 接收者可见   | 该 agent 当前允许读取什么 | 先全局混合，最后才遮挡，间接泄漏隐藏实体 |
| 动作合法     | 此时能否移动或攻击 j      | 把射程外但可见的敌人从观测删除           |

RER 每个接收者有自己的允许实体工作区；每轮 attention、count 与读出都按该集合处理。imagined 分组使用“原生可见∩分组允许”的 mask，数量与历史也不能直接复制主分支已看全信息的结果。SMAC 没有防护目标，第三类目标计数为零；不能拿未观测敌人的全局存活数代替局部允许数量。

padding agent 给安全 no-op 占位，但从联合值与损失中排除；避免全 -inf 产生 NaN。死亡的真实单位与从不存在的 padding 槽不同，应沿用各方法一致的死亡处理。

**mixer 需要支持混合训练，但不必重新发明一个任意规模 mixer。** 训练时真实人数 4/6/8/10 不同，必须正确处理存在 mask、联合 Q、中心实体与 target 路径。若现有 HAD 已有可变实体 mixer，优先复用；否则参考 REFIL FlexQMixer。max=10 的固定训练容量可以接受，只要无效槽不影响计算；20v20 分散测试可以不运行 mixer。[REFIL FlexQMixer](https://github.com/shariqiqbal2810/REFIL/blob/master/src/modules/mixers/flex_qmix.py)

保留原生团队奖励，不再套 HAD 的伤害奖励或终末折算；团队奖励不能又对 N 个 agent 求和放大。超时对应的 terminated/episode_limit 与 bootstrap 必须和学习器规则对齐，并对所有方法一致。

TransfQMix 还须检查两个特定适配点：作者 actor/mixer 调用链的 padding mask 是否实际传入；mixer 的历史 hyper token 是否始终保持三个 token，首步与后续步索引一致。公开代码部分初始 hidden 的形状与 n_agents 绑定，在 N≠3 的新适配中需按论文核验，不能把可修复的接口问题留给基线而据此宣称胜出。保留完整 actor+mixer，不替换为 REFIL mixer 后仍叫完整 TransfQMix。

## 四、理论和论文叙事：解释结构允许什么，由实验判断实际得到什么

### 4.1 保留三个短性质，不再用理想收缩假设替代证据

理论的职责是说明结构约束与实验问题，不是推导一个无法核查的“规模越大仍保证最优”结论。下面的性质可以直接从当前结构论证，不需要假设训练已找到全局最优。

**性质一：实体置换一致、参数不随实体数增长。** 假设逐实体编码共享、没有槽位身份参数，实体置换同时作用于 mask、自身索引和实体动作映射，数量编码对置换不变。记实体排列矩阵为 P，则注意力块满足

$$
F_\theta(PH,PMP^\top,z)=P F_\theta(H,M,z).
$$

证明要点：线性映射按行共享，注意力 logits 及 mask 同时按行列置换，行 softmax 与该置换相容；残差、逐行归一化和 FFN 保持等变。对循环轮数归纳即可得到同样性质。个体 query 所对应的自身/历史也正确对应后，非目标动作输出不变，攻击动作值随目标索引置换。

这说明同一组参数可以用于不同数量、不同排列的实体；**不说明在未见人数上回报一定好**。对应的工程检查是置换、padding 与动作映射一致性，对应的实质检验是图 2 的冻结人数外推。TransfQMix 等实体结构也具有相关归纳偏置，不能把这个普遍性质单独作为新颖性。

**性质二：循环改变可读性，不凭空增加整个工作区的信息。** 在关闭 dropout 的确定性推理下，对固定模型和 mask/count 等侧信息 z，Hᵣ⁺¹ 是 Hᵣ 的确定性函数。对有限取值的任务关系标签 Y，数据处理不等式给出

$$
I(Y;H^{r+1}\mid z)\le I(Y;H^r\mid z).
$$

它不要求严格下降，也不意味着维度或 token 数减少。某一个实体 token 可从其他 token 获得关系信息，因此它的线性可读性仍可提高；这不与整个工作区的信息不增加矛盾。这是基本信息论边界，不包装为本文原创定理，也不为连续隐藏变量增加不可靠的互信息估计实验。

因此，论文写“关系重组/关系可读性”比“逐轮压缩全局信息”准确。实验 2.3 用固定容量线性 probe 检查可读性，M2 与重训对照再检查任务是否依赖这些表示。**R² 不是互信息估计，不能声称它验证了严格信息压缩。**

**性质三：共享是结构约束，多轮读取允许保留中间结果。** 当外部模块、宽度和固定深度相同，不共享的 R 层网络可以通过令所有块参数相同，复现共享循环网络。因此

$$
\mathcal F_{\mathrm{shared},R}\subseteq\mathcal F_{\mathrm{untied},R}.
$$

共享的可能收益来自数据有限时的学习偏置、优化和参数效率，不能证明为更大的固定深度函数类。D/E 对照及成本表直接检验这点。随机深度训练是另一个因素，不能用共享性质替它解释结果。

对多轮读出 c=Σᵣαᵣuᵣ、αᵣ≥0、Σᵣαᵣ=1，有直接的三角不等式：

$$
\|W_f(c-u^k)\|
\le \sum_r\alpha_r\|W_f(u^r-u^k)\|.
$$

这只说明：若各轮经融合投影后的上下文已相似，换读出可能影响很小；若差异较大，则值得检查具体行为。它**不保证** learned 优于 uniform，不保证循环收敛，也不保证相似上下文一定产生相同动作。对应 M2，比把 α 分散直接解释为语义分工更合适。

正文只保留约 0.3–0.4 页设计性质与实验指向，简单证明可以就地给出要点。长推导放补充，但关键论证不能全部藏在补充。原来的 softmax 稀释/理想收缩分析最多作条件性动机；没有对应可检验前提时，删除比保留夸大的“泛化保证”更好。

计算量也要诚实：共享参数不会消除多轮计算。在每个接收者各有 M 个允许实体时，密集 attention 的主项约为每接收者 O(RM²d)，还包含投影和 FFN 项；全队成本须再计接收者数量。不能把多轮叫作免费推理，也不能说第一轮只看局部、后轮才扩大图上的跳数——密集注意力第一轮已经能访问所有允许实体。

### 4.2 用结果决定故事强度，而不是为故事挑选证据

当前建议论文工作标题为 **Entity Refinement for Cross-Scale Multi-Agent Coordination**；保留 RER 作为架构简称，代码键继续 regir。标题暂不承诺“循环是规模泛化主因”“逐步压缩”或“越算越好”。如果最终 Single 在两个环境都不逊于 Full，应把循环作为被研究的设计维度，而不是强行保持标题中的首要创新。名字变动不能替代方法与近邻的实质差异。

引言可以按四段组织：小团队训练与大团队部署的不一致；已有实体 Transformer 已解决变长输入但不保证关系决策迁移；本文提出实体工作区更新与个体读取，并拆分单轮、训练深度、参数共享、K/V 更新；在两个任务域用预定外推划分检验有效性与边界。贡献写成“方法、外推证据、机制边界”三项，具体强度等结果确定。

| 最终出现的结果                         | 可以写的结论                                   | 不能写的结论                           |
| -------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| Single 在两域都接近/优于 Full          | 单轮实体关系处理已是强主体；循环必要性有限     | 主要性能来自多轮推理                   |
| Full 仅在 K 外推/联合外推优于 Single   | 循环收益取决于关系结构变化，非人数越多就越有效 | 普遍的规模外推优势                     |
| Full@R1 优于 Single，而 Full@R4 增益小 | 多深度训练方案可能比部署加深更重要             | 已证明随机深度正则化是唯一原因         |
| Fixed4 优于 Untied4                    | 在给定预算下共享更新有经验收益                 | 共享固定深度表达能力更强               |
| 两者相近，共享参数更少                 | 参数效率与接近的任务表现                       | 已证明完全等效或泛化机制唯一           |
| KV0 与 Full 相近                       | 暂无证据表明更新 K/V 来源是关键                | 滚动工作区必然解释与 TransfQMix 的差距 |
| last 差，Uniform 接近 Full             | 保留中间表示有用，学习轮次权重未显必要         | 自适应选择语义深度是主要贡献           |
| nocount 持续优于 Full 的 K 外推        | 显式数量条件可能造成特定外推脆弱性，值得报告   | 数量编码一直帮助泛化                   |
| probe 后轮变好但任务不变               | 有可解码的表示变化，尚无任务价值证据           | 已解释性能提升的因果机制               |
| TransfQMix 同样好，或 SMAC 不支持优势  | 承认近邻竞争力或环境适用边界，收窄贡献         | 通用 SOTA 或跨域普遍优越               |

数量编码即使有界，也不自动保证训练范围之外行为合理。nocount 的当前目标轴改善值得先完成评估、拆开 K 与联合外推确认；不立即叠加五个新的数量编码版本。若后续决定简化最终方法，必须明确这是利用已观察 OOD 开发出来的修订，用新的确认场景报告稳定性，并保留原 Full 结果。新场景能确认场景级重复性，但不能把已经用来设计方法的规模配置重新称作完全未见的开发测试集。

现在的 α 均值约 0.27/0.26/0.24/0.24，只说明这一案例平均近均匀；既不能证明不同个体选择不同深度，也不能证明权重无效。相同最高注意力箭头同样不能否定所有表示变化。用户发来的拦截率/己方碰撞图提示可能有行为层收益，但图中仍用旧标签 REFIL-Cycle，未说明配置、权重和误差条单位，不能直接归因循环。先对齐来源；作为补充的行为解释即可，不再增加一组主指标。

### 5.2 指标尽量少，统计与分组要严格

正式 HAD 汇总按现有 24 格重新分组，**不用为重新分组再训练**：

| 组               | 配置                                  | 格数 |
| ---------------- | ------------------------------------- | ---: |
| 原池内           | 4v4 K2、6v6 K2、8v8 K2、10v10 K3      |    4 |
| 人数支持内补充点 | 10v10 K2                              |    1 |
| 人数插值         | 5v5 K2                                |    1 |
| N-OOD            | N=15/20/25/30/40/50，K=2              |    6 |
| 纯 K-OOD         | N=10，K=4/6/9/12                      |    4 |
| 联合 OOD         | N=15/20/30 各 K=4/6，另加 N=30 K=9/12 |    8 |

主表 ID 沿用原四配置，10v10 K2 在人数曲线单列。必须核对最终配置清单与训练 sampler 的实际联合支持；如果训练只采特定 N/K 组合，不能仅因 N、K 各自出现过，就断言它们的组合见过。24 格总数为 4+1+1+6+4+8。

**D 是 HAD 主指标；胜率是 SMAC 主指标；R² 仅用于 probe。** 保留用户已经计算的 NDS 作补充校准即可，不再制造“规模泛化分数”。若定义为

$$
\mathrm{NDS}(c)=\frac{D_{\mathrm{random}}(c)-D_{\mathrm{method}}(c)}
{D_{\mathrm{random}}(c)-D_{\mathrm{rule}}(c)},
$$

则先核对当前代码确实使用这一公式，逐配置计算，再等权汇总；随机与规则使用相同场景分布，分母近零或反向时标明不可作正常标尺，不能静默处理。NDS 是参考策略归一化，不是文献公认的规模外推定理，也不能消除所有难度变化。正文同时给绝对 D 和规则参考就足够直接。

宏平均按“先对每个训练 seed 的每配置 300 局求均值，再对固定配置等权，最后跨训练 seed 汇总”；禁止把所有轨迹池化后按回合数加权。不满局数/缺 seed 的格继续显示进度，但不与完整正式表混排。最新报告的 s<3 标注只能表示可用数量，不能把三种子自动当作证据充分的阈值；当前承诺五种子就补齐五种子。

默认曲线和点图报告五训练种子均值与 95% seed-level t 区间；图注写明区间单位；这是给定测试场景库上的训练运行不确定性，不能说已经包含全部任务分布不确定性。胜率区间若近边界可以越出 0–1，不能默默截断后当严格覆盖区间。补充给每个 seed 的实际点，必要时用分层 bootstrap 检查核心结论稳健性。五 seed 仍然较少，不把“区间重叠”视为严格等效检验，也不把“无显著差异”说成零效应。RL 评估中区分运行随机性与回合随机性的依据可参见 [Agarwal 等，Deep RL at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)；本文的预定组平均是针对本任务的简化展示，不声称完全复刻其评估套件。

同 checkpoint 的深度/读出干预天然按模型配对，并用共同评估场景；比较平均差和各 seed 差值更直接。不同训练方法仅仅都叫 seed0，不自动构成严格的配对训练实验；若采用共同初始化和环境随机流的区组设计，应预先记录这一设计。对成本与显示的小差异，不需给每格塞 p 值。

训练图现有阴影是标准差；改为区间只需重画，不重训。最终图使用固定五种子公共横轴，不能早期五条、末期仅三条却不标样本数。机制深度柱图若误差条实际上跨场景而非跨训练种子，必须重画成图 3b 的分规模曲线，不能将场景难度波动解释为训练稳定性。拦截率和碰撞率的很小误差条同样要查单位；重复 episode 不等于独立训练运行。

### 5.3 优先级、投稿版面与进度

当前还差的不是“把已有分数再包装一下”，而是三件实质工作：**五种子与终评口径闭合；与 Transformer 近邻和单轮强变体的机制区分；第二环境的可信复现。** 没有这些时，复杂理论和更多案例图不能替代证据。

| 阶段               | 立即执行内容                                                 | 产出与停止条件                                     |

| P0：先回收已有价值 | 补齐现有五种子与 300 局；核查 final、预算和报告过期文字；导出 matched 与 Single/nocount/last 逐格 | 正式可比表，避免在未完成均值上决定方法             |

工作量分开估算：新增 HAD 为 20×1M 物理步、最多 144,000 局主终评；M1 最多 22,500 局，M2 最多 19,500 局；SMAC 为 20×4M 联合步、48,000 局终评。HAD 与 SMAC 步长/吞吐不同，不能把这些步数相加当统一耗时。probe 不训练新策略；同样要考虑前缀回放和存储。
