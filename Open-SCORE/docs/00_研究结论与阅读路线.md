# 研究结论与阅读路线

> **一句话：我们学习可跨人数复用的小规模单目标攻防能力，再用可校准的局部胜负预测驱动双方实时分组，从而在伤亡、增援和未见总规模下维持全局胜率。**

## 1. 本轮最终修正

| 用户关切 | 最终决定 | 直接原因 | 当前动作 |
|---|---|---|---|
| SMAClite 是否可用 | 作为第二环境，建立 SMAClite-AD | 高效、易改，但原版只有单边控制和 SMAC 动作 | HAD 先行，后续薄扩展 |
| S1 动作语义 | 27 个纯加速度量化向量 | QMIX 需要离散动作，不能塞入“朝敌人”规则 | 已改代码 |
| 网络是否过重 | DeepSets + 64 维 GRU + 小 mixer | 1–4 对 1–4 不需要 Transformer | 已缩小配置 |
| 是否用 PSRO | warm-start 后启用小型 PSRO | 对手过拟合是真问题，但 BR 训练并非零成本 | 已加元博弈骨架 |
| S1 场景 | 单目标随机、训练10个红≥蓝规模，另测6格 | 形成 S3 可复用原子博弈并明确支持边界 | 已实现训练闭环 |
| S2 是否需要 ALMA/Set Transformer | 不需要；采用规范化输入的小 MLP ensemble | 局部最多 4v4，预测任务明确 | 已改代码 |
| S3 到底做什么 | 构造双方分组收益矩阵并求在线 maximin | 它是“分组对分组”的上层零和博弈 | 已明确输入输出 |
| S4 到底做什么 | 用整局胜负学习残差并交替更新 S1/S2/S3 | 前三阶段局部最优不保证全局最优 | 已加最终胜负残差骨架 |

## 2. 四阶段最直观的输入输出

```text
S1  Local Game Executor
输入：1–4 名队友、1–4 名对手、1 个随机目标、局部观测
输出：防守/攻击 QMIX 策略种群及 PSRO 元策略

S2  Outcome & Time Predictor
输入：某个目标附近的规范化全局状态 + 给定敌我子群
输出：防守胜率、短窗失守率、预计剩余步数及 95% 模型区间

S3  Grouping Game Commander
输入：全局态势、双方候选分组、逐目标 S2 输出
输出：防守分组混合策略、最坏攻击响应、实际执行分组及诊断矩阵

S4  Global Co-Adaptation
输入：完整系统轨迹和最终整局胜负
输出：修正后的上层收益、更新后的 S1 PSRO 策略与刷新后的 S2
```

## 3. 价值判断

这项工作的价值不在“第一次使用 QMIX、PSRO、MLP 或博弈论”，而在一个可检验的组合假设：**小规模单目标能力能否作为可复用原语，被结局预测器量化，再由上层双方分组博弈组合成对未见总规模更稳健的全局策略。**

它不保证优于端到端 MARL。预期优势只应放在以下三点：

1. 局部 1–4 对 1–4 经验可以跨总人数和目标数复用；
2. S2/S3 给出可审计的胜率、时长、置信区间和最坏响应；
3. 人口变化后只需重新分组，不必等待整网重新适应。

若同分布固定规模上端到端方法更强，这是合理结果；论文必须证明 Open-SCORE 在未见规模、未见对手或人口事件后的最坏表现更好，才能成立。

## 4. 当前唯一开发目标

先只做 HAD 的 S1：

- 每局一个随机目标；
- 训练从 $1\le n_A\le n_D\le4$ 的10格选择，另在6个红<蓝规模做压力测试；
- 红蓝两个 QMIX 团队都只控制加速度；
- 先规则策略/简单自博弈 warm-start，再做最多 8 轮 PSRO；
- 同时报告逐规模胜率矩阵和估计 NashConv，而不是要求物理上不利的 1v4 也超过 50%。

只有 S1 可稳定训练，才采集 S2 数据。
