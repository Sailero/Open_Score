## 3. 任务与角色语义

### 3.1 两个主环境的角色不能混用

| 环境 | Red | Blue | 主要用途 |
|---|---|---|---|
| HAD | 目标防守方 | 目标攻击方 | 动态规模主策略、Stage 2 数据来源 |
| SMAClite-AD | 资产攻击方 | 资产防守方 | 独立 AD 环境及 stock→AD 微调 |

HAD 的攻击智能体开火后自毁，因此只注册 `Red > Blue`：

```text
2v1, 3v1, 3v2, 4v1, 4v2, 4v3
```

这里 `2v1` 表示 2 个 Red 防守者对 1 个 Blue 攻击者。不得把 HAD 的颜色含义复制到 SMAClite-AD。

SMAClite-AD 注册：

```text
2v1, 3v2, 5v3
```

这里 Red 是资产攻击方、Blue 是资产防守方。

### 3.2 “动态规模”结论边界

HAD 主策略在六个注册规模上共同训练。通过后允许声称：

> 一套共享参数策略覆盖六个训练支持域配比。

不允许声称：

- 对六格之外任意人数有效；
- 六格中的某格是 zero-shot；
- 对未见对手策略泛化；
- 精确复现 REFIL、SPECTra 或 SPMARL。

### 3.3 两条 stock 链必须分开

```text
EPyMARL + 原版 SMAClite
    └─ 用于外部标准协议复现，不迁移 checkpoint

Open-SCORE 同构实体模型 + 原版 SMAClite/3s5z
    └─ 用于产生可审计 source checkpoint，再迁移到 SMAClite-AD
```

EPyMARL 与 Open-SCORE 的网络结构不同，禁止把 EPyMARL checkpoint 静默载入自研 AD 模型。报告中“复现标准表现”和“沿用参数微调”必须分别描述。

## 4. 参考工作与实现定位

正式报告只把以下工作作为方法来源或比较依据：

- [VDN](https://arxiv.org/abs/1706.05296)：值分解基线；
- [QMIX](https://proceedings.mlr.press/v80/rashid18a.html)：单调混合基线；
- [MAPPO](https://papers.nips.cc/paper/2022/file/9c1535a02f0ce079433344e14d910597-Paper-Datasets_and_Benchmarks.pdf)：集中训练、分散执行基线；
- [SMAClite 论文](https://arxiv.org/abs/2305.05566)与[官方仓库](https://github.com/uoe-agents/smaclite)：原版环境和上下文结果；
- [EPyMARL](https://github.com/uoe-agents/epymarl)：stock 三算法执行框架；
- [REFIL](https://proceedings.mlr.press/v139/iqbal21a.html)：可变实体、多任务表示动机；
- [SPECTra](https://arxiv.org/abs/2503.11726)：实体注意力与 target-action 设计动机；
- [SPMARL](https://proceedings.mlr.press/v267/zhao25o.html)：学习进度课程动机；
- [Deep Sets](https://papers.nips.cc/paper/2017/hash/f22e4747da1aa27e363d86d40ff442fe-Abstract.html)：Stage 2 排列不变集合编码；
- [DeepHit](https://ojs.aaai.org/index.php/AAAI/article/view/11842)：离散竞争风险建模动机；
- [Temperature Scaling](https://proceedings.mlr.press/v70/guo17a.html)：概率温度校准；
- [Conformal Risk Control](https://arxiv.org/abs/2208.02814)：风险上界与覆盖审计动机。

本项目的 `OpenSCORE-SAQA-QMIX-SP` 是原创 PyTorch 组合实现：共享实体编码、SAQA、动态 mask、参数共享、学习进度课程、规则示范 BC 和 RL 微调。它受上述工作启发，但没有复制 SPECTra/SPMARL 源码，也不声称是其精确复现。

Stage 2 使用的是 **DeepHit-style 离散竞争风险 NLL**；当前没有 DeepHit ranking loss，因此报告中不得写“精确复现 DeepHit”。

审计参考但不保留本地副本的源码版本：

| 项目 | URL | 审计 commit |
|---|---|---|
| SPECTra | `https://github.com/funny-rl/SPECTra.git` | `ffababf6187216c9d16b2109ee8ef6fe5fdf1172` |
| SPMARL | `https://github.com/wenshuaizhao/spmarl.git` | `2e9a08ecd704dd583e6c9a71b6f918d9f0130a50` |


每 seed 用 Validation 按以下字典序最大化：

### 10.6 三类结论必须分开

AD 任务成功门（每算法 stock-transfer）：

- 5 个 seeds；
- 每个 selected checkpoint 真实改变；
- 五 seed 平均 Held-out win rate ≥ 0.80；
- 每 ratio 五 seed 平均 win rate ≥ 0.70；
- 每个 transfer seed 最后 5 个 Validation 点：绝对 slope ≤ 0.02/次，range ≤ 0.10。

- changed copied tensor count > 0；
- source selected updates > 0，source total ≥ selected；
- scratch/transfer 初始随机模型哈希一致；
- ordered Held-out layout hashes 一致。

1. 在每个 seed 内按相同布局计算 `transfer return - scratch return`；
2. 以训练 seed 为 bootstrap 单位；
3. 95% CI 下界 > 0 才能声称“正迁移收益得到支持”。

若两臂都接近 100% 且差值不劣于 -0.05，可描述为 `ceiling_limited_noninferior`，但不能改写成正迁移。任务成功、迁移完整、正迁移收益是三个独立结论。

### 13.2 计划规模与 snapshot attrition

若 prefix 在 step 10/20 前自然终局，对应 snapshot 不存在。因此 483,840 是上限，不是必须恰好产生的行数：

```text
计划 roots = 140 × 6 × 3 = 2,520
每个实际 root 行数 = 3 × 2 × 32 = 192
最大行数 = 2,520 × 192 = 483,840
最小必有 snapshot-0 roots = 140 × 6 = 840
仅 snapshot-0 时最小行数 = 840 × 192 = 161,280
```

manifest 必须逐 scale×snapshot 报告：planned、realized、terminal-before-snapshot、unexplained missing。硬门：

```text
realized_roots + terminal_attrition_roots == 2520
unexplained_missing_roots == 0
snapshot0_roots == 840
records == realized_roots × 3 × 2 × 32
```

自然终局造成的 attrition 合法；静默缺失不合法。

### 13.3 Common Random Numbers

continuation seed：

```text
root_seed × 1,000,000
+ snapshot_step × 1,009
+ threat_index × 10,007
+ continuation_index
```

同一 `root×threat×continuation_id` 的三个 Red candidates 使用完全相同 continuation seed。Red policy RNG 加 `1,000,003`，Blue policy RNG 加 `2,000,003`。不同 continuation 不得复用 seed。

### 13.4 标签语义

竞争风险类别共 `2K+1`，`K=6`、每箱 5 步：

- 6 个 defender-win 时间箱；
- 6 个 breach 时间箱；
- 1 个 30 步预测窗口结束时仍未观察事件的 survival tail。

若 HAD 原生 `max_steps=50` 到达，应记为已观察 `defender_win`；只有 continuation 预算先耗尽且环境未终局，才是行政右删失。

历史字段 `payoff_red` 的正式名称是“30 步窗口安全效用”：窗口内 breach 为 -1，否则为 +1。右删失记录的 +1 只表示“截至窗口末未失守”，不是最终整局胜利。事件类型/时间仍按右删失竞争风险处理。

13 个物理监督标签：

| 字段 | 直观含义 | 单位/范围 |

| `target_final_health_fraction` | 窗口结束目标剩余健康 | 0–1 |

| `defender_survivors` | 窗口结束 Red 存活数 | 0–初始 Red |
| `attacker_survivors` | 窗口结束 Blue 存活数 | 0–初始 Blue |
| `defender_casualties` | 从 snapshot 起 Red 伤亡数 | 0–初始 Red |
| `attacker_casualties` | 从 snapshot 起 Blue 伤亡数 | 0–初始 Blue |

## 15. S2-B：监督学习、校准与一次性测试

### 15.1 五路 lineage 切分

| 分区 | 比例 | lineage 数 | 唯一用途 |
|---|---:|---:|---|

| Validation | 15% | 21 | early stopping、tabular 超参选择 |
| Temperature-Cal | 10% | 14 | 只拟合 temperature |

### 15.2 主模型

`had_deepset` 输入：

- 85 维 canonical state：target 8、Red `4×9`、Blue `4×9`、roster/alive 4、remaining horizon 1；
- 两方实体分别通过共享 `phi`；
- present mask 后做 sum/mean pooling；
- slot permutation 不改变输出；
- 策略、威胁、capability one-hot 和数值上下文作为条件；
- policy/capability `<UNK>` augmentation 各 0.10。

正式超参：

| 字段 | 值 |
|---|---:|
| horizon bins × steps | 6 × 5 |
| hidden dim | 96 |
| ensemble members | 5 |
| epochs / minimum | 160 / 30 |
| early stopping patience | 20 |
| batch size | 256 |
| AdamW lr | 0.0007 |
| weight decay | 0.00001 |
| gradient clip | 5.0 |
| physical loss weight | 0.50 |
| physical interval | member p10–p90 |
| seed | 20260831 |

每个 ensemble member 以 `lineage_group_id` 为单位有放回 bootstrap。13 个标签的 z-score 只在 Train 拟合。Validation 目标：

```text

+ 0.5 × normalized physical MSE
```

### 15.3 竞争风险与校准

已观察事件的似然为对应 cause×time mass。删失于箱 `c` 时，似然为：

```text
defender event mass after c
+ breach event mass after c
+ survival tail mass
```

Temperature-Cal：先在 `[0.2,5]` 对数网格 161 点粗搜，再局部 121 点精搜，以 joint NLL 最小为准。

Risk-Cal：`alpha=0.10`。先在每个 `root×Red candidate` 内对 Blue threats 和 32 continuations等权平均；再对每 lineage 取 sibling roots/candidates 的最大残差，形成 selection-safe additive upper offset。21 个 Risk-Cal lineages 的有限样本秩为 `ceil((21+1)×0.9)=20≤21`。

该上界只能称“交换性假设下的有限样本经验 selection-safe 上界”，不能声称覆盖任意部署分布。

### 15.4 基线

必须报告：

- Train breach prevalence climatology；
- Laplace-smoothed Train joint outcome-time empirical frequency；
- Train observed-event time median；
- 13 个标签的 Train median；
- random Red candidate；
- Train/global-best fixed Red candidate；
- `sklearn HistGradientBoosting`：max_iter `50/100/200`，lr 0.08，max leaf 31，L2 1.0；分类器按 Validation Brier、回归器按 Validation event MAE 选择。

当前协议没有 held-out policy family；所有三种 Red candidates 和两种 Blue threats 都出现在五路 lineage 中。`<UNK>` augmentation 不能冒充未见策略实验。最终报告不得写 held-out policy-pair 泛化。

### 15.6 指标：直观定义

概率：

| 指标 | 一眼可懂的含义 | 方向 |
|---|---|---|
| Brier | 概率和 0/1 事实的均方差 | 越低越好 |
| NLL | 给真实结果分配的概率是否足够大 | 越低越好 |
| ROC-AUC | 高风险样本是否排在低风险样本前 | 越高越好 |
| AP | 失守较少时对失守样本的排序质量 | 越高越好 |
| ECE/MCE | 预测 70% 是否真的约 70% | 越低越好 |
| Accuracy/Balanced accuracy | 分类命中率/类别均衡命中率 | 越高越好 |

事件与时间：

| 指标 | 含义 |
|---|---|
| right-censored joint NLL | 同时评估终局类型、时间和删失 |
| integrated breach Brier | 每个时间点“是否已经失守”的概率误差 |
| cause×time top-1/top-3 | 真实终局类型与时间箱是否排前 1/3 |
| event-time MAE/RMSE/MedAE | 已观察终局样本的剩余步误差 |
| RMST | 考虑删失后的截断期望剩余时长 |
| censor log score/lower-bound violation | 删失样本是否被预测得过早终止 |

风险与 Red 决策：

| 指标 | 含义 |
|---|---|
| candidate coverage | 每个 Red 候选的真实失守率是否被上界覆盖 |
| post-selection coverage | 挑中候选后，上界是否仍覆盖真实风险 |
| interval width / mean upper | 上界是否有信息，而不是永远接近 1 |
| mean/worst/minimax regret | 模型挑的 Red 策略比真实最优多多少失守率 |
| selection accuracy | 是否选中真实最优 Red 候选 |
| pair ranking accuracy | 任意两个 Red 候选的优劣顺序是否排对 |

13 个物理头逐一报告 MAE、RMSE、R²、Train-median baseline、MAE/RMSE skill、合理范围比例、ensemble p10–p90 覆盖/宽度和 ensemble std。还必须报告：

```text
defender_survivors + defender_casualties - initial_defender_count
attacker_survivors + attacker_casualties - initial_attacker_count
```

两者的平均绝对预测残差。真实物理结果给出 mean/median/p10/p90、方向和窗口安全效用损失 CVaR90。

所有核心指标按 scale、Red candidate、Blue threat 和最差 scale 切片。Brier、event-time MAE、Red regret 使用 lineage cluster bootstrap 95% CI；其他点估计必须标明没有该 CI，不能制造伪精度。

### 15.7 Stage 2 最低 go/no-go

3. joint censored NLL 和 integrated breach Brier 都低于 Train empirical joint baseline；

5. `candidate_rate_coverage ≥ 0.90`；
6. `post_selection_coverage ≥ 0.90`；

## 17. 失败、恢复与停止规则

### 17.1 工程故障

进程崩溃、断电、磁盘满、依赖损坏、checkpoint 无法加载属于工程故障：

1. 保存日志和失败目录；
2. 记录失败原因和最后完成位置；
3. 不把 partial 指标并入正式统计；
4. 在相同 commit/config/seed 下从该 run 的起点重跑；
5. 若必须改代码，则提升协议版本并重跑整个实验族。

### 17.2 性能失败

性能低、曲线未平台化、迁移无收益、S2 不优于基线都属于科学结果。禁止：

- 删除坏 seed；
- 改 Held-out/Test seed；
- 降低阈值；
- 用 Held-out/Test 选 checkpoint；
- 只给某算法增加预算；
- 从报告删除 scratch、规则或强基线；
- 反复打开同一 Test 调参。

如需扩大预算，先发布 v1.1 预注册协议，所有相关 arms/seeds 从头训练；已经看过的 Test 不能继续作为新版本唯一 Test，必须换新 lineage 范围。

### 17.3 阶段阻断

| 失败位置 | 必须写出的结论 | 禁止继续声称 |
|---|---|---|
| S1-A | stock 正式复现未完成 | 经典算法标准复现完成 |
| S1-B | 对应算法 source 不合格 | 对应算法 stock-transfer |
| S1-C | AD 环境审计失败 | SMAClite-AD 环境可用 |
| S1-D | AD 任务门失败 | AD 智能策略已训练可用 |
| S1-E | HAD 工程链失败 | HAD 正式训练接口可靠 |
| S1-F VDN/MAPPO | 纯 RL 复现门失败 | 三经典算法全部复现 |
| S1-F QMIX | 主策略门失败 | 优秀动态智能策略/正式 S2 输入 |
| S2-A | 数据合约失败 | 冻结数据可用于科研结论 |
| S2-B | 性能门失败 | Stage 2 科研性能完成 |

Stage 1 主策略失败时可以保留 Stage 2 工程测试代码，但不得生成依赖失败 checkpoint 的正式 Stage 2 结果。

### 18.2 参考机器调度

- S1-A：最多 5 个 CPU run 并行；无法确认物理核时串行。
- S1-B/S1-D/S1-F：同一 GPU 一次只跑一个 trainer；脚本内部按 seed/algorithm 顺序执行。

- S2-B：5 个 ensemble member 按当前实现训练；不得同时启动其他 GPU 训练。
- 开始每一阶段前确认系统盘和项目盘可用空间；至少保留冻结 JSONL 大小的 2 倍余量用于临时文件和 checkpoint。
