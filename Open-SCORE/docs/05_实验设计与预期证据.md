> 计划编号：`OpenSCORE-S1S2-Rounds-v1`
>
> 计划冻结标签：`s1s2-multiround-plan-v1`
>
> 适用电脑：Windows 11、i7-14700KF、RTX 5070 Ti 16 GB、`torch310`
>
> 当前状态：只完成计划和代码静态核对，正式训练尚未开始
>
> 执行原则：先完成两天最小闭环，再逐轮增强；上一轮没有报告，下一轮不得开始

这份文档是后续实验的唯一执行依据。最重要的任务只有四件事：

1. 用经典 QMIX 在 HAD 中训练一套能够同时处理不同人数的 Red 策略；
2. 分别测出这套策略在六种人数规模下的真实胜率；
3. 收集更多“当前全局态势—最终胜负”样本；
4. 用**同一个动态规模网络**输入任意已注册规模的全局态势，输出 Red 最终获胜概率。

第一轮不做 VDN、MAPPO、PSRO、S3、S4，也不同时预测十几个指标。它们只有在前两阶段已经可靠之后，才进入后续轮次。

## 2. 奖励、QMIX 参数和两个网络的核对结论

以下结论来自当前代码的逐项检查和单元测试，不是训练结果。相关基础测试目前为 `40 passed`。

**HAD 奖励。** 正式胜负和训练中的辅助奖励必须分开理解：

| 内容 | 固定定义 | 核对结论 |
|---|---|---|
| Red 成功 | 所有 Blue 打击智能体被摧毁，或目标坚持到第 50 步 | 最终结果记为 `+1` |
| Red 失败 | 目标在 50 步内被摧毁 | 最终结果记为 `-1` |
| Blue 奖励 | Red 奖励取相反数 | 两方总和始终为 0 |
| 中间辅助奖励 | `0.5 × (0.99 × 下一时刻态势分数 − 当前态势分数)` | 帮助网络更早得到学习信号 |
| 终止时态势分数 | 固定设为 0 | 不改变最终胜负目标 |
| HAD 底层原生奖励 | 原代码中的 `reward_episode=10` | 适配层不会把它送给 QMIX，避免两套奖励混用 |
| 正式评估 | 只统计最终 `+1/-1`，不把中间辅助奖励当胜率 | 正确 |

“态势分数”只综合四件直观的事：目标剩余生命、双方剩余人数、Blue 离目标有多远、Red 离 Blue 有多近。它的输入都来自当前时刻，不使用未来信息。辅助奖励与 QMIX 使用同一个 `gamma=0.99`，终止时归零，因此一局中的辅助项会前后抵消；它改善学习速度，但不会把“守住目标”替换成别的任务。

第一轮固定 `shaping_scale=0.5`。不能在看到测试胜率后临时改为 0.1、1.0 或其他数值。若后续需要比较奖励强度，只能作为新一轮独立实验。

**Stage 1 的 QMIX。** 当前实现保留了经典 QMIX 的关键部分，同时增加了动态人数输入：

```text
每个 Red 看到的实体列表
        ↓ 同一小网络逐个处理实体，并忽略补齐的空位
一个 128 维态势摘要 + 自身信息 + 任务信息
        ↓ 128 维循环记忆
27 个加速度动作的价值
        ↓ 所有存活 Red 的价值由 QMIX 合并
整队动作价值
```

所有 Red 共用同一套参数；六种规模不是六个模型。补齐位置带有效位标记，死亡智能体只能选择空动作。合并网络的权重始终为正，因此每个智能体认为更好的动作不会被整队价值反向解释。这符合 QMIX 的单调合并要求。当前第一轮网络约有 `283,709` 个可训练参数，远小于 5070 Ti 的显存限制。

固定参数如下；除非程序报错，否则第 1 轮不得修改：

| 参数 | 第 1 轮固定值 | 为什么这样设 |
|---|---:|---|
| 算法 | QMIX | 经典合作 MARL 方法，本轮只验证一条主线 |
| 训练种子 | `20260831` | 先完成最小闭环 |
| 训练局数 | 1000 | 能开放全部规模，又能控制两天预算 |
| 每局最大步数 | 50 | 与“守住 50 步即成功”的任务一致 |
| 每次学习的完整对局 | 8 | 完整轨迹较长，小批量更节省时间 |
| 经验池 | 最近 512 局 | 可重复学习，又不会长期被早期数据占满 |
| 每局后的更新次数 | 1 | 控制计算量 |
| 学习率 | `0.0005` | QMIX 当前实现的稳定起点 |
| `gamma` | `0.99` | 与奖励中的折扣完全一致 |
| 多步目标系数 | `0.6` | 当前代码固定采用 TD(lambda) |
| 目标网络更新间隔 | 200 次学习 | 避免学习目标每一步都剧烈变化 |
| 梯度上限 | 10 | 防止一次异常更新破坏模型 |
| 随机探索 | `1.0 → 0.05` | 前期多尝试，30000 环境步后保持少量探索 |
| 实体/循环隐藏维数 | 128 | 动态规模输入的主要容量 |
| QMIX 合并隐藏维数 | 128，内部合并维数 64 | 足以处理六种小规模 |
| 规模开放 | 0～199 局仅 2v1；200～399 局加入 3v1/3v2；第 400 局后六种全开 | 先学简单规模，再训练全部规模 |

代码还使用 Double-Q 方式选下一动作、用独立目标网络计算学习目标，并按有效轨迹位置计算损失。上述做法与动态人数标记均通过了现有测试。

**Stage 2 必须是一套动态规模网络。** 旧计划中的“把全部位置直接展开后送入普通 MLP”不再采用。当前仓库已有逐个单位处理和无顺序汇总的基础结构，但现有正式 Stage 2 同时预测胜负时间、多个物理量并使用多个网络，超过本轮需求。第 1 轮必须先提供一个简化的二分类模型，且只能产生一个最终权重文件：

```text
每个单位的 9 个数值
        ↓ 所有单位共用 9 → 32 → 32 的小网络
Red 单位分别求总和与平均值；Blue 单位也分别求总和与平均值
        ↓
目标的 8 个数值 + Red 摘要 + Blue 摘要 + 人数/剩余时间 5 个数值
        ↓ 141 → 64 → 64 → 1
Red 最终获胜概率（0～1）
```

不存在的单位由 `present=0` 排除，不参加总和和平均值。因此同一个模型可以接收 2v1、3v1、3v2、4v1、4v2、4v3，交换同一方单位的排列也不能改变输出。网络约有 1.5 万个参数，不按规模训练六个模型，不使用模型集成。

Stage 2 固定训练参数为：二分类交叉熵、Adam、学习率 `0.001`、batch 512、最多 100 个 epoch、Validation Brier 连续 10 个 epoch 不改善就停止、梯度上限 5、种子 `20260831`。不使用类别加权，因为评估器应保留自然胜率；若数据几乎全胜或全负，应判定数据不足，而不是用加权制造好看的准确率。

参考关系只需记住两点：Stage 1 的学习更新来自经典 [QMIX](https://proceedings.mlr.press/v80/rashid18a.html)；两个阶段处理不同人数的方式采用 [Deep Sets](https://papers.nips.cc/paper_files/paper/2017/hash/f22e4747da1aa27e363d86d40ff442fe-Paper.pdf) 的“逐个处理再汇总”思想。我们的动态规模网络是面向 HAD 的工程适配，不能写成对 REFIL、SPMARL 等其他论文的逐行复现。

| 项目 | 明确内容 |
|---|---|

| 通过条件 | 7200 局全部完成；最多约 72000 行；六种规模和两个对手均无缺失；Train/Validation/Test 全局都同时含胜局和负局 |
| 预期结果 | 比旧计划多 50% 的独立对局，并把每 10 步采样改为每 5 步采样，状态样本上限由约 24000 增至约 72000 |

每行只保留理解 Stage 2 必需的信息：

```text
episode_id       一局的唯一编号
split            train、validation 或 test
scale            例如 3v2
opponent         rush 或 split_rush
step             记录态势时的步数
global_state     85 个数值：目标、双方单位、人数和剩余时间
red_win          最终 Red 成功为 1，目标被摧毁为 0
sample_weight    1 除以本局实际保存的状态行数
```

为了让任何人得到相同划分，六种规模按上表顺序编号 `0～5`，两个对手按 `rush=0、split_rush=1` 编号，每个组合的第 `i` 局使用：

```text
episode_seed = 31,000,000 + scale_index × 100,000 + opponent_index × 10,000 + i
```

`i=0～419` 放入 Train，`420～509` 放入 Validation，`510～599` 放入 Test。划分单位必须是完整 episode；同一局的十个时刻绝不能跨越三个划分。若一局提前结束，只保存结束前实际存在的记录，不复制最后状态凑满十行。

训练和主要测试指标使用 `sample_weight`，使每一局的总权重都等于 1。否则坚持到后期的长局会因为留下更多时刻而被重复强调。这个权重只修正“一局有几行”的差异，不是为了人为平衡胜局和负局。

| 目标 | 从任意注册规模的当前全局态势直接输出 Red 最终胜率 |
| 输入 | 步骤 3 的 85 维全局态势；标签只使用 `red_win` |
| 执行 | 按第 2 节的共享单位编码器训练一个网络；每局总权重为 1；只用 Train 更新；只用 Validation 停止；最后打开一次 Test |
| 输出 | `stage2/model/dynamic_win_model.pt`、`metrics.json`、`test_predictions.csv` |
| 对照 | 总体固定胜率：永远输出 Train 总胜率；只看人数：输出该规模在 Train 的胜率 |
| 分析 | Test Accuracy、AUC、Brier；六种规模的真实胜率与平均预测胜率；按预测区间检查“预测 70% 的样本是否大约赢 70%” |
| 通过条件 | 一个权重处理六种规模；可保存、重载并重复同一预测；AUC 至少 0.60；Brier 小于总体固定胜率；六种规模平均绝对胜率误差不超过 0.15 |
| 未通过时 | 报告“代码跑通但评估器暂不可靠”；不能看 Test 后继续调网络并覆盖原结果 |

固定训练命令接口：

```powershell
& $PythonExe scripts\train_stage2_win_model.py `
  --dataset outputs\round_01_mvp\stage2\data\win_dataset.jsonl `
  --device cuda `
  --seed 20260831 `
  --entity-hidden-dim 32 `
  --hidden-dim 64 `
  --batch-size 512 `
  --learning-rate 0.001 `
  --max-epochs 100 `
  --patience 10 `
  --output-dir outputs\round_01_mvp\stage2\model
```

Accuracy 只是“猜对多少”；AUC 看胜局是否通常得到更高分，0.5 约等于随机排序；Brier 是预测概率与真实 0/1 的均方误差，越低越好。主判断使用 Brier，因为本任务需要的是可信概率，不只是胜负分类。

## 4. 第 2 轮：验证结论是否稳定

只有第 1 轮报告完成后才开始。本轮不增加算法、不改奖励、不改网络，只改变随机种子并扩大数据。

| 步骤 | 类型 | 输入与执行 | 必须得到的分析结果 | 通过/失败判定 |
|---|---|---|---|---|
| 2.0 复核第 1 轮 | 结果整理 | 读取第 1 轮报告和固定配置 | 明确哪些门槛通过、哪些未通过 | 未通过项若是程序错误，先修复并作为新版本重跑；性能不好不是程序错误 |
| 2.1 再训练两个 QMIX | 正式实验 | 使用完全相同参数，只把种子改为 `20260832`、`20260833`；各 1000 局 | 三个种子的训练曲线、六规模胜率的平均值/最小值/最大值 | 三个都必须展示，不能删除最差种子；至少两个种子的总体胜率相对初始提高 0.10 |
| 2.2 扩大 Stage 2 数据 | 正式实验 | 每个新增 QMIX 也采 `6 × 2 × 600=7200` 局；三套策略合计 21600 局、最多约 216000 行 | 不同 QMIX 种子产生的态势和胜率差异 | 新数据沿用同一 85 维格式，不增加“策略种子”作为预测输入 |
| 2.3 跨策略评估 | 正式实验 | 用前两个 QMIX 的 episode 训练/验证评估器，把第三个 QMIX 的全部 episode 作为最终 Test | AUC、Brier、六规模误差与第 1 轮相比如何 | Brier 仍优于总体固定胜率；若失败，结论是评估器只适合原策略数据 |
| 2.4 报告 | 结果整理 | 汇总以上结果 | 清楚回答“换种子是否还成立”和“不稳定来自哪些规模” | 生成且只生成 `round_02_report.md`，最多 4 张图 |

Stage 2 仍然只交付一套动态规模网络。这里的“跨策略测试”只是让 Test 来自一个没参与训练的 QMIX 种子，并不是为三个种子分别训练三个评估器。

第 2 轮期望价值是把“一个种子上的初步现象”升级为“多个种子下大致可重复的结果”。三个种子仍不足以支持很强的统计结论，但已经可以发现偶然成功和明显不稳定。

这两轮不影响 HAD 两阶段的最低交付。它们被放到后面，是为了保证“先跑原版、再修改环境、最后训练 AD”的顺序清楚。

4. 训练前后或基线相比，实际提高了多少？

| 步骤 | 实际输入 | 实际运行量/用时 | 核心结果 | 是否通过 | 简单解释 |
