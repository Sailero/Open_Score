# Open-SCORE 两天最小实验计划

> 计划编号：`OpenSCORE-S1S2-2Day-MVP-v1`
> Git 执行标签：`s1s2-two-day-mvp-v1`
> 适用电脑：Windows 11、i7-14700KF、RTX 5070 Ti 16 GB、`torch310`
> 时间目标：尽量在 48 小时内完成
> 当前状态：只完成计划，正式实验尚未开始
> 本轮不做：VDN、MAPPO、PSRO、S3、S4、复杂风险模型、13 个预测指标

这份文档只安排一个最小闭环：

1. 在 HAD 中用一个 QMIX 模型训练六种人数规模；
2. 分别统计六种规模下的胜率；
3. 保存战斗过程中的全局态势和最终胜负；
4. 用一个普通 MLP 神经网络，根据全局态势预测 Red 最终获胜概率；
5. 画图并写一份结果报告。

SMAClite 原版复现和 SMAClite-AD 修改保留为附加实验。只有上面的最小闭环完成且时间有剩余时才做，不能挤占核心任务。

---

## 1. 最后到底要得到什么

两天结束时，最低交付只有两项。

### 1.1 Stage 1 最低交付

一个 QMIX 权重文件。它不是为某一个固定人数单独训练，而是在下面六种 HAD 规模中共同训练：

```text
2v1、3v1、3v2、4v1、4v2、4v3
```

HAD 中：

- Red 是防守方；
- Blue 是攻击方；
- Blue 开火后会自毁，所以只使用 `Red > Blue` 的规模；
- 六种规模共用同一个模型，不为每种规模分别训练六个模型。

### 1.2 Stage 2 最低交付

一个普通的二分类 MLP：

```text
输入：当前全局态势
输出：Red 最终获胜的概率，范围 0～1
```

例如输出 `0.82`，表示模型认为 Red 从当前态势继续打下去，最终获胜概率约为 82%。

## 2. 实验、检查和附加任务的区别

后续所有步骤只使用下面三个标签。

| 标签 | 含义 | 会不会进入最终结果 |
|---|---|---|
| 工程检查 | 只确认环境和代码能运行 | 不会 |
| 正式实验 | 会产生训练曲线、胜率或预测结果 | 会 |
| 附加实验 | 核心完成后有时间才做 | 单独报告，不影响核心结论 |

判断方法很简单：

- 只跑几局、检查报错、检查显卡，都是工程检查；
- 训练 QMIX、统计正式胜率、采集监督数据、训练 MLP，都是正式实验；
- SMAClite 原版和 SMAClite-AD 在本轮属于附加实验。

## 7. 步骤 1：HAD 动态规模 QMIX

**类型：正式实验。**

### 7.1 目标

用一个 QMIX 模型同时学习六种 HAD 人数规模。这里不比较 VDN、MAPPO，也不做博弈算法。

为了处理不同人数，模型采用最简单的共享方式：

- 所有 Red 智能体共用同一个决策网络；
- 不存在的智能体位置用 0 填充；
- mask 告诉网络哪些位置是真实智能体；
- 六种规模仍然只保存一个模型权重。

### 7.2 输入

- HAD 环境；
- Red 防守方；
- Blue 规则对手 `rush` 和 `split_rush`；
- 六种注册规模；
- 随机种子 `20260831`。

### 7.3 固定训练参数

| 参数 | 值 | 普通解释 |
|---|---:|---|
| 算法 | QMIX | 本轮唯一 MARL 算法 |
| 训练种子 | `20260831` | 最低要求只跑这一个 |
| 训练局数 | 1000 | 六种规模共享 |
| 每局最大步数 | 50 | HAD 的一局长度上限 |
| batch | 8 局 | 每次学习使用的轨迹数 |
| replay buffer | 512 局 | 保存最近经验 |
| learning rate | 0.0005 | 神经网络学习率 |
| gamma | 0.99 | 未来奖励折扣；代码固定值 |
| 探索率 | 1.0 降到 0.05 | 训练早期多尝试随机动作 |
| 评估间隔 | 每 100 局 | 训练中看一次当前效果 |
| 正式评估 | 每规模、每对手 50 局 | 训练后不再更新权重 |

训练前 200 局先以较小规模为主，之后逐渐开放到全部六种规模。这样做只是让训练更稳定，不会产生六个不同模型。

### 7.4 执行命令

```powershell
& $PythonExe scripts\train_stage1_baselines.py `
  --algorithms qmix `
  --train-side Red `
  --device cuda `
  --seeds 20260831 `
  --episodes 1000 `
  --batch-episodes 8 `
  --replay-episodes 512 `
  --updates-per-episode 1 `
  --target-update-interval 200 `
  --learning-rate 0.0005 `
  --shaping-scale 0.5 `
  --max-steps 50 `
  --eval-every 100 `
  --eval-episodes-per-scale 5 `
  --heldout-episodes-per-scale 50 `
  --opponent-styles rush split_rush `
  --episodes-per-stage 200 `
  --epsilon-anneal-steps 30000 `
  --agent-hidden-dim 128 `
  --critic-hidden-dim 128 `
  --encoder-kind deepset `
  --bc-demo-episodes-per-scale-opponent 0 `
  --output-dir outputs\two_day_mvp\stage1\seed_20260831 `
  --evidence-dir outputs\two_day_mvp\stage1\seed_20260831\internal `
  --evidence-prefix seed_20260831
```

`deepset` 在这里只表示“先分别处理每个智能体，再汇总”，不需要理解额外数学理论。

### 7.5 输出

| 输出 | 用途 |
|---|---|
| `summary.json` | 本次训练和评估的总结果 |
| `training_curves.csv` | 训练曲线 |
| `*.pt` | QMIX 权重文件 |
| `internal/` | 程序自动保存的内部记录，不单独阅读 |

### 7.6 预期结果

最低工程要求：

- 完成 1000 局；
- loss 不是 NaN 或无穷大；
- 神经网络参数确实发生变化；
- 最佳权重能够重新加载；
- 六种规模都至少被训练和评估过。

最低性能目标：

- 训练结束时总体胜率比训练开始时至少提高 10 个百分点；
- 六种规模中至少 4 种的最终胜率高于初始策略；
- 如果没有达到，仍然保存结果，但结论写“QMIX 在当前预算下未学好”，不能继续假装成功。

因为最低方案只有一个随机种子，这只能叫“初步结果”，不能声称算法稳定或显著优于其他算法。

## 8. 步骤 2：按规模评估策略

**类型：正式实验。训练脚本会在权重选择完成后自动执行这部分，评估时不更新网络。**

### 8.1 目标

回答最直观的问题：

> 同一个 QMIX 权重，在 `2v1、3v1、3v2、4v1、4v2、4v3` 中分别能赢多少局？

### 8.2 输入

- 步骤 1 中验证表现最好的 QMIX 权重；
- 六种规模；
- 两个 Blue 规则对手；
- 每个“规模 × 对手”50 局新评估。

这些评估随机数与训练不同，不能把训练过程中的局直接拿来算最终胜率。

### 8.3 输出

必须整理成一张简单表：

| 规模 | 对 rush 胜率 | 对 split_rush 胜率 | 平均胜率 |
|---|---:|---:|---:|
| 2v1 | 待运行 | 待运行 | 待运行 |
| 3v1 | 待运行 | 待运行 | 待运行 |
| 3v2 | 待运行 | 待运行 | 待运行 |
| 4v1 | 待运行 | 待运行 | 待运行 |
| 4v2 | 待运行 | 待运行 | 待运行 |
| 4v3 | 待运行 | 待运行 | 待运行 |

保存为：

```text
outputs/two_day_mvp/stage1/evaluation/win_rate_by_scale.csv
outputs/two_day_mvp/stage1/evaluation/summary.json
```

### 8.4 预期成果

- 得到六种规模的真实评估胜率；
- 画一张六规模胜率柱状图；
- 明确哪些规模容易、哪些规模困难；
- 不要求六种规模全部达到某个很高的胜率。

Stage 1 是否“跑通”的最低判定：一个权重能在六种规模正常推理，并完成全部 600 局正式评估。性能好坏单独报告。

## 9. 步骤 3：采集 Stage 2 监督学习数据

**类型：正式实验。**

### 9.1 目标

生成最普通的监督学习数据：每一行包含“某个时刻的全局态势”和“这一局最后 Red 是否获胜”。

不预测剩余时间，不预测伤亡，不做风险上界，也不生成 13 个额外指标。

### 9.2 输入

- 固定使用种子 `20260831` 训练得到的 QMIX 最佳权重；
- 六种规模；
- Blue 对手 `rush`、`split_rush`；
- 每个“规模 × 对手”运行 400 局；
- 总计 `6 × 2 × 400 = 4800` 局；
- 在 step `0、10、20、30、40` 记录态势；提前结束的局只记录结束前存在的时刻。

### 9.3 每条数据保存什么

```text
episode_id        这一局的唯一编号
scale             例如 3v2
opponent          rush 或 split_rush
step              当前是第几步
global_state      当前全局态势数字向量
red_win           最终 Red 获胜为 1，否则为 0
```

全局态势至少包含：

- 目标当前生命值；
- 每个 Red/Blue 的位置、速度、生命值和是否存活；
- 当前步数；
- 当前 Red/Blue 人数；
- 不足最大人数的位置用 0 填充，并带有效位置标记。

### 9.4 数据划分

按完整 episode 划分：

| 部分 | 比例 | 用途 |
|---|---:|---|
| Train | 70% | 训练 MLP |
| Validation | 15% | 选择停止训练的时刻 |
| Test | 15% | 最后只评估一次 |

同一局的多个时刻必须全部进入同一部分。绝对不能把同一局的 step 0 放入 Train、step 20 放入 Test，否则模型会间接见过测试局。

### 9.5 输出

```text
outputs/two_day_mvp/stage2/data/win_dataset.jsonl
outputs/two_day_mvp/stage2/data/dataset_summary.json
```

`dataset_summary.json` 只需要报告：

- 实际完成的 episode 数；
- 实际数据行数；
- Train/Validation/Test 各有多少局；
- 各规模真实胜率；
- Red 胜/负样本数量。

### 9.6 预期结果

- 4800 局全部完成；
- 最多约 24,000 行态势数据；
- 六种规模都有数据；
- Train、Validation、Test 都同时包含胜和负；
- 如果某个划分只有胜或只有负，Stage 2 数据无效，不能用准确率掩盖这个问题。

## 10. 步骤 4：训练最终胜率 MLP

**类型：正式实验。**

### 10.1 目标

训练一个简单神经网络：

```text
global_state → 128 维隐藏层 → 64 维隐藏层 → Red 胜率
```

最后一层使用 sigmoid，所以输出一定在 0～1 之间。

### 10.2 输入

- 步骤 3 的 `win_dataset.jsonl`；
- 输入特征只使用 `global_state`；
- 标签只使用 `red_win`；
- 不把最终结果、未来伤亡等信息放入输入。

### 10.3 固定训练参数

| 参数 | 值 |
|---|---:|
| 网络 | MLP，隐藏层 128、64 |
| 激活函数 | ReLU |
| 损失函数 | 二分类交叉熵 |
| 优化器 | Adam |
| learning rate | 0.001 |
| batch size | 256 |
| 最多 epoch | 100 |
| early stopping | Validation 连续 10 个 epoch 不改善则停止 |
| 随机种子 | 20260831 |

输入标准化的均值和标准差只能从 Train 计算，再应用到 Validation 和 Test。

### 10.4 最简单的比较基线

除了 MLP，再计算两个不训练神经网络的简单答案：

1. **固定胜率基线**：任何态势都输出 Train 的总体胜率；
2. **只看规模基线**：只根据 `2v1、3v1...` 输出该规模在 Train 中的平均胜率。

这样可以判断 MLP 是否真的利用了当前态势，而不只是记住哪种人数容易赢。

### 10.5 测试指标

最终只报告四个容易理解的结果：

| 指标 | 解释 |
|---|---|
| Test accuracy | 胜负判断正确的比例 |
| Test AUC | 获胜局的预测通常是否高于失败局；0.5 约等于随机 |
| Test Brier | 概率与真实 0/1 的均方误差，越低越好 |
| 分规模误差 | 每种规模的平均预测胜率与真实胜率差多少 |

### 10.6 输出

```text
outputs/two_day_mvp/stage2/model/win_mlp.pt
outputs/two_day_mvp/stage2/model/metrics.json
outputs/two_day_mvp/stage2/model/test_predictions.csv
```

### 10.7 预期结果和判定

工程跑通要求：

- 训练正常结束；
- loss 为有限值；
- 模型可以重新加载；
- 每个 Test 样本都得到 0～1 的预测概率。

最低性能目标：

- Test AUC ≥ 0.60；
- MLP 的 Test Brier 小于“固定胜率基线”；
- 最好也小于“只看规模基线”；
- 六种规模的平均预测胜率与真实胜率平均相差不超过 0.15。

如果只达到工程要求而没有达到性能目标，结论必须写：

> 胜率评估器代码已跑通，但当前数据量或特征不足，暂时不能作为可靠评估器。

## 12. 第二个随机种子

**类型：附加，但优先级高于 SMAClite。**

核心最低结果只要求 `20260831`。如果步骤 1～5 在 36 小时内完成，再用完全相同参数运行：


## 17. 只需要理解的几个词

| 词 | 本文中的简单意思 |
|---|---|
| QMIX | 多个智能体合作学习的一种经典算法 |
| 动态规模 | 同一个模型面对不同数量的智能体 |
| seed | 控制随机数的一串数字；换 seed 相当于重新随机训练一次 |
| checkpoint | 保存下来的模型权重文件 |
| global state | 仿真器知道的完整当前态势 |
| MLP | 最普通的全连接神经网络 |
| Validation | 训练过程中用于决定何时停止，不是最终成绩 |
| Test | 最终只使用一次的数据 |
| AUC | 模型把胜局排在败局前面的能力，0.5 约等于随机 |
| Brier | 预测概率和真实胜负之间的均方误差，越低越好 |

除上表外，本轮报告不主动引入新的专业名词。旧版完整论文级方案保留在 Git 标签 `s1s2-protocol-v1` 中，但不再作为两天 MVP 的执行计划。
