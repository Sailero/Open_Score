# Open-SCORE 实验设计与预期证据

## 1. 主问题与主指标

整篇论文只回答一个主问题：

> 在总人数、对手策略和局内人口发生变化时，把大规模攻防组合为可评估的小型子博弈，是否比单体端到端策略和传统单边层次分配具有更高的最坏防守成功率？

主指标：

$$
RobustSuccess=\min_{c\in\mathcal C_{scale,event}}
\min_{\nu\in\mathcal U_{opp}}
P(\text{all targets survive}\mid c,\nu).
$$

逐阶段指标只能解释主结果，不能替代最终胜率。

## 2. 环境协议

### 2.1 S1 HAD 原子子博弈

- 1个目标，位置每局从固定三维区域均匀采样；
- 红蓝人数分别为1–4；训练注册红方不少于蓝方的10格，其余6格只作压力测试；
- 单位初始位置/速度和目标位置使用可追溯 seed；
- 双方都只输出27个量化加速度，规则开火对所有方法一致；
- 目标被毁为攻击胜，攻击方全灭或存活至300步为防守胜。

三套协议必须区分：

1. **支持域学习**：训练全部10个 $n_D\ge n_A$ 注册组合，验证一套模型的覆盖能力；
2. **留规模泛化**：从10格中预注册留出2–3格，例如3v2和4v3，其余训练，评价零样本/少量适应；
3. **物理劣势压力**：在从未作为支持域训练的6个 $n_D<n_A$ 组合上报告能力边界。

如果训练过某一组合，就不能再把该格写成规模零样本泛化；“任意规模”只指接口可运行，不能替代清楚的 train support。

### 2.2 正式多目标场景

用多个 S1 局部子博弈组成2–4个目标的全局任务。训练主分布以自然战损为主；伤亡时刻扰动和增援只作为独立 OOD。SMAClite-AD 在 HAD 主结论成立后复验关键结果。

## 3. 实验组

### E0：环境、动作和可复现性

检查：

- 27个动作都只对应加速度，模长不超过1；
- 相同 seed 的目标位置、初始状态和 rollout 一致；
- 红蓝奖励严格零和；
- 防守者不会攻击自家目标；
- timeout、目标被毁和攻击方全灭语义分离；
- `gpu_py_310` 的CPU/GPU前向、反向和环境吞吐。

这一组不产生论文主结论，但不通过就不能训练。

### E1：S1 不同规模 × 不同策略

用户提出的胜率矩阵是第一核心实验。每个方法对下列对手评估：

- nearest/attack-target 等规则策略；
- simultaneous self-play 最新策略；
- PSRO population 中所有历史策略；
- 未参与训练的独立 QMIX seed；
- 可选的人为速度/火力扰动策略。

每个 $(n_D,n_A)$ 输出完整 pairwise payoff matrix。只保留五个汇总量：

| 指标 | 含义 | 为什么需要 |
|---|---|---|
| Win rate | 逐规模真实胜率 | 直观能力边界 |
| Worst-opponent win | 对策略库最坏胜率 | 防止对单一对手过拟合 |
| Estimated NashConv | PSRO可利用度 | 判断种群是否稳定 |
| Scale interpolation drop | 未见规模下降 | 验证变规模结构 |
| Env steps / wall time | 训练代价 | 判断3060可行性 |

不设置“所有规模至少50%”门槛，因为1v4与4v1的真实均衡值本就不应相同。更合理的通过条件是：支持域平衡规模表现可用、留出规模下降受控、相对 Fixed-Capacity QMIX/naive self-play 的最坏对手胜率提高；6个压力格只报告边界。

### E2：PSRO是否值得

比较相同环境步预算下：

1. 规则对手训练；
2. simultaneous self-play；
3. fictitious/uniform population play；
4. PSRO meta-Nash。

展示每轮 population size、meta-game value、estimated NashConv、BR improvement 和 wall time。BR必须达到预注册预算并展示验证曲线；否则短训练产生的零 gap 只能记作无效 oracle，不能当成收敛。若PSRO没有减少可利用度或代价不可接受，就把它降为训练 baseline，而不强行作为 S1 必需组件。

### E3：S2结局—时间预测

按完整 root-state lineage 划分 Train/Cal/Test，防止同一状态的不同 rollout 跨集合泄漏。比较经验频率、逻辑回归、单 MLP、MLP ensemble和可选 Set Transformer。

只报告：

| 指标 | 测量对象 | 通过条件 |
|---|---|---|
| Brier/NLL | 胜负概率 | 优于经验/单MLP基线 |
| Time MAE | 剩余步数 | 明显优于全局均值 |
| Interval coverage | 95%模型区间 | 不严重欠覆盖 |
| Short-window breach AUC | S3直接使用的风险 | 可区分高低风险候选 |
| Calibration by scale | 不同人数桶 | 没有系统性乐观偏差 |

解释性图只展示2–3个真实状态：输入局面、S2联合时间分布、真实多次 rollout 频率和区间。无需画大量相关性热图。

### E4：S3分组是否真的提高最终胜率

先做小规模离线 oracle：对同一全局根状态，把所有候选对真实 rollout，得到真实 payoff matrix。比较 heuristic、ALMA-AQL、点预测 argmax、S2 maximin和高层 MAPPO。

主要证据：

- 真实 decision regret；
- 闭环目标全存活率；
- 最坏攻击响应下胜率；
- 人口事件后恢复时间；
- 每次在线求解时延。

必须明确展示一次决策的完整链条：全局态势 → 双方候选 → 每目标S2预测/区间 → 收益矩阵 → maximin混合策略 → 实际分组 → 真实结果。这比额外添加一个不可解释网络更能说明价值。

### E5：S1→S4是否逐步进化

用同一批固定测试场景依次运行：

1. S1 无上层、固定分组；
2. S1 + S2 点预测贪心；
3. S1 + S2 + S3 maximin；
4. Full S1–S4；
5. Monolithic end-to-end baseline。

阶段曲线同时展示最终胜率、最坏胜率、求解代价和中间预测误差。只有最终胜率随模块加入稳定提高，才能支持“四阶段统一创新”。中间输出变得更漂亮但最终胜率不变，不算有效。

### E6：对端到端与层次方法的关键比较

| 方法 | 结构 | 训练目标 | 关键比较 |
|---|---|---|---|
| Monolithic Variable-QMIX | 一个实体网络 | 整局回报 | 固定/未见规模 |
| Monolithic MAPPO | 集中 critic、分散 actor | 整局回报 | 连续或离散微操 |
| ALMA-style hierarchy | 学习单边分组 | 整局回报 | 动态任务分配 |
| Frozen Open-SCORE | S1–S3 | 局部结果/短窗风险 | 分解本身的收益 |
| Full Open-SCORE | S1–S4 | 局部监督 + 最终胜负 | 全局共同适应 |

端到端方法在固定规模上可能更高，Open-SCORE必须在未见总规模、未见对手、目标数变化或伤亡/增援后表现出优势。

## 4. 消融实验

只做直接对应论文论点的四项：

| 消融 | 移除内容 | 预期验证 |
|---|---|---|
| w/o variable mixer | 固定容量QMIX | 跨规模结构是否必要 |
| w/o PSRO | naive self-play | 对手过拟合是否真实存在 |
| w/o uncertainty game | 点预测贪心 | 置信上界/maximin是否减少灾难失守 |
| w/o global residual/guard | 冻结或朴素联合训练 | S4是否提升全局且防遗忘 |

## 5. 敏感性分析

保留三个真正可能改变结论的参数：

1. 指挥周期 $H_c$；
2. S3切换成本 $\lambda_{sw}$；
3. S4残差权重 $\eta$。

PSRO轮数和ensemble成员数作为计算预算曲线报告，不需要形成庞大的网格搜索。

## 6. 统计与防止自欺

- S1 Demo 3 seeds，正式结果至少5 seeds；
- 每个固定 checkpoint 的胜率使用相同 episode seeds 配对比较；
- episode级 bootstrap 95% CI；
- PSRO payoff cell 使用独立评估局，不能复用 BR 训练回报；
- S2按 root lineage 切分；
- 主终点一次检验，次指标作 Holm 修正；
- 失败 seed、S4 rollback和超时全部保留。

## 7. 第一阶段 go/no-go

进入 S2 前至少满足：

1. 同一模型无需改层维即可运行10个注册规模和6个压力规模；
2. 平衡规模对规则/独立学习对手能稳定学习；
3. 预注册留出规模相对 seen 平均下降不超过0.15，压力域单独报告；
4. PSRO pilot 相对 naive self-play 降低最坏对手损失或 estimated NashConv；
5. 3060上的完整训练 wall time 可接受。

若PSRO失败但变规模QMIX成功，可以先用多策略自博弈进入S2；若变规模执行本身失败，则后续S2–S4没有可信基础。
