# Open-SCORE 实验设计与预期证据

## 1. 主问题与主指标

整篇论文只回答一个主问题：

> 在总人数、未知对手策略和局内人口发生变化时，把大规模攻防组合为策略条件化且可校准的小型子博弈，并用受限动态双方分组求解，是否能在相同预算下比单体端到端策略、传统单边层次分配和已有双方联盟求解获得更高的最坏防守成功率？

主指标：

$$
RobustSuccess=\min_{c\in\mathcal C_{scale,event}}
\min_{\nu\in\mathcal U_{opp}}
P(\text{all targets survive}\mid c,\nu).
$$

逐阶段指标只能解释主结果，不能替代最终胜率。

“未知对手”预注册为：测试时不提供 checkpoint/类型 ID，只提供交互历史；$\mathcal U_{opp}$ 包含训练库内隐藏身份、留出策略、策略切换和至少一种开集行为。本文不以有限实验声称覆盖任意对手。

## 2. 环境协议

### 2.1 S1 HAD 原子子博弈

- 1个目标，位置每局从固定三维区域均匀采样；
- 红蓝人数分别为1–4；训练注册红方不少于蓝方的10格，其余6格只作压力测试；
- 单位初始位置/速度和目标位置使用可追溯 seed；
- 双方都只输出27个量化加速度，规则开火对所有方法一致；
- 目标被毁为攻击胜，攻击方全灭或存活至300步为防守胜。

三套协议必须区分：

1. **支持域学习**：训练全部10个 $n_D\ge n_A$ 注册组合，验证一套模型的覆盖能力；
2. **留规模泛化**：从10格中预注册留出2–3格，例如3v2和4v3，其余训练，评价零样本/少量适应；
3. **物理劣势压力**：在从未作为支持域训练的6个 $n_D<n_A$ 组合上报告能力边界。

如果训练过某一组合，就不能再把该格写成规模零样本泛化；“任意规模”只指接口可运行，不能替代清楚的 train support。

### 2.2 正式多目标场景

用多个 S1 局部子博弈组成2–4个目标的全局任务。训练主分布以自然战损为主；伤亡时刻扰动和增援只作为独立 OOD。SMAClite-AD 在 HAD 主结论成立后复验关键结果。

## 3. 实验组

### E0：环境、动作和可复现性

检查：

- 27个动作都只对应加速度，模长不超过1；
- 相同 seed 的目标位置、初始状态和 rollout 一致；
- 红蓝奖励严格零和；
- 防守者不会攻击自家目标；
- timeout、目标被毁和攻击方全灭语义分离；
- `gpu_py_310` 的CPU/GPU前向、反向和环境吞吐。

这一组不产生论文主结论，但不通过就不能训练。

### E1：S1 不同规模 × 不同策略

用户提出的胜率矩阵是第一核心实验。每个方法对下列对手评估：

- nearest/attack-target 等规则策略；
- simultaneous self-play 最新策略；
- PSRO population 中所有历史策略；
- 未参与训练的独立 QMIX seed；
- 可选的人为速度/火力扰动策略。

每个 $(n_D,n_A)$ 输出完整 pairwise payoff matrix。只保留五个汇总量：

| 指标 | 含义 | 为什么需要 |
|---|---|---|
| Win rate | 逐规模真实胜率 | 直观能力边界 |
| Worst-opponent win | 对策略库最坏胜率 | 防止对单一对手过拟合 |
| Estimated NashConv | PSRO可利用度 | 判断种群是否稳定 |
| Scale interpolation drop | 未见规模下降 | 验证变规模结构 |
| Env steps / wall time | 训练代价 | 判断3060可行性 |

不设置“所有规模至少50%”门槛，因为1v4与4v1的真实均衡值本就不应相同。更合理的通过条件是：支持域平衡规模表现可用、留出规模下降受控、相对 Fixed-Capacity QMIX/naive self-play 的最坏对手胜率提高；6个压力格只报告边界。

### E2：PSRO是否值得

比较相同环境步预算下：

1. 规则对手训练；
2. simultaneous self-play；
3. fictitious/uniform population play；
4. PSRO meta-Nash。

展示每轮 population size、meta-game value、estimated NashConv、BR improvement 和 wall time。BR必须达到预注册预算并展示验证曲线；否则短训练产生的零 gap 只能记作无效 oracle，不能当成收敛。若PSRO没有减少可利用度或代价不可接受，就把它降为训练 baseline，而不强行作为 S1 必需组件。

### E3：S2 策略条件结局—时间预测

按完整 root-state lineage 划分 Train/Cal/Test，防止同一状态的不同 rollout 跨集合泄漏；同一 root 下不同局部策略对也必须留在同一划分。比较经验频率、逻辑回归、无策略条件 MLP、策略条件单 MLP、MLP ensemble和可选 Set Transformer。

只报告：

| 指标 | 测量对象 | 通过条件 |
|---|---|---|
| Brier/NLL | 胜负概率 | 优于经验/单MLP基线 |
| Time MAE | 剩余步数 | 明显优于全局均值 |
| Upper-bound coverage | 独立校准的单侧风险上界 | 不严重欠覆盖 |
| Short-window breach AUC | S3直接使用的风险 | 可区分高低风险候选 |
| Calibration by scale | 不同人数桶 | 没有系统性乐观偏差 |
| Held-out policy-pair NLL/Brier | 未见局部克制关系 | 策略条件模型优于无条件模型 |
| Post-selection coverage | S3实际选中候选 | 不因 optimizer's curse 严重失效 |
| Decision-weighted regret | 预测误差对上层选择的影响 | 优于只优化平均 NLL 的模型 |

解释性图只展示2–3个真实状态：输入局面、S2联合时间分布、真实多次 rollout 频率和区间。无需画大量相关性热图。

### E4：S3 的模型、求解与未知对手是否有效

先做小规模离线 oracle：对同一全局根状态，把所有候选对和局部策略条件真实 rollout，得到真实 payoff/Q matrix。比较 heuristic、ALMA-AQL、Double-IC、Blotto 特例、点预测 argmax、完整候选 S2 maximin、本文列生成 ambiguity-set 求解和高层 MAPPO。

主要证据：

- 真实 decision regret；
- 闭环目标全存活率；
- 最坏攻击响应下胜率；
- 对手类型识别/开集后的适应—保底曲线；
- 列生成候选数、oracle gap 与完整枚举值差；
- 人口事件后恢复时间；
- 每次在线求解时延。

必须明确展示一次决策的完整链条：全局态势/对手历史 → 对手后验与开集分数 → 双方候选列 → 每目标 S2 预测/校准上界 → $Q$ 矩阵 → maximin 混合策略/最坏响应/gap → 实际分组 → 真实结果。这比额外添加一个不可解释网络更能说明价值。

长期性单独比较 $L=1$、$L=1+$S4 终端残差、$L=2/3$ model rollout 和高层 MAPPO。若 $L=1$ 已接近真实多步 oracle，就没有理由承担更昂贵的规划；若差距大，才能声称 S4/多步模型是必要模块。

### E5：S4 结果对齐是否值得新增成本

用同一批固定测试场景依次运行：

1. S1 无上层、固定分组；
2. S1 + S2 点预测贪心；
3. S1 + S2 + S3 maximin；
4. S4-A（只加宏观价值残差）；
5. S4-B（再追加 S1 种群最佳响应）；
6. 朴素 joint fine-tuning（直接共同更新、无 guard）；
7. Monolithic end-to-end baseline。

阶段曲线同时展示最终胜率、最坏胜率、环境步数、wall time、旧规模遗忘和中间预测误差。只有最终胜率随模块加入稳定提高，才能支持“四阶段统一创新”。S4-A 若无提升，不启动 S4-B；中间输出变得更漂亮但最终胜率不变，不算有效。

### E6：对端到端与层次方法的关键比较

| 方法 | 结构 | 训练目标 | 关键比较 |
|---|---|---|---|
| Monolithic Variable-QMIX | 一个实体网络 | 整局回报 | 固定/未见规模 |
| Monolithic MAPPO | 集中 critic、分散 actor | 整局回报 | 连续或离散微操 |
| ALMA-style hierarchy | 学习单边分组 | 整局回报 | 动态任务分配 |
| Double-IC | 双方联盟形成 | 手工联盟效用/均衡 | 双方性与动态重分配 |
| Blotto-with-subgames baseline | 双方分兵后局部博弈 | 一阶段结构收益 | 本文 S3 的静态特例 |
| Frozen Open-SCORE | S1–S3 | 策略条件局部结果/短窗风险 | 学习子博弈与显式求解的收益 |
| Open-SCORE + S4-A | S1–S3 + value residual | 局部监督 + 最终胜负 | 低成本结果对齐 |
| Full Open-SCORE | S1–S4-B | 局部监督 + 最终胜负 + 新 BR | 完整共同适应 |

端到端方法在固定规模上可能更高，Open-SCORE必须在未见总规模、未见对手、目标数变化或伤亡/增援后表现出优势。

## 4. 消融实验

只做直接对应论文论点的七项：

| 消融 | 移除内容 | 预期验证 |
|---|---|---|
| w/o variable mixer | 固定容量QMIX | 跨规模结构是否必要 |
| w/o PSRO | naive self-play | 对手过拟合是否真实存在 |
| w/o policy context | S2 不输入策略对/行为上下文 | 非传递性是否真的需要条件化模型 |
| w/o opponent ambiguity | 固定全 maximin 或 posterior best response | 自适应—保底折中是否存在 |
| w/o column generation | 固定启发式候选或完整枚举 | 组合 oracle 是否降低成本且保持值 |
| w/o uncertainty game | 点预测贪心 | 校准上界/maximin是否减少灾难失守 |
| w/o global residual/guard | 冻结或朴素联合训练 | S4是否提升全局且防遗忘 |

## 5. 敏感性分析

保留四个真正可能改变结论的参数：

1. 指挥周期 $H_c$；
2. S3切换成本 $\lambda_{sw}$；
3. 对手 ambiguity 半径/开集阈值 $\rho$；
4. S4残差权重 $\eta$。

PSRO轮数、列生成时限/候选上限和 ensemble 成员数作为计算预算曲线报告，不需要形成庞大的网格搜索。

## 6. 统计与防止自欺

- S1 Demo 3 seeds，正式结果至少5 seeds；
- 每个固定 checkpoint 的胜率使用相同 episode seeds 配对比较；
- episode级 bootstrap 95% CI；
- PSRO payoff cell 使用独立评估局，不能复用 BR 训练回报；
- S2按 root lineage 切分；
- 对手策略按 checkpoint lineage 切分，留出策略不能是同一训练轨迹的相邻 checkpoint；
- S3 同时报告完整枚举可用的小问题和限时列生成的大问题，不能只在不同规模各挑对自己有利的求解器；
- 主终点一次检验，次指标作 Holm 修正；
- 失败 seed、S4 rollback和超时全部保留。

## 7. 第一阶段 go/no-go

进入 S2 前至少满足：

1. 同一模型无需改层维即可运行10个注册规模和6个压力规模；
2. 平衡规模对规则/独立学习对手能稳定学习；
3. 预注册留出规模相对 seen 平均下降不超过0.15，压力域单独报告；
4. PSRO pilot 相对 naive self-play 降低最坏对手损失或 estimated NashConv；
5. 3060上的完整训练 wall time 可接受。

若PSRO失败但变规模QMIX成功，可以先用多策略自博弈进入S2；若变规模执行本身失败，则后续S2–S4没有可信基础。

## 8. S3/S4 分阶段 go/no-go

进入 S3 在线闭环前：

1. S2 在 held-out 策略对上能排序上层高价值候选；
2. 被 S3 选中候选的风险覆盖没有出现系统性乐观；
3. 小问题上的 S2 矩阵 maximin 相对真实 rollout oracle 的 decision regret 低于预注册阈值。

进入 S4-A 前：

1. S3 相对 heuristic/ALMA-style/Double-IC 至少在真实 decision regret 或最坏最终胜率上有一项稳定优势；
2. $L=1$ 与真实多步 oracle 之间存在可归因的长时域差距；
3. 列生成在目标时限内达到可接受 gap。

进入 S4-B 前：S4-A 必须在未用于残差训练的规模 × 对手 × 人口事件 guard grid 上提高最坏胜率；否则停止低层共同适应。这个门控直接回答 S4 是否“功能必要但成本太高”。
