# 第二阶段：策略条件监督学习与评估报告

> 状态：Stage 2 数据—训练—双重独立校准—测试—保存/加载闭环可运行；泄漏修复后的 HAD 规则策略 pilot 为 **no-go**，尚不能进入 S3。它不是 S1 智能策略收敛证据，也不是论文最终结果。

## 1. 本轮完成结论

本轮把原先只有一个 `OutcomeTimeMLP` 的 S2 骨架扩展为以下可执行闭环：

1. HAD、SMAClite-AD 或其他 runner 均可调用同一个 `record_from_rollout(...)` 写入策略条件数据；
2. 每条记录显式保存环境、场景、物理 root、rollout、随机种子、双方人数、双方策略 ID/版本、能力版本、终局、持续步数、短窗失守标签、规范化状态和行为上下文；
3. Train/Temperature-Cal/Risk-Cal/Test 只按 `lineage_group_id` 四路切分；同一母 seed 派生的跨规模 roots 必须整组移动；
4. 5 个 bootstrap MLP 预测统一的“终局类型 × 时间桶”分布，避免胜率和剩余时间来自互相矛盾的预测头；
5. Temperature-Cal 只拟合温度，互斥的 Risk-Cal 才拟合单侧风险残差，避免用同一批数据先改变评分函数再做 split conformal；
6. ensemble 按完整 `lineage_group_id` cluster bootstrap，不再把同 root 的四个策略对当作四个独立样本；
7. 训练时以固定 seed 对双方 policy 和 capability 做 20% 的 `<UNK>` augmentation，使未见 ID 不会落到完全未训练的随机输入列；这只保证接口有训练支撑，不证明 open-set 泛化；
6. 测试输出概率、分类、时间、短窗风险、分规模、分策略对、ensemble 分歧、风险上界和选择后决策指标；
7. checkpoint 包含模型、特征词表、标准化参数、温度和风险校准量，加载后预测与保存前一致。

## 2. 数据契约与泄漏防线

### 2.1 Query 与 label 分离

`Stage2Query` 只包含指挥时刻可获得的信息，`Stage2Record` 再附加未来 rollout 的真实标签。这样可以检查训练特征中没有混入未来信息。

| 字段 | 直观含义 | 约束/用途 |
|---|---|---|
| `environment_id` / `scenario_id` | 来自哪个环境、哪个任务 | 分环境和场景审计 |
| `lineage_group_id` | 共享母 seed、目标布局或上游生成器的父谱系 | **唯一切分键**；跨 scale 近重复 roots 也不能跨分区 |
| `root_id` | 一个 scale 下的真实物理初态 | 同一初态的全部反事实策略对共用它，但它不是充分的切分键 |
| `rollout_id` | 一条实际执行轨迹 | 追踪重复 rollout，不能用于随机切分 |
| `seed` | 环境/采样种子 | 复现与去重 |
| `defender_count` / `attacker_count` | 当前局部红蓝规模 | 分规模校准和 OOD 审计 |
| 双方 `policy_id` / `policy_version` | 谁在执行、哪个 checkpoint/规则版本 | 防止同名不同版本被平均 |
| `capability_version` | S1 环境—执行器整体版本 | S4 增量刷新 S2 时识别版本 |
| `horizon_steps` / `command_steps` | 预测总窗和 S3 短指挥窗 | 定义 timeout 与短窗失守 |
| `canonical_state` | 固定宽度局部规范化状态 | 模型主输入 |
| `behavior_context` | 可选近期行为摘要 | 未知策略时替代直接策略身份 |
| `candidate_id` | S3 候选对 ID | root 内排序、选择后覆盖和 regret |
| `outcome` / `terminal_steps` | 防守胜、失守或超时及发生时间 | 联合监督标签 |
| `short_window_breach` | 是否在一个指挥窗内失守 | 由终局和时间自动推导并在读取时核对 |

JSONL 是无损训练格式；CSV 把向量编码为 JSON 数组，便于人工检查。`record_from_rollout` 不依赖 HAD 类，SMAClite runner 后续只需传入自己的 canonical feature 和上述元数据。

### 2.2 为什么必须按父谱系而不只是 root 切分

同一初态通常会运行多个防守策略 × 攻击策略的反事实组合；此外，若六个 scale 重用相同母 seed，目标坐标/上游随机布局也会近重复。仅把 scale 写进 `root_id` 会让这些 sibling roots 跨 Train/Test，旧 pilot 的高 AUC 正是因此失效，已经全部作废并覆盖。

本实现执行三层防护：

1. collector 持久化 `lineage_group_id=master-seed`，相同 `(scenario, scale, seed)` 的策略对另共享 `root_id`；
2. `split_records_by_lineage_group` 四路整组移动父谱系，且 HAD pilot 为每个 scale 配置不相交的 12 个 master seeds；
3. manifest 同时列出全部 group/root ID，`assert_no_lineage_leakage()` 和训练入口分别拒绝 group 或 root 交叉；
4. Temperature-Cal、Risk-Cal 严格互斥，Test 仅在两种校准均冻结后使用。

本次 288 条 HAD 记录来自 72 个独立 master groups/roots，按每个规模 6/2/2/2 分成 36/12/12/12 个 Train/Temperature-Cal/Risk-Cal/Test groups，即 144/48/48/48 条记录。父谱系与 root 交叉检查均为 `passed`。正式实验仍需登记更上游的地图/场景生成谱系，不能假定 seed 不同就必然统计独立。

## 3. HAD 状态规范化

`HADCanonicalizer` 把全局实体表转换为 84 维固定向量：

- 目标的归一化位置、速度、健康、存活：8 维；
- 最多 4 个防守槽和 4 个攻击槽，每槽为目标中心相对位置、相对速度、健康、存活、是否真实槽：`8 × 9 = 72` 维；
- 双方 roster 比例与存活比例：4 维。

目标固定在关系坐标原点；双方分别按距目标距离和特征字典序排序。`present` 与 `alive` 分离，因此阵亡单位不会被误当 padding。回归测试会随机置换实体行，确认输出完全不变。这个编码适用于 HAD 当前同质 4v4 容量；SMAClite-AD 若保留兵种、射程或冷却信息，应实现自己的 canonicalizer，不能静默丢弃这些字段。

## 4. 模型、训练与校准

### 4.1 联合结局—时间分布

本次 `K=8`、每桶 10 步、总 horizon 80 步，模型输出 17 类：

```text
防守胜@B1...B8，目标失守@B1...B8，timeout
```

由同一个 softmax 分布直接求和得到：

- 防守成功概率（防守终结或存活至 horizon）；
- 任意时刻失守概率；
- 30 步指挥窗内失守概率；
- timeout 概率；
- 按时间桶中点计算的预计剩余步数。

输入由 84 维状态、显式人数、指挥窗/总窗、`policy_id@policy_version` one-hot、能力版本 one-hot 和可选行为上下文组成。未知 ID 映射到 `<UNK>`。本次训练复制一份训练样本并分别以 20% 概率替换双方 policy 与 capability（固定 seed；实际命中防守 30 行、攻击 24 行、capability 25 行），避免这些列保持随机未训练状态。它只提供“无已知身份”的退化输入，正式开集实验仍必须加入行为上下文并单独评估，不能据此声称识别未知 checkpoint。

### 4.2 Bootstrap ensemble 的正确解释

5 个成员用不同初始化和有放回的 **lineage-group clusters** 拟合；一个 group 内全部 roots、策略对和 UNK 增广行同时被抽中或排除。成员标准差、预测熵和互信息只表示 **模型分歧**；它们不是覆盖区间。

### 4.3 两级独立校准

1. 12 个 Temperature-Cal groups 只选择联合类别温度；本次温度 `3.7498`，该集合 joint NLL 从 `3.8996` 降至 `2.1330`；
2. 模型和温度冻结后，另用 12 个互斥 Risk-Cal groups 聚合 `(root,candidate)` 残差；
3. 普通候选 offset 为 `0.6131`；按每个独立父谱系取全部 sibling roots/candidates 最大残差后，group-max offset 为 `0.7331`；
4. Test 在两步校准完成后只评估一次。该 pilot 的单候选 rollout 仍不足以把经验上界解释成部署保证。

offset 很大不是“安全性很好”，而是当前样本少、每个候选只有一次确定性 rollout，风险估计不够尖锐。正式数据应对同一 root/candidate 做多随机 continuation，再校准真实频率；否则 0/1 单样本会迫使上界接近 1。

## 5. 指标体系：名称、直观意义与决策用途

| 类别 | 输出指标 | 一眼可懂的含义 |
|---|---|---|
| 联合分布 | joint NLL / Brier / accuracy / top-3 accuracy | 整个“谁赢、何时结束”的概率质量 |
| 防守/失守/超时 | Brier、NLL、accuracy、balanced accuracy | 概率误差和 0.5 阈值分类是否可靠 |
| 排序能力 | ROC-AUC、Average Precision | 高风险候选是否真的排在前面 |
| 概率校准 | ECE、MCE、预测均值减真实频率 | 是否系统性乐观/悲观，最差概率桶偏差多大 |
| 描述性频率 | row-level Wilson 95% | 只描述 48 个相关候选行；不是按 12 个 root 聚类的置信区间 |
| 短窗风险 | 30 步失守 Brier/NLL/AUC/recall | S3 当前指挥窗直接使用的风险 |
| 剩余时长 | MAE、RMSE、中位绝对误差、terminal-only MAE | 预计还可坚持多少步；RMSE突出灾难性大误差 |
| 简单基线 | 训练集平均时长的测试 MAE | 时间预测是否真的优于“永远猜平均值” |
| 人群切片 | 每个 NvM 的全部失守/短窗/时间指标 | 平均值是否掩盖某个人数配比失效 |
| 策略切片 | 每个防守策略 × 攻击策略指标 | 是否保留克制关系而非只学人数 |
| OOD 策略 | seen / held-out policy-pair 指标 | 未见策略对是否退化；本 smoke 尚无 held-out 对 |
| 模型分歧 | breach std、p90 std、预测熵、互信息 | 哪些输入超出成员共识；不是覆盖保证 |
| 风险上界 | candidate coverage、平均/中位宽度、最坏欠覆盖 | 上界是否覆盖且是否窄到有用 |
| S3 决策审计 | post-selection coverage、平均/最坏 regret、排序一致率 | 经“挑最好候选”后是否仍可靠，以及选错付出多少 |
| 最坏切片 | 最大规模 Brier、最大规模 time MAE | 用一个数字暴露最差规模，而非只报平均 |

所有 JSON 都内嵌中文 `metric_definitions_zh`。AUC 在测试切片只有一种类别时返回 `null`，不会伪造为 0 或 1。

## 6. 真实 HAD forward-rollout smoke

### 6.1 设置

- Windows + `torch310`：Python 3.10.20、PyTorch 2.13.0+cu130；
- GPU：NVIDIA GeForce RTX 5070 Ti；
- 场景：单目标 `2v1、3v1、3v2、4v1、4v2、4v3`；
- 防守规则：`guard、intercept`；攻击规则：`rush、split_rush`；
- 每个规模 12 个互不重叠的 master seeds，每个 root 运行 4 个策略对，共 288 条；
- 模型：5 × 64-hidden MLP，80 epochs，CUDA；
- 完整采集、训练、双重独立校准和测试 wall time：15.58 秒。
- 结果 JSON 的 `data_source` 固定为 `had_forward_rollout`，`evidence_level` 固定为 pilot；合成生成器没有参与本表结果。

### 6.2 主要测试结果

| 指标 | 值 | 本轮解释 |
|---|---:|---|
| Joint NLL / accuracy / top-3 | 2.1298 / 0.2292 / 0.6250 | 联合细分类明显困难，尚不可用 |
| 失守 Brier / NLL | 0.2394 / 0.6718 | 仅略有概率信号 |
| 失守 accuracy / balanced accuracy | 0.5833 / 0.5826 | 接近弱分类器水平 |
| 失守 ROC-AUC / AP | 0.6070 / 0.6821 | 去除近重复泄漏后远低于旧 AUC 0.8691 |
| 失守 ECE | 0.1133 | 仍有校准偏差 |
| 30 步失守 Brier / AUC | 0.2737 / 0.3906 | 排序低于随机，本项 **未通过** |
| 时间 MAE / RMSE | 12.15 / 16.75 步 | 误差明显扩大 |
| 平均时长 baseline MAE | 11.50 步 | 模型比均值基线差 0.64 步，**时间建模未通过** |
| 候选风险 coverage / 平均宽度 | 1.000 / 0.481 | coverage 来自极宽、饱和上界，不能解释成精确 |
| 上界平均值 | 1.000 | 对 S3 没有风险区分力，**风险接口未通过** |
| 选择后 coverage / mean regret | 1.000 / 0.333 | coverage 饱和且选错代价明显；不能进入 S3 |
| 排序一致率 | 0.478 | 候选顺序接近随机 |
| Ensemble breach std | 见 JSON | 仅用于分歧排序，不解释为统计置信度 |

新结果推翻了旧 pilot 的乐观判断：旧数据让相同母 seed/目标坐标以不同 scale-root 身份跨分区，旧 AUC、coverage 和 regret 全部作废。修复后只有“训练—双重校准—测试—checkpoint”工程闭环成立；短窗排序、时间预测和可用风险宽度均未通过。本阶段当前结论是 **S2 no-go，不能进入 S3**。

分规模和 4 个策略对的完整 Brier/NLL/AUC/ECE/时间误差都在机器可读 JSON 中。每个规模测试仍只有 8 条记录，且每个候选单元只有一次 0/1 rollout，因此任何局部 AUC 或 coverage 都只能作诊断。

## 8. 正式 S2 实验的下一步接口

进入 S3 之前，按以下顺序扩展，不需要改本轮模型 API：

1. 用 S1 训练得到的规则策略 + 智能策略 checkpoint 替换纯规则对，并保存真实版本/hash；
2. 每个 root/candidate 至少运行多个独立 continuation，得到经验失守率与 Wilson/Clopper–Pearson 区间；
3. 预注册 lineage group/root 数、策略对、规模、随机 continuation 数及 Train/Temperature-Cal/Risk-Cal/Test manifest；
4. 运行 `w/o policy context` 消融；若策略条件模型不优于无条件模型，则不能把克制关系写成贡献；
5. 保留完整策略对作为 held-out pair，并另设未知单策略/行为上下文测试；`<UNK>` augmentation 只防随机未训练列，不能代替该实验；
6. 增加经验频率、逻辑回归、单 MLP 基线，比较 NLL/Brier/时间 MAE 和 decision regret；
7. 增大 calibration roots，目标不是单纯 coverage 高，而是在接近目标覆盖率时显著缩窄上界；
8. 在同一个全局 root 枚举 S3 候选，用真实 counterfactual payoff 重算 post-selection coverage 和 regret；
9. HAD 与 SMAClite-AD 分别训练/校准并分别报告，不能把两个引擎的数据直接混合后称作跨环境泛化；
10. 若联合时间模型在扩大数据后仍不优于均值/分规模均值，先调整时间桶或使用有序/生存建模 baseline，再进入 S3。

## 9. 验收边界

本轮可以确认：

- 监督训练代码真实更新参数且 cluster-bootstrap member loss 从约 2.8 降到约 0.014–0.029；
- CUDA、HAD rollout、数据 writer、父谱系四分、双重独立校准、全指标和 checkpoint 闭环可运行；
- 72 个 master groups 无交叉，Temperature-Cal 与 Risk-Cal 互斥；
- 测试概率归一化，group-max 经验上界数值上不低于点预测；
- JSON 不包含 NaN，单类别指标用 `null`；
- 合成生成器只用于自动测试，发布 smoke 数据源明确为 HAD。

本轮不能确认：

- S1 学习策略或任一 RL 基线已收敛；
- S2 对未见智能策略对有效；
- `<UNK>` augmentation 能带来 open-set 泛化或对手识别能力；
- 95% 风险保证、正式 post-selection 保证或 S3 已得到最优分组；
- 时间预测优于简单基线；
- 短窗失守排序或风险上界宽度已达到 S3 使用门槛；
- 规则策略 smoke 的绝对胜率可以代表 HAD 或 SMAClite-AD 的最终性能。

这些否定项已经保留为下一轮可直接填充的数据和评估接口，而不是用当前小样本指标提前下结论。
