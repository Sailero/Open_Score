# v2.0 小预算验证与汇报口径

本轮已完成已知固定对手下的真实环境训练、合法分组、checkpoint 恢复、配对评估和 E1–E3 诊断。`main_ready` 与 `core_ready` 均正常结束，但只采用单个训练种子和小额交互预算，**没有证明主方法优于基线**。

固定设定为 `reactive` 完整对手、冻结 REFIL-QMIX 下层、两个任务点、50 步时限，每 5 步及非终止减员重决策。本轮训练与推理设备为 CPU，Torch 使用一个线程。主算法在 8v8 开发场景训练；核心比较混合 8v8/12v12 训练并包含 8v8、12v12、16v16 评估。B5 是 ALMA 风格适配，不是严格复现。

## 实验数据的含义

- `main_ready`：B4 小预算训练后，对初始化模型、训练后模型与 `static_matched` 做共同种子的配对评估。`static_matched` 沿用训练后模型本回合的相同初始编组，此后只删除死亡成员；它不是 B0 的均衡初始化规则。
- `core_ready`：B0–B6 在共同测试条件上评估；各学习方法分别训练，规则及 DLOM 不训练。各规模分别报告完整配对数，不能把三个规模合成更多训练种子。
- E1/E2/E3：区分分组是否真正改变执行、共同候选的价值排序，以及局部释放范围。少量诊断回合只提供线索，不证明整个动作空间的最优性或算法优势。

## 主算法实际结果

`main_ready` 完成 **2,003 个物理交互步、628 个上层事件、10 次 PPO 更新**，训练用时 39.47 秒；随后完成 20 组三路配对评估，共 60 局，用时 17.92 秒。两段合计约 57.4 秒，不含程序启动和报告收尾。该次运行与其他验证并行，耗时不能视为独占硬件基准。

| 策略 | 成功/回合 | 决策耗时中位数/P95 | 平均释放比例 | 约束违规 |
| --- | ---: | ---: | ---: | ---: |
| 初始化模型 | 0/20 | 6.60 / 11.38 ms | 0.477 | 0 |
| 训练后 B4 | 0/20 | 4.70 / 9.51 ms | 0.211 | 0 |
| 相同初始化静态对照 | 0/20 | 0.05 / 0.09 ms | 0 | 0 |

**三个策略均为 0/20，没有成功率提升证据。** 每个成功率的 95% Wilson 区间为约 [0%, 16.1%]，仅描述评估回合不确定性。模型参数确有变化，但释放比例下降、约束合法和链路跑通都不能替代任务成功率证据。

数据见 [训练日志](../outputs/v2_validation/main_ready/training.jsonl)、[2,003 步模型快照](../outputs/v2_validation/main_ready/snapshots/step_2003.pt)、[评估报告](../outputs/v2_validation/main_ready/eval_step_2003/briefing.md)及[评估表](../outputs/v2_validation/main_ready/eval_step_2003/results.csv)。72 项实现测试已经通过；测试通过不代表研究假设成立。早期源码试跑不并入当前结果表。

另从 Git 暂存文件导出独立目录，实际通过了 64 步训练及 2 组配对评估的脚本验证，说明运行不依赖已删除的旧文件。它属于部署完整性检查，不并入研究结果。

## 续训恢复验证

对同一模型额外给出 3 秒训练预算，实际新增 201 个物理步和 1 次更新，用时 4.08 秒；安全更新边界造成约 1.08 秒超时。当前 `latest.pt` 因此为 **2,204 步、11 次更新**，原 2,003 步模型已归档。建议续训命令从这个最新状态追加 20 分钟。

随后同一组 20 个评估种子中，训练后模型为 **1/20**，初始化与相同初始化静态对照均为 **0/20**。训练后成功率 5%，其 95% Wilson 区间约 [0.89%, 23.61%]；样本不足以支持稳定优势。评估用时 18.64 秒，连同恢复训练与程序收尾整次约 24.6 秒。

这是同一个训练种子的继续运行，且重复使用原评估种子；不能将两轮合并成独立训练重复或合计 40 个独立评估样本。新结果见 [最新训练状态](../outputs/v2_validation/main_ready/status.json)及[2,204 步评估报告](../outputs/v2_validation/main_ready/eval_step_2204/briefing.md)。

## B0–B6 小预算核心比较

`core_ready` 中，五个学习方法各完成约 2,000 步训练（实际 2,002–2,004 步），B0/B1 不训练。8v8、12v12、16v16 各完成 20 个全方法配对单元，共 **60 组、420 局**，没有未完成配对，约束违规均为 0。评估耗时 211.84 秒；包括训练和诊断的整条比较流程约 506.1 秒（8 分 26 秒），其中存在其他验证任务的并行竞争。

| 方法 | 8v8 成功/回合 | 12v12 成功/回合 | 16v16 成功/回合 |
| --- | ---: | ---: | ---: |
| B0 静态均衡分组 | 0/20 | 0/20 | 0/20 |
| B1 DLOM 期望代理搜索 | 0/20 | 0/20 | 2/20 |
| B2 完整重构 | 1/20 | 0/20 | 2/20 |
| B3 随机释放 | 3/20 | 0/20 | 2/20 |
| B4 选择性重构 | 0/20 | 1/20 | 2/20 |
| B5 ALMA 风格适配 | 0/20 | 0/20 | 3/20 |
| B6 规则释放 | 0/20 | 0/20 | 3/20 |

B4 没有形成一致领先；各方法成功回合较少，不据这张小样本表作算法排名。B4 在三个规模的决策 P95 分别为 7.25、10.77、14.62 ms，平均释放比例分别为 0.185、0.204、0.235。决策较快或释放较少本身不代表任务更有效。

核心比较使用 8v8/12v12 混合训练，主算法快速验证只用 8v8；两者不能合并为独立训练种子的重复实验。详细指标见 [核心比较报告](../outputs/v2_validation/core_ready/comparison_report.md)与[逐方法评估表](../outputs/v2_validation/core_ready/reactive/seed_20260905/comparison/a616f1298b0c/results.csv)。

## E1–E3 诊断

诊断保存 3 个状态，完成 200 次真实续行、3,481 个物理步，用时 21.42 秒：

- E1 完成 4 对固定任务归属的组关系比较，首步动作和物理轨迹均不同，最终成功差异为 0 对。这证明组关系能影响执行，不能证明成功率提高。
- E2 完成 3 个共同候选池（16、16、10 个候选）的独立续行评价，全部失败。当前样本无法识别有效候选、代理排序质量或高收益动作所需的最小调整量；零参考差距不是有效性证据。
- E3 完成 12 个同释放人数的对照模式，使用同一训练模型和修复器切换释放规则。样本量不足以判断学习释放优于完整或普通局部调整。

逐候选结果、独立随机种子和轨迹见 [诊断报告](../outputs/v2_validation/core_ready/reactive/seed_20260905/diagnostics/a616f1298b0c/diagnostics.md)。

## 执行器诊断

额外的冻结下层诊断共 40 局：8v8 的全部蓝方输入与局部输入上限均为 0/10；16v8 分别为 3/10 和 6/10。所有蓝方始终保留在共享物理环境中，权重未改变。这提示执行器输入范围与任务难度值得继续检查，但小样本点估计不能证明输入裁剪有效，16v8 也不替代主任务。细节见 [执行器诊断报告](../outputs/v2_validation/executor_probe/report.md)。

## 接下来如何运行

当前主算法的追加训练命令见 [README](../README.md)。建议先追加 20 分钟训练，再给每个策略计划 100 局、最多 4 分钟的配对评估，整条命令预计 21–25 分钟。时间在完整计算或配对边界检查，实际耗时可能越过名义上限。

恢复从最近完成更新继续，累计交互步数和日志保留，新回合使用继续推进的训练种子；代码、任务配置及冻结资产必须兼容。新增预算不是训练收敛的声明。若成功率仍为零，应优先检查任务难度、下层执行能力与稀疏回报，而不是直接将问题归因于训练时间不足。

汇报应同时展示实际训练步数与更新数、配对成功数/回合数、决策耗时、释放和实际变化量、约束违规数，以及失败轨迹。正式结论还需要冻结预算后的多训练种子比较和足量独立评估。
