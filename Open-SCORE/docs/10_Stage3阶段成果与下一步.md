# Stage3：目前的结果、方法含义与下一步

> 本页是 Stage3 的简明阅读入口，后续在同一文件更新。数据截点：2026-09-05 16:06（北京时间）；实现版本：`690d83e`。完整方法见 [方法文档](07_MVP完整方法_S1-S3.md)，详细设置见 [实验协议](08_S3实验执行与分析协议.md)，最终结果仍统一保存在 [Stage1–3 综合报告](../outputs/stage123_unknown_upper_v1/experiment_report.md)。本页中的未完成结果不代替正式全量结论。

## 1. 先回答最关心的两个问题

**现在的主方法还没有证明接近知道蓝方策略的参照方法。** 在唯一已经完成整套比较的条件中，主方法赢了 6/10 局，知情参照赢了 10/10 局，相差 40 个百分点，超过希望控制在 10 个百分点以内的目标。这是一个明确的局部不足，但还不能据此判断全部场景。

**也不能说它完全没有改善。** 同一条件、同一批种子下，旧方法赢了 5/10 局，主方法赢了 6/10 局，多赢了一局。这只能算改善的迹象，尚不足以说明稳定提升。与此同时，主方法平均一次决策需要 25.17 秒，旧方法为 4.36 秒，计算时间约为旧方法的 5.8 倍。目前没有足够证据说明这份额外计算值得。

因此，当前准确的结论是：**实验基础比以前清楚了，但更复杂的主方法还没有证明更好，也没有达到实时使用要求。** 下一步应优先解决计算浪费，并判断“观察对手”和“多步规划”各自是否带来了实际收益。

## 2. 我们究竟在研究什么

底层已经能够执行运动和局部交战命令。Stage3 要决定的是：**哪些红方成员组成一组，去保护哪个目标，准备拦截哪些蓝方成员，以及哪些成员暂时留作后备。**

困难在于红方不知道蓝方本局采用哪一种分配规则，只能看到位置、速度、血量和运动轨迹。我们希望它逐步判断对手的习惯，再作出合适的分组，而不是直接读取蓝方的真实名单。

本轮已经简化为：蓝方整局保持同一种上层规则，不在途中换成另一种规则。固定规则仍可根据位置和伤亡重新安排成员。底层有两种已知运动方式，可以先理解为“直接接近目标”和“组内带侧向偏移地接近目标”。两者都要验证，不能只在其中一种方式下有效。

“知道蓝方策略的参照”，也就是以前说的 **oracle**，知道对手采用哪条规则，但不知道它这一次具体随机选了哪个动作。这比普通红方多了一条重要信息，但不是能够预知一切、永远作出最优决策的神谕。

## 4. 现在的实际结果

### 4.1 先看公平、完整的一组比较

以下全部来自同一条件：**18 个红方、12 个蓝方、2 个目标；蓝方直接接近目标，并采用均衡分配规则。** 八种方法各完成相同的十个种子，共 80 局。

“平均决策时间”指每次重新分组时的准备与规划耗时，不是整局时间，也不是单次神经网络前向时间。

| 后续统一使用的中文名称 | 一句话解释 | 赢了几局 | 平均决策时间 |
|---|---|---:|---:|
| 均分防守 | 把红方大致均匀地派往各目标 | 4/10 | 0.42 秒 |
| 旧版分组 | 使用之前的身份分组求解方法 | 5/10 | 4.36 秒 |
| 短期稳健防守 | 兼顾几种可能的对手分配，主要看眼前五步风险 | 3/10 | 3.20 秒 |
| 规则推断＋短期防守 | 用已知的四条规则解释运动，再作短期响应 | 6/10 | 3.10 秒 |
| 学习推断＋短期防守 | 用训练出的模型判断对手，再作短期响应 | 5/10 | 3.31 秒 |
| **学习推断＋多步规划（主方法）** | 根据学习到的判断，模拟后续分组及终局 | **6/10** | **25.17 秒** |
| 知道策略的参照 | 提前知道蓝方采用哪条规则，再作多步规划 | 10/10 | 15.32 秒 |
| 看见当前分组的参照 | 直接看见蓝方这次的完整分组，再作短期响应 | 8/10 | 3.15 秒 |

这个表目前支持四个观察。

第一，主方法还没有接近知情参照。第二，相对旧版分组，它只多赢了一局，不足以证明稳定改进。第三，在这个条件下，“规则推断＋短期防守”用少得多的时间，也赢了六局，所以学习模型和多步规划的额外价值仍需证明。第四，最后两种参照的方法不同：一个会往后规划，一个主要作眼前响应，因此不能仅按信息多少要求它们的胜率严格排序。

这些观察都不能推广为总体结论。第二个条件还没有跑齐八种方法，各方法已经完成的局数不一样，因此不把这些未齐的结果混成一个“总排行榜”。

### 4.2 为什么“多赢一局”还不够

假设一种方法十局赢六局，另一种赢五局，我们知道前者在这批对局中表现更好，但不知道换一批初始状态是否仍然如此。

本例里，主方法与旧版分组存在互有胜负的配对：主方法独赢三局，旧方法独赢两局，净胜一局。按已完成这十对计算，胜率差的不确定范围很宽，既容许变差，也容许改善。因此，现阶段可以说“有正向迹象”，不能说“已经显著提升”。

这里也不能把新主方法的 60% 与早期旧实验的 36.7% 直接相减。早期 Blue 的产生方式、信息条件和执行协议不同。判断改进应使用上表中**在新协议下重跑的旧版分组 50%**。

### 4.3 学习模型对蓝方分配的判断还不够准确

QOM 是学习对手行为的组件。它在 360 条独立测试轨迹上的结果为：

| 问题 | 当前结果 | 直观含义 |
|---|---:|---|
| 看过当前窗口的运动后，能否判断每个蓝方攻击哪里？ | 51.1% | 按记录中的存活成员逐个评分，约一半目标判断正确 |
| 还没看到新动作的运动，能否预测下一次攻击哪里？ | 45.3% | 提交动作前的预测，含对手尚未公开的随机选择 |
| 能否判断哪些蓝方属于同一组？ | 同组关系 F1 为 0.265 | 成员关系预测仍弱；这个数不能直接读成 26.5% 准确率 |

这里的 51.1% 是**目标分配判断**，不是“识别出蓝方策略类型的概率”，更不是红方胜率。本轮希望第一个指标至少达到 80%，当前这批独立轨迹上还没有达到。

这些测试轨迹由简单红方探测规则采集，正式主方法可能产生不同轨迹。正式对局中的指标还要另算，不能拿测试集结果直接替代，但也不能忽略这里已经出现的不足。

### 4.4 计算时间也是当前负结果的一部分

在上表相同条件中，主方法平均每次决策 25.17 秒，P95 为 54.02 秒。“P95”可以理解为：按已记录的决策时间排序，约 95% 不超过这个数，还有约 5% 更慢。早先交流中的 25.7 秒和 56.4 秒来自包含另一未完成条件的耗时采样；这里改用同一个完整条件，让胜率和耗时对应。

单次决策会模拟很多未来物理步，所以慢不等于神经网络很大。一次独立剖析发现约 2.4 万次组匹配、309 万次到达时间计算，组匹配累计约占该次剖析的 45%。剖析本身会增加运行时间，不能用它的总秒数代替正式耗时，但足以确认重复计算热点。

当前程序计算时，仿真世界会等待。它尚未把“算了几十秒，蓝方已经继续移动了”的损失计入胜率。若将环境一个时间单位理解为一秒，每五步重规划对应的常规窗口只有五秒，当前主方法显然不满足这一要求。这是需要修正的实验与部署边界。

## 5. 只需要先理解这几类指标

| 名称 | 它回答的问题 | 怎样判断 |
|---|---|---|
| 防守胜率 | 一批对局里守住所有目标的比例是多少？ | 越高越好；同时看局数和测试条件 |
| 与知情参照的差距 | 不知道蓝方规则，比知道规则少赢多少？ | 越小越好，但参照本身也应有较好胜率 |
| 目标分配判断准确率 | 根据轨迹，猜对每个蓝方要去哪个目标的比例是多少？ | 越高越好；不等于防守胜率 |
| 决策时间 | 一次重新分组要等多久？ | 看平均值，也看较慢情况的 P95 |
| 置信区间 | 由于测试局数有限，估计可能有多大不确定性？ | 差值区间跨过零时，不能轻易断言谁稳定更好 |

“百分点”与“百分比”不同。胜率从 50% 到 60%，是提高 **10 个百分点**。知情参照 100%、主方法 60%，是差 **40 个百分点**。

目标分配指标在代码里写作 `micro-F1`。因为本任务中每个存活蓝方只能对应一个目标，它等于按这些成员预测记录汇总的准确率。统计同组成员对时，F1 综合了“预测同组的成员对有多少是真的”与“真正同组的成员对找回了多少”，不能再当成普通准确率。

## 6. 当前需要做什么：按顺序，而不是继续堆方法

### 第一步：先把明显的计算浪费去掉

同一公开状态下，成员到目标的距离、到达时间和组质心没有必要反复计算。应先缓存这些量，复用同一组动作的匹配结果，并去掉物理分支里生成后又被丢弃的全局观测。再把多个小组和对手模式的网络计算合成批量调用。

这一步主要改执行效率，不训练新的 Stage1/2，也不为了提速悄悄减少候选和搜索次数。只需少量有针对性的同快照一致性校验，确认缓存没有改变匹配、动作或物理结果，再测一次实际决策耗时。提高 worker 数可以另行改善整批实验吞吐量，但不能替代单次延迟优化。

**完成标志：** 给出相同输入、相同预算下的优化前后耗时，并确认决策语义一致。现在不能预先保证提速几倍。

### 第二步：给“可用”一个明确的时间标准

当前只规定“每次模拟 32 次”，没有把墙钟时间作为硬约束。同样模拟 32 次，不同人数和不同方法的耗时可能差很多。

建议把常用上层决策压到一秒以内作为工程目标，并根据实际事件间隔确定最大等待时间；五秒只能作为当前常规窗口下的候选上限，伤亡事件可能需要更短。这个预算目前是建议，尚未修改正式配置，也不是已经达到的性能。

如果去掉重复计算后仍然太慢，再考虑减少昂贵的终局续演，用学到的未来价值或快速候选评分辅助搜索。这样的修改属于方法变化，需要有独立版本，不能与原结果混为同一方法。

**完成标志：** 主方法与知情参照在相同允许等待时间下比较，记录超时比例，并明确超时时执行什么合法动作。

### 第三步：优先完成两个已经注册的关键对照

目前最缺的不是更多方法名称，而是下面两个问题的答案：

| 关键问题 | 对照方式 | 为什么重要 |
|---|---|---|
| 观察历史、逐渐修正判断是否有用？ | “规则推断＋多步规划” 对 “每次重新猜＋多步规划” | 两者使用同一规则库和规划预算，主要区别是是否保留历史判断 |
| 学习出来的行为模型是否比规则库更有用？ | “学习推断＋多步规划” 对 “规则推断＋多步规划” | 两者都进行多步规划，能更清楚地检查学习组件的价值 |

这两个对照已经在原 480 局计划中，不需要再添加零散试验。后续应优先安排成套的注册对照，尽早支持研究判断；它们不能代替最终完整网格。

如果规则推断能接近知情参照，而学习推断不能，优先处理学习模型的目标、同组预测及动作生成问题。若两者都不行，再看公开运动是否足以区分策略，以及好的成员组合是否进入了候选。不要预设一定是训练次数太少。

### 第四步：让多步规划证明它值得花时间

主方法在当前完整条件里与短期规则方法同为六胜，但慢得多。下一步需要回答：在给定时间内，多考虑未来到底能多赢几局？

应同时看短期响应、多步规划和知情参照。如果多步规划没有稳定收益，就应修改搜索和未来价值估计，或暂时采用更简单的方案。不能因为方法已经命名为主方法，就把复杂性本身当成贡献。

同样，知情参照与未知方法共享候选。若两者都很弱，差距小也不代表成功；可能只是双方都没有找到好的分组。

**完成标志：** 额外计算对应可重复的防守收益，或明确报告当前多步规划不值得其成本。

### 第五步：最后用完整网格决定论文结论

经过性能修正和必要的方法判断后，再以明确版本完成全量评估。仍需覆盖 30/40/50 人、两种已知底层、四种固定上层类型，保留共同种子和全部负结果。

若只是并发设置改变，耗时应注明并发条件；若代码或策略改变，必须记录版本并遵守输入哈希校验，不能把旧实现和新实现的时间混成一个指标。既有数据和模型在满足复用条件时保留，不无理由重训底层。

当前主方法仍是预先登记的“学习推断＋多步规划”。如果后续发现规则模型更好，原主方法的负结果应保留；改换论文方法时重新登记版本，并使用独立的最终验证，不能在同一测试集上反复挑赢家。

论文首先要证明的是一个集中问题：**在合理的决策时间内，利用公开轨迹判断对手，能否改善具体成员分组，并缩小与知情参照的差距？** 现在不扩展未知底层、局中策略切换或 Stage4。

## 7. 中文名称与代码名称对照

阅读正文先使用中文名称。只有查配置、日志或原始文件时，才需要右边的代码名称。

| 中文名称 | 代码名称 |
|---|---|
| 均分防守 | `balanced_identity` |
| 旧版分组 | `legacy_idb` |
| 短期稳健防守 | `event_risk_idb`，简称 ER-IDB |
| 规则推断＋短期防守 | `finite_type_bbr`，简称 FT-BBR |
| 学习推断＋短期防守 | `qom_bbr` |

| 每次重新猜＋多步规划，关键对照待完成 | `prior_mcp` |

几个经常出现的词可以这样理解：

| 术语 | 在本项目中的意思 |
|---|---|
| Stage3 / 上层决策 | 选择谁和谁一组、去哪里、何时重新安排 |
| 身份级 | 区分具体成员，而不只关心派了几个人 |
| Blotto | 用有限资源争夺多个目标的一类分配博弈 |
| 信念 / posterior | 对几种可能的蓝方策略或行为模式分别有多大把握 |
| Bayesian / 贝叶斯更新 | 根据新看到的运动，调整上面的把握程度 |
| 有限类型 / FT | 假定蓝方来自已知的几条规则，但不知道本局是哪条 |
| QOM | 从轨迹学习若干行为模式，再用这些模式预测蓝方分配 |
| BBR | 根据目前对蓝方的判断，选择有利响应；当前实现主要作短期评估 |
| MCP / MCTS | 多次模拟可能的未来，用模拟结果挑选当前动作 |
| PUCT | 给搜索中“当前看起来好”和“还没充分试过”的动作分配模拟机会 |
| 候选动作 | 预先生成的若干套合法部署；当前最多保留八套供选择 |
| BA-DIB | 本项目整套上层建模框架的名称，不是额外第十一种实验方法 |
| SALDAE | 早期改进联盟搜索的求解器，仅保留历史对照，不是当前对手推断组件 |

例如，对两种规则分别有 50% 的把握，观察后变成 80% 和 20%，就是一次信念更新。这只是解释概念的例子，不是本实验的实际后验数值。
