# 工作量、论文档位与收缩边界

## 1. 当前判断

收缩到局部最多4v4、S2小MLP后，方法比上一版清楚，但 S3 的真实工作量不能写成“小型LP”：LP很便宜，策略条件数据、未知对手上下文、组合候选 oracle、列生成和宏观闭环才是成本。完整S1–S4仍不是1–2个月可完成的工作。其论文水准取决于是否在同等预算下击败端到端、ALMA-style、Double-IC/Blotto等强 baseline，而不是阶段数量。

## 2. 工作量估计

| 工作包 | 人日 | 最小交付 | 最大风险 |
|---|---:|---|---|
| S1 HAD QMIX | 15–24 | 双边训练、16规模、3 seeds | 环境吞吐/探索 |
| S1 PSRO | 10–18 | payoff、BR、3–8轮 | 近似BR不稳定 |
| Open-HAD复现接口 | 10–18 | 私有PRNG、clone、测试 | 改变旧环境语义 |
| S2 | 16–26 | 策略条件数据集、MLP ensemble、选择后校准 | root/策略 lineage 泄漏 |
| S3-L1 | 22–35 | 对手上下文、匹配、双边列生成、LP、闭环 | 组合 oracle 与局部风险失真 |
| S3-L2/3（条件项） | 10–18 | 离散宏观转移、滚动求值 | 模型误差累积 |
| S4-A | 10–18 | 宏观 value residual、guard | credit assignment/离线偏差 |
| S4-B（条件项） | 18–30 | 种群追加、增量 S2、cross-play | 非平稳/重复采样/遗忘 |
| SMAClite-AD | 15–25 | 双边API、目标、关键复验 | C++/Gym兼容 |
| 正式实验与论文 | 22–35 | 5 seeds、统计、复现包 | baseline重跑 |

核心 S1–S3-L1 + S4-A + 双环境与正式实验约140–220人日；加入 S3-L2/3 与 S4-B 后约168–268人日。单人完成核心闭环约8–13个月，完整扩展更接近10–16个月；两人仍有 S1→S2→S3 的串行依赖。

## 3. 近期可执行周期

S1的合理周期是5–8周：

| 周 | 代码 | 实验 | 决策门 |
|---|---|---|---|
| W1 | 双边runner、buffer | 随机动作/吞吐 | 环境语义正确 |
| W2 | sequence QMIX | 1v1、2v2过拟合 | 双方都能学习 |
| W3 | 多规模factory | 插值协议 | 同一网络跨规模 |
| W4 | baseline/evaluation | 16格胜率矩阵 | 最坏表现可接受 |
| W5 | payoff evaluator | self-play vs population | 是否启用PSRO |
| W6–7 | PSRO 3轮pilot | NashConv/BR曲线 | 是否扩大到8轮 |
| W8缓冲 | 性能与失败seed | 最终S1报告 | 继续或停止 |

用户最初的1–2个月目标可以完成S1及PSRO pilot，不能承诺四阶段论文投稿。

## 4. 论文档位

| 完成范围 | 可能形态 | 合理档位 | 主要缺口 |
|---|---|---|---|
| S1 HAD | 技术报告/预实验 | 不足Q2 | QMIX+PSRO新意有限 |
| S1–S3 HAD | 可解释开放分组 | Q2候选 | 单一自建环境 |
| S1–S3 + S4-A HAD | 结果对齐的双方动态分组 | 强Q2候选 | 外部有效性/理论界较弱 |
| S1–S4-B HAD | 种群式共同适应 | 强Q2/弱Q1边缘 | 训练成本与稳定性 |
| 双环境且胜过端到端 | 统一系统论文 | 强Q2/弱Q1边缘 | 理论保证有限 |

如果 S4-A 不能稳定提高最终胜率，最诚实的论文范围是 S1–S3，不应继续投入 S4-B；如果 S3 的显式博弈也不如高层 MAPPO、Double-IC 或完整枚举 oracle，则需要重新定位为“可解释性/稳健性换取部分峰值性能”，不能继续声称性能改进。

## 5. 一篇还是两篇

首选仍是一篇统一论文，因为四阶段共同回答“局部能力如何组成开放人口下的全局博弈”。但可按失败模式拆分：

- 论文A：S1–S3-L1/S4-A，策略条件局部博弈驱动的开放人口双方稳健分组；
- 论文B：S3 多步规划与 S4-B，策略种群变化下的能力—指挥共同适应。

不建议单独发表“S1 = QMIX + PSRO”，除非发现新的跨规模种群训练机制或形成公开benchmark。

## 6. 本学期范围建议

本学期最合理的目标不是完成四阶段，而是建立能决定项目生死的最小证据链：

1. 完成 S1 及小型策略库；
2. 用策略对条件采集一版 S2 数据，证明/否证“非传递性会被人数模型平均掉”；
3. 在可完整枚举的小型全局场景验证 S2 驱动的分组 decision regret；
4. 实现 S3-L1 固定候选，再加入双边列生成并测候选数—gap—时延；
5. 对手未知只先做隐藏库内身份 + 一组留出/切换策略；
6. 最多做到 S4-A，只有其有效才把 S4-B 排入下一阶段。

这个范围能回答 S3 是否有可行模型、组合求解是否降本以及 S4 是否真的必要，信息价值高于同时铺开第二环境和完整 joint training。

## 7. 投稿方向

期刊分区每年变化，投稿时必须重新核对JCR/中科院和单位口径。方法如果以多智能体系统为主可考虑 JAAMAS；偏算法与复现可考虑 Applied Intelligence；偏工程仿真可考虑 Engineering Applications of Artificial Intelligence。不能用当前文档保证具体分区或审稿速度。
