# 相关工作、SMAClite 与 PSRO 审计

> 调研更新日期：2026-08-30；本机环境审计日期：2026-08-30。所有“本文方法”均是待实验目标，不是已有结果。

REFIL 和 ALMA 仍然重要，但不再直接决定本文 S2 的网络。S2 面对的是已经规范化、最多 4v4 的监督学习问题，小 MLP 足够作为首版；Set Transformer只保留为“MLP在实体排序/规模上失败时”的升级项和消融，不进入默认方法。

### 1.1 变人数训练采用什么，而不采用什么

REFIL 证明一个参数共享、实体输入的价值分解模型可以跨不同队伍/实体数量训练；EPC 证明从小人口逐级扩大比直接训练困难人口更稳；SPMARL 进一步指出仅用绝对回报判断课程难度会误导，并以 TD-error 的学习进展调节人数任务。三者共同支持当前实现：**一套共享模型 + 分阶段解锁 + 已解锁任务内学习进展采样**。

当前代码并非复制 SPMARL：它将其思想缩减为快慢 TD-error EMA 之差，加访问次数奖励并混入 20% 均匀覆盖。必须与全程均匀随机、纯线性 EPC 式课程和逐规模独立 QMIX 比较；若没有样本效率或最坏规模收益，该课程不是贡献。

这张表意味着：**“动态规模”“层次分组”“双方联盟”“对手建模接入决策”“分兵后进行子博弈”都不能单独作为创新。** 本文能争取的是这些结构在开放人口、未知策略和多阶段局部执行下的统一、计算可控及误差可审计。

## 2. SMAClite 是否适合

### 2.1 适合的部分

[SMAClite（AAMAS 2023）](https://arxiv.org/abs/2305.05566)是脱离 StarCraft II 的 NumPy/Gym 重实现，[官方仓库](https://github.com/uoe-agents/smaclite)支持 JSON 场景/单位定义和可选 C++ RVO2。论文报告其内存约为 SMAC 的六分之一；启用 C++ RVO2 的 `SMAClite_plus` 在所测场景中比 SMAC 每步快约 17%–51%。它非常适合：

- Windows 上快速跑大量 S1/S2 rollout；
- 用 JSON 创建 1–4 对 1–4 场景和不可移动目标单位；
- 复用 ePyMARL/QMIX/VDN/MAPPO baseline；
- 作为 HAD 之外的二维动力学确认。

### 2.2 不能忽略的限制

1. 纯 Python SMAClite 在论文多个场景里反而比 SMAC 慢，性能优势主要来自可选 C++ RVO2；必须在本机实测，不能只写“轻量所以更快”。
2. 原版只接收 allied actions，敌方从初始化起固定 `attack_move`；双边 PSRO 需要开放 enemy action API。
3. 原版动作是 stop、四方向移动和指定单位攻击，不是 HAD 的连续/量化加速度。
4. JSON group 只定义初始布置；原版没有保护目标语义、随机目标区域、增援和双方分组接口。

### 2.3 最终定位

采用 **SMAClite-AD** 作为第二环境，而不是替代 HAD：

- 新增一个速度为零、伤害为零的 protected asset 单位；
- reset 时在注册区域随机化资产位置；
- 同时暴露 allied/enemy actions，双方共享相同动作规则；
- 加入 `set_assignment`、active mask 和人口事件；
- 保留一组未修改的标准 SMAClite 场景复现 QMIX/VDN，证明扩展没有破坏基础接口。

HAD 与 SMAClite-AD 的底层动作不必相同：HAD 验证纯加速度控制，SMAClite 验证标准 SMAC 微操命令。论文贡献是上层分解与组合接口，而不是宣称同一个动作头跨物理引擎零样本迁移。

## 3. PSRO 是否“成熟且不难”

结论是：**元博弈求解成熟且容易复用，深度 RL 最佳响应训练仍然昂贵。**

OpenSpiel 已公开 payoff table、meta-strategy、best-response oracle 和 PSRO v2 示例。但它的 RL oracle面向 OpenSpiel game API，不能直接拿来训练 HAD 的多智能体 QMIX。首版应复用算法流程，而不是强行依赖整个 OpenSpiel：

```text
初始化规则策略和 warm-start QMIX 策略种群
→ 跨 HAD 中红方严格多于蓝方的 6 个注册规模评估 payoff matrix
→ LP 求双方 meta-Nash
→ 防守 QMIX 对攻击混合策略训练近似 BR
→ 攻击 QMIX 对防守混合策略训练近似 BR
→ 独立评估并加入种群
→ NashConv与meta value连续3轮稳定、且BR达到预算，或达到最大轮数后停止
```

注意三点：

- PSRO 的一个“玩家”是整个防守团队或攻击团队，团队内部仍由 QMIX 协作；
- 每个 population checkpoint 都是覆盖 1–4 人的条件策略，不为每个规模单独建种群；
- 深度 BR 只是近似，因此只能报告 estimated NashConv 和置信区间，不能宣称求得真实 Nash 均衡。
- 平均 archive/规则策略胜率稳定不构成停止证明；一个未被发现的 exploiter 可以被平均值掩盖。

本轮先完成规则策略和共享动态规模智能策略的独立 warm-start，并复现 QMIX、VDN、MAPPO；PSRO 保留为后续对手多样性实验，不作为本轮 S1/S2 验收门槛。只有两方学习曲线、多 seed 独立评估和计算预算都成立后，才进入 3 轮以上 PSRO pilot。

## 4. 为什么仍然有研究缺口

现有研究已经覆盖可变实体、开放 ad-hoc teamwork、对手建模到动作选择、层次任务分配、双方联盟、Blotto 子战场、策略种群和 joint training。本文不能声称这些单点空白。调研尚未发现一项工作同时满足以下全部条件：

1. 双方人口在局内因伤亡/增援改变，并触发双方重新分组；
2. 一套局部策略在多个小规模间共享，且保留策略克制关系而非只按人数查表；
3. 局部结局/转移预测经过校准，并直接构成上层双方收益；
4. 对手类型不可见，在线行为上下文实际改变上层稳健集合；
5. 组合候选用 oracle/列生成控制，而非完整枚举或一个不可审计的全局动作头；
6. 最终整局回报通过版本一致的残差/交替更新纠正局部代理目标。

因此可信缺口是：

> 现有证据尚不足以说明，在“多目标、双方人口变化、对手策略不可直接获得”的攻防场景中，策略条件化且可校准的小型子博弈模型，能否通过受限动态双方分组博弈和结果对齐共同适应，在同等预算下优于单体端到端策略、单边层次分配和已有双方联盟求解。

这一表述仍是基于当前检索的“组合缺口”，不是数学上的穷尽性首次证明。开放环境协作 MARL 的综述指出成员和任务动态性仍是主要问题，但不能据此说没有人研究动态团队：[开放环境 MARL 综述](https://arxiv.org/abs/2312.01058)。论文引言应使用“we investigate / we are not aware of a systematic study”，避免“the first”。

## 5. 最终环境与 baseline

### 环境

| 环境 | 论文角色 | 需要改造 | 运行位置 |
|---|---|---|---|
| HAD/Open-HAD | S1 Demo、主诊断环境 | 双边控制、随机单目标、后续 clone/增援 | Windows 原生 |
| SMAClite-AD | 第二动力学与高吞吐 | 双边 API、保护目标、人口事件 | Windows，先纯 Python |
| SMAClite 标准场景 | 外部 sanity check | 不修改任务 | ePyMARL 路线 |
| ALMA `sc2multiarmy` | 最近方法复现锚点 | 只复现/适配 baseline | 后期 WSL2 |
| [Gigastep](https://openreview.net/forum?id=UgPAaEugH3) | 大规模双队压力测试 | 任务适配 | WSL2 + JAX |
| [MAgent2](https://github.com/Farama-Foundation/MAgent2) | 网格超大规模补充 | 场景重定义 | Linux/WSL2，可选 |

不再把 Open-SMAX-AD 作为首选第二环境；SMAClite 更容易在当前 Windows 机器上修改和复现。只有 SMAClite 吞吐或控制接口改造失败时才回退到 SMAX。

Gigastep 是 NeurIPS 2023 的双队、向量化 JAX 环境，适合检验层次方法在更大人口下的吞吐与规模趋势；但本机当前是原生 Windows + PyTorch CUDA，JAX GPU 更适合 WSL2，因此不应阻塞 HAD/SMAClite 主线。MAgent2 面向高性能网格群体且官方平台不含 Windows，物理抽象也与三维加速度相差较大，只能作为可选第三证据。最终顺序是：**HAD 先验证控制语义，SMAClite-AD 做第二动力学和基线复验，Gigastep 在论文主结论成立后做大规模外推。**

### baseline

- S1：Shared-IQL、VDN、Fixed-Capacity QMIX、REFIL/Attention-QMIX、Variable-Scale QMIX；训练方式比较 self-play 与 PSRO。
- S2：经验频率、逻辑回归/单 MLP、五成员 MLP ensemble、无策略条件模型；Set Transformer仅作可选复杂 baseline。
- S3：固定分组、人数均衡/最近目标、ALMA-AQL、Double-IC、Blotto 特例求解、点预测贪心、完整候选 maximin、本文 ambiguity-set + 列生成、高层 MAPPO。
- 全系统：Monolithic Variable-Entity QMIX、Monolithic MAPPO、ALMA-style hierarchy、Frozen S1–S3、Full S1–S4。

CUDA、HAD、SMAClite stock/AD 和 Stage2 forward-rollout smoke 均已在这台 RTX 5070 Ti 上完成。`python -m pip check` 当前没有报告破损依赖。为兼容官方 ePyMARL 使用的 Sacred 0.8.7，`setuptools` 固定为 80.9.0；其 `pkg_resources` 弃用提示属于已知旧栈告警，不是训练失败。

Git 2.55.0 已安装在 `D:\Software\Git\cmd\git.exe`，VS Code 用户设置已写入 `git.path`。若仍看到 “Git not found”，需要完整退出并重启 VS Code，让其主进程重新继承 PATH；命令行脚本也都接受显式 `GitPath`，不依赖旧进程环境。

SMAClite v2.0.0 的普通 wheel 会漏打子包和地图 JSON，因此本机使用固定 commit 的 clean editable checkout；官方 ePyMARL 同样固定 commit，并把 stock 与 Open-SCORE 扩展结果分别归档。具体指纹和许可证边界见 [SMAClite 原版与 AD 环境审计报告](09_SMAClite原版与AD环境审计报告.md)。
