# ID-CS-BBG-v5 与 SALDAE-DO-v1 实验执行与分析协议

> 本轮目标：重训完整 1–4v1–4 Stage2，运行身份级硬 4v4 Stage3，并用同种子内部对照和上一版历史结果判断修改是否有意义。数学定义见 [07_MVP完整方法_S1-S3.md](07_MVP完整方法_S1-S3.md)。

## 1. 固定实验设置

### Stage2

| 项目 | 固定值 |
|---|---|
| 初始人数域 | Red 1–4 × Blue 1–4，共 16 个格点 |
| Blue 底层规则 | `rush`、`split_rush` |
| 独立 episode | 每格点每规则 600 局，共 19,200 局 |
| 保存事件 | 步 0、5、…、45；非空伤亡状态 |
| 控制器语义 | 每个保存/指挥事件重置 Stage1 循环状态 |
| 数据切分 | 按 episode lineage 分 train/validation/calibration/test |
| 空方 | `p(r,0)=1`、`p(0,b)=0`，解析给定 |
| 4 人以上 | 不采样、不训练、不外推、不作为合法 Stage3 动作 |

Stage2 只汇报 Brier、ECE、AUC、剩余时间 MAE、16 配比初始胜率平均绝对误差和形状违反率。训练 loss 仅用于诊断，不按其是否继续下降决定最终 checkpoint；checkpoint 由 validation 综合分数早停选择。

### Stage3

| 项目 | 固定值 |
|---|---|
| 目标数 | 每局初始化时固定；演示为 2、4、5 |
| 总人数 | 30（18R/12B）、40（24R/16B）、50（30R/20B） |
| 上层动作 | Blue 为带标签 agent 到 `(目标, 通道)` 的完整分区；Red 为活跃组与 reserve 的完整分区 |
| 通道匹配 | 每目标按组规模非增序占用通道；同规模组仍保留身份次序决策 |
| 局部组 | 每侧 1–4 人硬上限；允许无Red对应的 `0v1`–`0v4` Blue组 |
| 同一目标多组 | 允许 |
| reserve | 只允许 Red reserve；每个 Red 恰处于一个活跃组或 reserve，Blue 必须全部活跃覆盖 |
| 对手假设 | Blue 底层规则在该条件中已知；Blue 上层仍战略决策 |
| 求解 | 受限矩阵零和 LP + Red集合装填/Blue集合划分 MILP 最佳响应 + Double Oracle |
| 重规划 | 每 5 步和任一方伤亡事件 |
| reserve执行 | 公开位置威胁巡逻；等待距离350、横向间距90、距离尺度1000 |

## 2. 三组必要实验

### E1：求解器基础正确性

在 3R/3B、2 个目标的完整身份纯策略空间中：

1. 枚举完整纯策略矩阵并求零和均衡；
2. 注册所有 1–4 人联盟列、Red reserve 动作并运行 Double Oracle；
3. 对比价值误差与 exploitability；
4. 必须获得 `full_game_certified=true`。

验收：最大价值误差和最大 exploitability 均不超过 `1e-6`。

约束回归另覆盖：14R 对3个 Blue 单兵可形成三个 `4v1` 加2名 reserve；4R 对10B 可合法产生 `0v4`、`0v2`；每个 Red 身份必须恰好活跃一次或 reserve，每个 Blue 身份必须恰好活跃一次。原失败 seed `20360907` 必须完成整局且不得出现 MILP infeasible。

### E2：30/40/50 人规划

每个规模运行 5 次独立当前态势。只看：

- P95 规划时间；
- 以解析上界 `M·|B|` 归一化后的候选域 exploitability；
- 是否取得候选域证书；
- Red/Blue 候选联盟列数。
- Red reserve 比例和 Blue 无对应防守组比例。

大规模只对预注册候选列负责。未取得候选域证书时仍保存可行 anytime 结果和 MIP 状态，不得报告为完整博弈精确解。

归一化是对整个零和 payoff 的正比例缩放，不改变策略或均衡。预注册门槛为归一化 exploitability 不超过 `0.10`；P95规划时间门槛分别为30人 `8s`、40人 `12s`、50人 `25s`。50人的门槛来自本轮修复前已保存的同硬件规模诊断，不作为实时控制延迟承诺。

为控制通道对称性，30–50 人实验对每个目标只启用配置中明确给出的可扩展活动通道数；候选联盟由全部单兵、目标近邻组、以目标近邻为锚点的同伴组和种子分区组成。因此“候选域证书”既不等于全部身份分区的全局 Nash 证书，也不等于算法失败；限时未获证书时只把返回策略当作可行 anytime 解。

### E3：HAD 共享世界物理对抗

每个 `目标数 × Blue底层规则 × Red方法` 运行 10 局。三个 Red 方法为：

1. `balanced_identity`：均匀身份分组基线；Blue 使用同一身份级博弈求解器的策略。
2. `identity_blotto`：本轮主方法；Red/Blue 同时使用身份级 Blotto 均衡策略。
3. `revealed_blue_br`：从与主方法相同的 Blue 均衡策略采样当前动作并透露给 Red；Red 在相同候选域内用 1–4 人组和 reserve 求最佳响应。

主要效果指标只有 Red 胜率。主要比较是同场景、同 Blue 规则、同初始 seed 的 `identity_blotto - balanced_identity` 配对胜率差及 bootstrap 95% CI。

诊断指标只保留：

- 每局目标数是否始终固定；
- 每个 Red 身份是否恰好属于一个活跃组或 reserve、每个 Blue 身份是否恰好属于一个活跃组；
- 是否存在大于 4 人的组；
- 无 Red 对应的 Blue 组比例；
- reserve 比例、规划时间与 Red 切换数。

`revealed_blue_br` 只在当前 Stage2 代理价值和注册候选联盟域中拥有信息上界含义。共享 HAD 世界中的胜率受模型误差和跨战场外部性影响，不要求它严格高于主方法，也不把它称为真实胜率理论上界。

## 3. 与上一版比较的解释

流水线自动读取：

- `outputs/mvp/stage23_bayesian_adaptive_v3/stage3/analysis/summary.json`
- `outputs/mvp/stage23_bayesian_adaptive_v3/stage2/model/metrics.json`

上一版匿名/count-based Stage3 与本轮在数据域、动作表示和 Blue 上层协议上不同，所以只能作为非配对历史量级，不能把胜率差单独归因于身份级建模。

是否改善主要由以下证据判断：

1. 本轮配对 `identity_blotto - balanced_identity`；
2. 身份、固定目标和 4v4 约束是否逐条成立；
3. 小规模求解是否与完整矩阵一致；
4. Stage2 是否在真实合法域上校准；
5. 大规模规划是否在时间限制内返回可审计结果。

## 4. SALDAE-DO 增量实验

该实验保持 v5 的身份级 Blotto、Stage2 checkpoint、HAD交互、固定目标、1–4人上限、Red reserve 与 Blue 精确覆盖不变，只比较最佳响应求解器。

### E4-A：完整小博弈质量

在 3R/3B、2目标完整矩阵上比较 SALDAE-DO 与精确零和价值。SALDAE是启发式anytime算法，不要求或伪造 `full_game_certified=true`；10个正式场景的最大价值误差门槛为0.05，并检查报告没有错误全局证书。

### E4-B：30/40/50人同状态规划

在同一个HAD状态先运行空间候选列MILP-DO，再以其完整均衡支持热启动SALDAE-DO。每个规模3次，只报告：

- 两种方法的规划时间；
- SALDAE相对旧Blue混合策略找到的Red域外响应增益；
- SALDAE相对旧Red混合策略找到的Blue域外响应增益；
- 是否实际使用未注册身份联盟。

Red和Blue的响应增益分别衡量旧候选域对两方的遗漏，不把SALDAE自身的经验gap称为全局exploitability证书。

### E4-C：HAD同种子配对

30/40/50人与2/4/5个固定目标下，对 `rush`、`split_rush` 分别运行：

1. `milp_do`：双方使用旧候选列MILP-DO；
2. `saldae_do`：双方使用MILP热启动的SALDAE-DO。

每格5局，共60局。主要结果是各目标数胜率和同种子 `saldae_do - milp_do` 配对差；规划时间作为必要代价指标。若代理响应改善但物理胜率未改善，报告必须明确写成“求解域改进，端到端收益未证实”。

## 5. 正式运行

前台运行：

```powershell
& .\scripts\run_stage23_aligned.ps1 -Mode Formal -RunRoot "outputs\mvp\stage23_identity_blotto_v5"
```

后台运行：

```powershell
& .\scripts\run_stage23_aligned.ps1 -Mode Formal -RunRoot "outputs\mvp\stage23_identity_blotto_v5" -Background
```

本次 Stage2 已完成且通过验收。修正 Stage3 后应使用恢复入口，跳过19,200局采集与训练：

```powershell
& .\scripts\run_stage23_aligned.ps1 -Mode Formal -RunRoot "outputs\mvp\stage23_identity_blotto_v5" -ResumeStage3 -Background
```

恢复入口不会无条件相信旧文件。它要求 Stage2 状态为 `completed/accepted`，并校验配置语义、完整调度哈希、Stage1哈希、数据集哈希、训练配置哈希和 checkpoint 哈希；任何一项不一致都会在 Stage3 启动前失败。验证记录写入 `reused_stage2_validation.json`。旧 Stage3 失败原因只保留一份简洁记录于 `diagnostics/stage3_failed_attempt.json`，不复制大体积中间输出。

PowerShell 的 `-ResumeStage3` 对应底层 Python 参数 `--reuse-stage2`；常规实验使用上面的 PowerShell 入口即可。

只做快速连通性测试：

```powershell
& .\scripts\run_stage23_aligned.ps1 -Mode Smoke
```

不要把 Smoke 结果用于论文结论。

SALDAE-DO 独立正式实验（自动复用已完成的Stage1/2，只运行Stage3增量实验）：

```powershell
& .\scripts\run_stage3_saldae.ps1 -Mode Formal -Background
```

只做SALDAE连通性与约束烟雾测试：

```powershell
& .\scripts\run_stage3_saldae.ps1 -Mode Smoke
```

## 8. 自动判定

只有小博弈正确、物理计划约束全通过、规划时间达标，且身份级方法相对均匀基线没有低于 -5 个百分点的实质退化，Stage3 才通过本轮门槛。

若结果未通过，报告必须定位为以下三类之一：

- Stage2 价值/校准问题；
- 大规模候选域或求解时间问题；
- 局部可加代理迁移到共享 HAD 后失效。

门槛通过只说明当前原型值得继续，不证明大规模完整动作空间全局最优，也不证明已处理未知 Blue 策略库。
