## 1. 本版范围与固定口径

- 学习方法只用训练种子 **0、1、2**，不自动追加 3/4。规则没有训练种子，保留同一组固定场景锚点。
- HAD 每运行 **1,000,000 物理步**；SMACv2 每运行 **4,000,000 联合环境决策步**。末次采样可能存在已注明的小幅物理步超额，报告实际值。
- 正式比较只用达到预算、完成训练的 **final.pt**。best.pt 只保留训练内选择记录；不得缺 final 回退 best，也不按 OOD 成绩挑权重。
- 每个正式配置、每个训练种子 **300 回合**。共同场景使方法之间可配对，但训练种子仍是统计独立单位。
- 训练与训练内验证保留当前 GPU 批处理链路；终评使用 CPU+GPU，M1、M2、M3 用 CPU。M4 在两卡中选择一张并登记，全部48格使用同一卡，不能与本项目训练重叠。
- **允许物理 GPU0、GPU1**，按实时可用显存选择，不设固定优先级；只管理本项目进程，不操作 Ollama 或他人的任务。
- 代码继续沿用 `ParallelRunner → EpisodeBatch → controller → learner → mixer`，入口仍为 `train.py / eval.py / plot.py`；只增加 profile、原生观察可选字段、算法与任务分支，不复制训练框架。

|---|---|---:|
| regir | Full，采集按回合抽R，学习按更新另抽R，R∈1…4 | 复用3 |
| regir_r1 | Single，采集与学习固定一轮 | 复用3 |
| refil / b2_qmix_atten / dcg / spectra / alma | 原有完整算法对照 | 各复用3 |

### TransfQMix 来源及适配

[TransfQMix正式论文](https://www.ifaamas.org/Proceedings/aamas2023/pdfs/p1679.pdf)发表于AAMAS 2023；固定[作者代码](https://github.com/mttga/pymarl_transformers/tree/2ef0a0726f1f186097b4b560509ceb5a801fdafe)的提交 `2ef0a0726f1f186097b4b560509ceb5a801fdafe`。

| 项目 | 固定设置 |
|---|---|
| actor / mixer | embedding32、4 heads、2层、FFN×4、dropout0；保留作者每head32维投影 |
| 学习 | Adam lr=.001、γ=.99、TD(λ)=.6、clip10、Double-Q |
| replay / minibatch | 5000 / 32 episodes |
| epsilon | 100k联合步内1→.05；终评0 |
| target | 每200训练episodes硬更新 |
| 更新频率 | replay足够后，每个新完成episode对应1次更新；并行8回合即8次 |
| 输入 | 关闭agent ID、上一动作one-hot，保留时间记忆 |

HAD采用通用九动作头；SMAC保留作者六基础动作加共享敌人评分头。各层固定K/V的**来源**，各层仍有各自投影。保留mixer对agent hidden的detach；online/target mixer初始及后续记忆统一为论文§4.3的三个hyper token。补充变规模padding、可见性和动作mask。源码标明来源及许可未明确状态，不擅自套用其他基线许可证。

### 机制解释边界

Single vs Full@R1比较深度训练方案整体；Full@R1 vs Full@R4比较同权重增加执行深度；Fixed4 vs Untied4比较共享参数（同时报告参数量）；Full vs KV0比较更新表征再次进入K/V；Full vs last比较保留中间读出的训练收益；Full vs matched/TransfQMix分别挑战容量解释和完整算法竞争力。读出干预只说明已训策略依赖什么，不能替代重训消融。

## 4. M1–M4 机制任务

| 任务 | 固定内容 | 环境运行量 |
|---|---|---:|
| M1 | Full的3个final；10/30/50同人数K2；R1…6 | 新增最多13,500局，R4复用final |
| M2 | 固定计算4轮和4次读出；Learned、Read1…4、Uniform；10K2/50K2/30K12 | 新增11,700局；不复用Read1时上限13,500 |
| M3 | 五配置公共500轨迹，同状态导出三checkpoint的H0…H4并拟合probe | 公共轨迹500条，不乘3 |
| M4 | REFIL/matched/Single/Full/Fixed4/Untied4/KV0/TransfQMix，3种子，N10/N50 | 复用M3状态，不增加对局 |

M1/M2使用相同final和登记场景。三个已训Full的Read1@4与R1，在同一合法混规模输入和非零h_prev下Q/hidden逐位相同，证据及三个checkpoint_id已登记 `experiment.json`；仅复用真正相交配置和场景。Uniform接近Learned时需收窄关于学习深度权重的主张。

M3公共配置为10v10 K2/K3、30v30 K2、50v50 K2、30v30 K12，每配置100轨迹，50来自Full seed0、50来自REFIL seed0 final，场景seed200000…200499，与正式终评流分开。每轨迹取至多4个有效时刻、至多2名观察者、5名敌人；本版按稳定槽顺序取前两个/前五个合法对象，保留此选择边界。保存完整原始观察/动作前缀，在每个被分析模型自己的同一h_prev下读取H0…H4，历史以真实行为动作teacher-force重建。

三个标签只用观察者可见信息：敌人到最近目标的距离、到其他存活可见防守者的最近距离、最近目标分区敌我人数不平衡；沿用L=2500。未定义标签剔除并报告比例。ID每配置50/25/25作拟合/验证/测试，OOD每配置50探索/50确认；按场景分组且按行为策略分层，防止行为来源与划分混淆。每训练seed独立ridge，标准化仅ID训练；λ候选1e-4/1e-3/1e-2/.1/1/10/100，以跨轮平均ID验证表现选择。报告测试R²（保留负值）；控制包括H0、3个未训练同架构网络、置乱训练标签。可读性不单独证明因果机制。

M4只计全队actor前向，不含环境step、mixer和状态构建；三种子使用同一公共场景/时刻/实际行为动作前缀。固定FP32、batch1，先重建h_prev，每次调用在计时外恢复相同历史；50次预热、200次GPU同步计时，记录中位数、p25/p75/p95。分别列部署actor参数及训练总可训练参数（在线actor+mixer，不含target副本）；每方法/seed/N一行，保留身份与设备说明。待HAD GPU训练结束后单独排队；按可用显存选择并登记同一张物理GPU，48格均使用该卡，记录共享显存条件，不声称独占课题组整张卡。

no-imagined-loss、Uniform重训和配对几何场景不在默认队列。

保持四个训练规模实例切换（每worker最多缓存4个），不依靠reset更改已构造实例人数。沿用[官方Protoss分布](https://github.com/oxwhirl/smacv2/blob/577ab5a2cff2391f8df582da5731ea9cd6adf3c6/smacv2/examples/configs/sc2_gen_protoss.yaml)：stalker/zealot/colossus=.45/.45/.10，等人数敌军复制己方构成，不对称配置再补敌人；不改原生奖励与战斗规则。

| 项目 | 协议 |
|---|---|
| 方法 | Full、Single、REFIL、QMIX-Atten、SPECTra、TransfQMix |
| 训练 | 每回合均匀4v4/6v6/8v8/10v10，共享一套策略 |
| 数量与预算 | 6方法×3种子×4M，共18运行、72M步 |

actor使用原生局部 `observer_entities[A,E,32]`，只做字段重排/补零；中央 `entities[E,18]` 仅给mixer，不用于补齐不可见信息。存在、可见性、动作mask均保留；可见不等同于可攻击。角色为self/ally/enemy，count与类型分支内部统一映射friend=self+ally、enemy、target=0，维持HAD计数语义。REFIL imagined先与局部可见性取交集，再进行编码、计数、循环和共享攻击头。

终评在 `scenes/manifest.json` 预生成8×300完整官方reset_config，同时记录scenario_seed和engine_seed。每回合新game；错误重试同场景最多3次（评估环境内部reset重试设1，外部总预算3）。失败仍未完成，不计作战败、不替换场景。每方法/seed的协议故障记录随恢复保留。

训练恢复保存网络、target、优化器、replay、Python/NumPy/Torch/CUDA RNG、调度进度、环境抽样RNG；SC2内部引擎运行态不能序列化，不声称恢复跨进程战斗轨迹逐位一致。正式评估的新game/登记场景独立于评估顺序。

正式训练前核验去重11配置、混规模batch、有限TD、局部信息隔离、padding、攻击映射、死亡/no-op、timeout以及恢复。本版固定4M；ID训练内未学会时只报告有限预算表现，不能称为泛化失败。

共享显存的空闲量可能在准入后变化。CUDA OOM 时子训练器释放资源，保留最后一个完整采集＋更新事务的恢复点，禁止用半更新的网络覆盖它。父队列最多自动重试3次，分别至少等待60/120/240秒，再检查两卡显存并重新选择；恢复包含模型、target、优化器、replay、RNG和进度。正常周期每600秒保存，并在首次完整更新和验证前保存；OOM可能重做上次安全点之后的工作。无安全恢复点的初始化故障或重试耗尽会明确报错、受控停止其余本项目任务并保留日志，不能标成训练完成。`failure.json`、`resource_retry.json`、`resource.json`记录原因和状态。

M4显存异常保留已完成测量格，使用同一登记卡受控重试；CPU终评/机制不占GPU显存。运行器用`nohup`启动后不依赖交互终端存活；终止请求仍须等待子进程完成当前事务并被回收。临时文件、编译缓存、运行锁位于工作区的`tmp/`、`.cache/`，不改共享环境和他人目录。
