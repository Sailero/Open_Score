# main0923：试训 → 分支闸门 → 公共 + 分支特有实验（执行协议）

本文件固定 main0923 的实验设计与运行方式，依据是 `docs/HAD实验复盘与AAMAS2027论文规划.md`（下称“规划文档”）第 4、5 章。机器可读的矩阵、闸门规则与登记时间见同目录 `experiment.json`（首次 `start` 之前由初始化写入，试训期间不修改）。正式结果以 `decision/分支判定.md`、`episodes.csv`、`learning.csv` 为准。

## 1. 目的

用五种子 IQM 替换 main0921 的规划数字，并在事先登记的规则下，从三个逐级叠加机制的候选中选定主方法：

| 级别 | 论文名 | 代码键 | 相对上一级新增的机制 | 种子 |
|---|---|---|---|---|
| 地基参照 | R0 | `regir_r0_sg` | 记忆查询直接读原始实体 H0（一阶） | 0–2 |
| C | 1-round（RCR） | `regir_r1_sg` | 实体两两注意力 1 轮 + 记忆条件读出（二阶） | 0–4 |
| A | ARR | `regir_kv0_sg` | 锚定迭代：每轮 K/V=H0，随机深度 1–4，测试 R=4 | 0–4 |
| B | IAR | `regir_kv0_intent_sg` | 队友意图推断：预测可见队友动作分布并注入下一轮 K/V | 0–4 |

四者都以 REFIL 为宿主，启用 `global_query_detach_memory=True`（读出查询中的 GRU 记忆不回传梯度，前向不变；规划文档 S1）。其余学习超参与 main0921 相同：HAD 1M 物理步、训练分布 N∈{4,6,8,10}、K∈{1,2,3}、8 个采集 worker、每 20k 步 4 配置 ×25 局验证、只用最终模型、24 配置 × 场景 9000–9299 终评。

## 3. IAR 的定义（`rer_intent=True`，建在 ARR 的锚定迭代上）

- 每轮结束后，对观察者视角中每个**可见、存活**的红方队友槽位（不含自己），用共享预测头 $W_p$ 从当前表征 $H^r_j$ 预测它这一步的动作分布 $p^r_j$（HAD 9 类；SMAC 7 类 = 6 个基础动作 + 合并的“攻击”）。
- 意图嵌入 $e^r_j=W_e p^r_j$（无偏置），下一轮 K/V 为 $H^0+E^r$，$E^r$ 只在队友行非零；第 1 轮 K/V 仍为 $H^0$。$W_e$ 零初始化，预测头与嵌入在独立分叉的随机数流中创建，因此**训练开始时 IAR 与同种子 ARR 的全部其他参数、mixer 初值和 Q 值逐位相同**（已验收）。
- 辅助损失：$p^r_j$ 与队友 $j$ 在该时间步真实动作的交叉熵，对轮次（≤本批采样深度）与可见队友取平均，只用主批次（不含 REFIL 想象分支），`intent_aux_weight=λ=0.02`。λ 事先按“辅助损失初值（ln9≈2.2）×λ 与 TD 损失初值（≈0.045）同量级”确定，不调参。
- 执行时只用观察者本地信息，无通信；测试 R=4，R=1 时没有意图注入。
- 有界性：$\|W_e p\|\le\|W_e\|_2$（$p$ 在单纯形上），与团队规模无关。

## 4. 训练矩阵（同一“代码键×种子”只训练一次）

| 段 | HAD | SMAC（2M 步，3 种子） |
|---|---|---|
| 试训 | B、A、C 各 5 种子 → R0 3 种子（按此顺序排队） | — |
| 公共 | Looped `regir_sg`（P0）、Untied4 `regir_untied4_sg`（P1） | REFIL、SPECTra、TransfQMix、1-round（P0）；QMIX-Atten（P1） |
| 分支 C | `regir_r1_nomem`（P0）、`regir_r1_norefil_sg`（P1）、`regir_r1_nocount_sg`（P2） | ARR（P2） |
| 分支 A | `regir_kv0_nomem`（P0）、`regir_kv0_norefil_sg`、`regir_kv0_fixed4_sg`（P1）、`regir_fixed4_sg`、`regir_kv0_nocount_sg`（P2） | ARR（P0）、Looped（P2） |
| 分支 B | `regir_kv0_intent_noaux_sg`（P0）、`regir_kv0_intent_nomem`（P1）、`regir_intent_sg`、`regir_kv0_intent_norefil_sg`（P2） | IAR（P0）、ARR（P1） |

合计 HAD 60 次训练（试训 18、公共 6、C 9、A 15、B 12），SMAC 24 次（公共 15，ARR 被三个分支共用）。

**放行顺序**：试训 → 公共 P0 → 特有 P0 → 公共 P1 → 特有 P1 → P2。HAD 公共在试训训练全部结束（完成或判为失败）后放行；SMAC 公共从一开始放行；特有任务在 `decision/branch.json` 出现后放行。等待人工决策期间，被 ≥2 个分支共用的任务（SMAC ARR）预先启动。

**并发**：HAD 每卡 ≤3 路；SMAC 试训期间每卡 ≤1 路，试训训练结束后每卡 ≤2 路；HAD 评估 ≤32 进程、SMAC 评估 ≤16 进程（可用 GPU 分片）。显存按实时空闲量准入：`_sg` 变体沿用 main0921 同结构的实测峰值；IAR 没有先例，第一个 IAR 训练按“未知架构”规则单独启动，测得峰值后其余再并行。

**速度守护**：HAD 试训与 SMAC 并行满 2 小时后，若试训训练的平均速度低于 main0921 同结构速度的 80%（`experiment.json["reference_speed"]`；关系变体缺同名记录时按 ARR），SMAC 训练保存恢复点暂停，直到试训训练结束。

## 5. 训练记录、失败与重试

- 每次采集记录该批 8 次更新的最大梯度范数 `grad_norm_max` 与累计尖峰数 `grad_spikes`（梯度范数 >10，或 >前 200 次更新中位数的 20 倍）；IAR 另记 `intent_loss`、`intent_acc`。面板中单个训练尖峰 >5 标黄。
- **训练失败判据**（对所有方法同样统计，附录报告次数）：结束时（第 50 个验证点，1M 步）ID 验证损伤 >1.0，或第 25 个验证点（50 万步）仍 >3.0。
- **自动重试**：训练进程异常时从最近的完整恢复点（`resume.pt`，不可读时 `resume.prev.pt`）重试，最多 2 次；第 3 次失败后标为失败（`task_failure.json`），需要 `retry`。CUDA OOM 单独处理：释放显存后按 60/120/240 秒退避、按实时显存重新准入，最多 3 次。评估任务失败自动重试 2 次。单个任务失败不影响其他任务。

## 6. 评估

- **终评**：24 配置 × 300 局（场景 9000–9299），每个最终模型训练结束后立即开始。所有新模型的每一局都记录 `dup_pursuit_frac`（M-G2），IAR 系列另记逐轮意图预测统计 `intent_stats`（top-1 命中、NLL、标签直方图）。
- **闸门辅助评估**：A、B 在 10v10、50v50 K2 上以 R=1 跑每格 100 局（`gate:depth:R1`，R=4 复用终评前 100 局）；B 的意图预测准确率直接取终评中 10v10、30v30、50v50 K2 前 100 局的记录（同一批场景，不另跑），与“总是预测最常见动作”的基线比较。
- **M-G2 重复追击率**：每步统计“被至少两架存活红机同时追击”的蓝机占存活蓝机的比例，按回合平均；“追击”= 红机与该蓝机距离 <1500 m 且红机速度方向与指向蓝机方向夹角 <30°。导入基线在 10/30/50v K2 上补跑每格 100 局（`arm=dup`，公共 P1）。
- **复用**：R=4 方法的终评即 `depth:R4`、`readout:learned`；`gate:depth:R1`、`depth:R1`、`deploy:R1` 在同一场景上互相复用（同一策略、同一深度、同一场景种子，策略随机数只由模型种子、配置与场景种子决定）。
- **分支机制评估**（分支确定后入队）：A — 执行深度 M-C（ARR 5 种子、Looped、ARR-Fixed4、Untied4；10/30/50v K2 × R=1–6，Untied4 为 1–4，每格 300 局）、读出干预 M-D（ARR 5 种子、Looped；50v50 K2 与 30v30 K12）、单轮部署 M-R1（ARR 5 种子 × 24 配置 × 300 局，R=1）、SMAC 执行深度 M-S1（10/15/20v × R=1、2、6 × 100 局）；B — 执行深度（IAR 与 ARR）、意图干预 M-T2（均匀、同观察者内打乱、换成队友本步真实动作的上界诊断；10/30/50v K2 × 100 局）、SMAC 执行深度。
- 统计：每种子每格 300 局求均值 → 组内配置等权 → 跨种子 IQM（5 种子时去掉最好与最差各 1 个后取均值；3 种子时即均值），分层 bootstrap（种子 × 配置）区间；附录保留均值 ± t 区间与逐种子值。

## 7. 分支闸门（`gate_v2`，试训启动前登记）

触发：C、A、R0 的训练与评估（终评、闸门辅助评估）全部完成，且 B 同样完成；B 未完成时最多等到 **2026-09-26 18:00（北京时间）**，之后只在 C、A 之间判定，B 的结果进附录。

1. 每个模型每个种子计算四组的组均值（ID、N-OOD、K-OOD、联合；组内配置等权）与 OOD 综合分 $O$ = 三个 OOD 组的平均；主统计量为 5 个种子 $O$ 的 IQM。
2. 分层 bootstrap 10,000 次（候选内对种子有放回重采样，三个 OOD 组内对配置有放回重采样、各候选共用同一次配置抽样），得到“X 优于 Y”的概率。
3. **X 显著优于 Y**：$(\mathrm{IQM}_Y-\mathrm{IQM}_X)/\mathrm{IQM}_Y\ge10\%$ 且概率 ≥0.90。
4. **地基检查**：C 必须显著优于 R0，否则一律转人工，报告首行标红。
5. **自动判定**（沿 C → A → B 逐级）：选满足下列全部条件的最高一级 $h$：(a) $h$ 显著优于阶梯上所有更低级别；(b) 没有更高级别的 $O$-IQM 数值更低；(c) 按训练内验证（最终验证点的 ID 损伤）挑出的最好 3 个种子，$h$ 的 $O$ 均值也低于所有更低级别；(d) 5 个种子中失败 ≤1 个。若 A、B 的 IQM 都不低于 C，自动选 C。任一候选失败 ≥2/5 时转人工并标出。其余情况转人工（典型：更高一级数值更好但不显著）。
6. 输出：`decision/分支判定.md` 与 `decision.json`；自动选定时写 `decision/branch.json`（`mode=auto`）并立即放行该分支；需要人工时创建 `decision/DECISION_REQUIRED`，面板首行提示 `select`。
7. 人工选择总是优先：`select X` 随时可用；试训结束前执行记为预先选择（闸门仍生成报告）；已选定后改选需 `--force`，原分支未完成的特有任务被移出队列并记为 `abandoned`，已完成的保留进附录。代码只判断性能与稳定性，故事取舍由你决定。

## 8. 命令（全部通过本目录的 `run_all.sh`）

```bash
cd /data3/dell/Saileron/projects/ReGIR
OUT=Open-SCORE/outputs/main0923
bash $OUT/run_all.sh start              # 首次：导入 main0921 → 验收（G3/G4，若未记录）→ validate → 后台启动流水线
bash $OUT/run_all.sh status             # 实时面板（--once 打印一次）
bash $OUT/run_all.sh stop               # 训练在当前批次后保存 resume.pt，评估写完当前局
bash $OUT/run_all.sh resume             # 暂停或任何意外中断之后续跑
bash $OUT/run_all.sh decide --preview   # 用已完成的种子预览判定（不触发分支）
bash $OUT/run_all.sh decide             # 重新生成正式判定报告
bash $OUT/run_all.sh select A|B|C [--force]
bash $OUT/run_all.sh cut P2 [--now]     # 截止前取消某优先级尚未开始的任务；--now 同时停止正在跑的
bash $OUT/run_all.sh retry METHOD SEED [--env smacv2]
```

日志：`run_all.console.log`（主循环）、`train.{had,smacv2}.console.log`、`eval.{had,smacv2}.console.log`、各运行目录的 `console.log`；状态文件：`pipeline.json`、`inventory.json`、`queue.{env}.json`、`scheduler.*.json`。

## 9. 实现验收（记录于 `implementation_acceptance.json`）

- `main0923_new_methods`（HAD，18 个新代码键 × 各自种子，共 60 行）：8 worker 混合规模采集、一次 TD 更新有限且参数变化、从快照重建的学习器下一次更新逐位一致；截断检查（开关前后损失逐位相同，读出查询经 `h_prev` 的梯度为零，关闭时非零）；IAR 专项（与同种子参照逐位同初值与同 Q、队友动作标签按视角置换对齐且自己/死亡/不可见/padding 不参与、修改不可见队友不改变观察者的意图预测与 Q、嵌入有界、200 次 CPU 更新内辅助损失下降、λ=0 时不产生辅助梯度）；R0 修改轮次参数不影响输出；NoMem 读出查询与 `h_prev` 无关；Fixed4 训练深度恒为 4。
- `smac_main0923_extension`（SMAC，`regir_r1_sg、regir_kv0_sg、regir_sg、regir_kv0_intent_sg` × 0–2）：4 worker 真实 SC2 混合规模采集 16 步、TD 更新、参数变化、恢复后下一次更新逐位一致、死亡/padding 的 Q 为零；种子 0 在 20v20 下严格加载参数并完成一局；IAR 的 7 类标签映射。输入路径与 main0921 已验收的 `regir/regir_r1` 相同。

## 10. 与规划文档的对应和实现上的取舍

- 规划中单列的 `gate:intent` 评估不另跑：意图统计在 IAR 的每一局评估中记录，闸门取终评里同一批场景（前 100 局）。
- 规划中的 M4 与轨迹诊断（M-V / M-B/J / M-F / M-I / M-K / M-T1）已接到 HAD 评估队列：终评出现后自动跑，不新加第 5 个调度器，不占训练卡。M4 在试训训练结束后、有空闲 GPU 时才测（增量：先测已有 final，后补 Looped/Untied4）。闸门要的参数量仍从最终模型计数。`python scripts/plot.py --output $OUT` 写身份校验后的 `实验报告.md` 与 `aggregates.json`（300 局、`checkpoint_id`、场景种子；缺格为 —，不插值；导入基线 IQM 与 main0921 表 1 逐项核对）；`--paper` 出 3 图 2 表论文版。TransfQMix 作者仓库 K/V 核实与离线梯度复查仍是人工项。需要 `stop` 再 `resume` 后新任务才会进入正在跑的流水线。
- Read-1 等价验证（G5.2）尚未登记为通过，因此 `readout:read1` 不复用 `depth:R1` 的结果，只是多跑一些局，不影响正确性。
