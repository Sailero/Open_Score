# main0928 远程操作说明

在远程服务器上拉取 `remote_train` 之后，按本文做环境与训练。实验协议见同目录 [实验计划.md](实验计划.md)。本文件只讲「机器上要敲什么」。

仓库：`git@github.com:Sailero/Open_Score.git`  
分支：`remote_train`（不要用 `main` 跑这一轮）  
输出目录：克隆根下的 `Open-SCORE/outputs/main0928`

---

## 1. 目标是什么

- 主方法是 **Looped**（代码键 `regir_sg`）：无 count、读出记忆梯度截断。
- 只有 HAD 上的 `regir_count_sg` 带 count。
- 3 个种子。HAD 新训 10 方法 × 3，SMAC 新训 8 方法 × 3。HAD 的 7 个外部基线从 `imported/` 展开，不重训。
- 多机挂同一份 `outputs/main0928`，自动发现 GPU、抢任务、心跳释放。
- 训练中会重写 `实验报告.md`。全部完成后（也可中途手动）打两个 zip 用 `scp` 拉走。

---

## 2. 拉代码

在**共享盘**上只克隆一份（多机推荐这样做）：

```bash
git clone -b remote_train git@github.com:Sailero/Open_Score.git
cd Open_Score
git status   # 应显示 ## remote_train...origin/remote_train
```

每台机器的工作目录都进这个克隆。不要在每台机器各克隆一份还各写一份 `outputs/main0928`，那样任务不会协同。

如果必须每台一份源码：把**这一目录**做成指向同一共享路径的符号链接（先在共享盘放好带 `imported/` 的 `main0928`，再链过来）：

```bash
# 示例：源码在本机，实验目录在 NFS
rm -rf Open-SCORE/outputs/main0928
ln -s /path/to/shared/main0928 Open-SCORE/outputs/main0928
```

## 3. 配环境（优先复用已有 conda 环境 `sarc`）

本仓库默认**复用名为 `sarc` 的 conda 环境**：已有的 PyTorch / CUDA 会留下，不再重装。脚本只会往这个环境里再装本仓库的 `had-env`、`open-score`，以及 SMAC 需要的 `protobuf==3.20.3` 和 `SMACv2`。

在每台要跑训练的机器上，于**仓库根**执行：

```bash
# 若 sarc 已能 conda activate，先激活再跑，定位更快
conda activate sarc
bash scripts/setup_farm.sh
```

成功时日志里会有 `reusing conda env 'sarc' at ...`，以及 `reuse torch ...`。不要看到这两行还以为失败了。

| 变量 | 默认 | 作用 |
|---|---|---|
| `REUSE_ENV` | `sarc` | 要复用的 conda 环境名 |
| `HAD_PY` | （空） | 直接指定 HAD 的 python，绕过按名字查找 |
| `SMAC_PY` | （空） | 直接指定 SMAC 的 python |
| `FRESH=1` | 关 | 忽略 sarc，在克隆内用 micromamba 新建 `envs/saileron` |
| `SKIP_SC2=1` | 关 | 不下载星际争霸 II；SMAC 任务保持 pending，HAD 仍可训 |
| `SC2PATH` | `envs/StarCraftII` | 若本机已经装过 4.10，指到现成目录 |
| `SAILERON_ROOT` | 克隆根 | 缓存和临时文件位置。克隆在 NFS 上时请改到本机磁盘 |

常见变体：

```bash
# sarc 不叫 sarc，或 conda 不在 PATH 上
REUSE_ENV=你的环境名 bash scripts/setup_farm.sh
HAD_PY=/abs/path/to/sarc/bin/python bash scripts/setup_farm.sh

# 仓库在 NFS：缓存写到本机，避免 NFS flock/临时文件打架
SAILERON_ROOT=$HOME/saileron-work bash scripts/setup_farm.sh

# 这台机器暂时不跑 SMAC
SKIP_SC2=1 bash scripts/setup_farm.sh

# 不要动 sarc，从零装一套
FRESH=1 bash scripts/setup_farm.sh
```

脚本会写：

- `envs/local.<主机短名>.env` — **这台机器**的 `PY` / `SMAC_PY` / `SC2PATH`（共享克隆时每台一份，互不覆盖）
- `envs/local.env` — 最近一次 setup 的副本，单机也可以 `source` 这个
- 若 HAD 的 protobuf 已是 3.20.x，SMAC 与 HAD 共用同一解释器
- 否则在克隆内的 `envs/saileron-smac` 建 `--system-site-packages` 的 venv，沿用 sarc 的 torch，只把 protobuf 钉在 3.20.3（不会去改你已有的同名 conda 环境；若你有专用 SMAC 解释器，设 `SMAC_PY`）

HAD 冒烟失败 = 还不能 `start`。SMAC 冒烟失败时 HAD 仍可训，SMAC 会一直 pending。

## 4. 启动训练

```bash
cd /path/to/Open_Score
source envs/local.$(hostname -s).env    # 可省略，run_all.sh 会自己 source
bash Open-SCORE/outputs/main0928/run_all.sh start
```

`start` 会：展开 `imported/` 基线 → 校验协议 → 在后台拉起本机 pipeline。多机就把上面这条在**每一台**上各跑一次（每台都要先跑过 `setup_farm.sh`）。

之后常用命令（任意一台、同一共享目录）：

```bash
bash Open-SCORE/outputs/main0928/run_all.sh status          # 实时面板，Ctrl+C 只关面板
bash Open-SCORE/outputs/main0928/run_all.sh status --once   # 打一行快照
bash Open-SCORE/outputs/main0928/run_all.sh report          # 立刻按当前 CSV 重写实验报告.md
bash Open-SCORE/outputs/main0928/run_all.sh bundle          # 立刻打 zip（训练中也是当前快照）
bash Open-SCORE/outputs/main0928/run_all.sh stop            # 只停本机：当前 batch 存 resume.pt 后退出
bash Open-SCORE/outputs/main0928/run_all.sh stop all        # 停所有机器
bash Open-SCORE/outputs/main0928/run_all.sh resume          # 本机从 resume.pt 继续
bash Open-SCORE/outputs/main0928/run_all.sh retry METHOD SEED
bash Open-SCORE/outputs/main0928/run_all.sh retry METHOD SEED --env smacv2
```

不要 `kill -9` 训练进程，也不要删 `cluster/claims/`。停机只用 `stop` / `stop all`。

`resume` 会清掉本机（以及共享的）停止文件，因此 `stop all` 之后若立刻在一台机器 `resume`，等于取消全场停止。应等各机 `status` 里没有 live 训练，再逐台 `resume`。

## 5. 多机行为（你不用再配 GPU 号）

- GPU 用本机 `nvidia-smi -L` 发现。HAD 默认每卡 3 路（上限 4），SMAC 每卡 1 路（上限 2）。
- 任务目录：`cluster/claims/<task_id>/`（NFS 上 `mkdir` 占坑）。心跳 `cluster/workers/<host>.json` 每 15 秒；120 秒无心跳则释放，别的机器从该 run 的 `resume.pt` 接着训。
- 无 GPU 的机器不会抢训练，最多做少量 HAD CPU 评估。
- 无 SC2 的机器不抢 SMAC。
- 日志：`run_all.<host>.console.log`、`train.had.<host>.console.log` 等，都在 `outputs/main0928/`。

## 7. 预算与矩阵（核对用）

- HAD 1M 步，SMAC 5M 步，验证间隔 40k。
- HAD 新训 P0：Looped / NoREFIL / R0 / 1-round / NoMem；P1：Last / Fixed4 / ARR / Untied4 / +count。
- SMAC 新训 P0：Looped / REFIL / SPECTra / TransfQMix / 1-round；P1：QMIX-Atten / ARR / Untied4。
- 导入基线（不训）：REFIL / REFIL-matched / QMIX-Atten / DCG / SPECTra / ALMA / TransfQMix。

## 8. 出了问题

| 现象 | 处理 |
|---|---|
| `setup_farm` 找不到 sarc | `conda activate sarc` 后再跑，或设 `HAD_PY=.../envs/sarc/bin/python` |
| 不想改 sarc | `FRESH=1 bash scripts/setup_farm.sh` |
| HAD smoke 失败 | 看是否 Python&lt;3.10，或 `had-env` 安装指向了别的树；日志里的 `had_env.__file__` 应在本克隆的 `third_party/HADE` |
| SMAC 一直 pending | 未装 SC2 4.10，或 `SC2PATH` 不对；可稍后设好 `SC2PATH` 再 `setup_farm` / `resume` |
| protobuf 冲突 | 不要把 SMAC 硬塞进 HAD 的 4.x protobuf；让脚本建 `saileron-smac` venv |
| 某任务失败 | `run_all.sh retry METHOD SEED` 后会重新入队 |
| 机器死了 | 等 120 秒，别的机器会接管其 claim |
| 误写了共享 `stop.request` | 各机 `resume`（会清停止文件） |
| 共享克隆上 A 机的 python 跑到 B 机去了 | 检查是否 source 了 `envs/local.<本机>.env`；不要手动 `source envs/local.env`（那是最后一次 setup 的机器） |

改了训练/调度代码并推到 `remote_train` 之后，各机 `git pull`，再 `bash run_all.sh resume`（先 `stop` 再 resume 更干净）。不要把 origin/`main` 推上去。
